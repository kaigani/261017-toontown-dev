# 03 — Colour, Palettes and Painting

**Scope.** This section specifies how colour works in the application: the colour model (palettes, palette styles,
swatches, colour IDs), the colour palette view and every palette/style/swatch command, the colour editor (solid colours,
gradients, alpha), texture swatches, tint offset and tint blend, the palette exchange file (`.animpal`), the painting
tools (paint, paint unpainted, unpaint, dropper, close gap, edit texture) and their options, automatic gap closing,
recolouring, transparency, and how colour data travels with drawings, the clipboard, templates and imports. It ends with
the agent interface for the `colour` namespace.

## 1. Concepts and data model

### 1.1 Indirect colour

Colour is **indirect**. Artwork never stores a raw RGB value for a painted zone, a line, a brush stroke or a text
object; it stores a **colour ID** that refers to a **swatch** in a **palette**. The swatch's actual value is looked up at
render time through the **palette style** selected for the scene being rendered. Consequences (MUST):

- Editing a swatch immediately recolours every zone, line, brush stroke and text object that uses it, in every drawing
  of the project (in every scene that shows the edited style).
- Switching a palette's style for a scene (for example from a "Day" style to a "Night" style) recolours all artwork in
  that scene that uses that palette's swatches, without modifying any drawing.

```
Project
 └─ Palette list (ordered, ≥ 1 visible palette)
     ├─ Palette "Default"
     │    ├─ Styles (ordered, ≥ 1): ["Default", "Night", ...]   each with a style ID
     │    └─ Swatches (ordered)
     │         ├─ Colour swatch: solid | linear gradient | radial gradient
     │         │     colourId, name, deformable flag,
     │         │     value per style: list of gradient stops (position 0..1, RGBA)
     │         └─ Texture swatch
     │               colourId, name, deformable flag,
     │               value per style: bitmap image + tile flag
     ├─ Palette "Character A" ...
     └─ (hidden internal palettes, never listed to the user)
 └─ Per-scene style map: for each scene, for each palette → selected style ID
 └─ Current colour (one colour ID, application-wide per open project)
```

### 1.2 Palette list

| Property | Requirement |
|---|---|
| Scope | One palette list per project, shared by all scenes. |
| Order | Ordered; the order is the order in which palettes are presented in the palette selector and in exports. New palettes are appended. |
| Minimum | At least one visible palette MUST exist; the last visible palette cannot be deleted. |
| Current palette | Exactly one palette is current. New swatches, tint operations and style operations from the GUI apply to it. |
| Hidden palettes | The list MAY contain internal palettes that are never shown to the user (e.g. a temporary palette that holds bitmap images as texture swatches while they are deformed by bones, or helper palettes used during an import). Hidden palettes MUST be excluded from the palette selector, the export list and dropper results, and are not user-editable. Agent queries list them only when explicitly requested. |
| Unique names | Palette names are unique within the project (case-sensitive comparison after trimming). When a name would collide (duplicate, import, creation by an importer), a unique name is generated by appending a space and the next free number: `Skin` → `Skin 2` → `Skin 3`. |
| Automatic colour update flag | A project-level boolean controlling whether swatch values arriving with pasted templates overwrite the values of swatches with the same colour IDs already in the project (§11.3). Default: off (project values win). |
| Loading | While a project's palettes load, progress feedback is shown (see section 01 for progress reporting). |

### 1.3 Palette

| Field | Type | Rules |
|---|---|---|
| id | opaque ID | Unique; assigned at creation; never changes. |
| name | string | Non-empty after trimming; unique in the project. |
| styles | ordered list of `{id, name}` | At least one. Style names are unique within the palette. |
| swatches | ordered list | User-controlled order (drag reorder or `colour.swatch.move`). MAY be empty. |
| hidden | bool | Internal palettes only (§1.2). |

### 1.4 Swatch

All swatch kinds share: **name** (string; names may repeat — names are labels, IDs are identity), **colourId**
(opaque ID, unique across the whole project), **kind**, **deformable** flag (whether a gradient/texture fill follows
bone deformation of the drawing, §7.5) and **one value per style** of the owning palette.

| Kind | Per-style value |
|---|---|
| `solid` | One RGBA colour, 8 bits per channel, alpha 0 (transparent) … 255 (opaque). |
| `linearGradient` | 2 … n stops, each `{position 0.0–1.0, RGBA}`. Colours interpolate along a straight axis. |
| `radialGradient` | 2 … n stops; colours interpolate outward from a centre. |
| `texture` | A bitmap image (stored in the project package, section 10) + **tile** flag (tile = repeat the image; off = stretch the image over the zone). Pixel width/height are derived from the image. |

Rules:

- **Value per style.** Every swatch holds one value for each style of its palette. Creating a style copies the values of
  the style it was created from; afterwards each style's value is edited independently. ID, name, kind and deformable
  flag are shared by all styles; only the colour/gradient/texture value differs.
- **Kind is shared across styles** for colour swatches: changing solid ↔ gradient (or linear ↔ radial) converts the
  swatch in all styles (§6.4 for the conversion rule); stop lists may differ per style.
- A texture swatch stays a texture swatch; it cannot be converted to a colour swatch or vice versa (create a new swatch
  instead). Two styles of the same palette MAY use different images for the same texture swatch (e.g. a "summer" and a
  "winter" fabric).
- Each gradient stop carries a stable stop index within the swatch so that the editor can keep track of the selected stop
  while stops are moved.

### 1.5 Palette styles and the per-scene style map

- A **palette style** is a complete alternative set of values for all swatches of a palette — e.g. "Normal", "Night",
  "Underwater".
- The applied style is chosen **per scene**: the project stores, for each scene and each palette, which style is active.
- Choosing a style in the style selector sets the style for the **current scene** only. It is undoable ("Style Change").
- When the user switches to another scene, the style selector shows that scene's style for the current palette.
- New scenes start with the first style of each palette. Palettes added later are shown in every existing scene with
  their first style.
- Rendering (Camera view, Drawing view, playback, export) resolves a colour ID as: find the palette containing the ID →
  take the style selected for the scene being rendered → take that style's value. If the ID is not found, the fallback
  colour is used (§1.7). Rendering a drawing outside any scene context (e.g. in a library thumbnail) uses each palette's
  first style.

Typical use: a character palette with styles "Day" and "Night"; scene 3 selects "Night"; all the character's drawings
render with the night values in scene 3 only.

### 1.6 Colour IDs and how artwork references colours

| Rule |
|---|
| Every palette, style and swatch has an opaque ID, unique across the project. IDs SHOULD be globally unique (e.g. random 128-bit or time-plus-random), because colour IDs travel with drawings, the clipboard and templates between projects and must not collide accidentally. |
| Drawings store colour IDs, not values. In a vector drawing (section 02): a **zone** has an *inside colour*; a **pencil / centre line** has a line style that includes a colour ID; a **brush stroke** is a filled shape whose fill is a colour ID; a **text object** references a colour ID. A pen preset (section 02) MAY also reference a colour ID. |
| A fill reference is a colour ID **plus a 2×3 affine mapping matrix** that positions/scales/rotates/skews a gradient or texture inside that particular zone (§7.2). For solid colours the matrix is ignored but preserved. |
| Vector strokes carry the fill reference of the zone on each **side** (left/right) through the zone model of section 02, which is how two adjacent zones separated by one stroke get different fills. |
| Duplicating a style keeps swatch IDs; duplicating a palette creates new IDs (§3.2); importing palettes follows the import ID policy (§3.6). |
| A drawing embeds a **recovery copy** of every swatch it uses: colour ID, owning palette name, owning style name(s) and the full swatch definition per style. This allows missing swatches to be rebuilt when the drawing is opened, imported, pasted or loaded from a template in a project that lacks them (§11.2). |

### 1.7 Special colour identities

| Identity | Meaning |
|---|---|
| Unpainted | A zone with no fill (fully transparent) or a line without visible colour. Produced by unpaint; the target of paint unpainted. Zones created by drawing lines start unpainted. Represented as the colour ID `null` in agent JSON. |
| Fallback | Used when a referenced colour ID cannot be resolved (deleted and not recoverable). **Design decision:** render fallback as opaque mid-grey in the viewer and flag the object in `colour.missing.list`; export renders it the same way. |
| Internal tool colours | Any colour used internally by tools (e.g. eraser preview geometry) MUST NOT appear in palettes or in agent results. |

### 1.8 Default palette of a new project

A new project MUST contain one visible palette named `Default` with one style named `Default`, containing a **default
palette of about 120 swatches**, all solid. Required coverage:

- black, white and one fully transparent swatch (alpha 0);
- a grey ramp of at least 16 evenly spaced steps from near-black to near-white;
- at least 4 skin tones spanning light to dark;
- the primaries and secondaries (red, green, blue, cyan, magenta, yellow) at full saturation;
- for at least 16 hue families evenly distributed around the hue circle (including warm greys/browns), a row of
  light → dark variants (at least 5 per family).

The exact values are a design task and are to be authored fresh. Swatches of the default palette are named `Colour 1` …
`Colour N` in palette order. The same default palette is used when a library template or imported drawing must be given
a palette and none exists. The default palette MUST be reproducible on demand (`colour.palette.create {preset:"default"}`).

### 1.9 Naming defaults

| Object | Default name |
|---|---|
| Swatch added with Add Colour | `New N` (N = smallest unused number in the palette: New 1, New 2, …) |
| Texture swatch added with Add Texture | `Texture` (unique-suffixed is not required; swatch names may repeat) |
| Swatches of the default palette | `Colour N` |
| Swatches created by vector/SWF/PDF/Illustrator import | `0`, `1`, `2`, … (per palette, next free number) |
| Duplicated style | `Style N` (smallest unused N in the palette) |
| First style of a new or default palette | `Default` |
| First style of palettes created by importers | `Default` (**Design decision**; any single consistent name is acceptable) |
| Palette created by bitmap vectorization "with texture" | `Vectorization Palette` (unique-suffixed) |
| Duplicated or colliding palette | `<name> 2`, `<name> 3` … |
| Recovered palette whose name is unavailable | `Recovered` (unique-suffixed) |
| Placeholder swatch for a deleted, unrecoverable colour / texture | `Deleted colour` / `Deleted texture` |

## 2. Colour palette view

### 2.1 Purpose

The colour palette view is where the user picks the **current colour** used by all drawing and painting tools, and
where palettes, styles and swatches are managed. It is a dockable view (docking, show/hide and default placement are
specified in section 01; it is shown by default in the standard workspaces next to the properties view and the library).

### 2.2 Contents

The view MUST provide:

| Part | Function |
|---|---|
| Palette selector | Lists all visible palettes in list order; choosing one makes it the current palette. Palette commands (new, duplicate, rename, delete) are reachable from it or next to it. |
| Style selector | Lists the styles of the current palette; choosing one sets that style for the current scene ("Style Change"). Style commands (duplicate, rename, delete, tint offset, tint blend) are reachable from it or next to it. |
| Swatch commands | Edit colour, add colour, delete colour, show/hide names — directly reachable (e.g. buttons). |
| Swatch list | The swatches of the current palette, shown with the values of the current scene's style. |
| Context menu | All colour, palette and style commands, palette import/export, and the show/hide-names toggle; reachable by right-click in the view and from a menu button in the view. |

Exact layout, iconography and grouping are design work.

### 2.3 Swatch list behaviour

| Behaviour | Requirement |
|---|---|
| Chip rendering | Solid: filled rectangle. Linear gradient: rectangle showing the gradient left to right. Radial gradient: rectangle showing rings from the centre. Texture: thumbnail of the image. Transparency MUST be visible (draw chips over a checker pattern or split light/dark background). |
| Names shown | One swatch per row: chip + name. |
| Names hidden | Compact grid of chips that wraps to the view width; the name is available as a tooltip. The names on/off state is a persisted view preference. |
| Single click | Selects the swatch and makes it the **current colour** for brush, pencil, line, rectangle, ellipse, polyline, text and the paint tools. If drawing objects are currently selected with the select tool, the selection is recoloured to that swatch as one undo step ("Set Colour", §9.1). |
| Double-click | Opens the editor for the swatch (same as Edit Colour). |
| Drag a swatch | Reorders the swatch within the palette. Undoable ("Move Colour"). Order is saved with the project. |
| Rename | In the colour editor's or texture properties' name field (part of the "Edit Colour" undo step). |
| Selection model | One current swatch at a time. |
| Palette switch | Changing the current palette selects that palette's first swatch (if any) and makes it current. |
| Live updates | The list redraws when swatches change by any path: editing, undo/redo, tint operations, imports, agent commands, or the dropper selecting a swatch in another palette. |

### 2.4 Current colour semantics

- There is exactly one current colour ID per open project. Every tool that creates or paints geometry uses it.
- Picking with the dropper changes the current palette (if needed) and the current swatch to the picked one.
- If the current swatch is deleted, the selection moves to the next swatch (or the previous one if it was last; or none
  if the palette is now empty — tools that need a colour then use the fallback and SHOULD warn once with
  `colour.noCurrentColour`).
- Gradients and textures as current colour: painted zones and brush strokes receive the gradient/texture fill. Texture
  and gradient swatches MAY be used on centre lines; the fill is then mapped across the line's bounding box.

### 2.5 Enablement

| Command | Enabled when |
|---|---|
| Add Colour, Add Texture | A project is open and the current palette is visible |
| Edit Colour, Delete Colour | A swatch is selected |
| Delete Palette | More than one visible palette exists |
| Delete Style | The current palette has more than one style |
| Duplicate/Rename Palette, Duplicate/Rename Style, Tint Offset, Tint Blend | A palette is current |
| Export Palette | At least one visible palette exists |
| Import Palette | A project is open |
| Show/Hide Colour Names | Always; shows its checked state |

Disabled commands invoked through the command layer return an error (`colour.lastPalette`, `colour.lastStyle`,
`colour.notFound`, …) instead of being silently ignored.

## 3. Palette commands

All modifying commands are undoable, one step each, unless stated. None has a default keyboard shortcut; all can be
bound (section 01).

### 3.1 New Palette

- Asks for a name (prefilled with a unique suggestion, e.g. `Palette N`), then creates a palette with one style named
  `Default` and **one opaque black swatch** (`New 1`) so that a current colour always exists, and makes it current. Undo
  label "Add Palette".
- Validation: empty name → `colour.nameEmpty`; name used by another palette → `colour.nameExists`. In the GUI the name
  prompt stays open for correction.
- Appended to the end of the palette list; every scene uses its first style.

### 3.2 Duplicate Palette

- Creates a new palette from the current one: same swatches (names, kinds, deformable flags, values for every style) and
  same style names, but a **new palette ID, new style IDs and new colour IDs**.
- Name: unique-suffixed copy (`<name> 2`). Inserted after the source palette. Becomes current.
- Existing artwork keeps pointing at the source palette. (Use Duplicate Style to get an alternative colour set for the
  same artwork.)

### 3.3 Rename Palette

- Prompts for the new name, prefilled with the current name and fully selected. Errors `colour.nameEmpty` /
  `colour.nameExists`. Renaming does not change IDs; artwork is unaffected. Undo label "Rename Palette".

### 3.4 Delete Palette

- The GUI MUST ask for confirmation that the palette **and all its styles** will be deleted. Through the command layer
  the confirmation is the `confirm` parameter (§16).
- Not allowed for the last visible palette (`colour.lastPalette`).
- Undo label "Remove Palette"; undo restores the palette with the same IDs, order and per-scene styles.
- Artwork that uses the palette's swatches behaves as for Delete Colour (§5.4).

### 3.5 Select current palette

- Choosing a palette in the palette selector makes it current (§2.3 palette switch). Not undoable (UI state).

### 3.6 Import Palette

- **Purpose:** bring palettes from a palette exchange file (`.animpal`, §12) into the project.
- Behaviour:
  1. The user chooses a `.animpal` file. The file is validated (format identifier and version). Invalid files are
     rejected with `colour.invalidFile`; files of a newer, incompatible version with `colour.unsupportedVersion`.
  2. Every palette in the file is appended to the project palette list; names are made unique (`<name> 2`).
  3. Texture images are read from the exchange file and copied into the project package. Missing images produce
     `Deleted texture` placeholders for the affected style values and a warning listing them
     (`colour.textureMissing`).
  4. **ID policy:** keep the IDs from the file, so that drawings and templates from the same source link to the imported
     swatches. If a palette with the same palette ID already exists in the project, the GUI default is to import it as a
     copy with new IDs (like Duplicate Palette); the command layer offers `onIdConflict: "copy"|"replace"|"skip"`. If an
     individual colour ID already exists in another palette, that swatch gets a new ID (an ID is never shared by two
     swatches).
  5. One undo step ("Import Palette"). The first imported palette becomes current.

### 3.7 Export Palette

- The user chooses one or more visible palettes (all listed with check boxes; the current palette is pre-checked;
  select-all and clear-all helpers) and a destination path, then the application writes a `.animpal` file containing
  those palettes (all styles and swatches, texture images embedded).
- The file records the author and copyright text from the user's preferences (section 01).
- Validation: empty/malformed path or non-existent folder → `colour.invalidPath`; no palette chosen → export is not
  possible (OK disabled; command error `colour.nothingToExport`); missing extension → `.animpal` is appended; existing
  file → the GUI asks whether to overwrite (No returns to the choice), the command layer requires `overwrite: true`
  (otherwise `colour.fileExists`); write failure → `colour.writeFailed`.
- Not undoable (does not change the document).

## 4. Style commands and tinting

### 4.1 Select style for the current scene

- Choosing a style in the style selector sets it for the current scene (§1.5). Undoable ("Style Change").

### 4.2 Duplicate Style

- Adds a new style to the current palette whose values are copies of the current style's values, with **the same colour
  IDs** (swatch identity is shared by all styles of a palette).
- Default name `Style N`. Inserted after the source style. The new style becomes the selected style for the current
  scene; other scenes keep their styles. Undo label "Duplicate Style".

### 4.3 Rename Style

- Prompts for the new name, prefilled with the current style name. Errors `colour.nameEmpty`; `colour.nameExists` when
  another style of the same palette has that name. Undo label "Rename Style".

### 4.4 Delete Style

- Removes the current style and its values from every swatch of the palette. Not allowed when it is the palette's only
  style (`colour.lastStyle`).
- Scenes that used the deleted style switch to the first remaining style (the command layer accepts an explicit
  `replacementStyleId`).
- No confirmation is required (it is undoable). Undo label "Delete Style"; undo restores values and per-scene selections.

### 4.5 Tint Offset

Shifts every colour of one style of the current palette by fixed amounts.

| Parameter | Default | Range | Effect |
|---|---|---|---|
| Mode | RGB | RGB \| HSB | Which offsets apply |
| R, G, B offsets (RGB mode) | 0 | −255 … +255 | Added to each channel |
| H offset (HSB mode) | 0 | −360 … +360 degrees | Hue rotation |
| S offset (HSB mode) | 0 | −100 … +100 | Saturation change in percentage points |
| B offset (HSB mode) | 0 | −100 … +100 | Brightness change in percentage points (lighten/darken) |
| Alpha offset | 0 | −255 … +255 | Added to every swatch's alpha |
| Blending % | 100 | 0 … 100 | Scales all offsets: applied offset = offset × blending / 100 (e.g. brightness +50 at 50 % behaves like +25) |

Algorithm (applied to every solid swatch and every gradient stop of the target style):

```
k = blending / 100
RGB mode:  r' = clamp(r + k*dR, 0, 255); g' = clamp(g + k*dG, 0, 255); b' = clamp(b + k*dB, 0, 255)
HSB mode:  convert to HSB (H 0..360, S 0..100, B 0..100);
           H' = (H + k*dH) wrapped into [0, 360); S' = clamp(S + k*dS, 0, 100); B' = clamp(B + k*dB, 0, 100);
           convert back to RGB, rounding to nearest
both:      a' = clamp(a + k*dA, 0, 255)
```

- Offsets are always applied to the values the style had **when the operation started** (never cumulatively while the
  user drags a slider).
- The RGB and HSB offsets are kept separately; only the active mode's offsets are applied.
- Texture swatches are not changed.
- Slider and numeric field are kept in sync; typed values outside the range are clamped.
- The result is previewed live on the artwork while the tint UI is open, committed on OK as one undo step ("Offset
  Style"), and fully reverted on Cancel.

### 4.6 Tint Blend

Mixes one colour into every colour of one style (e.g. to make a dusk or underwater version of a style).

| Parameter | Default | Range | Effect |
|---|---|---|---|
| Blend colour mode | RGB | RGB \| HSB | How the blend colour is entered |
| Blend colour R, G, B | 0, 0, 0 (black) | 0 … 255 | Blend colour (RGB mode) |
| Blend colour H, S, B | 0, 0, 0 | H 0 … 360, S 0 … 100, B 0 … 100 | Blend colour (HSB mode) |
| Blend alpha | 255 | 0 … 255 | Alpha of the blend colour |
| Blending % | 50 | 0 … 100 | Amount of the blend colour mixed into each swatch; 100 % = every swatch becomes the blend colour |

Algorithm (every solid swatch and every gradient stop of the target style):

```
t = blending / 100
c' = round(c + (blend_c - c) * t)     for c in {r, g, b, a}, clamped to 0..255
```

The blend colour's alpha is mixed into swatch alpha like the other channels. Texture swatches are not changed. Live
preview, commit ("Blend Style") and cancel behave as for Tint Offset. A colour chip shows the blend colour.

Typical workflow: Duplicate Style → rename it "Night" → Tint Blend with dark blue at 30–50 % → the scene that selects
"Night" renders all its artwork in night colours.

## 5. Swatch commands

### 5.1 Add Colour

1. Creates a solid swatch named `New N` in the current palette.
2. Initial value: a copy of the selected swatch's value in the current style (first stop colour if the selected swatch is
   a gradient; opaque black if the selected swatch is a texture or nothing is selected).
3. Every style of the palette receives the same initial value.
4. Inserted after the selected swatch, or at the end if none is selected; it becomes selected and current.
5. A new colour ID is allocated. Undo label "Add Colour". There is no maximum number of swatches per palette.

### 5.2 Add Texture

1. The user chooses an image file. Accepted formats: the bitmap formats accepted by image import (section 09), at least
   PNG, JPEG, TIFF, BMP, TGA and PSD (flattened). The image is copied into the project package (section 10) with its alpha
   channel preserved.
2. Creates a texture swatch named `Texture`, tile **on**, deformable **off**, with the image as its value in every style.
3. Inserted like Add Colour; becomes selected and current. Undo label "Add Texture".
- Cancelling the file choice does nothing. An unreadable image fails with `colour.imageLoadFailed`. The last folder used
  is remembered.

### 5.3 Edit Colour

- Opens the **colour editor** (§6) for a colour swatch, or **texture properties** (§6.6) for a texture swatch.
- Edits apply to the swatch's value **in the current scene's style only**; name, kind and deformable flag apply to all
  styles.
- Changes are applied live to the artwork while the editor is open and become one undoable step "Edit Colour" when
  committed.

### 5.4 Delete Colour

- Removes the selected swatch from its palette (all styles). Undo label "Remove Colour". No confirmation is required in
  the GUI.
- Artwork that used the swatch keeps the colour ID. Such zones/lines keep rendering from the drawing's embedded recovery
  copy (§1.6) and the swatch is re-created by colour recovery the next time the drawing is loaded or pasted (§11.2); if
  no recovery data is available they render with the fallback colour (§1.7).
- Through the command layer, `replaceWith: colourId` MAY be given to recolour all uses to another swatch in the same
  undo step (§9.3).
- Deleting the last swatch of a palette is allowed; the palette becomes empty.

### 5.5 Move swatch

- Drag-reordering in the swatch list, or the equivalent command, moves a swatch to a new index within its palette
  ("Move Colour"). Moving swatches between palettes is not supported (copy via create + recolour instead).

### 5.6 Show/Hide Colour Names

- Toggles between list mode (chip + name) and compact chip mode. Persisted view preference; not undoable.

### 5.7 Set current colour

- Selecting a swatch (click, dropper, or command) sets it as current. Not undoable (UI state).

## 6. Colour editor

### 6.1 Purpose

Edit the value, kind (solid/gradient), gradient shape, gradient stops, name and deformable flag of a colour swatch, for
the current scene's style. The same chooser (without the swatch-specific controls) is used by every "colour field"
elsewhere in the application (preferences colours, onion-skin colours, scene background, element marker colours, effect
colours); in that mode only a solid RGBA colour can be chosen and the name, gradient and deformable controls are
hidden or disabled.

### 6.2 Controls

| Control | Requirement |
|---|---|
| Name | Swatch name; editing renames the swatch. |
| Kind | Solid / Gradient. |
| Gradient shape | Linear / Radial (enabled only for gradients). |
| Gradient bar | Shows the gradient with its stops beneath the bar; stop editing per §6.4 (enabled only for gradients). |
| Colour area + slider | A 2-D colour field (a slice of the 3-D colour space) plus a slider for the third axis; which component the slider controls is selected in the colour model panel. |
| Colour model panel | Two models: RGB (R, G, B) and HSV (H, S, V). Each component has a selector (choose the slider axis) and a numeric field. |
| Alpha | Slider + numeric field. Higher = more opaque. |
| New / previous colour | Two chips: the colour being edited and the colour at the moment the editor opened; activating the previous chip reverts to it. |
| Deformable | Check box: the gradient fill follows bone deformation (§7.5). |
| OK / Cancel | Commit / discard (when the editor is modeless, closing it or selecting another swatch commits). |

Value ranges: R, G, B, alpha 0–255; H 0–359 degrees; S, V 0–100 %. Numeric entries outside a range are clamped.

**Design decision:** the editor MAY be implemented with the platform's native colour panel, provided all controls above
are available (native panels typically add colour wheels, CMYK sliders, swatch lists and a screen-pixel sampler; these
are welcome but not required).

### 6.3 Live editing and undo

- Changes are continuous: the swatch and all artwork using it update while the user drags.
- The editor is a floating, modeless window; it stays open while the user selects other swatches and re-targets itself
  to the newly selected swatch. Re-targeting or closing commits the pending edit as one undo step "Edit Colour"; Cancel
  restores the values present when the editor last targeted the swatch.

### 6.4 Gradient editing

| Gesture | Effect |
|---|---|
| Click a stop | Selects it; the colour controls now edit that stop's colour and alpha. |
| Click just below the bar, not on a stop | Adds a stop at that position, initialised with the gradient's colour at that position; it becomes selected. |
| Drag a stop sideways | Moves its position (clamped to 0.0–1.0). Stops may cross; the list is kept sorted by position. |
| Drag a stop away from the bar | Removes it, unless only 2 stops remain (a gradient always keeps at least 2 stops). |
| Switch solid → gradient | Starts with two stops at 0 and 1, both the current solid colour, in every style. |
| Switch gradient → solid | Keeps the first stop's colour (in every style). |

Interpolation between stops is linear per channel including alpha; before the first and after the last stop the end
colours extend. Stops need not sit exactly at 0 and 1.

### 6.5 Agent equivalent

Every control maps to parameters of `colour.swatch.set` (full stop list, kind, shape, rgba, name, deformable) — agents do
not drive the editor.

### 6.6 Texture properties

Opened by Edit Colour (or double-click) on a texture swatch.

| Field | Default | Effect |
|---|---|---|
| Name | swatch name | Renames the swatch (non-empty). |
| Width, Height | image size in pixels | Read-only display. |
| Tile | on for new swatches | On: painted zones are filled by repeating the image at its native size. Off (stretch): the image is stretched to fill each painted zone's bounding box. The mapping is computed when a zone is painted, so a change applies to zones painted **afterwards**; already-painted zones keep their mapping (they can be re-fitted with `colour.fillMapping.set {mapping:"default"}`). |
| Deformable by bones | off | Texture follows bone deformation (§7.5). |
| Preview | — | Thumbnail of the current style's image. |
| Replace image | — | Replaces the swatch's image in the current style with another image file. |
| OK / Cancel | — | OK commits all changes as one undo step ("Edit Texture"); Cancel discards. |

## 7. Fill kinds — rendering and mapping

### 7.1 Solid colours

Flat RGBA fill. Alpha < 255 makes the zone/line translucent; overlapping translucent objects composite normally (§10).

### 7.2 Fill mapping matrix (gradients and textures)

Each painted zone (or brush stroke, or line) that uses a gradient or texture stores a 2×3 affine matrix with its colour
reference. It maps the unit gradient/texture space into drawing space for that particular object, so two zones painted
with the same gradient can have different directions.

| Situation | Mapping |
|---|---|
| Painted with a single click | Default mapping from the object's bounding box and the swatch kind. Linear: axis across the box from the left edge (position 0) to the right edge (position 1). Radial: centre of the box, radius reaching the box corner. Texture with tile off: image scaled to the box. Texture with tile on: image at native pixel size (1 image pixel = 1 drawing unit at 100 % — see section 02 for drawing units), anchored at the box's top-left corner, repeated. |
| Painted with press–drag–release | Linear: position 0 at the press point, 1 at the release point. Radial: centre at the press point, radius = drag length. Texture: image origin at the press point, scaled so its width equals the drag length, rotated to the drag direction. |
| Edited with the edit texture tool | Modified interactively (§8.7) or numerically (`colour.fillMapping.set`). |
| Object transformed (move, rotate, scale, flip, skew) | The matrix is transformed with the geometry so the fill stays attached. |
| Zone split or merged by editing (section 02) | The resulting zones inherit the fill reference including its matrix. |

### 7.3 Linear and radial gradients

Rendered by interpolating the scene style's stops along the mapped axis (linear) or by distance from the mapped centre
(radial; elliptical when the matrix scales non-uniformly).

### 7.4 Textures

- The image is the swatch's value for the scene's style; texture alpha is respected.
- Tile on: repeat outside the image; tile off: stretched once over the mapped area, transparent outside it.
- Display smoothing and texture display resolution are viewer preferences (section 01); final-render texture quality is
  specified in section 09.
- Operations that cannot handle textured fills (e.g. feathering edges, section 02) skip textured objects and report
  that they were skipped.
- Textures are created by Add Texture, by bitmap vectorization "with texture" (creates a `Vectorization Palette` with one
  texture swatch per vectorized image, named `1`, `2`, …; section 02), and by vector-file imports with bitmap fills
  (§11.5).

### 7.5 Deformable flag

- Applies to gradient and texture swatches (ignored for solid).
- On: when a drawing is deformed by bones (section 05), the fill warps with the deformed geometry. Off: the fill keeps its
  undeformed mapping and the deformed shape moves over it.
- Changing the flag is undoable ("Change Deformable Attribute").
- Bitmap image elements deformed by bones are internally rendered as texture fills held in a hidden palette (§1.2); this is
  invisible to the user.

## 8. Painting tools

Tool activation, tool cycling and the tool palette are specified in section 02 (`tool.*`). This section specifies what
the paint-group tools do and owns their structured equivalents (`colour.paint.*`, `colour.pick`, `colour.gap.close`,
`colour.fillMapping.*`).

### 8.1 Common rules

| Rule | Requirement |
|---|---|
| Tools in the group | Paint, Unpaint, Paint Unpainted, Dropper, Close Gap, Edit Texture. The stroke tool (section 02) is grouped with them in the tool palette. Exactly one drawing tool is active at a time. |
| Views | Work in the Drawing view and the Camera view on the current drawing of the selected vector drawing element at the current frame. |
| Temporary select | While the *temporary-select modifier* is held, any of these tools behaves as the select tool; releasing returns to the tool. |
| Temporary dropper | While the *temporary-dropper modifier* is held with Paint, Brush or Pencil active, the tool behaves as the Dropper; releasing returns to the tool. |
| Locked drawing | Painting a locked drawing is refused; the user is informed (`drawing.locked`, section 02). |
| Undo | Each click or drag is one undo step labelled with the tool name ("Paint", "Unpaint", "Paint Unpainted", "Close Gap", "Edit Fill Mapping"). |
| Target | Hit-testing considers the front-most object under the pointer in the current drawing: layers top to bottom (section 02); within a layer, lines before zones (a click within a line's rendered thickness hits the line). |
| Invisible strokes | Invisible strokes take part in zone detection exactly like visible lines. Showing strokes (section 02) helps find gaps. |
| Feedback | When automatic gap closing is active, the cursor indicates it and a circle showing the gap tolerance MAY be drawn around the cursor. |

### 8.2 Paint

**Purpose:** fill zones with the current swatch, or recolour lines, brush strokes and text.

| Target | Result |
|---|---|
| Inside a closed zone (bounded by lines, shapes, invisible strokes or eraser cuts) | The zone's fill becomes the current swatch, replacing any previous fill. |
| On a pencil/centre line | The line's colour becomes the current swatch; thickness unchanged. |
| On a brush stroke | The brush stroke's fill becomes the current swatch. |
| On a text object | The text colour becomes the current swatch. |
| In an area that is not closed | Nothing is painted, unless automatic gap closing closes the gap (§8.8). Command layer: `colour.zoneNotClosed`. |
| Outside all artwork | Nothing. |

- **Gradient/texture swatch:** click → default mapping fitted to the object's bounding box; press–drag–release → the
  drag defines the mapping (§7.2).
- **Solid swatch with drag:** **Design decision:** dragging with a solid swatch paints every zone and line the pointer
  crosses, as one undo step.
- **Zone detection (functional):** from the click point, find the smallest closed region of that layer enclosing it,
  bounded by all strokes of the layer (visible lines and invisible strokes). Islands inside a zone (holes) are separate
  zones and are not filled. A paint fill is itself a shape in the drawing, so to fill an area enclosed only by brush
  strokes the user typically extracts centre lines first (section 02).
- Zones created by the eraser can be filled.

### 8.3 Unpaint

- **Purpose:** remove colour from zones and lines.
- Clicking a painted zone resets it to unpainted: it becomes transparent; surrounding lines are untouched. Clicking an
  unpainted zone does nothing.
- On a line: the line becomes unpainted, i.e. an invisible stroke (visible only when strokes are shown), so geometry and
  zone boundaries are preserved (see §17).
- Brush strokes and text cannot be unpainted (they are filled shapes; delete them instead). Command layer:
  `colour.cannotUnpaint`.
- Automatic gap closing applies, so that an open region that Paint would find is also found by Unpaint.

### 8.4 Paint Unpainted

- **Purpose:** paint only zones that have no colour yet, so many zones can be filled quickly without disturbing zones
  already painted.
- Click: if the zone under the pointer is unpainted, fill it with the current swatch; if it is already painted (with
  anything), leave it unchanged.
- Drag: the drag draws a free-form lasso; on release every unpainted zone that has an interior point inside the lasso is
  filled with the current swatch. All fills of one drag are one undo step.
- Lines, brush strokes and text are not affected. Automatic gap closing applies.

### 8.5 Dropper

- **Purpose:** identify the colour of a painted zone, line, brush stroke or text and make it the current colour.
- Clicking picks the object's colour ID; the palette view switches to the palette containing that ID (changing the
  current palette if needed) and selects the swatch, which becomes current.
- Clicking an unpainted area or empty canvas: no change.
- Colour not found in any palette (deleted swatch): no change; the user is told the colour is missing and offered colour
  recovery for that drawing (`colour.missing`).
- The dropper picks palette swatches only; it does not create swatches from screen pixels.

### 8.6 Close Gap

- **Purpose:** close small openings in line art so that the enclosed area becomes a paintable zone.
- The user drags across or near the gap; a feedback line is shown while dragging. On release, the application finds the
  nearest stroke end point (or closest stroke point) to each end of the drag, within a tolerance proportional to the drag
  length and at least the large gap tolerance of §8.8, and adds a short straight **invisible stroke** connecting them.
- If no suitable pair is found, nothing is added (command layer: `colour.noGapFound`).
- If strokes are currently hidden, the user is warned once that the added stroke is not visible unless strokes are shown
  (section 02).
- Undo label "Close Gap".

### 8.7 Edit Texture (fill mapping)

- **Purpose:** change the position, size, orientation and skew of gradient and texture fills inside painted zones,
  brush strokes and lines.
- Clicking an object filled with a gradient or texture selects the front-most such object and shows a manipulator:

| Fill | Handles | Effect |
|---|---|---|
| Linear gradient | Start point, end point, axis line | Drag start/end to change direction and length of the transition; drag the axis to move it. |
| Radial gradient | Centre, radius handle, second-axis handle | Drag the centre to move; drag the radius handle to resize and rotate; the second-axis handle scales non-uniformly (elliptical). |
| Texture | Bounding frame with corner, side and rotation handles | Move, scale (corners; with the constrain modifier proportions are kept), stretch (sides), rotate; skew with the skew modifier on side handles. |

- Clicking a solid-colour or unpainted object shows no manipulator.
- The change is applied on release, as one undo step ("Edit Fill Mapping").
- **Copy/paste of fill mapping:** while this tool is active, the canvas context menu offers *Copy Fill Mapping*, which
  copies the selected object's mapping to the clipboard; Paste while objects are selected with this tool applies the
  same mapping to them.
- The temporary-select modifier works as in §8.1.

### 8.8 Automatic gap closing

A paint-tool option with four modes:

| Mode | Effect |
|---|---|
| Off | No automatic gap closing. |
| Small | Gaps up to the small tolerance are treated as closed while painting. |
| Medium | Medium tolerance. |
| Large | Large tolerance. |

- Exactly one mode is active (radio semantics). The mode is a persisted user setting; default **Off**. It is reachable
  from the main menu and the paint tools' options.
- Applies to Paint, Paint Unpainted and Unpaint.
- **Algorithm (functional):** when the region under the click is not closed, the painter tests candidate gaps (pairs of
  nearby stroke ends, and stroke-end-to-stroke distances) no wider than the tolerance, inserts closing segments, and
  finds the region again. Candidate closures that would create a zone smaller than a minimum area (4 × tolerance²) are
  ignored.
- The closing segments that were needed to bound the painted zone are **kept as invisible strokes** in the drawing, so
  that the zone stays closed when the drawing is edited later; unneeded candidates are discarded.
- Tolerances are measured on screen so that they feel constant at any zoom: Small 3 px, Medium 8 px, Large 16 px of view
  distance, converted to drawing units at the current zoom. Agent commands that paint without a view use the tolerance
  at 100 % zoom.

### 8.9 Stroke tool (relation to painting)

The stroke tool (section 02) draws invisible strokes that close gaps and create zones without adding visible line art.
For painting, invisible strokes bound zones exactly like visible lines; they can separate two differently painted zones
without a visible outline (e.g. shadow areas on a character).

## 9. Recolouring existing artwork

### 9.1 Recolour a selection ("Set Colour")

With the select tool, select one or more drawing objects, then choose a swatch: the selected objects take the new colour
— lines as line colour, brush strokes and text as fill, painted zones inside the selection as zone fill — as one undo
step ("Set Colour"). Unpainted zones in the selection stay unpainted.

### 9.2 Global recolouring

| Method | Effect |
|---|---|
| Edit a swatch | Every use of that swatch, in every drawing and scene that shows the edited style, changes immediately. |
| Switch the scene's style | Every use of the palette's swatches in the current scene changes to the other style's values. |
| Tint offset / tint blend | Every swatch of one style changes. |
| Paint / paint unpainted / unpaint | Individual zones and lines. |
| Replace colour (§9.3) | Every reference to one colour ID within a scope is changed to another colour ID. |
| Colour-transform effect | Per-element, animatable colour change at render time — section 06. |

### 9.3 Replace colour (bulk recolour)

The application MUST be able to replace every reference to colour ID A with colour ID B within a scope:

- **Scope:** a set of drawings, all drawings of a set of elements, all drawings exposed in a scene, or the whole project.
- **Targets:** zone fills, lines, brush strokes, text, or all (default all). Pen presets referencing A MAY be included.
- Gradient/texture mappings are kept when both A and B are gradients/textures; otherwise the default mapping is computed
  for B (§7.2).
- Locked drawings are skipped and reported.
- One undo step ("Replace Colour"). The result reports the number of references changed per drawing.

GUI access: from the swatch's context menu ("replace uses of this colour with…"). A "where is this colour used" listing
(§16) MUST also be available in the GUI (e.g. from the swatch's context menu), and selecting an entry navigates to the
drawing.

### 9.4 Draw top layer

The drawing option that merges brush strokes of the same colour into the top layer (section 02) is keyed on the colour
ID.

## 10. Transparency and alpha

| Rule |
|---|
| Every solid colour and every gradient stop has an 8-bit alpha (0 = fully transparent, 255 = opaque). |
| Alpha is edited in the colour editor, offset by tint offset (−255 … +255) and mixed by tint blend. |
| Partially transparent objects composite over what is behind them (source-over); stacked transparent objects produce cumulative effects. |
| Layer merging that would change the appearance of overlapping transparent objects is refused by the non-destructive merge and allowed (with appearance change) by the destructive flatten — section 02. |
| Unpainted zones are fully transparent; unpaint is the way to clear a fill. |
| Texture images carry their own alpha channel; it is respected when rendering. |
| Swatch chips show transparency (checker background). |

## 11. Colour data across copy/paste, templates and import

### 11.1 Copy/paste of drawing objects

Copying drawing objects puts a colour map on the clipboard: for each colour ID used, the owning palette name, style
names and full swatch definition. When pasting into a project where an ID is unknown, the swatch is recreated by colour
recovery (§11.2).

### 11.2 Colour recovery

- Triggered when loading drawings, templates or pasted content that reference colour IDs missing from the project.
- Each missing swatch is recreated from its recovery copy with the **same colour ID**: into the palette with the recorded
  name if it exists (adding missing styles by name when needed), otherwise into a new palette of that name; if the name is
  unavailable, into a palette named `Recovered`.
- Without recovery data, a placeholder swatch named `Deleted colour` (or `Deleted texture`) is created with the fallback
  value, so the ID resolves and the user can edit it.
- Recovery is one undo step ("Colour Recovery"). The user is informed which palettes received recovered swatches.
- Recovery can also be run on demand for chosen drawings or the whole project.

### 11.3 Library templates and update colours

- Templates carry the swatches their drawings use (as recovery copies).
- When a template is pasted or dragged in, the **update colours** option decides whether swatch values from the template
  overwrite the values of the same colour IDs already in the project (on) or whether the project's values win (off). Its
  default comes from the project's automatic colour update flag (§1.2). The same option exists when updating drawings
  from the library. See section 08.

### 11.4 SWF

- Export: an option stores swatch, style and palette information in the SWF so that re-importing several SWFs that
  share a palette produces a single palette and keeps automatic swatch updating (section 09).
- Import: SWF fills and lines become swatches (solid, linear, radial) in one palette per imported movie, swatches named
  `0`, `1`, …; identical values share one swatch. **Design decision:** colour transforms on imported instances are
  baked into additional swatches derived from the base swatch (named `<base> *`).

### 11.5 PDF / Illustrator / PSD import

Imported vector colours are gathered into a palette (find-or-add by RGBA; CMYK converted to RGB), gradients become
gradient swatches and bitmap fills become texture swatches. Helper palettes used during import are hidden and removed
when the import finishes. See sections 02 and 09.

### 11.6 Bitmap vectorization

Vectorization in black-and-white mode produces line art using the current colour; "with texture" produces shapes
filled with a texture swatch holding the source bitmap, collected in a palette named `Vectorization Palette` (one per
import, unique-suffixed). See section 02.

### 11.7 Palettes bundled with particle presets

Particle-effect presets (section 06) come with their own drawings and palettes. When such a preset is used, the palettes
it needs are added to the project (as by Import Palette, keeping IDs) so that the particle drawings' colour IDs resolve.
Bundled palettes are content to be authored fresh; they MAY also be offered for manual import.

## 12. Palette exchange file (`.animpal`)

### 12.1 Container

A `.animpal` file is a self-contained palette exchange file using the same container conventions as the project
package (section 10): an archive whose root holds `palettes.json` (UTF-8, the manifest below) and a `textures/` folder
with the texture images referenced by the manifest (PNG with alpha). A palette set without textures MAY also be written
as a bare JSON file with the same content; readers MUST accept both.

### 12.2 Manifest

```json
{
  "format": "animpal",
  "formatVersion": 1,
  "author": "string from user preferences, may be empty",
  "copyright": "string from user preferences, may be empty",
  "palettes": [ "Palette objects (§12.3)" ]
}
```

### 12.3 Palette JSON object

The same object shape is returned by the agent interface (`colour.palette.get`) and SHOULD be used by section 10 for
palettes inside the project package.

```json
{
  "id": "pal_01J9X",
  "name": "Character A",
  "styles": [ { "id": "sty_day", "name": "Day" }, { "id": "sty_night", "name": "Night" } ],
  "swatches": [
    {
      "colourId": "col_skin",
      "name": "Skin",
      "kind": "solid",
      "deformable": false,
      "values": {
        "sty_day":   { "rgba": "#F2D3B4FF" },
        "sty_night": { "rgba": "#8C7A8AFF" }
      }
    },
    {
      "colourId": "col_sky",
      "name": "Sky",
      "kind": "linearGradient",
      "deformable": false,
      "values": {
        "sty_day":   { "stops": [ { "position": 0.0, "rgba": "#70C8F0FF" }, { "position": 1.0, "rgba": "#FFFFFFFF" } ] },
        "sty_night": { "stops": [ { "position": 0.0, "rgba": "#10084AFF" }, { "position": 1.0, "rgba": "#300448FF" } ] }
      }
    },
    {
      "colourId": "col_fabric",
      "name": "Fabric",
      "kind": "texture",
      "deformable": true,
      "values": {
        "sty_day":   { "image": "textures/fabric-day.png",   "tile": true },
        "sty_night": { "image": "textures/fabric-night.png", "tile": true }
      }
    }
  ]
}
```

Rules:

- `kind` ∈ `solid | linearGradient | radialGradient | texture`. Value shapes: solid `{rgba}`; gradients
  `{stops:[{position, rgba}]}` with ≥ 2 stops sorted by position; texture `{image, tile}` (image path relative to the
  container root; `width`/`height` MAY be included and are informative).
- `values` MUST contain exactly one entry per style of the palette.
- Colours are `#RRGGBBAA` (sRGB, straight/non-premultiplied alpha).
- IDs are opaque strings; readers MUST NOT interpret them.
- Unknown fields are ignored on read. A reader rejects a file whose `format` differs or whose `formatVersion` is newer
  than it supports (`colour.unsupportedVersion`).

## 16. Agent interface

### 16.1 Agent-specific requirements

1. **Everything through commands.** Every palette, style, swatch, tint, import/export, painting, picking, recolouring
   and recovery capability of this section MUST be available as a `colour.*` command (table §16.3) and every piece of
   state shown in the colour palette view MUST be readable through queries. The GUI's colour palette view, editor,
   tint dialogs, texture properties and export chooser are clients of these commands.
2. **No modal paths.** File choices are `path` parameters; the export overwrite prompt becomes `overwrite: bool`;
   the delete-palette confirmation becomes `confirm: bool` (without it the command returns a structured
   `needs_confirmation` result with code `colour.needsConfirmation` and a usage summary, and changes nothing); name
   collisions return `colour.nameExists` instead of re-prompting; live preview in the tint dialogs becomes
   `dryRun: true`, which returns the before/after values without changing the document.
3. **Explicit values.** Creation and editing take complete explicit values (`rgba`, `stops`, `image` + `tile`, per-style
   `values`) so an agent never needs the colour editor. Omitted optional fields keep their current values.
   `styleId` defaults to the style selected for the current scene; `"all"` targets every style of the palette.
4. **Gestural tools as structured operations.** Paint, paint unpainted, unpaint, dropper, close gap and edit texture are
   exposed as `colour.paint.apply`, `colour.paintUnpainted.apply`, `colour.paint.remove`, `colour.pick`,
   `colour.gap.close` and `colour.fillMapping.set`. Each target is addressable either **by object ID** (zone, line,
   brush stroke or text IDs as returned by `draw.drawing.get`, section 02) or **by point** in one of the coordinate
   spaces of §16.2. A press–drag–release is expressed as `mapping: {from, to}` (gradient axis), `path: [point]`
   (paint every object crossed) or `lasso: [point]` (paint unpainted). Tool activation (`tool.*`) is never required
   for these commands.
5. **Zone identity and staleness.** Zone IDs are derived from the drawing's geometry and change when the geometry
   changes. Paint commands accept the `rev` returned by `draw.drawing.get`; if the drawing has changed since, an
   object-ID target fails with `colour.staleZoneId` (point targets are always re-resolved). Results return the new
   revision and the IDs of affected objects.
6. **Deterministic results.** Identical drawing content and identical parameters MUST produce identical results.
   Gap-closing tolerances for commands are evaluated at 100 % zoom unless a `view` is given. Point hit-testing follows
   §8.1 exactly.
7. **Read-back.** `colour.palette.get` returns the full palette JSON of §12.3; `colour.swatch.get` adds the value
   resolved for a given scene and an optional PNG thumbnail; `colour.usage.list` lists where colours are used;
   `colour.pick` returns both the colour ID and the rendered RGBA at a point; `colour.fillMapping.get` returns a fill
   mapping. Visual verification uses `render_frame` / `screenshot` (section 11).
8. **Atomicity and undo.** Every action is one undo step; several commands inside `batch` (section 11) form one step.
   Commands that would partly fail (e.g. some drawings locked) apply to the rest and report what was skipped.
9. **GUI coupling made explicit.** In the GUI, clicking a swatch both sets the current colour and, if objects are
   selected, recolours them. For agents these are two commands: `colour.current.set` (UI state) and
   `colour.selection.apply` (document change).
10. **Errors** use the codes of §15.1 in the standard structured error result of section 11.

### 16.2 Coordinate spaces and point targets

A point target is `{x, y}` interpreted in the space given by `space`:

| Space | Meaning | Extra parameters |
|---|---|---|
| `drawing` | Drawing space of one drawing (units and axes as defined in section 02). | `drawingId` (default: current drawing) |
| `scene` | Scene/field space of a scene at a frame (section 05). The point is resolved to the front-most vector drawing whose rendered artwork covers it at that frame (optionally restricted to `elementId`), then transformed into that drawing's space. | `sceneId` (default current), `frame` (1-based, default current), `elementId?` |
| `view` | Pixels of a named view as currently displayed (top-left origin), resolved the same way as a user's click in that view. | `view` (view ID, section 01) |

### 16.4 Queries and events

- `colour.palette.get` returns the palette object of §12.3 — the canonical read model for palettes; agents can
  round-trip it through `colour.palette.set`.
- Painting changes drawings; besides the result of the paint command, section 02's `draw.drawing.changed {drawingId}`
  event is emitted, and `draw.drawing.get` returns zones with their `colourId` (or `null` for unpainted) and fill
  mapping.
- `colour.pick` with `space: "view"` reports exactly what a user's dropper click would pick, plus the rendered pixel
  colour after compositing (useful to check transparency and style selection).
- `colour.usage.list` and `colour.missing.list` give the project-wide colour cross-reference needed before deleting or
  replacing swatches.
- Events are delivered through the application event stream (section 11).

## 17. Design decisions / open questions

| Topic | Decision to make | Recommended default |
|---|---|---|
| Default palette values | Exact colours of the ~120 default swatches (§1.8). | Author a fresh set meeting the coverage rules; keep a transparent swatch in a fixed early position. |
| Gap closing tolerances | Pixel tolerances for small/medium/large and minimum zone area. | 3 / 8 / 16 view pixels; minimum area 4 × tolerance²; default mode Off. |
| Persisting gap-closing segments | Keep the auto-inserted closing segments as invisible strokes, or discard them after painting. | Keep (§8.8), so painted zones stay closed after later edits. |
| Unpaint on lines | A line can be unpainted (becomes an invisible stroke) or unpaint affects zones only. | Line becomes an invisible stroke; section 02 must align with this. |
| Paint drag with a solid swatch | Drag paints every crossed object, or drag is ignored for solid colours. | Paint every crossed object in one undo step. |
| Paint unpainted lasso | Lasso semantics for drag. | Fill every unpainted zone with an interior point inside the lasso. |
| New palette content | Empty, or one swatch. | One opaque black swatch named `New 1`; style `Default`. |
| Importer style name | Name of the first style of importer-created palettes. | `Default`. |
| Import ID policy | Keep IDs from the exchange file or always re-ID. | Keep IDs; on palette-ID conflict import as copy with new IDs; colour IDs never shared by two swatches. |
| Tint blend alpha | Whether blend alpha is mixed into swatch alpha or only weights RGB. | Mixed like any other channel (§4.6). |
| Texture size fields | Whether texture width/height are editable (nominal size). | Read-only; scaling is done per zone with the fill mapping. |
| Fallback colour | Appearance of unresolved colour IDs. | Opaque mid-grey, reported by `colour.missing.list`. |
| SWF instance colour transforms | How to represent them on import. | Bake into derived swatches named `<base> *`. |
| `.animpal` container | Archive vs. bare JSON. | Archive with `palettes.json` + `textures/`; accept bare JSON when there are no textures. Align with section 10. |
| Edit texture handles | Exact handle set and modifiers. | As in §8.7; refine in UX design. |
| Linear-light compositing | Whether to offer it. | Not in the first version; sRGB compositing only. |
| Moving swatches between palettes | Support drag between palettes. | Not supported; use create + `colour.recolour.apply`. |
