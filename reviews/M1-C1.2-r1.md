## P1 findings — fix before accepting C1.2

### C12-R1-01 — Safe external code can replace the live project outside the registry

**Location:** `crates/executor/src/lib.rs:180`, `crates/executor/src/run.rs:592`; public model staging APIs supply the replacement.

**Repro:** obtain `snapshot()`, perform a normal command to advance the live revision, use the old snapshot's public `with_patched_entries` to change content, then call public `open_document(outside, Some(path), false)`. This external integration crate uses only safe Rust. The replacement succeeds, rolls revision 2 back to 1, discards history/checkpoints and marks the supplied path clean, without a command declaration, scope, `expectRev` or unsaved-changes decision. An immutable snapshot alone is fine; this unrestricted live replacement completes the bypass.

**Required:** plan §3.2 and 11 P2/§2 require registry/executor mutation capability enforcement; 01 §1.2/§3 requires the unsaved-project decision. The eight existing compile-fail cases prove private fields/constructors, but omit this public composition. Restrict installation to an executor-owned loading capability or a registered, guarded load transaction; do not remove the adversarial scenario by forbidding immutable snapshots.

**Regression:** `c12_r1_contracts.rs:249`, `external_safe_code_cannot_install_a_mutated_stale_snapshot`.

### C12-R1-02 — Dry runs and failed atomic batches leak cancellation and events

**Location:** `crates/executor/src/run.rs:50` (`Rollback`), `commands/job.rs:102`, `commands/edit.rs:687`.

**Repro:** submit a held job, invoke `job.cancel` with `dryRun:true`, release the job: its final state is cancelled. The same happens when cancellation precedes an unknown command in an atomic batch that returns an error. Separately, `edit.clipboard.set` emits `edit.clipboard.changed` during both dry run and failed batch, although the clipboard itself is restored. `Rollback` copies app/UI/checkpoints/clipboard, but neither the shared job state nor pending events.

**Required:** 11 §7.2 changes nothing in a dry run; §7.3 is all-or-nothing. Irreversible external effects must be deferred, simulated, or rejected in this context; events must represent committed state. This is not fixed merely by restoring document bytes.

**Regressions:** `dry_run_cannot_cancel_a_running_job`, `failed_atomic_batch_cannot_cancel_a_running_job`, `dry_run_clipboard_emits_no_change_event`, `failed_batch_clipboard_emits_no_change_event` in `c12_r1_contracts.rs:43`.

### C12-R1-03 — Batch dry runs can commit real edits or predict the wrong result

**Location:** `crates/executor/src/run.rs:369`, `:474`, `:510`; `commands/doc.rs:864`.

**Repro A:** an atomic batch containing only `doc.object.patch {dryRun:true}` writes the document and advances its revision. The outer single-call path reads the command's dry-run parameter, but the atomic step path does not. **Repro B:** a non-atomic batch with `dryRun:true`, patch then get, reads the old value in step 2; the real batch reads the newly patched value. Each simulated step is rolled back before the next step runs.

**Required:** 10 AG-02 explicitly defines the command parameter; 11 §7.2–7.3 requires no mutation and prediction of the command sequence. Simulated state must survive between preview steps without escaping to live history or revisions.

**Regressions:** `parameter_dry_run_is_honoured_inside_atomic_batch`, `sequential_batch_dry_run_queries_see_previous_simulated_edits`, `c12_r1_contracts.rs:100`.

### C12-R1-04 — `job.wait` bypasses the common invocation contract

**Location:** `crates/executor/src/lib.rs:161`, `:222`.

**Repro:** call `job.wait` with `timeoutMs:0` and a request ID while a job runs, finish it, retry the same call. The result changes from running/timed-out to succeeded instead of returning the original envelope. The shortcut also returns `documentRev:null` with an open project and never evaluates `InvokeOptions.expect_rev`; its source checks only read scope and parameter schema.

**Required:** 11 §7.2 idempotency/optimistic guards, 10 AG-09 revision in every envelope. Waiting off the document thread is sensible, but must preserve the shared command contract. The explicit wait timeout is separately adjudicated below; it is not itself the P1.

**Regression:** `job_wait_obeys_request_id_and_retains_document_revision`, `c12_r1_contracts.rs:137`.

### C12-R1-05 — Agents can inspect and cancel another session's jobs

**Location:** `crates/executor/src/commands/job.rs:35`, `:102`; `crates/executor/src/lib.rs:222`.

**Repro:** create a held job owned by `agent:other`. An agent with read scope can request `job.list {all:true}` and receive it; an agent with UI scope can cancel its guessable `job-N` ID. `all` unconditionally removes the session filter, while cancel and wait perform no ownership check. Job records can include private command results.

**Required:** 11 §15.2 says jobs of this session, with all jobs reserved for the GUI; 11 P8/§6 defines session-scoped permissions. Enforce ownership on every lookup, not just the default list filter. C1.4's authentication work does not repair an already supplied `Origin::Agent` being ignored here.

**Regressions:** `agent_cannot_read_another_sessions_jobs_with_all_true`, `agent_cannot_cancel_another_sessions_job`, `c12_r1_contracts.rs:176`.

### C12-R1-06 — Request-cache eviction re-executes old edits within the same session

**Location:** `crates/executor/src/run.rs:23`, `:40`.

**Repro:** patch metadata to 1 with request ID `original`; independently change it to 2; issue 10,001 different keyed calls; retry `original`. The edit executes again, overwrites 2 with 1, adds undo step `u-3` and advances documentRev to 4, instead of returning the original revision-2 result. The shared bounded FIFO silently drops its memory of the request.

**Required:** 11 §7.2 promises the original result for repeated IDs within the session, without a 10,000-call exception. ADR-0013's documented capacity is not a spec amendment. Use a session-lifetime policy that cannot silently re-execute an evicted mutation (or obtain an explicit protocol/spec ruling).

**Regression:** `session_idempotency_survives_more_than_ten_thousand_other_requests`, `c12_r1_contracts.rs:442`. Persistence across process restarts is **not** required by this citation.

### C12-R1-07 — `expectRev` ignores listed guards and omits required conflict details

**Location:** `crates/executor/src/commands/doc.rs:874`; `crates/executor/src/run.rs:164`.

**Repro:** patch a scene with the command-parameter map `{paletteId:999999}`. It commits because the handler only checks entries corresponding to patch targets. A normal stale target does return `rev.conflict`, but details use `actual`, not `currentRev`, and omit the current small object JSON. The envelope-level implementation likewise omits the specified conflict details.

**Required:** 10 REV-05 says **any listed object** mismatch fails without changing anything, with `details.currentRev` and current JSON when smaller than 64 KiB; 11 §10 repeats `details.currentRev`. A cross-object guard is a legitimate optimistic dependency.

**Regressions:** `expect_rev_map_checks_every_listed_object_not_only_patch_targets`, `expect_rev_error_reports_current_rev_and_small_current_object`, `c12_r1_contracts.rs:220`.

### C12-R1-08 — Historical `doc.diff` is incorrect beyond its snapshot fast path

**Location:** `crates/executor/src/commands/doc.rs:1167`; `crates/executor/src/session.rs:104`.

**Three independent reproductions:** (1) batch two writes to the same scene, then make 257 more edits; `doc.diff {sinceRev:1}` fails `history.diverged` after only 258 transactions. Back-patches for one entry are aligned against the same starting document rather than applied progressively/merged as undo replay does. (2) after 300 single edits, `doc.diff {sinceRev:1,untilRev:2}` returns `toRev:2` but a changed object's `rev:45`: old content is reconstructed without restoring old revision stamps. (3) open a clean saved document, make 10,001 edits, diff from the save revision: `doc.diffUnavailable`, because the fixed queue discarded the last-save base.

**Required:** 10 REV-02/04, AG-09 and decision D11 require accurate change tracking, at least to the last save **and** the last 10,000 transactions. The 10k random undo test does not exercise this separate reconstruction algorithm.

**Regressions:** `diff_older_than_snapshot_window_replays_repeated_entry_batch`, `historical_diff_reports_the_revision_of_its_requested_end_state`, `diff_retains_the_last_save_even_after_ten_thousand_transactions`, `c12_r1_contracts.rs:421`, `:550`.

### C12-R1-09 — `doc.diff` cannot read prior steps in an atomic batch

**Location:** `crates/executor/src/commands/doc.rs:1211` and `:1167`.

**Repro:** atomic batch: patch scene metadata, then `doc.diff {sinceRev:<base>}`. The diff reports no changes, although `doc.object.get` can see the staged edit. It reads `cx.project()?.doc` and reconstructs from committed history rather than using the transaction's staged document.

**Required:** 11 §7.3 explicitly permits query steps and requires them to see earlier uncommitted state. This is a distinct active-transaction bug from historical reconstruction in finding 08.

**Regression:** `doc_diff_sees_prior_uncommitted_atomic_steps`, `c12_r1_contracts.rs:292`.

### C12-R1-10 — A checkpoint inside a batch stores changed content with the old revision

**Location:** `crates/executor/src/commands/checkpoint.rs:60`, `:78`.

**Repro:** atomic batch: patch metadata, create checkpoint `inside`; the batch commits revision 2, but `checkpoint.list` reports revision 1 for a snapshot containing the changed content. The checkpoint captures `cx.document()` before the staged transaction is stamped and is not reconciled at commit. This creates two different contents claiming the same revision and corrupts the meaning of subsequent checkpoint-based diffs.

**Required:** 10 REV-01/02 and 11 §7.3/§7.7/§15.2 require coherent revisioned snapshots. Establish explicit checkpoint semantics within atomic batches, including checkpoints created between edits; do not merely change the reported number while leaving the captured object stamps stale.

**Regression:** `checkpoint_in_atomic_batch_has_the_committed_content_revision`, `c12_r1_contracts.rs:276`.

### C12-R1-11 — Drawing revision changes are absent from change records

**Location:** `crates/executor/src/cx.rs:604`, particularly the touched-object loop; `crates/model/src/document/stamp.rs` supplies the drawing stamp.

**Repro:** modify one stroke's metadata. Both stroke and containing drawing receive revision 2, but the invocation's change list contains only the stroke. Drawing-own-view diffing also suppresses a content-only parent change because own views exclude child content and rev fields. A client tracking drawing revisions cannot update its optimistic guard from the returned change list.

**Required:** 11 P6 says each mutating call returns changed objects and their new revisions; 10 REV-02 explicitly makes drawing content affect drawing rev. Preserve the efficient touched-object strategy while including these mandated invalidations.

**Regression:** `changes_report_drawing_revision_when_a_stroke_changes`, `c12_r1_contracts.rs:310`.

### C12-R1-12 — Most inventory declarations do not meet the registry/schema/parity contract

Current stub handlers reject execution, so this is not claimed as an already working file/network permission exploit.

**Regressions:** `registry_stubs_have_actual_parameter_constraints_and_examples`, `registry_file_and_network_commands_declare_required_scopes`, `every_registry_entry_has_a_gui_binding_or_agent_only_justification`, `c12_r1_contracts.rs:364`, `:496`. Complete per-entry evidence is in the register JSON.

### C12-R1-19 — Valid maximum-u64 revision panics the document thread

**Location:** `crates/executor/src/cx.rs:387`.

**Repro:** construct a validated fixture with `DocumentParts.document_rev = u64::MAX`, open it, and patch ordinary metadata.
