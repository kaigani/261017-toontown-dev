## Findings

### C52A-R1S-01 - P2 - Missing shared-state event

Citation: E-57 (one state); spec/A_command_registry.md:504 requires
xsheet.lightTable.changed for contents or item-state changes.
Path: crates/executor/src/commands/draw_aid.rs:608-615, 908;
crates/executor/src/commands/xsheet_view.rs:461-466 (announce_light).
Input: add lt1 through xsheet.lightTable.add, then hide it through
drawAid.staticLightTable.set. The latter calls announce, which emits only
drawAid.changed. A subscriber to the sheet's declared event sees no change,
although xsheet.lightTable.list now reads hidden. Correct: announce the
sheet event for effective mutations through either family, with changed ids.

### C52A-R1S-02 - P2 - Thumbnail cache survives project identity changes

Citation: E-56 (immutable drawing snapshot at its revision, stale images never
shown); spec/04_timeline_xsheet.md:823-838 (cell thumbnail represents drawing).
Path: crates/executor/src/lib.rs:394-395 creates one service per executor;
crates/executor/src/thumbnails.rs:85-95 keys only drawing id, rev, size;
crates/executor/src/host.rs:875-890 supplies the newly opened document to it.
Input: fork a saved project into A and B, edit the same drawing once in each
with different content, preserving its id and giving it the same revision in
both forks. Open A and request its thumbnail; close A, open B in the same
executor, and request that drawing at the same size. The cache hit answers A's
image for B. In-flight A jobs can likewise populate this shared cache after B
opens. Correct: isolate cache and pending work by project generation or reset
and reject old-generation completions on project replacement.

### C52A-R1S-03 - P2 - Exposure-edge release ignores changed exposure

Citation: E-23 and E-28 (reviews/M5-C5.1-plan.md:479-481,496-499);
spec/04_timeline_xsheet.md:907.
Path: crates/executor/src/xsheet_gesture.rs:251-275 builds add/remove;
crates/executor/src/timing_gesture.rs:957-960 compares outcomes, but
1117-1118 falls back to command and parameters for these commands.
Input: press the bottom edge of drawing A exposed at frames 1-4, preview
lengthening by two frames, then change frame 4 to drawing B before release.
Both comparisons return the same add parameters (element, from/to 4, frames 2).
The release succeeds and lengthens B rather than cancelling the changed grab.
Correct: compare the grabbed exposure and absolute shifted following cells
against the press snapshot; refuse timeline.targetChanged on this sequence.

### C52A-R1S-04 - P2 - Horizontal scroll escapes coordinate validation

Citation: E-31 (reviews/M5-C5.1-plan.md:525-528): every sample and scroll
position outside the stated bound must be arg.invalid before arithmetic.
Path: crates/executor/src/timing_gesture.rs:891-899 validates scrollTop and
samples only; crates/executor/src/xsheet_gesture.rs:125-134 adds scrollLeft.
Input: timing replay on xsheetGrid with scrollLeft=1e300 and ordinary finite
samples. It passes check_input and performs hit-testing with that value,
returning a no-op rather than arg.invalid. Correct: bound scrollLeft and the
new light-table rectangle's coordinate members at the same entry boundary.

### C52A-R1S-05 - P2 - Seven new handlers excluded from argument sweep

Citation: E-26, E-33 and E-38; reviews/M5-C5.2-plan.md:75-76 explicitly
requires the argument sweep for each of the seven commands.
Path: crates/executor/tests/c51_argument_sweep.rs:26-35 selects only
xsheet.currentCell.set and timeline./playback. prefixes.
Input: run the sweep with this checkpoint's registry. None of display.set,
panel.set, columnWidth.set, lightTable.add/move/remove/set is selected;
its unreached-handler assertion considers only the filtered set and passes
without calling any of them. Correct: include all seven and require handler
and numeric-boundary coverage for them. This contradicts the handoff's claim
that the seven run under that sweep.

## Observations

- Case 6: the two dev hooks are gated by test-hooks (lib.rs:1271 and
  history.rs:266); no default product exposure found. No direct unwrap,
  expect, panic, unsafe or allow occurs in the three newly added kernel files
  checked (thumbnails, xsheet_gesture, xsheet_view). Geometry uses guarded
  indices and saturating frame conversion; omitted horizontal bounds are
  separately reported above.
- Case 6: thumbnail tests wait on notices, not fixed sleeps. The latency
  comparison uses four times baseline plus 5 ms; read-shape timing is a
  scaling comparison with a generous absolute ceiling. No under-four-times
  absolute headroom violation established from static evidence. Some checks
  (for example all over ready results) would be vacuous alone, but adjacent
  length assertions make those tests falsifiable.
- Case 6: light-table/session mutations use the executor session path; derived
  thumbnails intentionally mutate the shared cache before commit but reject
  staged drawing values by pointer identity. No staged-content cache leak
  established in that path.


- Case 2: the plan at M5-C5.2-plan.md:75-77 explicitly requests dialog
  coexistence refusal. The handoff narrows this to focus-changing commands.
  Spec 11:237-241 contains both the general mutation-wait rule and the
  focus-change refusal. Existing host arbitration lets these ui mutations run
  under dialogs; a clarification should reconcile these statements.
- Case 3: worker rendering has no panic recovery: a renderer panic leaves
  worker=true and rendering set, preventing later worker creation. A concrete
  renderer panic input was not established statically.
- Case 3: parse_entry is preceded by safe_name and resolves a document drawing,
  not a filesystem path. The command requires read scope; no per-drawing scope
  boundary was found. MCP drops shell.* in server.rs:1974-1975.
- Case 5: the matrix matches the cells it transcribes, but omits rename drawing
  and paste as new drawings, and skips several dash cells for clear/lock. Thus
  it does not prove the entire 13.20 table. No new handler mismatch established.
- Case 5: the two reviewer diffs preserve result assertions and implement the
  authorised preview setup/read-back and dispatch-notice cancellation changes.


- Case 1: patch sizing uses serialized values rather than allocated JSON size.
  Snapshot sizing excludes entries shared between before and after, even though
  subsequent edits can leave those entries retained only by history snapshots.
  This deserves a retained-allocation measurement; no runtime claim is made here.
- Case 1: push and typing extension enforce the bound; replay replacement
  remeasures bytes but does not itself call keep_bound.
