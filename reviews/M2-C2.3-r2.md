## Findings

### C23-R2-01 — P1: a timed-out queued mutation later commits

**Clause/ruling:** C23-R1-07; ADR-0015 watchdog history; 02 §13.1.12; plan never-block/atomic cancellation contract. A caller timeout must cancel that request and prevent its commit.

**Reproduction:** `cargo test -p tt-executor --locked -j 4 --test c23_r2_watchdog -- --nocapture`.

The test opens the fixture with a 600 ms budget, adds a 400-anchor path, and uses the existing dev-only work hook to make one Smooth charge spin for two seconds. Smooth returns `command.timeout`. A rename queued behind it also returns `command.timeout` before the charge finishes. After resetting the hook and letting the worker drain, the drawing name is **`Timed out queued rename`**, and the document revision advances **2 → 3**. Both caller errors precede that mutation. The test remains failing.

**Observed versus required:** Smooth's running request observes cancellation and stops, but the queued rename survives its own caller's timeout and commits later. `ExecutorHandle::call` stores the worker's *current* sequence in the shared cancellation slot, without associating the queued request with its caller. `document_thread` assigns the rename a new sequence only when it dequeues it. Required: cancellation belongs to the originating request, including while queued; a timed-out mutation must never begin or commit afterward.

**Fix direction:** allocate a request identity/cancellation token before enqueueing; carry it with the request and mark that exact token on timeout. Reject cancelled requests at dequeue and before transaction/effect commit. Retain the passing running-command spin test, work-account and renderer cancellation controls, MCP typed-timeout delivery and non-waiting audit. Add a queue/running-request race control proving one caller cannot cancel another caller's request.

### C23-R2-02 — P1: explicit `createDrawing:false` is lost by all four shape wrappers

**Clause/ruling:** C23-R1-10; 02 §13.1.4; ADR-0016 explicit cell addressing.

**Reproduction:** `cargo test -p tt-executor --locked -j 4 --test c23_r2_closure r10_ -- --nocapture`.

Set Bob's exposure to `[[null,24]]`, then call each of `draw.rectangle.add`, `draw.ellipse.add`, `draw.line.add`, and `draw.polyline.add` with `elementId: 'scene:#1/element:"Bob"'`, `frame:1`, **`createDrawing:false`** and valid geometry. Polyline also uses `snap:true`. Every call succeeds, creates a drawing and artwork, fills the cell, and advances the revision. The separate `true` controls succeed as required. Both proving tests remain failing.

**Observed versus required:** the new fields pass schema validation, but the wrapper's `add` helper inserts `createDrawing` into `StrokeAddParams` only when it is true. When false is omitted, that handler's default is true. Required: an empty addressed cell with explicit false refuses without changing drawings, bank membership, exposure or revision.

**Fix direction:** forward the boolean value for both cases and keep the specified default true in the shape parameter schemas. Keep the empty-cell polyline snapping behavior and the successful explicit-cell tests; verify false refusal and true creation separately on all four commands, with undo/dry-run/failed-batch controls for created cells.

### C23-R2-03 — P1: a valid selected zone disappears before the next command

**Clause/ruling:** 02 §7.1.1, §8 default-selection semantics, §13.1.10; C23-R1-12 fill-only warning; 03 §9.1.

**Reproduction:** `cargo test -p tt-executor --locked -j 4 --test c23_r2_closure r12_ -- --nocapture`.

Create and paint a rectangle at `(2000,2000)–(2100,2060)`. Pass its returned zone ID to `draw.selection.set`. The setter reports that ID in `selectedIds` and returns correct bounds. An immediate `draw.selection.get` returns **`selectedIds:[]`, `bounds:null`**. `draw.centreLine.apply` with only `drawingId` then refuses with **`drawing.nothingToDo`**, rather than `drawing.centreLineOnFill`. Both assertions remain failing. The round-1 explicit-zone Centre Line test passes.

**Observed versus required:** the successful setter's state is pruned during executor context repair. `app::selectable_exists` checks `Document::locate`, which cannot locate derived zone IDs. Required: a valid selected zone survives ordinary command completion, is readable, and is available to commands using the documented default selection. This affects zone selection itself, beyond the warning that first exposed it.

**Fix direction:** validate derived drawing-zone references through the current planar maps during selection repair. Preserve valid zone IDs, prune stale ones after topology changes, and retain compound drawing identity. Check `set → get → colour.selection.apply` and `set → centreLine` for painted/unpainted zones, plus unrelated edits, undo/redo and drawing isolation.
