## Findings

### C23-R3-01 - P1: a timed-out UI-only selection applies session state afterward

**Clause/ruling:** C23-R2-01 per-request cancellation and pre-effect commit ruling; ADR-0015 cancellation history; the atomic/session-state rollback contract in `run.rs`; 02 sections 7.1.1 and 13.1.10. A timed-out request must not apply its requested state later, even when it has no document transaction.

**Reproduction:** `cargo test -p tt-executor --locked -j 4 --test c23_r3_selection_cancel -- --nocapture`. The new unignored test is intentionally failing. It opens the seed-1 fixture with one drawing containing 3,000 simple disjoint pencil strokes, uses a 200 ms executor budget, and calls `draw.selection.set {drawingId, by: "all"}` from an initially empty selection. It uses real command work, without the spin hook. It then waits for the worker to answer `app.state.get` and checks the resulting selection and document revision.

**Observed versus required:** the caller receives `command.timeout` after **0.215496 s**. At **2.090948 s** from the call's start, `app.state.get` reports **3,000 selected compound IDs**; document revision stays **1**. Required: the original empty selection remains empty after the timeout, with no late session mutation. Setup/open succeeds; the failing assertion is the late-selection assertion, not a timing or fixture assertion. [Raw receipt](evidence/M2-C2.3-r3/selection-cancel.log).

**Cause:** `draw.selection.set` computes bounds, then calls `set_drawing_selection`, which mutates `cx.app_mut()` directly and defers its event. `run::commit` returns early for empty transactions **before** `cancelled_check`. `apply_effects` does observe cancellation, but its error is handled as a post-commit publication failure, without restoring the saved `Rollback` state. The request-specific token is correctly marked; the UI/session acceptance path fails to roll back. Selection bounds also perform repeated scans without a work-account cancellation check, explaining why the worker continues after its caller's timeout.

**Fix direction:** check request cancellation before accepting **any** staged session/UI changes, including the no-document-transaction path. Restore `Rollback` on cancellation before a real commit; preserve the established post-document-commit publication-error semantics. Prefer staging session changes with the transaction/effect acceptance boundary, and make long selection/bounds loops bounded and cancellation aware. Keep this proving assertion, the original R2 queue/running races, atomic-batch replay exclusion and valid-zone tests. Add controls preserving a previous nonempty selection and point/tool session state; do not widen the budget or weaken the assertion.

The exact protected-path glob has a declared-new-file discrepancy, documented below. Existing C22-T2, C23-T1, C23-T2, C21-R1-11 and R1-12 obligations retain their owners; **R3-01 requires C2.3 scoped closure and is not deferred to C2.4**.

**Selection history interpretation:** 02 §7.1 defines selection and permanent geometry transformations; §13.1.10 requires valid selection readback. Neither requires selection snapshots in document undo. Selection is transient session state under 10 §2.7. Thus undo restores document geometry/zone identity, while an already-pruned selection remains cleared. The test proves the restored zone is valid by explicitly selecting its original ID before redo; it does not infer validity solely from an empty readback.

**Cancellation ownership:** `call` allocates from the cancellation state shared by cloned handles before enqueueing, tags the request, and marks that token on caller timeout. Dequeue refuses marked tokens; work accounts observe the running token; transaction/effect entry checks reject cancellation. **R3-01 shows that the no-document-transaction session path still accepts UI state despite the later effect rejection.** Fresh independently spawned executors have separate token domains, so equal local counter values do not cross-cancel. The review does not claim globally unique numbers across unrelated executors or prove every instruction-level race around a commit/publication boundary.
