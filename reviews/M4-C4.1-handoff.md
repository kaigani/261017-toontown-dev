## 1. Built

**Kernel (`crates/executor`).**
- `prefs.*` over a data catalogue (`src/prefs.json`: every key of 01 §7.3, the agent keys of 11, the keys earlier
  commands use; SI-117): typed per-key validation, atomic `prefs.set`, only non-default values stored, stale stored
  values fall back to their default, staged reads within a call, agents cannot change `agent.*`, `prefs.changed`.
- `keymap.*`: bundled default set (`src/keymap-default.json`; 01 §8.2 platform shortcuts plus simple defaults for
  frame, drawing and element stepping, zoom, view rotation, panel show/hide), user overrides stored as deltas
  (`keymap.json`), canonical platform-neutral sequences, per-platform reserved keys, conflicts with mode/global
  shadowing, override, reset, export/import (merge/replace), `keymap.changed`.
- `ui.*`: tips and "don't show again", status bar (visibility is the preference; segment texts), themes (user theme
  files validated), start screen (01 §2 rule following `general.startup.behaviour`), context-help mode, help for every
  command, panel, preference and message, `ui.help.open`, `ui.preferences.open`, `ui.message.shown`.
- `window.geometry.get/set`, `window.minimized.set`, `window.raiseAll.run`, `window.fullScreen.set`: kernel state plus
  `shell.*` notices applied by the host after acceptance (headless: a virtual window); geometry clamped to the screens
  and restored at start. `workspace.export/import`.
- View windows in the kernel (type, previous type, per-type transforms, sizes, active view; mode from the active
  view's type). `view.*` commands stay with C4.2 as registered.
- Host kernel API (not commands; agents cannot reach it): `report_shell` (sensor facts), `resolve_key` (the one key
  dispatch), `complete_reference` (menu items), user priority for agent calls (`ui.busy`, `ui.modalOpen`,
  `set_wait_for_user`), `events_broadcast` / `await_rendered` (inspect_ui freshness), `release_abandoned_recovery`.
- `inspect.ui.tree` implemented (pulled from C4.2): the GUI-reported tree in attached mode, the kernel's virtual tree
  headless.
- Settings files: `preferences`, `keymap`, `state` (suppressed tips, first-run flags, window geometry), `recent`,
  `workspaces`; written at the acceptance boundary; corrupt files set aside.

**MCP (`crates/mcp`).** Streamable HTTP transport on `std::net` (`src/http.rs`; loopback, bearer token, Origin and Host
checks, SSE answers, GET stream, DELETE, several sessions over the one executor), each session running the stdio
protocol loop; the `key` tool through `resolve_key`; `inspect_ui` freshness wait with `stale`; `shell.*` notices not
forwarded.

**Host (`desktop/src-tauri`).** `run_command` (every GUI action), `cancel_request`, `report_shell`, `dispatch_key`,
`pick_path` (native pickers), `startup`, `restart_engine`; engine event pump; native window effects and geometry
reports; window close runs the quit flow; native menu from manifest v2 with live enablement, check marks, undo/redo
labels and keymap accelerators; single instance; attached mode lifecycle and discovery file; engine watchdog.

**Front end (`desktop/src`).** Mirror store with resync on event gaps; action router (dialogs, unsaved-changes rule,
job progress with `job.cancel`, request cancellation shown as cancelled); message boxes with ids, don't-show-again,
agent notifications; dock adapter (drops become `window.panel.move`, floating panels as in-window floats); status bar
segments and the agent indicator (Pause, Resume, Stop, Activity); main toolbar and the vertical tool-palette rail;
start screen and New Project form; Project Properties; preferences with search, restore defaults, the shortcut editor
(capture, reserved keys checked by a kernel dry run, conflict Override/Cancel, reset, reset all) and tips; themes
(light, dark, follow system, user themes); History panel; the rendered UI tree reported for `inspect_ui`; window title;
start-up behaviour and deferred documents; engine-not-responding banner.

## 6. Residual risks and partials

- **Floating panels float inside the main window**, at their kernel geometry, not as separate OS windows (01 §5.4
  "floated as a separate window"); moving or resizing a float is not yet written back with `window.panel.set
  {geometry}`. Owner: C4.1 review round (the host side of multi-window: one webview per float).
- **Splitter drags are not stored** (SI-118): no user command exists; the drawn size returns to the stored one on the
  next dock rebuild.
- **macOS screen captures** in the GUI job are best effort (runner screen-recording permission); the UI trees are the
  gated receipt.
- **Native menus, global shortcuts in menus, native pickers, single instance across a Finder or Explorer double-click,
  multi-monitor clamping and following the system theme** need a person at the machine: `reviews/manual/M4/` (seven
  scripts, user-pending).
- **Watchdog timing:** three missed 5 s heartbeats (15 s) mark the engine not responding; a busy-but-healthy engine
  under a long synchronous command can cross that bound on a slow machine (the banner offers Wait; restart is never
  automatic).
- **Inherited timing risks** (merge note §8 item 7): timing-index risks, `c14_r1_autosave` noise, O-6 retry/filter
  limits, absolute throughput samples, scheduler-dependent deadline ambiguity; unchanged.
- The GUI job's first-start bound is 120 s (a cold webview on a fresh runner); the restart test waits up to 30 s for
  the autosave thread (≥ 3× a local write).
