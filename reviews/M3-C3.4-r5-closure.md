## Additional product changes

1. **Enqueue instant.** `Request::Tagged` carries `Instant`; caller deadline uses the same instant. `Core::call_start` is installed and cleared around each request. Both sequential waited-job and job.wait paths use saturating subtraction of elapsed time and the tenth-budget margin, so an exhausted remainder is zero, never a replenished budget. Independent queue/action and queue/batch probes pass in `c34_r5_deadlines`, including budgets consumed past expiry with no later commit, and a job.wait step queued for 700 ms of its 1000 ms budget returning two steps within budget. The builder queued waited-render probe also passes.
2. **Caller deadline.** A probe ending at/after the deadline sets `held`; the timeout then wins even over a committed remembered reply. Independent remembered-commit coverage is in `c34_r5_deadlines`. There is no deterministic public hook between reply delivery and caller receive: the before-deadline-delivery/late-wake case is reviewed in `call_with`, not claimed as deterministically reproduced. `rx.try_recv` takes an available reply before marking timeout; timeout marks and immediately returns, so this caller cannot subsequently take a reply after its own timeout mark. There is no reply timestamp: delivery after the deadline but before a descheduled caller checks it is indistinguishable from timely delivery. No reproducible P1 interleaving is claimed. The queued-expiry probe verifies refusal and no later commit.
3. **Activity reason.** Section 11 ?11 does not forbid additive audit metadata. The implementation serializes `errorReason` consistently in list, JSONL export/persistence and MCP app://activity (which calls list). Batch replay reads its explicit replay fields and ignores errorReason. Old entries default the new field to None. However the implemented command returns generic maps, so its generated result schema permits arbitrary properties without declaring errorReason or its type. The inventory also omits it. The permanent failing `activity_reason_is_declared_for_consumers` test requires an optional typed property. Fresh generators alone cannot correct this Rust result-type declaration.
4. **Nested labelling.** The labeller requires the running cancellation cause and only rewrites command.timeout nodes, recursively following details.error. It leaves an arg.invalid node untouched. The passing independent nested-cause test exercises an argument error before later cancellation. Cancellation hints identify a refused invocation; previously committed sequential steps remain committed. No claim that a sequential batch rolls back earlier steps is made.
