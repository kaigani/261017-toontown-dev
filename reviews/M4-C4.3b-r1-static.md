## C43B-R1S-01 — GUI operations declared agent-only

Violates D-25/D-31's exhaustive three-state gate. `spec/05_scene_planning.md` §19.1.1 lines 1174–1177 explicitly maps FOV wedge dragging to `anim.camera.set`; §9.4 line 690 explicitly maps motion-point properties to `anim.path.point.set`; §9.4 line 704 and §9.6 lines 720–725 describe remove-point, whose command row is §19.3 line 1253 (`anim.path.point.remove`).

Violations: `crates/executor/src/commands/anim_camera.rs:374`, `crates/executor/src/commands/anim_path.rs:797` and `:1042` declare these agent-only, explicitly acknowledging the corresponding future GUI surfaces. Those surfaces operate the same commands, rather than a distinct bulk operation. This removes the future obligation to bind them: PA3 will keep accepting the agent-only state at M6 handoff.

Closure: classify these three as deferred to the appropriate M6 checkpoint with spec citations, then require their bindings when it hands off. Whole-list replacement (`anim.function.set`, `anim.path.set`) differs from editing a point and does not establish the same defect. Camera deletion via element deletion likewise does not establish identical command dispatch.

## C43B-R1S-06 ? commit callbacks can clear a later gesture's preview

P2, case 5; violates preview note ?2/?5 PV1 and generation invariant T6. `desktop/src/canvas/CanvasView.tsx:685?698` schedules an untagged callback that later writes the shared `clearOverlayAt`. Meanwhile the collector becomes idle at release (`desktop/src/canvas/input.ts:194?200`), allowing another press/preview at `CanvasView.tsx:745?779`. When the earlier answer arrives it arms clearing of the new preview; the frame loop at lines 510?517 then calls `endPreview` on that later gesture. The same callback has no generation/stopped guard. `adoptGeneration` lines 290?300 calls `cancelGesture`, but after release `collector.cancel()` returns false, so lines 269?277 do not clear the outstanding preview. A restart between release and answer can therefore retain and apply the previous generation's affine to the new model.

Closure: tag pending commits and previews by gesture and generation, discard obsolete callbacks, and always discard preview resources on generation adoption/unmount; add deterministic delayed-answer and restart-after-release tests.

## C43B-R1S-07 ? three-way tests assert agreement without spec values

P2, case 6; violates D-23. `scripts/c43-gesture-equivalence.py:285?305` compares produced commands, content and labels across the three paths, with at most one label. No per-row spec label, target or channels are asserted. The direct path receives the produced commands, so a common incorrect label/target passes. In particular 05 ?5.0 line 398 and ?5.1?5.2 lines 405?418 require Select to edit static values, Transform to key the changed channels at the current frame, and a pivot drag to move a static pivot. The script never independently asserts those requirements. The Rust two-way tests' spec expectations do not satisfy the ruling that every three-way row states them. Closure: give every row a spec citation and independently derived command/parameter/label expectation, including no-step rows, before comparing paths.

## C43B-R1S-08 ? budget receipt does not isolate drag work or enforce its fixture

P2, case 6; violates D-33 and plan ?6. `scripts/c43-camera-measure.py:121` records `dragWork` from `workMs`, which is an unconditional last-300-frame ring (`desktop/src/canvas/metrics.ts:48?51`), not gesture work. It is sampled after post-drag sleeps and undo/redraws, diluting the gesture workload. The script then labels and tests it as work during scene drags (lines 204?214). It also waits for 1,000 resident drawings but, on timeout, merely records the smaller count and proceeds (lines 190?197), and records actual backend/fallback without requiring the requested backend. Thus both-backend/1,000-element claims can pass on a smaller scene or fallback.

Closure: separately collect gesture work, assert the resident count and requested backend with no fallback, require the full sample/frame counts rather than `min(30, drags)` at lines 232?233, and add read-only/unit fixtures showing incomplete measurements fail.
