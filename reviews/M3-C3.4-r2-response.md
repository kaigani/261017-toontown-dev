## 2. Rulings and items

- **Interpretation to confirm (rule 1 and queries).** Rule 1 says an already-cancelled request never begins and nothing
  is remembered under its `requestId`. The reviewer's unchanged
  `retry_cache_and_late_cancellation_are_stable_for_three_thousand_calls` sends a query (`doc.state.get`) with a probe
  that is true from the start, and requires that answer to be remembered and the retry to be served from the cache.
  Its sibling `already_cancelled_mutation_never_commits` requires an action under the same probe to be refused. Both
  hold, and both pass, because rule 1 is applied to every request that can change something (actions, jobs, batches);
  a wait answers its cancellation with the `jobId` (rule 4). A query changes nothing: it is not refused before it begins and its worker does not ask the caller, and a
  cancellation stops it at its next work-account check through the marked token. ADR-0020 decision 8 rule 1 says so.
  If queries should be refused too, the reviewer test needs amending.
- **SI-111** is recorded (interim, awaiting spec owner; next free id SI-112) and listed in merge note §4.
- **Token hygiene:** watchdog tokens are bounded to outstanding calls. `token()` registers a token and `forget()`
  removes it; `mark()` of a token no longer outstanding does nothing (the late-mark interleaving), with the same lock
  order in `mark` and `forget`. `test-hooks` counters give the marked and outstanding token totals.
  `c34_tokens::thousands_of_cancelled_and_timed_out_calls_leave_no_token_behind` makes 3000 calls (cancelled
  actions, queries and batches with probes flipping at 0-240 µs, and calls under a 3 ms watchdog budget). Both
  counters return to zero.
- **Reviewer Python collectors.** `c34-r2-sdk.py` and `c34-r2-inventory.py` are listed in
  `scripts/run-reviewer-python-suites.py` as not suites, with reasons, as `c23-r3-finalize.py` is. They are round

  `reviews/evidence/M3-C3.4-r2/inventory.json`, and asserts that the register's last heading is SI-110, which the
