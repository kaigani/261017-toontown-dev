### C41-R2-01 - P2 - idle unauthenticated clients exclude valid new requests

Clause: ADR-0022 decision 2 resource bounds; A2 admission-cap availability requirement.

Reproduction: fill the unauthenticated cap with idle sockets, then send a complete correctly authenticated request on a fresh socket. At `http.rs:692` admission is attempted before reading any header or token, so it returns 503. At defaults, 16 local idle sockets can deny every fresh authenticated connection for ten seconds; replenishing them sustains denial. Existing admitted streams are not claimed to stop.

Permanent reproduction: `cargo test -p tt-mcp --test c41_r2_review idle_unauthenticated_clients_leave_authenticated_service_available --locked`. **Fails at 43508ba**. Uses cap 1 and head deadline 2 s, synchronizes on an observed 503, sends the valid request, and measures the operation with Instant (under one second). Expected authenticated session lookup 404; observed 503. Builder must make the test pass with its body unchanged. Evidence: `a2.txt`.

Required: a bounded admission design that preserves authenticated service under idle unauthenticated saturation. Observed: the smaller cap denies all new clients before they can identify themselves. Fix direction: reserve bounded parsing capacity for complete heads/credentials and prevent idle clients from monopolizing it. Owner: C4.1 HTTP transport.
