## Findings

### C41-R1-01 (P1) — closing a dialog never cleared the modal state — accepted

- **Root cause.** `ShellReport.modal` is `Option<Option<ModalReport>>` with plain serde, which reads `null` as an absent
  member (`None`), so `{"modal":null}` changed nothing. The builder's kernel tests built `Some(None)` as a struct and
  never went through JSON; the GUI e2e opened Preferences but never closed it, and its 28 checks and the 16 gesture tests
  asserted the open side only (the JSON the front end sent on close was never compared with what the kernel did).
- **A second defect found while proving the fix in the real application:** a dialog opened by a command or an agent
  (`ui.preferences.open`) never took the keyboard focus, so its Escape handler, bound on the dialog element, never ran;
  Escape went to the page body. Dialogs and message boxes now take the focus when they open and give it back when they
  close (`desktop/src/shell/modalFocus.ts`).
- **Fix.** A `present` deserializer: absent stays `None`, `null` becomes `Some(None)` (`crates/executor/src/host.rs`).
- **Tests added.** Kernel: `tests/c41/busy.rs` `modal_on_the_wire_distinguishes_absent_null_and_a_value` (the three wire
  states, the host's writer round-trips them, and over JSON closing releases shortcuts and agents); every builder busy
  test now builds its reports from JSON text. Front end: the exact JSON sent on close
  (`closing a message box sends exactly {"modal":null} with its generation`), and a dialog opened by the engine takes
  the focus, Escape closes it and the close is reported. GUI e2e on both OSes: Escape pressed through the OS closes
  Preferences in the GUI, the kernel then reports `modal: null`, F3 resolves to its command and runs (its effect shown
  in the GUI tree), and an agent action is accepted.
- **Rule applied to wire-level tests from now on.** A test of a value that crosses IPC or HTTP builds it from the JSON
  text the other side sends (or sends that text), never from the Rust struct; and every "opens" check has its "closes"
  check.
- **Audit: absent versus null on every type that crosses IPC or HTTP.**
  - `ShellReport` (front end → host → kernel): `modal` fixed. `textFocus`, `description`, `pointer`, `viewSizes`,
    `screens`, `attached`, `renderedSeq`, `messageShown`: the front end never sends `null` for them (typed in
    `desktop/src/ipc/engine.ts` without `null`); `null` and absent both mean "unchanged", which is the intended meaning.
    `uiTree`: a `null` tree is ignored, as intended.
  - Host IPC requests (`desktop/src-tauri/src/ipc.rs`): `RunRequest.options`, `requestToken`, `PickRequest.defaultPath`,
    `availability` references: `null` and absent mean the same (no options, no token, no default path, no params).
  - Command parameters: the six spec A parameters that admit `null` (found by a scan of every command row of spec 01-09
    and A): only `draw.textFormat.set` is implemented, and its `outlineColourId` accepts only `null` (absent and `null`
    both mean "no outline", SI-055); `tool.text.options.set`, `anim.bone.parent.set`, `lipsync.mapping.set`,
    `lipsync.mapping.mouth.set` and `import.options.set` are not implemented yet (their owners must use `present` for
    their `null`-clears parameters; noted in their declarations' owners' list in this response). Generic paths
    (`doc.object.patch`, `set_properties`, `prefs.set` values) carry `serde_json::Value`, which keeps `null`.
  - MCP tool arguments (spec 11): no tool argument admits `null` (none appears in 11).
  - Output direction (kernel → window and agents): `Option` fields are serialised with `skip_serializing_if` or as
    `null` by design; no reader collapses them (the front end distinguishes `null` where it matters, for example
    `modal`).
  - The JSON writers keep `null` (`stringifyWireJson`, the Rust wire writer).

### C41-R1-02 (P2) — non-loopback binds were accepted — accepted

- **Root cause.** `http::start` bound whatever it was given; ADR-0022's refusal lived only in the host's choice of
  `127.0.0.1`.
- **Fix.** `start`/`start_with` refuse a non-loopback address with the typed `StartError::RemoteBind` before binding
  (and check the bound address again); `--mcp-http` refuses one at argument parsing (`ArgsError::RemoteAddress`). The
  preference path can pass only a port (`agent.server.port`, 1024..65535) on `127.0.0.1`; `agent.server.allowRemote` is
  stored and never used (ADR-0022 decision 2).
- **Tests.** `crates/mcp/tests/c41.rs` `non_loopback_binds_are_refused_with_a_typed_error_in_both_families`
  (`0.0.0.0`, `[::]`, `192.0.2.1`, `[2001:db8::1]` refused; `[::1]` never refused as remote);
  `diagnostics.rs` `mcp_http_accepts_loopback_only`.
- **Same root cause elsewhere.** The only other listener is the single-instance socket (`instance.rs`), which binds
  `127.0.0.1` literally; checked.

### C41-R1-03 (P2) — ambiguous headers and framing reached dispatch — accepted

- **Root cause.** `read_request` kept the last duplicate in a map, ignored `Transfer-Encoding`, parsed
  `Content-Length` leniently and split the request line on any whitespace.
- **Fix.** A strict head parser before any header is interpreted (`crates/mcp/src/http.rs` `parse_head`): request line
  exactly `METHOD SP target SP HTTP/1.1`; CRLF line ends only (bare LF or CR refused); no folded lines; a colon and a
  token name in every header line; `Authorization`, `Host`, `Origin`, `Content-Length`, `Mcp-Session-Id` at most once;
  any `Transfer-Encoding` refused; `Content-Length` decimal digits only. Each refusal is a `400` with no session or tool
  side effect.
- **Bounds.** The head must arrive within 10 s of the connection being accepted and fit 16 KiB (`408` / `431`); the whole
  request within 60 s (an absolute deadline: each read's timeout is what is left of it, so a slow sender cannot extend
  it); 64 connections at once, 16 of them before their token check (`503` with `Retry-After: 1`, nothing read); an SSE
  subscriber is dropped when 1024 messages are queued for it or a write blocks 10 s.
- **Tests.** `parse_head` unit tests (15 malformed heads); `crates/mcp/tests/c41.rs`
  `malformed_heads_are_400_with_no_session_side_effect` (11 cases over a real socket, then `session_count() == 0`),
  `a_head_that_never_completes_is_answered_408_at_its_deadline`, `connections_before_their_token_check_are_capped`,
  `a_subscriber_that_does_not_read_is_dropped` (unit).

### C41-R1-04 (P2) — unsupported settings versions loaded silently — accepted

- **Root cause.** `settings::read` checked the envelope's `format` and `kind` but never `formatVersion`.
- **Fix.** The documents' policy (ADR-0021 decision 13): same major read (a newer minor's unknown members tolerated); a
  missing or malformed version is corrupt (`badVersion`); another major version is not read (`unsupportedVersion`); kept
  aside, defaults used, other files unaffected; the message says which.
- **Tests.** `settings.rs` `versions_follow_the_document_policy`; executor `tests/c41/settings.rs`
  `an_unusable_file_is_reported_with_its_reason_and_where_it_was_kept`.

### C41-R1-05 (P2) — unauthenticated requests reserved the maximum body — accepted

- **Root cause.** The body was reserved from the declared length (`vec![0; len]`, up to 64 MiB) and read with
  `read_exact` before the token, `Host` or `Origin` were looked at; one thread per connection with no cap; a per-read
  timeout only.
- **Fix.** Head first (bounded), then the path (`404`), `Host`/`Origin` (`403`), token (`401`), method (`405`), declared
  length (`413`) and session (`404`), all before a single body byte is read or reserved; then the body grows in 64 KiB
  steps as bytes arrive, within the absolute request deadline. **The body cap** is the session's inline payload limit
  (`maxInlineBytes`, 11 §6.5, default 50 MiB): the largest legitimate MCP message carries inline media (11 §6.2), and
  the stdio transport already frames messages with the same limit; 64 MiB had no reason of its own. Connection caps as
  in C41-R1-03.
- **Tests.** The reviewer's test; `a_body_over_the_limit_is_refused_before_it_is_read` (head only, `413` answered
  without the server waiting for a body); `connections_before_their_token_check_are_capped`.

### C41-R1-06 (P2) — `loopback_host` was not an authority parser — accepted

- **Root cause.** One function stripped schemes and anything after a slash for both headers and compared
  case-sensitively.
- **Fix.** `authority_host` (host and optional port only; no scheme, path, query, fragment, userinfo, backslash or
  whitespace; a bracketed IPv6 literal must parse; port 1..65535 digits; host lower-cased) and `loopback_name`
  (`localhost`, `localhost.` with its trailing dot — the same DNS name, accepted deliberately and documented in
  ADR-0022 —, `127.0.0.1`, the IPv6 loopback in any spelling). `Host` uses it directly; `Origin` must be
  `http`/`https` `://` authority with nothing after it; `null` is refused.
- **Tests.** The reviewer's three tests; `hosts_origins_and_tokens` (unit, 16 cases).

### C41-R1-07 (P3) — request-token ownership in the host — accepted

- **Root cause.** `Host::run` inserted a fresh flag under the token unconditionally and removed by token on return.
- **Fix.** `TokenGuard`: claimed only when the token is not in flight (otherwise `arg.invalid` with
  `reason: "requestTokenInUse"`), removed on drop only if the entry is still its own (pointer equality), also when the
  invocation unwinds. Tokens are now per window as well (ruling O-2).
- **Tests.** `host.rs` `a_request_token_is_owned_by_its_invocation`, `run_refuses_a_token_already_in_flight`,
  `a_window_cannot_cancel_another_windows_request`.

### C41-R1-08 (P2) — wrong data shapes loaded silently — accepted

- **Root cause.** Only the envelope was checked; each kind's loader skipped what it did not understand.
- **Fix.** Each kind's whole-file shape is checked on load (`store.rs` `shape`); a wrong shape is corrupt: kept aside,
  defaults for that file, reported. **Dividing line** (ADR-0021 decision 13): the file is corrupt when its whole data is
  not the kind's shape; a single value that fails its own validation inside a well-shaped file is stale (a preference
  falls back to its default, a binding or workspace entry is skipped).
- **Tests.** The reviewer's test; `tests/c41/settings.rs` (`state` with a wrong-typed member is `wrongShape`, the good
  files unaffected).

### C41-R1-09 (P2) — abandoned temporary files stayed — accepted

- **Safety condition.** Another live process of the application (a headless server next to the desktop application, a
  second instance before it hands over) may be writing a settings file in the same folder, and its temporary file must
  not be removed. **Design:** every settings write holds `<settings>/.settings.lock` shared (`File::lock_shared`) while
  it writes; the clean-up at start takes that lock exclusively with `try_lock` and only then removes
  `.<kind>.json.<hex>.tmp` files of the five settings kinds; when any writer holds the lock, it removes nothing (the
  next start cleans). No age heuristic, so the reviewer's test body (a fresh orphan removed at start) is satisfied by a
  safe design. Temporary files of other writers in the folder (the discovery file) are never touched.
- **Tests.** The reviewer's test; `settings.rs` `temporaries_are_cleaned_only_when_no_writer_holds_the_folder` (a shared
  holder blocks the clean-up; after it the orphan goes and a foreign temporary stays).

### C41-R1-10 (P2) — `prefs.changed` listed unchanged keys — accepted

- **Root cause.** `stage` listed every validated key.
- **Fix.** Only keys whose effective value changes are staged, written and listed; a call that changes nothing writes
  nothing and emits nothing.
- **Audit of the other change events.** `keymap.changed` already lists only the commands whose bindings changed and is
  skipped when none did (`keymap::changed_commands`). `workspace.changed` is emitted from an observed difference, so it
  never fires for no change; it now also fires when only the arrangement changed (a float moved, a panel re-docked in a
  workspace already modified), which it did not before: found while building floats (O-2), since nothing announced such
  a change to the windows or the host.
- **Tests.** The reviewer's tests; `tests/c41/settings.rs` `moving_a_float_is_announced`.

### C41-R1-11 (P2) — generic `prefs.set` bypassed the agent-policy domain — accepted

- **Fix.** `prefs::domain` holds the nested domain of 11 §15 (`policy` one of the presets, `maxJobs` 1..8,
  `maxBatchSteps` 1..100000, `maxInlineImagePx` 256..8192, `maxInlineBytes` 1..1 GiB) and runs inside the catalogue
  validator; `agent.policy.defaults.set` now merges its members into the present defaults and validates through the
  same function, then stages like any preference (atomic, `prefs.changed`).
- **Audit of composite catalogue entries.** The catalogue's types are bool, int, number, string, enum, colour, path and
  object. The object entries are `edit.pasteSpecial.timeline`, `edit.cutSpecial.timeline`, `edit.dragDrop.timeline`,
  `edit.pasteSpecial.motionPoint` (booleans only — the member-type check enforces their whole domain) and
  `agent.policy.defaults` (now enforced). No list-typed entries exist.
- **Tests.** The reviewer's test.

### C41-R1-12 (P2) — `keymap.import` erased typed errors — accepted

- **Fix.** A binding's own domain error keeps its code (`keymap.reservedKey`, `keymap.invalidSequence`,

### C41-R1-13 (P3) — an empty `keys` gave `arg.invalid` — accepted

### C41-R1-14 (P2) — the freshness acknowledgement was detached from its tree — accepted

- **Fix.** The shared state holds the tree's vouching sequence as one value under one lock with the tree's acceptance;

  reports are ignored and each generation numbers its events from 1.

- **Tests.** The reviewer's test; `tests/c41/restart.rs` (nothing released before the engine is named; the fenced engine

### O-2 — floating panels as separate OS windows

Design note first: [M4-design-floating-windows.md](M4-design-floating-windows.md) (committed before the code). Built:
one webview window per visible float (`float-<panelId>`, the bundle with `?panel=`); the host reconciles the OS
windows with the kernel after every state change, at start and on a workspace switch (`desktop/src-tauri/src/floats.rs`,
the plan is a pure function); a float's move or resize ends in `window.panel.set {geometry}` (clamped by the kernel to
the screens), its close button in `window.panel.set {visible: false}`, its focus in `window.panel.set {focus: true}`,
a double-click on its title strip docks it; the host's own placements are not reported back (a settle window plus the
last placed geometry). Each window has its own mirror store over the numbered events; the host keeps each window's
modal state, text focus and tree and forwards their combination (the most recent open modal; the focused window's text
focus; one tree with the floats as child windows, fresh only when every window has caught up); a destroyed or reloaded
window's facts go with it. Cancellation tokens are per window. The float windows share the main window's capability set
(`capabilities/default.json` windows `main`, `float-*`). Floats have no menu bar of their own on Windows (the menu is
removed from them); minimising the main window hides them, restoring shows them, Raise All raises them. A kernel gap
found on the way: an arrangement change that touched no app-state field emitted no event; `workspace.changed` now
announces any arrangement change. **Tests:** kernel (`tests/c41/settings.rs`: clamp to the screens, a float survives a
restart after `workspace.save` and after `app.quit` with autosave, a float move is announced); host (`floats.rs` plan and
wanted-floats tests; `host.rs` combined reports, a closed window releases its facts, per-window cancellation); front end
(`App.test.tsx`: the float route renders its panel, reports `float-history` and docks on a title double-click); GUI e2e
on both OSes (the float is listed by the OS as a window of the application, the combined tree has its node, a geometry
change resizes the OS window, it is restored after a restart, docking it closes the OS window); manual
`C4.1-floating-windows.md`.

### O-3 and O-3a — splitter drags (SI-118)

O-3 first used the re-insertion forms of `window.panel.move`, which leave an arrangement unchanged only in some layouts
(3 of the built-in workspaces' side areas; the gap was reported). Ruling O-3a defined the degenerate call the
declaration already admits as the same-place call, and that is what is built: `window.panel.move {panelId: P, area:
<P's present area>, relativeTo: P, position: "tab", size}` leaves the arrangement exactly as it is and sets `size` on P's
area (its first group's size); without `size` it is a no-op and emits no `workspace.changed`; `relativeTo: P` with any
other `position`, or another area, is still `arg.invalid` (`crates/executor/src/ui.rs` `move_panel`). The dock measures
each side area at the start and the end of a splitter drag and sends that call for every changed area, in every area of
every workspace (`layoutPlan.ts` `samePlaceResize`, `DockArea.tsx`). No declaration changed. **Tests:**
`tests/c41/kernel.rs` `a_splitter_drag_is_recorded_by_a_same_place_panel_move` (every built-in workspace and every side
area: the layout's JSON text is byte-equal except that area's size; the no-op is byte-equal and unannounced; the other
self-relative position is refused); `layoutPlan.test.ts`; GUI e2e on both OSes ("the same-place window.panel.move sets
the area size only": the kernel's docks equal the expected docks and the GUI's tabs and their selection are unchanged).

### O-6 — credentials fail closed

`fsx::secret_token` reads the OS random source only and returns an error; the token (`agent.token.regenerate`) and
session ids use it; on failure no token is made (`internal` with `reason: "randomUnavailable"`), the server does not
start and the window shows `agent.serverFailed` with the reason (a new `host-notice` event). `random_token` (with its
time-and-counter fallback) remains for temporary names only. **Tests:** `host.rs`
`a_planted_token_is_replaced_and_a_stale_endpoint_is_cleared`; the lifecycle probe's token format check.

### O-7 — sessions

Idle expiry of sessions with no open stream and no request in flight: 30 minutes (ADR-0022), swept every minute; an
expired id answers `404`. The cap check and the insertion are one critical section. Recorded in ADR-0022: a holder of
the installation token can use any session id it learns; the token already grants every session's powers to its holder
(one user, one installation), so a session id is a routing key, not a credential. **Tests:**
`an_idle_session_expires_and_its_id_answers_404`.

### O-8 — discovery file

On stop, at a graceful quit and at start while the server is off, the file is rewritten without endpoint and process
id, keeping the token; a file of a killed process is replaced at the next start. A token read from disk must be 48
lower-case hex characters or a new one is made. ADR-0022 states the Windows position (the per-user `%APPDATA%` folder's
inherited ACL, no ACL of its own) and the POSIX mode (`0600`). **Tests:** `host.rs`
`a_planted_token_is_replaced_and_a_stale_endpoint_is_cleared`; the probe checks the file remains after an abrupt exit.

### O-9 — sensor reports have an owner

The host keeps each window's facts and drops them when the window is destroyed (window event) or reloaded (page load
started); the engine restart starts with no facts and each window reports again on the new generation (modal state from
the message host, text focus). Covered in the float design note §3. **Tests:** `host.rs`
`reports_of_several_windows_combine_and_a_closed_window_releases_its_facts`, `a_report_of_another_generation_is_ignored`;
front end (reports name the new generation after a restart).

### O-14 — engine restart is a generation change

Design note amended first ([M4-design-engine-restart.md](M4-design-engine-restart.md)). 1: restarts are serialised; a
second one waits and answers with the new generation without restarting again (only the restarting call starts the new
event pump). 2: a request answers from its generation — its probe also sees a restart, so it is answered at once with
`command.timeout`, `reason: "engineRestarted"` and both generations, never shown as applied; old cancellation flags are
dropped; reports name the generation and old ones are ignored; events carry their generation, each generation numbers
from 1 and the window resyncs on a new one. 3: the code is SI-120's interim (by analogy with SI-111). 4: the watchdog
runs a fixed 5 s cadence on a monotonic clock (tick n due at start + n x 5 s); an unanswered heartbeat is a miss per
tick, three misses mark the engine (about 15 s), any answer clears it at once, a late one too; the clause "while no
user request is outstanding" is removed from the note with the reason (it would hide the most likely hang, a user's own
command). 5: the confirmation names the time of the last autosave the window saw (or that there is none). **Tests:**
`host.rs` `restarts_are_serialised_and_a_waiting_one_does_not_restart_again`,
`a_restart_drops_old_flags_renumbers_events_and_answers_in_flight_requests_as_restarted`,
`a_report_of_another_generation_is_ignored`; `watchdog.rs`
`the_cadence_is_fixed_and_three_misses_take_about_fifteen_seconds` (a late answer clears); `App.test.tsx` (the
confirmation names the autosave time; after the restart reports name generation 1; a request cut off by a restart is a
status line). Not covered by an automated test: a request genuinely in flight across a real restart (the host has no
hanging command in a product build; the answer logic is a pure function under test, and the executor's never-block
test covers a hanging handler); listed in the handoff.
