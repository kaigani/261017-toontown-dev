## Findings

| Finding | Answer | Change | Proving tests |

| C21-R2-01 P1 spatial dedupe averages pressure | **fixed** (`e547a1d`) | `crates/vector/src/fit.rs`: `collapse` merges **positions only** and returns, per kept position, the input samples it stands for. The pressure map is built from every input sample: smoothed by the centred moving average of half-width `round(smoothness)` over the input samples (02 §3.3 step 5, Smoothness alone smooths), each at the arc position of the fitted point it stands for. Samples merged into one position share that `t`, so a pressure step or extremum there stays as knots of equal `t`, which the sweep already places at both widths (R1-02). A dab keeps every sample's pressure (the sweep takes the widest). With smoothness 0 the reviewer's two samples 0.001 du apart keep pressure 1 and the radius-50 tip. The pressure simplification is charged to the fit's budget, and among equally bad knots the one nearest the middle splits the span: the reviewer's 100 000-sample alternating-pressure input now fits in 32 ms debug (was 14 s; under the 30 s watchdog either way). | `crates/vector/tests/c21_r2_geometry.rs::spatial_dedupe_preserves_pressure_extrema_for_the_brush_sweep` (debug and release); `::alternating_pressure_fitting_respects_watchdog`; `::swept_tip_containment_matrix_at_and_between_knots`; `crates/vector/tests/properties.rs` (7) |
| C21-R2-02 P1 NFC fallback loses unrelated formats | **fixed** (`e547a1d`) | `crates/vector/src/text.rs`: the whole-text first-run fallback is removed. New `text::nfc_with_origins` is a mapping-preserving NFC following UAX #15: per-code-point canonical decomposition (each output code point records its input code point), stable canonical ordering of non-starter runs, canonical composition with the blocking rule, a composite keeping its starter's origin. `Content::compose` gives every normalised code point the run of its origin; a mark moved by reordering before a mark of an earlier run keeps the later run, so runs stay contiguous. Bengali KA + E + AA + Z gives KA + O + Z, with O in E's run and Z bold. The routine's output equals `unicode-normalization`'s NFC on a fixed-seed corpus of 20 000 strings over composing, reordering, blocking, Hangul, Bengali, Oriya, Balinese, kana and Hebrew code points. | `c21_r2_geometry::nfc_composition_preserves_unaffected_character_formats`; `crates/executor/tests/c21_r2_contracts.rs::unrelated_format_survives_nfc_in_command_path`; `text.rs` `nfc_tests::a_class_zero_composition_keeps_unrelated_formats`, `::origins_follow_reordering_and_blocking`, `::nfc_with_origins_matches_the_library_on_random_text`; `c21_r2_contracts::unicode_ranges_round_trip_through_content_and_package`; R1-09 tests |
| C21-R2-03 P1 outline work unbounded | **fixed** (`e547a1d`) | `crates/vector/src/brush.rs`, `stroke.rs`: **one work budget for the complete brush geometry call**, `OUTLINE_WORK_BUDGET` = 1.2 × 10⁹ units (about one point operation each). It covers the centre fit's sample visits (deducted in `stroke::build`), placements, hull points, overlay input vertices (64 units each, charged **before** each overlay call), bridge vertex pairs, densified points, and the outline fit, now through `fit::fit_with_bounded` with what remains. Past the budget, or past 100 000 outline anchors, the call returns `limit.exceeded` before the next step starts: nothing is staged, so nothing commits, and the document worker is free. The cause of the 30 s+ was a single `i_overlay` call over 99 000 nearly identical overlapping hulls (96 s in release, measured). The union is now **hierarchical** (64 shapes per call, then 64 results per call), the same point set, so the reviewer's input is **accepted in 0.93 s release / 1.3 s debug** at 426 M units. Straight segments (control points within one grid step of the chord, e.g. corner anchors) are placed at their ends only; Wang's bound flattened zero-handle segments into about 44 placements each. Calibrated on a 10-case adversarial brush corpus, three runs each, every observation kept: worst accepted 0.97 s (99 000 alternating knots, oval tip), worst refusal 1.8 s (a 10⁶ du line with 90 000 alternating knots and a 0.05 du tip: 45 000 separate pieces; previously accepted after 58 s with 219 579 outline anchors). The corpus runs in CI's headless job on both OSes and is uploaded. | `c21_r2_geometry::many_pressure_knots_brush_respects_watchdog` (debug and release); `crates/vector/tests/c21_worst_case.rs::adversarial_brush_outlines_finish_or_are_refused_within_the_work_budget` (release); [observations](evidence/M2-C2.1/brush-worst-case-windows.json) |

C2.2 bridge corpus owns a faster splice.
