### C11-R2-02 — append and nested-move inverses — **fixed** (`e49b4e9`)

- **New `change::apply_with_inverse` / `invert_against(before, patch)`.** Each operation is applied to the
  evolving state, and its inverse is computed against the state that operation saw. The inverses are concrete:
  - `add …/-` inverts to `remove` at the index it created;
  - an object-member overwrite inverts to a `replace` with the old value;
  - a `move` is split as RFC 6902 §4.4 defines it: its destination is resolved after the source was removed. The
    inverse first undoes the insertion (replace or remove at the resolved destination), then re-adds the value at
    the source, so a shifted destination is restored where it really is.

  Every inverse operation carries `oldValue`, so the inverse is itself invertible.
- **Stateless `invert(patch)` is kept for resolved patches** (what `diff_json` and `invert_against` produce).
  - Its move-with-overwrite inverse is now `copy` back, then `replace` at the destination's path shifted by that
    insertion. The reviewer's nested case is restored even statelessly.
  - An append, or a move into the source's ancestor, inverts to an operation `apply` refuses, never a guess.
- **Property test** `random_rfc6902_sequences_invert_against_their_pre_state` (`properties.rs`, 128 cases).
  - Input: random documents (nested arrays and objects, keys with `~` and `/`), each with a random valid sequence
    of up to 9 operations: add with overwrite or `-` append, remove, replace, move with shifting and overwriting
    destinations, copy, test.
  - Checks: `apply(after, invert_against(before, p)) = before`; no `-` in any inverse path; the double inverse
    restores `after`.
  - A sampled run produced 81 adds, 19 overwriting adds, 25 appends, 67 copies, 52 moves (11 overwriting, 14
    appending), 79 removes, 105 replaces and 149 tests.
- `change.rs` unit test `inverse_against_pre_state_is_concrete`.

### C11-R2-03 — malformed range value deleted mouth text — **fixed** (`e49b4e9`)

A range replace is validated completely before anything is mutated:
- `value` and `oldValue` must have the target's form: strings for a mouth string, with only the letters A–G and X
  (10 §4.14); exposure runs for exposure;
- `range.from ≥ 1`;
- `range.to = from + max(|old|, |new|) − 1`;
- `oldValue` must equal the window's current content (blank frames past the end of an exposure).

Any mismatch is `arg.invalid`. The reviewer's `value: 42` is refused and leaves `"ABC"` unchanged. Unit test
`range_replace_checks_types_window_and_bounds` covers 7 malformed mouth cases and 2 malformed exposure cases.

## P2 (all fixed now, per ruling)

### C11-R2-04 — `copy` without `from` — **fixed** (`e49b4e9`)

`move` and `copy` without `from` are `arg.invalid` (RFC 6902 §4.4, §4.5). An explicit `from: ""` keeps its RFC
meaning, the whole document. Unit test `move_and_copy_need_from`.

### C11-R2-05 — composite numeric coercion — **fixed** (`e49b4e9`)

`wireJson.ts`:
- `anyOf`/`oneOf` alternatives apply to a container only when it matches them, either as parsed or with its
  digit-only `bigint`s read as doubles. A double branch cannot match before coercion; an inapplicable branch never
  matches. The integer branch therefore keeps `9007199254740993n`.
- A scalar's `allOf` members all apply. `x: 1e20` under `allOf: [{type: number}, {minimum: 0}]` becomes a double
  unless a member insists on an integer.

The alternatives are tested only for containers that hold a `bigint`, so plain values pay nothing. The reviewer's
10 MB validation measured 1 059 ms (`measurements/ts-10mb-drawing-node.log`).

### C11-R2-06 — `property_schema` — **fixed** (`e49b4e9`)

- The lookup keeps every candidate schema down the path: `$ref` targets, all members, both conditional branches.
- At each token it collects the property, tuple position, item, map value or pattern-map value of every candidate.
- The final candidates are merged in order: a declaration's own annotations come before the referenced
  definition's keywords.

Results: `property_schema(Element, "/params/transform/origin/x")` is `{type: number, …}`, and
`property_schema(Pen, "/id")` keeps `readOnly: true` and `x-since` beside the `Id` pattern.

### C11-R2-07 — writer emits a depth its reader rejects — **fixed** (`e49b4e9`)

`canonical::to_canonical_string` and `to_compact_string` (used by `to_wire_json`) now count depth as both readers do:
the root value is depth 1, scalars are included, and the limit is 128. A scalar inside 128 arrays is refused by the
writer, so anything written can be read back. `canonical::to_value` (serialisation to a value, not to text) keeps its
container count, which the reviewer's `canonical_writer_limits_are_explicit` pins. The front-end writer already
counted this way. ADR-0011 and ADR-0012 record this.

### C11-R2-08 — frame-map keys — **fixed** (`e49b4e9`)

Keys of `cellNotes` (10 §4.7) and mouth-track `labels` (10 §4.14) are frames: `int ≥ 1`, and `int` is signed 32-bit
(10 §1.1). The schema's `patternProperties` now use `schema::FRAME_KEY_PATTERN` (1–2 147 483 647). The object rules
add `is_frame`, and label keys must also be within the placement's frames, like the manual ranges.
`2147483647` stays valid; `0` and `2147483648` are rejected.
