## New finding C33-R3-01 ? P2 ? cancelled records discard the typed error

**Clause/ruling:** charter A, C33-R2-02: cancelled and failed records carry warnings and the typed error through `job.list` and `job.wait`; states stay cancelled/failed.

**Reproduction:** `cargo test -p tt-executor --locked -j 4 --test c33_r3_recovery cancelled_record_keeps_typed_error`.

**Observed:** both command responses show `state: cancelled` and `render.stagingDiscarded` warnings, but no `error`. The independent assertion fails on `record.error.is_some()`. `jobs.rs` routes every non-success cancellation outcome through `_ if cancelled => r.state = JobState::Cancelled`, dropping `Err(e)`. Failed records retain `export.targetInvalid` and warnings, verified by the passing response test. MCP `job_status` maps directly to `job.list` at `crates/mcp/src/tools.rs:685`, and the dedicated `c33_r3_jobs::cancelled_error_is_visible_through_job_status` independently reproduces the same omission over the MCP transport. Its failed-job companion passes with `export.targetInvalid` and recovery warnings.

**Required:** retain the cancellation's typed error without changing its state or losing warnings. **Fix direction:** retain `Err(e)` in the cancellation branch; verify list, wait and MCP terminal records, including rollback errors when cancellation races failure. Existing failed-state behavior must stay intact.

## Residual risks

1. R3-01 is a demonstrated contract gap; the waiting-test amendment is a demonstrated ruling/test conflict requiring disposition before restoring its CI coverage.
2. Windows liveness uses a bounded `tasklist /FI PID eq ... /NH /FO CSV`, matching a quoted PID; macOS uses bounded `kill -0`, treating an English ?not permitted? error as alive. Timeouts/spawn failures yield unknown and preserve files. PID reuse conservatively retains an unrelated live PID's stale sidecar, except reuse as the current process PID bypasses OS liveness and relies on live tokens. This can delay recovery; it is not proof of the original process's identity. macOS non-English EPERM diagnostics are not explicitly classified, a source-level portability limitation. No new liveness implementation was introduced by the +6 hook change.
3. Builder live-child and simultaneous-job probes pass. The independent `c33_r3_live::separate_live_process_holding_job_is_untouched` also passes with a separate child holding an actual 48-frame range job while the parent exports into that directory. It verifies sidecar bytes and absence of recovery warnings. This finite interleaving does not exhaust every cross-process race.
4. Cancellation checks bracket encoding/flush and raster work; one encoder/flush call has no proven interruption latency bound. Byte limits are checked after encoding. No hard cancellation-time guarantee is certified inside those calls.
5. Refused restore is induced with filesystem boundaries rather than exhausting the disk or every ACL/device failure. Retry restores original bytes and failed publication exposes no partial manifest in the independent probe. Concurrent cleanup races and persistence failure while rewriting `published` are not exhaustively covered.
6. Jobs are session state, not project data. Save/open in the same executor does not serialize records into the project; a new executor session has a fresh job table. MCP mapping shares the list path. The independent `failed_receipt_survives_save_open_only_in_existing_session` passes: failed warnings/error survive save/open in the existing executor, while the same ID is not found in a fresh executor. MCP cancellation and failed-state transport probes also execute in this round. Cancellation-error retention across save/open remains dependent on fixing R3-01.
7. Fractional `anim.*` queries remain distinct from integer inspection; conservative invalidation does not promise exact pixel-change correspondence. Attached rendering remains M4 C4.2, thumbnails M5 C5.2. Other named milestone deferrals stand.
