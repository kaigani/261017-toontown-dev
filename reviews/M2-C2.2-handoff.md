## 1. What was built

**`tt-vector::planar`** (pure library; ADR-0017):

| Module | Spec | What |
|---|---|---|
| `flat` | 02 §3.12 | flattening within 1/128 du with path parameters (persistent splits, SI-060 keys) |
| `graph` | 02 §3.5, §13.4; 10 §4.8 | snap-rounded integer arrangement (exact i128 predicates), half-edges, faces, holes by a grid index of face boxes + exact point in polygon, brush fills by winding, zones (area, bounds, verified interior point, holes, parent, boundary pieces), SHA-256 zone IDs, point location, stroke sides |
| `node` | 02 §3.2, §3.12 item 1 | persistent noding of pencil/invisible strokes at crossings, self-crossings and T-junctions; shared junction anchors; brush outlines never split (SI-059) |
| `fill` | 10 §4.9; 02 §3.12 | fills read from sides and brush exterior records (SI-060), longest-length repair, deterministic write, carry-over by exact overlap with the lower-ID tie rule |
| `layer` | 02 §3.12 | settling one layer: noding of changed strokes, maps, carry-over or staged fills, painted fills, stored sides/records |
| `gap` | 03 §8.6, §8.8 | point tests, automatic gap closing (bounding candidates only, 4 × tol² minimum), Close Gap segments |
| `work` | readiness 3 | shared work accounts (`limit.exceeded`) |

`brush::bridge` (SI-053) is now linear per contour (exact candidate filtering, identical outlines).

**Executor:** the settle pass on every transaction (`Cx::settle`, run after every handler and before preview/commit;
all layers of a pass share one budget), the session's derived-map cache (`planar.rs`), zone changes in
`draw.drawing.changed` (commit path: commands, batches, undo, redo, restore), zones and side zone IDs in
`draw.drawing.get`, derived drawing zones in `doc.object.get`, the `unpaintedZones` lint, settled stroke and zone IDs
in edit results, and colour recovery on paste (same transaction) and on save (recovery lists).

**Commands** (11 implemented; registry owners moved from the C2.3 rule to C2.2 as ruled): `colour.paint.apply`,
`colour.paintUnpainted.apply`, `colour.paint.remove`, `colour.pick`, `colour.gap.close`, `colour.gapClosing.set`,
`colour.gapClosing.get`, `colour.missing.list`, `colour.recovery.run`, `colour.recovery.performed` (event),
`draw.hitTest.get`. Every one has executed examples retained in `crates/registry/src/example-results.json`.

The first gate showed every edit of the 100k drawing slower, even edits that leave the layer's geometry alone. Cause:
the settle pass and the commit's zone changes serialised every layer of a changed drawing to compare it. Fix
(`crates/executor/src/planar.rs` `same_planar`, used by `Cx::settle` and `zone_delta`): layers are compared as model
values first (stroke identity, kind, closed flag, points, sides, exterior records), and only layers that differ are
serialised. The first gate's raw file and analysis are kept in
[first-measurement/](evidence/M2-C2.2/first-measurement/). Adding a stroke to a 100 000-stroke layer still costs about
5 s more than in C2.1, because the whole layer is re-noded and its map rebuilt. Incremental graph building is ticket
C22-T2 (M2 C2.4, with R1-12). Retained bytes per edit stay flat: process live bytes level off over the 70 calls.
