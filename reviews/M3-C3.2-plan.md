## 2. `crates/anim` modules (pure, no executor; only `tt-model` + pinned `libm`)

| Module | Content |
|---|---|
| `num` | `sin/cos/tan/atan/atan2` from `libm` (`force-soft-floats`, the same pin as `tt-vector`), degree helpers with exact multiples of 90° |
| `matrix` | `Mat4` (row-major, §2.1), `T`, `R`, `K`, `S`, product, affine inverse, §2.5 decomposition |
| `tcb` | §9.1 tangents with reflected phantoms, Hermite `C(s)` and derivative, §9.2 64-step arc-length table, point at arc length restricted to a keyframe segment |
| `function` | §10.3 cubic Bézier solve (bisection, explicit iteration constant), §10.4 preset table (normative rationals), hold/constant/spline/interpolation/velocityBased |
| `velocity` | §10.5 pins, normalised intermediate keys, `V(f)`, clamped travel, passage frames by bisection to 1e-4, reported to 3 decimals |
| `timing` | §2.10 local frame, range hold, §8.4 cycle length, cycle index, `positionLoop: offset` |
| `node` | effective values (§1.5), pivots (§2.3, including `useChildDrawingPivot`), orient-to-path (§8.3), `M_local` (§2.2) |
| `eval` | `W` through the hierarchy (§2.4) with per-frame memo; path tables cached per call |
| `camera` | rigid view matrix (§2.6), projection, near plane, frame corners at Z = 0 |

**Numerics (ADR-0004; new ADR-0019 "Animation evaluator").** Only `+ − × ÷ sqrt` and pinned `libm`; `f64`; a fixed order
written in the code and in the ADR: scene frame → local frame → cycle → velocity → arc length → curve; static + animated;
matrices composed left to right exactly as §2.2 prints them. A keyframe frame returns its stored point exactly (no table
round trip), and linear segments short-circuit the Bézier solve, so exact inputs give exact outputs. Results serialise
through one path; `-0.0` is normalised to `0`. Non-finite results are refused, never returned.

**Budgets (ADR-0019).** `BEZIER_MAX_ITERATIONS = 64` (to 1e-9), `PASSAGE_MAX_ITERATIONS = 40` (to 1e-4 frame),
`ANIM_WORK_BUDGET` for one call, charged per curve sample, per table build and per node-frame through a meter closure,
so the caller's watchdog cancels at each charge and an oversized request answers `limit.exceeded` before the watchdog.

## 3. Channel model and D-5 migration note

`position` stays the spec's motion path (`points`), `position.x/y/z` read-only-shaped projections (value edits only),
all other channels 1-D `keys`. Keys are stored as **local** frames; every command parameter and result is a **scene**
frame (§19.1.4), first cycle only (`anim.frameInvalid` otherwise). IDs: channel, key and point IDs come from the
transaction stream and survive moves, re-timing and copies (with C3.1's copy remap).

**SI-096 (D-5, unresolved, spec owner).** Migration if per-axis channels are adopted: a format step (versioned manifest,
`crates/persist/tests/fixtures/migrations/`) rewrites each `position` channel into `position.x/.y/.z` 1-D channels:
each keyframe becomes one key per axis (same frame; IDs derived deterministically from the point ID), the velocity
timing is baked into sampled per-axis keys only where control points or non-linear velocity exist, `meta`/`ext` move to
the x channel. IPC types the amendment would break, noted in the handoff and not frozen: `anim.path.*`, the `position.*`
projection form of `anim.function.*`, `NodeEval.animated.velocity`.

**Velocity storage (§10.5).** Keys store `u` normalised to their keyframe segment; a key record at a pin frame carries
shape data only (easing/handles), never a value. Results report fields. Removing or inserting a pin renormalises
(same frame, same normalised position in the merged or split segment).

## 4. Decisions to record

- **SI-089 (ruling applied, closed).** Before truncation evaluate the original curve at the new local end and keep a
  key there (1-D channels; motion path: a keyframe at the evaluated position, control points past it dropped, velocity
  keys renormalised). Moving the start never shifts local keys. **Cycle length:** count loops: `L = ⌊duration ÷ loops⌋`,
  a remainder plays as a partial cycle; fill loops need `L` persisted, so `Element.cycleLength` is added (optional,
  written only for `fill`), because `duration` and `loops` cannot express it.
- **SI-097** E4's bones: bones are M6 C6.3 by plan; E4 numeric poses pegs and elements, the bone row stays with M6.
- **SI-098** `anim.evaluate {frames}` accepts fractional scene frames (readiness item 10) as a superset of the table's
  `[int]`; other frame parameters stay as the table says.
- **SI-099** Constant Z: the arc length of a locked keyframe segment is measured in its X/Y plane, so control-point Z
  really is ignored (§9.3); a control point in a constant segment reports the segment's start frame as its passage frame.
- **SI-100** `visible` and clipped points: `visible` = in front of the near plane and overlapping the frame (and, for
  nodes, not hidden, not an annotation, with content at that frame); a clipped point reports `x`, `y` as `null`;
  `frameCornersAtZ0` is `null` when the camera is at or behind the table plane's near limit.
- **SI-101** numeric bounds: positions, pivots ±1e6 fields, scale |s| ∈ [0.001, 1e6], rotation ±1e9°, 1-D values ±1e9,
  all `anim.valueOutOfRange` with limits (§18); evaluation that overflows is refused the same way.
- World position targets the node's position `P`, not its pivot-displaced origin; camera last-delete refusal
  (`anim.lastCamera`) is enforced in `anim.camera.delete`, `element.delete` and generic delete alike, and deleting the
  current camera picks the first remaining in Timeline order everywhere.
- Drawing bounds: 1 field = 100 du (02 §3), so `bounds` = `W · S(1/100)` over the exposed drawing's content.

## 5. E4 script

`scripts/e4-cutout-numeric.py`, official `mcp==2.0.0` over stdio against the release headless binary: builds a puppet
(master peg → torso → head, upper arm → forearm; element pivots at joints; nested and mirrored parents), poses three
keyframes with `anim.transform.set`, reads `anim.evaluate` at exact and in-between frames, and compares against an
independent Python implementation (no product code; `fractions` for exact rationals where angles allow, an independent
formula otherwise) within **1e-6**. It runs twice from the same base and compares stable JSON bytes; CI compares the
Windows and macOS outputs byte for byte. Inputs, outputs, tool versions and head SHA are retained as artifacts.

## 6. Test and golden strategy

- `crates/anim/tests/c32_*.rs`: independent oracles in the tests (a small exact-rational type for Hermite, Bézier
  and matrix identities; numerical quadrature for arc length; hand-derived pose values); proptest for monotonicity,
  inverse round trips, determinant sign, cycle mapping.
- `crates/executor/tests/c32_*.rs`: every command's contract (explicit/current targets, dry-run isolation, stale guards,
  queued and running cancellation, rollback, undo/redo, save/open, stable IDs, unchanged drawing revisions, zone IDs and
  selection across animation edits); SI-089 and loop matrices.
- `crates/mcp/tests/c32_protocol.rs`: extrema through the generic tool; the worker keeps answering.
- `crates/executor/tests/c32_budgets.rs` (measurement, ignored by default): long-range evaluation against the watchdog.
- No image goldens (C3.3). Cross-OS numeric determinism: E4's JSON and a hash of an evaluator sweep.

## 7. CI layout

New jobs instead of minutes: `e4 release (windows-latest, macos-latest)` and `e4 cross-OS`, which compares the two
outputs byte for byte. Heavy property runs go to the existing `m3 properties release`; the measurement goes to
`measurements release`. Windows `check` stays under 55 minutes.
