## 6. ADR-0007: results and the decision

ADR-0007's amendment (`docs/decisions/ADR-0007-interactive-canvas.md`) records the results and the decision:

- **Open questions 1-7, decided:** identity by drawing id and form at one revision; revision checks on every payload;
  backpressure by whole-state pulls (at most one scene and one load per drawing in flight); resync on revision, zoom
  bucket or palette stamp; eviction by composition; tessellation in Rust off the document thread; painter order from
  the final renderer's walk.
- **E-C1** (1,000 drawings, view and composition changing every frame): scene delivery p95 8.8 ms (WebGL2) and 8.1 ms
  (WebGPU), frame p95 16.8-16.9 ms. Met.
- **E-C2** (20 sustained edits of the 50,000-point drawing): worst frame 17 ms on both. Met.
- **E-C3** (the Windows runner's software adapter, no GPU): the webview's software WebGL2 draws the product's frames at
  frame p95 15.7 ms on the large drawing with the static layers cached, but every frame that redraws a stress scene in
  full misses 57 fps (rule-set cells 11.3 / 22.0 / 15.3 fps). Tiled host bitmaps cannot beat it there (C0.3: 36-44 ms
  per full frame of transfer alone). Decision: the software path stays the webview's own software WebGL2.
- **The decision per machine class (the rule set's output):** workstation, row 6, "go as written", whichever back end
  measures the higher worst scene (both meet all three scenes); Windows runner and macOS runner, row 3 as the rule set
  gives it (no-go for the webview canvas as designed on the 1,000-group stress scene), with the question whether row
  3 applies to the software floor and to a virtual machine raised for the owner. Real Macs (E-C4) are unmeasured.
- **Round 2's finding, recorded in the amendment:** the rule set's scenes are static redraws, so they could not see
  WebGL2's per-frame overlay upload; with the overlay drawn only when it changes both back ends meet the plan §6
  bounds on the workstation (§5), so either selection is within plan §6. The rule set itself is unchanged.

## 7. Declared behaviour changes

- **The incremental commit path in `crates/model`.** `Document::with_patched_entries_undo_only` takes a fast path when
  a commit only appends nodes to a drawing (`/nodes/-`, the Brush and Pencil tools' new layer) or strokes to one layer:
  the appended objects pass the full object input path on their own, the typed drawing is extended and checked as a
  whole, the undo is the general path's for an append; `change::diff` has the matching fast path for appended nodes.
  In debug builds the general path also runs on every use and must agree (`debug_assert_eq!` on the document, the
  undo patch and the change records), so every debug test that adds a stroke compares them; any other shape takes the
  general path unchanged. A failure after fast-path steps discards the staged commit (c42 test). E1's outputs are
  unchanged (round-2 response §11).
- **New undo labels (C42B-R2-04).** `draw.rectangle.add`, `draw.ellipse.add`, `draw.line.add` and
  `draw.polyline.add` commit as "Rectangle Tool", "Ellipse Tool", "Line Tool", "Polyline Tool" (were "Pencil Tool");
  `draw.cut.apply` with `rect` as "Scissor Tool" (was "Cutter Tool"); `draw.transform.apply` with one operation as
  "Move Object", "Scale Object", "Rotate Object" or "Copy Object" (was "Move/Scale/Rotate Object", which remains for
  combined operations, skew and matrix). History, `edit.history.get` and saved histories show the new labels; the
  reviewer receipt `c42b_r2_review::seeded_script_profile_receipt` pins the old ones (re-record requested).
- **The scope of `lastGesture` (ruling D-19).** The canvas's UI-tree value carries the window's last committed gesture;
  `inspect.ui.tree` serves its samples (positions, pressure, tilt, timing, modifiers) and the commands' parameters only
  to a session holding `input`; with `read` alone, its summary (origin, tool, view, pointer kind, count, answer,
  command ids); above 4,096 events the record keeps the count and the command ids only.
- **The common addressing parameters, carried from C4.2a.** The 27 point-taking `draw.*` and `colour.*` commands take
  `space` (`drawing`, `view`, …) and `view` and convert through the view mapping (gate: common addressing 27 of 27);
  the gestures C4.2b's window commits use them unchanged.
- **The Polyline.** Enter commits an open Polyline; the window losing focus discards it; a triple click's third press
  opens nothing.
- **The acting tool's label** (round 3): the alternate Scissor commits as "Scissor Tool" (was "Cutter Tool"); the
  core takes a one-invocation label override from the gesture driver.
- **An agent's routed gesture activates its tool when the call arrives** (before the window plays it), not at the
  commit; the answer's shape is unchanged; a refused activation is the call's answer.
- **The user's own window gestures** go through `pointer_in_window`; their answer's hover carries no `objects` (the
  window never read it); agents' calls are unchanged.
- **Earlier behaviour changes of C4.2b** (declared at round 1, unchanged): an agent's `pointer` for a shown view is
  played and committed through that window; attached `inspect.screenshot` is the window's capture (`source: "gui"`),
  inside a batch the virtual view; routed calls are answered at once when their engine restarts or their window goes
  away; two Display preference keys (SI-140); the `startup` answer carries the canvas's launch options.
- **Reviewer-owned files:** only as ruled. D-20 (`8643b9d`): `tests/adversarial/c42b-r3s-labels.py` (its second
  check's two lines deleted) and `crates/executor/tests/c42b_r3_review.rs` (one `#[ignore]`). D-21 (`1165bba`):
  `crates/executor/tests/c42a_r1_review.rs` (`cut("scissor", true);` deleted from `fn scissor()`) and the four

  panic, unsafe or allow in product code (the model's equivalence checks are `debug_assert!`).
- **CI:** `desktop gui` runs the C4.2 e2e, the canvas measurements and the reviewer's round-1, round-2 and round-3
