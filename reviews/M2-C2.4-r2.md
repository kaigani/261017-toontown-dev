### C24-R2-01 — P1: independent comparisons still do not verify the changed topology of every route

**Clause/ruling:** C2.3 round-3 readiness item 2; the C24-R1-01 ruling requiring expected partitions, boundaries, side fills and canonical IDs for every topology-changing route; 02 §3.12 and §13, 03 §16.1(5).

**Reproduction:** inspect `crates/executor/tests/c24_oracle_routes.rs` functions `lines_to_brush_and_centre_line_keep_the_oracles_partition` and `break_apart_leaves_the_line_layer_to_the_oracle_and_makes_one_group_per_glyph`, and `c24_topology.rs::vectorized_shapes_enclose_one_unpainted_zone_per_paper_component`. The new `c24_r2_routes.rs::r1_01_route_oracle_rejects_a_noop_centre_line_mutant` also evaluates the shipped comparison against the unchanged state that a no-op Centre Line would leave. Release execution and the dispatch-count receipt are linked below.

**Observed versus required:** the oracle itself is independent: no product geometry imports; its intersections, angular order, exact interior points, point location, snapping, canonical text and SHA-256/Crockford encoding are separately implemented with `BigRational`. This closes the arithmetic/identity machinery portion of R1-01. Stroke add/set/delete, segment Cutter, pencil-region Eraser, pencil Flatten, transforms, affine envelopes and selected point moves now have substantially stronger pre-command expectations.

The remaining gap is in the consumers:

| Route | What the committed independent property actually verifies | Missing ruled comparison |
|---|---|---|
| Lines to Brush / Centre Line | Converts an isolated straight line outside every zone; compares the other line layer's unchanged faces. After Centre Line the expected segments duplicate the already retained invisible centre. | A no-op Centre Line can satisfy that face comparison. No independent changed partition/boundaries/IDs for a closed loop or a spineless outline. |
| Break Apart | Exact comparison of the unrelated line layer; glyph zone count (`O` versus letters without counters), one brush boundary ID and null fill. | Independently predicted glyph boundaries, side fills and canonical zone identities. |
| Vectorize | Counts `unpaintedZones` issues against enclosed paper components of a pixel mask. | No exact-oracle call for its output, boundary/side comparison, zone-face geometry bijection or canonical-ID expectation. The tiny ring variant is a useful functional control, not this missing proof. |
| Smooth | Only selected collinear runs whose geometry remains straight. | A changed-shape within-tolerance case through the independent route comparison. |
| Eraser / Flatten | Generated source layers contain pencil strokes only. | Brush-outline/SI-059 erasure and mixed-kind overlapping layers under the full comparison. |
| Envelope / snapped point move | Affine parallelograms only; interior-of-segment snaps return `Ok(())` without dispatching the move. | A non-parallelogram case and snapping onto a curved contour through the independent expected-result checks. |

The latter rows are restrictions, not allegations that each product command is defective. The non-vacuous Lines to Brush/Centre Line, Break Apart and vectorize obligations alone prevent closure of “every route.” Adding a font or a paintable component count does not independently predict the changed boundary and its ID. Output strokes are used to label newly assigned boundary IDs; this is distinguishable from obtaining expected geometry from the output, but it does not fill the curved-route gap.

**Fix direction:** retain the new exact oracle and all original tests. Add non-vacuous independently predicted changed-result checks for the omitted route domains, including brush occupancy and holes; derive expected geometry from the persisted starting state and command semantics. Verify canonical boundaries/IDs and fill transfer for the changed output, rather than only an unaffected layer. Reject a no-op mutant. Keep the snap-unsafe/interior-snap exclusions explicit and count actual dispatched commands separately from generated property cases. Re-run with independent seeds and both-OS CI. This is a verification finding, not a request for universal symbolic proof of all curves.

### C24-R2-07 — P1: noding duplicates a closed retrace across a zero-length closing segment

**Clause/ruling:** 02 §3.12 split/re-node invariants; SI-067's shared-coordinate and exact-crossing rules; retained degenerate/retrace coverage and ADR-0017's parameter-span rule. Noding may split a stroke, but must not invent extra traversals of an unaffected part of that stroke.

**Reproduction:** `cargo test --release -p tt-vector --locked -j 4 --test c24_r2_noding -- --nocapture`. Two enabled assertions fail; the same fold without a repeated terminal anchor passes. [Node output](evidence/M2-C2.4-r2/closed-fold-noding.txt), [closing-parameter assertion](evidence/M2-C2.4-r2/closed-fold-parameter.txt), [actual SDK Flatten readbacks](evidence/M2-C2.4-r2/flatten-sdk-control.json), [independent rational traversal counts](evidence/M2-C2.4-r2/flatten-traversal-counts.json).

**Observed versus required:** one layer holds a closed pencil path `(0,80)–(80,20)–(0,80)`; the second holds open `(0,40)–(80,80)–(40,20)` and `(20,40)–(40,60)`. The second layer's existing T-junction is persisted before merging. The closed path traverses `(10,72.5)` exactly twice, once each way. Flatten produces **four** traversals through that exact point, in two separate out-and-back pieces. That span is far from every added-stroke junction; grid snapping cannot justify duplicating it. The direct node test isolates this to the first input stroke's `Outcome::Split`, independently of executor IDs or fill carry-over. Removing only the repeated terminal anchor preserves two traversals.

The closed three-anchor path has segment 1 from `(80,20)` to `(0,80)` ending at parameter 2, and a zero-length segment 2 closing back to the already identical first anchor. `flat::flatten` removes the repeated terminal vertex/parameter; `Flat::edges` then gives the nonzero closing chord parameter range **1→3**, spanning the zero-length segment, instead of **1→2**. `node` interpolates crossing parameters over that range and `sub_path` extracts the wrong portions. The fixed parameter assertion observes `(1,3)` versus required `(1,2)`. Preserve the closing entry parameter when deduplicating; merely maintaining the first vertex's outgoing parameter does not fix this cyclic case.

The same output also gains an extra junction at `(32.703125,55.46875)`. The property first notices small-face area **11.439208984375** versus the independently snapped **11.4375 du²**. Both SDK and Rust reproduce the duplicate paths. The P1 is based on extra source traversals, not that small numerical difference or an unproved rendering change. This review does not attribute when the defect was introduced.

**Fix direction:** preserve correct cyclic entry/exit parameters across repeated terminal anchors and zero-length closing segments, then verify that cut intervals partition the original closed traversal exactly once. Retain the non-repeated-end control, the repeated-end failure, the 4096-case route seed, every-pass/fixpoint tests and unsplit-overlap rulings.
