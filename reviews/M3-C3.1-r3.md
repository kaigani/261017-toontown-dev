## Findings

### C31-R3-01 — P1 — Delegated copy/move reads before preceding ordinary operations are staged

- **Clause/ruling:** 10 AG-02, ordered RFC operations; ADR-0013 §2; C31-R2-01/02 response requires source resolution from the current staged object, with `props` preceding `ops`.
- **Reproduction:** `cargo test -p tt-executor --locked -j 4 --test c31_r3_patch`. Three retained failures: `copy_reads_a_plain_source_written_immediately_before_it`, `move_reads_a_plain_source_created_immediately_before_it`, and `copy_of_a_source_removed_immediately_before_it_refuses_atomically`.
- **Input/observed:** with `/meta/r3 = "old-928"`, patch `[replace /meta/r3 = "new-928", copy /meta/r3 → /note]` succeeds but writes `old-928` to the note. `[add /meta/freshR3 = "moved-928", move /meta/freshR3 → /note]` incorrectly refuses `arg.invalid`. `[remove /meta/removedR3, copy /meta/removedR3 → /note]` incorrectly succeeds and commits the removed value.
- **Required:** a copy/move sees every earlier operation. The first two examples succeed using the new source; the third refuses atomically and preserves revision, content and history.
- **Cause:** `doc_object_patch` calls `delegated_steps(cx, ...)` before `stage_run` flushes its pending ordinary run. `delegated_steps` therefore reads a stale `cx.document()`. Flushing only when consuming the returned `Step::Delegated` is too late.
- **Fix direction:** stage preceding ordinary operations before resolving a copy/move source that touches delegated semantics, or interpret against one fully current staged view. Preserve ordered `test` behavior, `props` then `ops`, all-target rollback and one undo step.
- **Evidence:** `patch.txt`, `sdk-source-copy.json`, `sdk-final.json`. Official release SDK confirms the old-value result. The independent mixed-order/middle-and-final-failing-test control passes; all original R2 proving assertions pass.

### C31-R3-02 — P1 — Cross-project drawing-ID collisions bypass captured artwork

- **Clause/ruling:** 04 §13.16, §14; C31-R1-04 self-contained captured artwork and destination remapping; C31-R2-06 collision preservation; M2 handoff item 6.
- **Reproduction:** `cargo test -p tt-executor --locked -j 4 --test c31_r3_binary same_ids_in_another_project_do_not_reuse_destination_artwork`.
- **Input:** two valid packages have different project IDs but the same bank/drawing IDs, with distinct 1×1 PNGs. Copy Background frame 1 in source project `pr_01K742SG00FJ099GV49H4H709C`, open destination `pr_01K742SG00MVT60N5CRXC4F9SK`, then `cell.clipboard.apply {elementId:Background,frame:29}`.
- **Observed:** the pasted cell uses destination image hash `24667b5217b7e250d2622ffea25bb651bc25583256e6b1fc4008c5894078d6bd`, instead of copied source hash `50b8be0a33aa6a1e3d7fb691fc243c3ffb0a7e57a2a9824a7a8f7d79933c1b49`. Source/destination project inequality is an enabled assertion. The captured payload contains the correct source bytes.
- **Required:** a different project's colliding IDs cannot establish same-bank identity. Paste retains source artwork and destination artwork, remapping as needed. Actual same-project clone-group reuse remains binding.
- **Cause:** `Transfer::place` returns the live drawing immediately when `doc.bank_of(d) == self.bank`, before checking captured provenance/content or calling `place_blobs`; it ignores `ArtPayload.project_id` at this fast path. The generic paste bridge shares this transfer. Whole-element paste's existing-bank reuse also warrants a scoped audit for the same premise.
- **Fix direction:** qualify reuse by source-project provenance and intended same-project live-bank semantics. Apply payload-first drawing/blob placement when provenance differs; audit all bank reuse paths rather than only allocating a fresh entry after this early return.
- **Evidence:** `binary-complete.txt`, `sdk-clipboard.json`; source/destination packages and SHA-256 provenance are retained in `repros/`. Official release SDK independently returns the destination hash.

### C31-R3-03 — P1 — Copy after paste in one atomic batch omits staged binary bytes

- **Clause/ruling:** ADR-0013 §17 and ADR-0015 acceptance/transaction visibility; 04 §13.16; C31-R1-04 self-contained clipboard; C31-R2-06 command-wide staged binaries.
- **Reproduction:** `cargo test -p tt-executor --locked -j 4 --test c31_r3_binary paste_then_copy_in_one_atomic_batch_captures_the_staged_binary_bytes`.
- **Input:** copy a real bitmap from a saved source, replace the project with another seeded project, create an image target, then atomic batch `[cell.clipboard.apply target@9, cell.clipboard.set target 9..9]`.
- **Observed:** the batch succeeds; the new clipboard carries the staged drawing JSON but its `payload.blobs` is `{}`. The source clipboard has the PNG's base64 bytes. Closing/replacing the destination can therefore invalidate a copy that was successfully accepted as self-contained.
- **Required:** later steps see both earlier staged document content and the binary entries needed to use it. Capturing the staged drawing must capture its staged bytes in the same transaction; failures/dry runs must still discard the effects.
- **Cause:** `ArtPayload::capture_drawing` reads only `cx.project().store.blobs`; it does not consult the `Effect::Blob` overlay that `Cx::blob_bytes` already exposes to placement.
- **Fix direction:** use a common staged binary read view for capture as well as placement and other same-call consumers. Retain atomic rollback/dry-run isolation; add an accepted paste→copy→project replacement→paste→save/open byte read-back.
- **Evidence:** `binary-complete.txt`, `sdk-clipboard.json`; official release SDK independently observes the empty blob map after a successful atomic batch.

### C31-R3-04 — P1 — Saving drops copied texture bytes referenced by drawing recovery data

- **Clause/ruling:** 04 §13.16 and §14.1; 10 §4.8/§4.11 recovery completeness and persisted binary references; C31-R1-04/13 and C31-R2-06 explicitly include texture references and save/open byte fidelity.
- **Reproduction:** `cargo test -p tt-executor --locked -j 4 --test c31_r3_binary texture_recovery_references_remap_collisions_and_preserve_both_saved_blobs`.
- **Input:** two valid sources have texture-coloured vector artwork, recovery swatches referencing `textures/r3-shared.png`, and different valid PNG bytes. Copy each and paste as new drawings into a third project with different colour IDs. The source's palette and drawing recovery definitions agree.
- **Observed:** the shared transfer correctly captures the texture bytes and remaps the collision to `textures/r3-shared-b3e7ff2fd6810c3a.png`. Both references are present before save. After save/open, the saved package contains **neither** texture blob (`hasOriginal:false`, `hasRemapped:false`); direct blob read fails `project.invalidFormat: no entry`.
- **Required:** saving preserves both copied texture definitions and their actual binary content. A remapped reference is incomplete without its bytes.
- **Cause:** `persist::load::refs` scans drawing objects with `collect_blobs` (structured `entry/mediaType/size/sha256` references), but scans string-valued texture `image` references only in live palettes. Texture references retained in `drawing.colourRecovery[*].swatch.values` are excluded from `saved_blob_refs`, so save drops their newly staged entries.
- **Fix direction:** include typed texture references in persisted recovery data in the shared binary reachability model, while preserving opaque namespaces and unreferenced-media policy. Verify both original/remapped entries from the saved package, including recovery and reopening where no live source palette exists.
- **Evidence:** `texture-finding.txt`, `binary-complete.txt`, and the failing saved `repros/textures.animpkg`. Initial texture attempts used stale fixture recovery data and then the compact drawing read model; those setup attempts are retained and superseded by the full object-model read-back.
