## 1. Goal and exit condition

C4.4 builds every GUI location that D-30 places in M4 and that C4.3b deferred, so that at C4.4's handoff **no
`deferred` entry is owned by M4** (D-31) and the parity gate stays exact. `reviews/M4-merge-note.md` and the merge to
`main` follow C4.4's pass (D-30).

**Ruling D-39 applies to every surface C4.4 adds:** each binding gets one end-to-end row in a table test through the
real window (the person's action; the exact command and parameters observed; the effect on the document or state; the
spec's label where it makes an undo step; the disabled state when the precheck refuses; a toggle clicked twice), as
`scripts/c43-d39-bindings.py` does for C4.3b. Each surface section below lists its rows under **Tests**.

The rules of C4.3 carry over unchanged: one command layer (every surface sends registered commands); declared prechecks
and their inventory rows (O-24); spec-stated labels in every equivalence test (D-23); the three-way through the real
window for every new tool (D-4, D-22), with the headless replay given the window's view size (D-32); budgets measured on
the workstation in a release build on both back ends, with D-33's control; a design note pushed before its code; an SI
before any interpretation; declared behaviour changes; a completed green run before the handoff commit.

**D-40 additions, for every C4.4 surface:**

- **D-39 in CI as well as on the workstation.** Each surface's rows join the bindings table
  (`scripts/c43-d39-bindings.py` or its C4.4 successor) in both forms: the MCP form in CI (`inspect_ui` finds the
  control and its declared reference, the command entry point or `pointer`/`key` acts, the activity record and document
  reads observe, the tree shows the new state, disabled without a project), and the OS form on the workstation (real
  input, the page's IPC observed). A row that truly cannot run on a runner is named with the reason in the handoff.
  Every control declares the parameters its click sends (`data-tt-params`), so the MCP form tests the binding.
- **Agent changes reflected.** Every C4.4 control shows a change made by an agent (the kernel's event, not a local
  mirror), with a test per control, as ruled for C43B-R1S-09.
- **UI conventions** of the C4.1 brief apply to every new panel: commit on release, one undo step per commit, keyboard
  reach, disabled rather than hidden.
- **macOS:** each surface section names what differs there (the secondary click for context menus, the native menu's
  roles and the application menu, key equivalents) and how the macOS runner exercises it (the MCP form of the table,
  the `desktop gui` job).
- **Manual scripts** under `reviews/manual/M4/` for what only a person can check: text entry with an input method
  (C4.4b), the Contour Editor's feel with a pen (C4.4b), the confirmation sheet's wording (C4.4a), and keyboard-only
  operation of each new panel (both halves).
- **Receipts (D-42):** each committed receipt is a summary (`scripts/receipt-summary.py`: figures, verdict per row,
  hashes of the raw files, the command to regenerate them); no receipt file over 200 KB and at most 5 MB per round;
  raw transcripts and tree dumps stay outside the repository. The M4 merge note lists the receipt folders over 5 MB for
  the orchestrator's trim (26 folders when C4.3b round 2 began, from 6 MB to 101 MB; `reviews/evidence/` 727 MB).
- **GUI-only reason `clipboard`** (answer 6): an action that writes text to the system clipboard and changes no
  document or application state; the gate checks that a `clipboard` element's handler does nothing else.

## 3. Proposed split and order

**C4.4a, panels and settings (no new gesture).** The Pen panel and its advanced options; the tool-options page and the
three persistent toggles with the paint tools' gap closing; the Tablet preferences; the Text panel as the defaults for
new text (`tool.text.options.set`); the drawing inspector; the agent surfaces; the load report window; the toolbar
customisation sheet; the camera list; the two views' context menus. 34 of the 46 entries. Everything here is a dialog,
panel, list or menu: Vitest, the parity gate, the running application e2e; no three-way.

**C4.4b, the four drawing tools.** The Contour Editor (with Snap to Contour), Perspective, Reposition All Drawings and
the Text tool with in-canvas editing and `draw.textFormat.set` on highlighted text: their gestures in the kernel's
driver (they answer `command.notImplemented` today, SI-129), their previews, the headless equivalence with spec labels,
the three-way through the real window in the Drawing and Camera views, budgets. The remaining 12 entries, and the
merge note.

Order a then b: the tools read the options a builds (Snap to Contour, the Text panel's defaults, the current pen for
Contour Editor previews). Each half has its own handoff on a green run; C4.4b's handoff carries the zero-M4 check.

## 4. C4.4a surfaces

### 4.1 Pen panel (02 §6.1, §6.2)

- **Binds:** list and row selection `tool.pen.select {penId}` (Brush and Eraser each remember theirs; switching the
  active tool switches the panel); New `tool.pen.create` (initialised from the current pen, next free "Pen n");
  Delete `tool.pen.delete` (the last pen of a type refused: `pen.lastPen`); in-place rename `tool.pen.rename`
  (`pen.nameExists`); the settings sliders and fields `tool.pen.set` (committed on slider release or field commit: one
  "Set Pen Style" step each; Minimum above Maximum pushes Maximum, and back); the preview stroke drawn from
  `tool.pen.list`'s values (02 §13.2: no render call); advanced options (hidden by default): symmetry
  (`tool.symmetry.set`, bound) and Draw Behind `tool.placeBehind.set`.
- **Labels (D-23):** "Set Pen Style"; the list edits' labels as the commands declare them, checked against 02 line 374
  ("list edits are undoable too": the label names are not given; SI if they differ from the registry's).
- **Prechecks and inventory:** `pen.lastPen`, `pen.nameExists` are parameter-class rows; no state refusals expected.
  The `lint` inventory script will add any new handler pairs.
- **Tests:** Vitest of the panel against a scripted host (every control sends its command; slider drag sends nothing
  until release); kernel: the push-up/push-down rule and one step per commit; e2e: a pen edit through the window
  changes the next Brush stroke's width, not existing strokes (02 line 376).
- **Budget:** a commit's preview redraw within one frame (work p95 ≤ 8 ms under D-33).

### 5.2 Perspective (02 §7.1.3)

- **Gestures:** selection as Select (click, marquee, constrain adds, alternate outside the selection lassos); a corner
  handle drag moves that corner; alternate + side handle drag changes the opposite sides symmetrically →
  `draw.envelope.apply {corners}`; label "Perspective Tool".
- **Preview:** a projective (or bilinear, non-convex) map is not affine: the window maps the selection's tessellated
  vertices through the envelope: exact at vertices, approximate between them until the commit (D-40 answer 8: an
  SI-154 extension). The e2e measures the difference between the last preview frame and the committed drawing on the
  sample drawing and asserts at most 1 view pixel.

### 5.3 Reposition All Drawings (02 §7.1.4)

- **Gestures:** as Select on the whole drawing: drag to offset, box handles scale and rotate, envelope handles →
  `draw.repositionAll.apply {translate, scale, rotate, corners}`, one step "Reposition All Drawings" for all drawings
  of the element. **Preview:** the current drawing through the affine (exact) or envelope (as 5.2).

### 5.4 Text tool (02 §7.6, §7.6.1)

| Gesture | Command | Label (02 §7.6) |
|---|---|---|
| click empty canvas | `draw.text.add {position, text: ""}` | "New Text Object" |
| drag empty canvas | `draw.text.add {position, width}` | "New Text Object" |
| typing, Backspace, Delete, Return | `draw.text.set` at every keystroke; one "Typing" undo step per contiguous run (D-40 answer 2) | "Typing" |
| drag a text box border | `draw.text.set {width}` | "Set Text Width" |
| drag a text object by its frame | `draw.text.set {position}` (D-40 answer 7, interim; an SI before the code) | "Move Text Object" |
| Text panel change on highlighted text | `draw.textFormat.set {range}` | "Text Property Modified" |
| leave an empty text object | the deletion | "Delete Text Object" |

- **Commit granularity (D-40 answer 2):** the document is updated at every keystroke, so agents and renders see the
  text; the undo history has one "Typing" step per contiguous run, ended by a caret move, a format change, a selection
  change or leaving edit mode, with no timers. An agent's `type_text` of a string gives one step, and the user typing
  the same string without interruption gives one step, so the three-way holds. The design note says how the kernel
  coalesces; an SI records the rule.
- **In-canvas editing:** a caret and highlighted range drawn over the canvas; caret positions and hit tests use glyph
  metrics from the kernel (D-40 answer 3; §4.4); IME composition through a hidden input element (keyboard focus rules
  of 01 §8.4: shortcuts suspended while editing; an SI if the spec is silent).
- **Three-way:** the text gestures plus `type_text`; the headless path uses `pointer` then `type_text` (11 §7.6).

## 9. Answers (ruling D-40)

1. **`tool.tablet.set`:** the Preferences dialog edits preference keys through `prefs.set`, as every category except
   Agent access does; `tool.tablet.set` is declared agent-only as the structured equivalent. A test shows both write
   the same state and raise the same event. The entry's location is corrected to 01 §7.3. An SI records the
   two-commands-one-state overlap.
2. **Text commit granularity:** the document is updated at every keystroke; the undo history has one "Typing" step per
   contiguous run, ended by a caret move, a format change, a selection change or leaving edit mode; no timers. An
   agent's `type_text` of a string gives one step, and the user typing it without interruption gives one step, so the
   three-way holds. The design note says how the kernel coalesces; an SI records the rule.
3. **Glyph metrics and fonts:** the kernel is the layout authority. First an existing query in 02 §13 or what M2 C2.1
   built for text nodes; if none serves, new queries by SI and registry addition, visible to agents, with the font
   list from the font source M2 decided on, so rendering stays deterministic on both OSes. No metrics derived in the
   front end.
4. **Drawing inspector before M5:** the current element's current drawing, recorded as an SI; M5 extends it to the
   selected cell.
5. **List B:** confirmed. A query a later surface will read stays agent-only until that surface declares the read; the
   gate then fails on the two states and forces the move. Those justifications are rewritten to describe the agent's
   use and promise nothing.
6. **"Copy as batch JSON" and "copy details":** GUI-only with a new reason `clipboard` (text written to the system
   clipboard, no document or application state changed); the gate checks that a `clipboard` element's handler does
   nothing else.
7. **Ambiguous gesture mappings:** one SI per mapping, before the code. Interim defaults: alternate plus drag of a
   point sends `draw.point.set` with the handles that result, the anchor unmoved; dragging a text object by its frame
   sends `draw.text.set {position}` with the spec's label "Move Text Object". The D-23 rows state these.
8. **Perspective preview:** accepted as an SI-154 extension, exact at vertices and approximate between until the
   commit; the e2e asserts at most 1 view pixel between the last preview frame and the committed drawing on the sample
   drawing.
9. **The split:** C4.4a then C4.4b, each with its own handoff on a green run and its own review; the merge note follows
   C4.4b.
10. **Camera list:** `anim.camera.current.set` keeps its registered undo behaviour; its D-39 row states the spec's
    value from the 05 command table.
11. **Feather Edges:** a command that is not implemented has no menu item; its owner adds the item in both menus when
    it implements the command; listed in the merge note's deferrals.
12. **Camera view context menu:** C4.4 builds the mechanism for both views, the Drawing family's full menu of 02 §4.4
    in both views, and the scene family's menu with the general edit items of 01 §6 only. The items of 05 §3.2 lines
    326-328 are M6 C6.1's by D-30; their `deferred` owners stay, and the merge note says the menu grows in M6.
