### 3.1 The undo history's memory bound (E-51, E-60)

`history.rs`: each step's size is measured from its patch when recorded (pointers and the serialised length of every
value, new and previous; a snapshot step: the entries before and after that are not shared). `push` discards the oldest
steps while the total passes **1 GiB** (`MEMORY_BOUND`, E-60, **SI-217**), never below **200** steps (01 §6.1's floor);
the 1,000-step limit stays. When 200 steps alone pass the bound they are kept and stderr says so once per history. The
position, the clean marker and a repaired open's floor follow a discard as they follow the step-count discard; a typing
run's extended step and a replayed step are measured again.

### 3.3 Thumbnails (plan §7, E-56)

- **The window, off the document thread.** `crates/executor/src/thumbnails.rs`: the window asks through
  `ExecutorHandle::thumbnails_read` (the host command `thumbnails_read`, never a command): one short call on the
  document thread takes each drawing's current revision and an immutable snapshot (the copy-on-write document, the
  planar cache, the blobs) and answers what the cache holds; the rest is queued for one worker thread that renders from
  the snapshot (`draw_render::thumbnail_png`, the queries' render from shared sources) into the cache, keyed by drawing,
  revision and size (16 to 512 px) and bounded (64 MiB, least recently used first), announcing each with the host-only
  `shell.thumbnailsReady {items, pending}` (the progress line). A read replaces the queue (a scroll drops what is out of
  view); a drawing edited meanwhile has a new revision, so its old image is never answered for it. No job, no spec A
  member.
- **The agents' derived `thumbnail`** (10 line 493, a blob; synchronous, 04 §17.1 item 9): `doc.object.get {include:
  ["derived"]}` answers a drawing's `thumbnail` naming the derived-cache entry `cache/thumbnails/<drawing>-<revision>-64.png`
  (10 line 743), rendered on the document thread when the cache does not hold it and kept in the same cache (the session
  holds the service). `doc.blob.get {entry}` reads the entry while the drawing is at that revision and answers
  `project.mediaMissing` once it has changed. A drawing the call has changed but not committed has no thumbnail
  (revisions are stamped at commit; a cached image of staged content would outlive a failed batch under the old
  revision): it is named in `doc.derivedUnavailable`; a drawing the renderer refuses (its time limit) leaves the read
  whole and is named too. `fields` without `thumbnail` renders nothing.

Tests: `c52a_thumbnails.rs` (test-hooks, 5): with a renderer delay, 200 thumbnails pending while `doc.state.get` answers
at its normal median; an edited drawing never shows its old image; the cache holds its bound; a read replaces the queue;
missing drawings and no project. `c52a_derived_thumbnail.rs` (5): the blob validates against the drawing's schema and
`doc.blob.get` reads the same bytes, a 64 × 64 PNG **identical to `element.drawing.list {thumbnails: 64}`** (one
renderer); the entry follows the revision; the window's read finds the agents' thumbnail in the shared cache; a drawing
changed in an unfinished batch has none, an untouched one in the same batch has its own; `fields` without it renders
nothing. The budget (a first batch within 250 ms, the screen within 2 s) is a workstation receipt with the window
(C5.2b).

### 3.5 The cell commands' availability by element type (plan §2 item 5; 04 §13.20)

`c52a_availability.rs` runs the matrix: each cell command on a cell of each element type of the sample scene (drawing,
image, media, sound, annotation, peg), a dry run and the command's availability. "—": the run answers
`cell.notApplicable` and availability is off; ✓: neither refuses for the type; availability agrees with the run
(prechecks = handlers). **Six gaps in M3's cell commands, reported here before any change** and held by the test as
reported (a change without its ruling fails it), §5.

C5.2a's own, fixed: `xsheet.lightTable.add` answered `cell.typeMismatch` for a type it does not take (now
`cell.notApplicable`, its precheck as its handler), and its form without items sent a media column's drawings (now the
drawing, image and annotation columns only, one function with the gesture).

### 3.6 The read's shape at scale (plan §11, D-45)

`c52a_read_shape.rs`: `xsheet.exposures.get` of a 40-column by 60-frame window on scenes of 40, about 500 and about
1,000 columns, each 9,999 frames long with runs in every column, measured in turns (ten rounds, best of each): at most
linear against the 40-column scene and when the columns double, a 2 s ceiling for a gross regression. Workstation,
debug: 20.5, 25.1, 32.8 ms (ratio 1.60, doubling 1.31): the window's read follows the window. The 5 ms release p95 is a
workstation receipt with the window (C5.2b). **Known limit:** each column's cost in the window grows with its whole
length (its runs are found by walking the column), about 20 ms in debug for 40 × 60 on 9,999-frame columns; if the
release receipt misses, the walk becomes a search by frame.

### 3.7 E-66 (a menu the window did not draw)

When no frame comes within the bound, the window's `openContextMenuFor` answers `notRendered`; the host maps it to
`{handled: false, reason: "notRendering"}`. Each opening has a number (`menuAt`); an opening that did not render is
retired, and `ContextMenu` renders nothing for it, so the menu never appears later for a caller told it did not open; a
later opening is not retired. `agentContextMenu.test.ts` (`8040e0e4`).
