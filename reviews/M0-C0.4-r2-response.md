## C04-R2-01 — tablet rules exhaustive and total — fixed as ruled

- **Numeric intervals.** Every band in ADR-0009 Step 1 is half-open, `[low, high)`, and applies to the analyzer's
  unrounded value:
  - rate: `[0, 60)`, `[60, 120)`, `[120, ∞)` and `[120, 200)`, `[200, ∞)`;
  - pressure: `[0, 16)`, `[16, 256)`, `[256, ∞)` and `[256, 1024)`, `[1024, ∞)`.

  A null rate (a single-sample A2) is the named Step 0 outcome **"insufficient evidence: repeat A2"**, never partial.
  Other Step 0 outcomes are an omitted, unfinished or unrecorded action, and an unstated pen capability where the
  row fails. Row 9 is the deliberate exception: a single sample in A6 is the failure the row tests.
- **Total aggregation**, as ruled:
  1. Every measured candidate is evaluated against every row. The ruled labels and priority are W web > R raw HID >
     H RealTimeStylus > D dedicated window with direct WM_POINTER, and W > A on macOS.
  2. A candidate is eligible when the core rows 1, 2 and 7 are not at fail.
  3. Score = rows at pass; the highest eligible score wins, ties by priority.
  4. The decision is **go** (all applicable rows pass), **go-with-conditions** (the candidate plus each non-pass row
     and its mitigation from a fixed table), or **platform no-go** (no eligible candidate).
  5. **Two sources are never combined.**

  The mitigation table contains the ruled entries:
  - pressure partial → accept the measured resolution (row 2) or ≥ 256 levels (row 3);
  - tilt fail → tilt unsupported on this platform;
  - rate in [60, 120) → interpolated sampling off, and the ≥ 200 Hz target recorded as below target.

  Unmeasured candidates (R before E-R1, D before E-D1) are not scored.
- **Core-row eligibility** is my addition, needed for totality. It stops a candidate that fails pen identity,
  pressure or rate from winning on its count of other passes, where a mitigation would have to say "no pen". If you
  read the ruling as scoring without it, removing the filter is a one-line change in `aggregate`.
- **Row 7's partial-native exception is gone**, folded into the aggregation. ADR-0009 now says that passing native
  pen identity proves only that row, not native pressure, tilt or rate.
- **Executable.** `scripts/analyse-tablet-log.py` implements Steps 0–3 and prints `### Decision (ADR-0009 tablet
  rule set)` for every manual log, with a row × candidate table, scores, eligibility, the outcome and its
  conditions. It also writes the decision to `--json`.
- **Tests:**
  - reviewer `test_C04_R2_01_rate_intervals_cover_fractional_hz`: **passes**. The test's own parser raises
    "Unrecognized numeric rule; update the parser explicitly" for new notation, so I added the half-open branch it
    asks for, four lines with a comment saying why. The existing branches and assertions are unchanged;
  - mine, in `scripts/test_decision_rules.py`, run in the gate by `desktop/src/test/decisionRules.test.ts`:

    - every boundary value falls in exactly one band;

      tilt unsupported; macOS → go-with-conditions A with rows 7 and 8;
    - priority ties, insufficient evidence and platform no-go.

## C04-R2-02 — actions vs episodes — fixed; the reviewer test cannot pass as written

- **Choice: page markers.** I chose page markers over a gap threshold, because the user's run is expensive to repeat
  and a threshold would guess at clicks.
  - The tablet page shows "Next: A1 pressure ramp. Press Space to start (K = skip)". Space starts and finishes each
    action, and K skips it. The page records `actions`: id, state `done` / `skipped` / `unfinished`, and start/end on
    the performance clock (web samples) and as epoch ms (native packets' host clock).
  - Keys produce no pointer events. Typing in the form is ignored, and so are `--spike-auto` runs.
  - "Pen has tilt" and "Pen has barrel rotation" are now form fields, for Step 0's n/a.
- **Analyzer.** It assigns each episode to the action whose span contains its first sample. Per action and path the
  result is:
  - "episode n";
  - "split" (the largest episode is measured);
  - **"performed, no events"**, which is distinct from **"omitted"** (K), "unfinished" (saved mid-action) and "not
    recorded";
  - UI clicks are listed as "outside every action" and ignored.

  Malformed markers (wrong order, duplicates, reversed times, overlap) are exit 2.
- **Procedures.** Both manual tests now describe actions A1–A6 with the Space/K steps. Each has an explicit
  mapping table: action → web episode and native episode (k + n, where k counts the clicks before A1) for both
  barrel-rotation branches. ADR-0009 references actions only.
- **Tests:**
  - `desktop/src/spikes/tablet/actions.test.tsx` mounts the real page and drives the full procedure: three actions,
    a stray contact outside any span, K on A4, a hover with no contact, the stationary A6. It saves, runs the real
    analyzer, and checks every mapping, "outside", "unfinished", malformed-marker rejection, and that the decision
    section is printed;
  - `scripts/test_decision_rules.py` takes the reviewer's own six-action fixture, adds the markers, and checks that
    A6 maps to episode **4** without rotation and **5** with it. That is the property the reviewer's test asserts,
    in both branches.
- **The reviewer's `test_C04_R2_02_stationary_instruction_identifies_an_existing_contact_row` cannot pass for any
  document.** It reads one integer from ADR-0009 row 9 (`int(capability_row(9)[2])`). It then asserts that integer
  equals `len(web_analysis(...)['strokes'])` for **both** fixtures. Those lengths are 4 (no rotation) and 5
  (rotation), because the fixture without rotation has one contact fewer. One integer cannot equal both, so no
  document change can satisfy the test, and the reviewer's own failure message names both numbers.
  - With action ids, the cell now reads `A6`, so the test errors at `int()` instead of failing its assertion.
  - I did not edit the test: changing its lookup is beyond an invited parser extension. If you rule it, the minimal
    edit is to read the mapping table, `A6 → 4 / 5`, instead of one integer. My ActionMapping test already asserts
    exactly that against the reviewer's fixture.
  - The reviewer suite is still standalone, as the reviewer left it. Result: 2 of 3 pass.

## C04-R2-03 — canvas completeness and null scores — fixed

- **Step 0 cell statuses.** ADR-0007's rule block (and the report's identical copy) gives every back end × scene
  cell exactly one status:
  - met;
  - missed;
  - **insufficient evidence** (fps null);
  - failed;
  - unavailable (a "… unavailable" error, or no WebGPU API);
  - **not measured (missing run)**.

  An analyzer exit 2 is "not evidence: repeat". Missing cells are listed as "not measured: repeat with
  `--spike canvas --spike-auto` [`--spike-renderer webgl2`]", and insufficient ones likewise. Only measured cells
  are decided.
- **Null-safe selection.** Only a back end with all three cells met or missed is scorable (score = worst fps). A back
  end without a valid measurement is **never selected over** one with a valid measurement. No scorable back end →
  "insufficient evidence: repeat the listed runs".
- **The outcome rows**, applied in order:
  1. both back ends broken → no-go until investigated;
  2. nothing scorable → insufficient evidence;
  3. groups1k missed → no-go, native-wgpu prototype;
  4. brush10k missed → go-with-condition;
  5. paths100k missed → go plus culling and level-of-detail;
  6. all met → go.

  On top of that: WebGL2 broken → investigate, with the interim WebGPU outcome; any missing or insufficient cell →
  **provisional**.
- **Executable.** `scripts/analyse-canvas-log.py` prints `### Decision (ADR-0007 canvas rule set)` for every
  accepted log and writes it to `--json`. The reviewer's two counterexamples **pass through the real analyzer**:
  - `partial-canvas.json` → insufficient evidence, with groups1k and brush10k "not measured" and paths100k
    "insufficient evidence";
  - `null-cadence-both.json` → insufficient evidence, with no score on either back end.

  On committed logs:
  - local RTX → go;
  - Mac CI runner → go plus culling;
  - Windows software-GL CI runner → no-go (non-blocking runner evidence, as before);
  - forced-WebGL2 log → go, provisional, with the WebGPU cells listed.
- **Tests:**
  - the reviewer's `test_C04_R2_03_…missing_scenes` **passes**;
  - mine (`test_decision_rules.py`): both reviewer fixtures through `validate` + `canvas_decision`; an unscored back
    end never selected over a scored one; worst-scene selection and the WebGPU tie; all four outcome rows.
