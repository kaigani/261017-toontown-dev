## Findings

### C22-R2-01 — P1: true vertex crossing uses inexact floating-point orientation

**Requirement:** 02 §3.2, §3.12(1); binding SI-067 and ADR-0017 §1: strictly crossing directions at an anchor must form a junction, using exact orientation predicates.

**Reproduction:** `crates/vector/tests/c22_r2_geometry.rs::vertex_crossing_uses_exact_orientation_for_grid_coordinates`:

```text
cargo test -p tt-vector --test c22_r2_geometry vertex_crossing_uses_exact_orientation_for_grid_coordinates --locked -- --nocapture
```

Let `N=500000000`. Stroke A has anchors `(-N,-(N-1))/64`, `(0,0)`, `(N,N-1)/64`; B has `(-(N-1),-(N-2))/64`, `(0,0)`, `(N-1,N-2)/64`. All coordinates are exactly on the grid and inside ±10⁷ du. The exact directional determinant in grid units is `N(N-2)-(N-1)² = -1`, so these lines strictly cross. The implementation computes zero and returns only a moved B; neither stroke splits at zero. [Raw reproduction](evidence/M2-C2.2-r2/geometry-final.log).

**Location/cause:** `planar/node.rs::{cross,crossing,at_vertex,inside_arc,crosses_at}` use `f64` multiplication, subtraction and equality, not exact predicates. This is a correctness failure on this Windows run; it does **not** establish different Windows/macOS results. Deterministically missing the crossing on both would still violate the ruling.

**Fix direction:** use robust exact orientation/sign predicates for represented coordinates, including the non-grid/one-ulp cases, and use them consistently for vertex classification and collinear/shared-direction exclusion. Keep ordinary proper crossings and tolerance resolution consistent. Do not substitute a larger epsilon that classifies strictly different directions as collinear.

### C22-R2-02 — P1: JSON import bypasses fill-consistency repair

**Requirement:** round-1 binding ruling expressly includes colour recovery **and fill-consistency repair on JSON import** in C2.2; 10 §4.9/§7.2 and readiness 6 require deterministic longest-boundary repair and `drawing.fillInconsistent` reporting. Preserving imported geometry without noding is compatible with repairing its stored fills.

**Reproduction:** `c22_r2_commands::json_import_repairs_clockwise_side_disagreement_without_renoding`:

```text
cargo test -p tt-executor --test c22_r2_commands json_import_repairs_clockwise_side_disagreement_without_renoding --locked -- --nocapture
```

Import a project bundle with a clockwise 100×10 rectangle stored as four pencil strokes. Its right sides alternate red/blue; the two 100-du sides are blue and the two 10-du sides red. After `doc.import.json {idPolicy:"preserve"}`, the stored sides still alternate. Required: all four internal sides blue, repaired in the import transaction. The same clockwise fixture **does** repair deterministically on normal open and gives the required report and unundoable base. [Import and load observations](evidence/M2-C2.2-r2/commands-final.log).

**Location/cause:** `commands/bundle.rs::import` marks created drawings `keep_verbatim`, patches entries, and runs missing-colour recovery only. `Cx::settle` treats those drawings as equal to themselves, skipping them. `load_repair::repair_sides` is not called by import.

**Fix direction:** run side-fill repair on imported drawings without re-noding them, stage the result in the import's existing transaction, and report the inconsistency. Retain C1.3 ID/geometry fidelity and undo the import and repairs together.

### C22-R2-03 — P1: colour recovery discards swatch extensions, including protection

**Requirement:** 10 §2.2 requires unknown `ext` namespaces preserved verbatim; §4.11 stores the **full swatch object**; 03 §1.6/§11.2 requires recreation from that copy. SI-061's paint-protection flag lives in `ext["dev.toontown.paint"].protected`.

**Reproduction:** `c22_r2_commands::recovery_preserves_full_swatch_extensions_including_paint_protection`:

```text
cargo test -p tt-executor --test c22_r2_commands recovery_preserves_full_swatch_extensions_including_paint_protection --locked -- --nocapture
```

Paste a line using a missing colour and a complete recovery copy whose swatch has `ext = {"dev.toontown.paint":{"protected":true},"org.review.swatch":{"tag":"retain"}}`. The colour is recreated with the right name and value, but its entire `ext` is absent. Required: both namespaces survive. The normal path-paint protection/explicit override control passes when the original swatch actually retains its flag. [Full swatch observation](evidence/M2-C2.2-r2/recovery-extension.log).

**Location/cause:** `commands/colour_recovery.rs::recover_with` constructs a fresh swatch from a fixed list of fields and omits extensions. This shared routine serves paste, on-demand, load and import recovery.

**Fix direction:** preserve the complete validated copied swatch envelope/extension data while changing only the necessary revision, identity and remapped style-value fields. Retain unknown namespaces as well as the application protection namespace.

### C22-R2-04 — P1: rounded clipping turns unequal overlaps into an ID tie

**Requirement:** binding largest **exact** overlap / lower-ID-on-exact-tie rule; 02 §3.12(1), SI-060 and ADR-0017 §4. Snapping map vertices does not make the intersection of two integer-grid polygons integral.

**Reproduction:** `c22_r2_geometry::overlap_ranking_keeps_rational_intersection_area_before_grid_rounding`:

```text
cargo test -p tt-vector --test c22_r2_geometry overlap_ranking_keeps_rational_intersection_area_before_grid_rounding --locked -- --nocapture
```

Old zones A=`[0,1]×[0,1]`, B=`[1,2]×[0,1]` have distinct fills. New zone is triangle `(0,0),(100,0),(0,65/64)`. Its exact overlaps are A=1 du² and B=`8311/8320` du²: the removed corner has width `6/13`, height `3/640`, area `9/8320`. These are 1-du-wide old zones, not collapsed sub-tolerance features. All input vertices are on the documented grid.

The test deterministically selects valid boundary IDs with B's ID lower. Observed: B's `smaller` fill wins; required: A's `larger` fill wins regardless of ID. [Exact numbers and result](evidence/M2-C2.2-r2/rational-overlap.log).

**Location/cause:** `planar/fill.rs::overlap2` obtains an `i32` intersection contour from `i_overlay` and sums its integer vertices. The sloping intersection is rounded back onto the grid; the lost B corner disappears and both scores become equal. Conservative box candidate enumeration is now correct, but scoring is not exact.

**Fix direction:** compare exact rational intersection areas (or an equivalent robust exact-area method) before any contour output rounding. Charge the work to the existing account and invoke the ID tie-break only for mathematically equal overlap areas. Retain holes and nonconvex polygon coverage.

### C22-R2-05 — P2: tiled textures still use box-stretch click mapping

**Requirement:** 03 §7.2 click-mapping row: tile-on textures use native pixel dimensions at 1 pixel/du, anchored at the top-left. This was an explicit round-1 register divergence/residual risk, separate from the fixed pencil/solid-matrix defects.

**Reproduction:** `c22_r2_commands::tiled_texture_click_uses_native_pixel_dimensions`:

```text
cargo test -p tt-executor --test c22_r2_commands tiled_texture_click_uses_native_pixel_dimensions --locked -- --nocapture
```

A valid fixture texture has `tile:true,width:16,height:8` in every style. Clicking its colour onto a 100×100 zone stores `[100,0,0,100,1000,1000]`. Required scale magnitudes are 16 and 8. The test asserts scale only, avoiding an unrelated convention dispute about texture-axis direction. [Observation](evidence/M2-C2.2-r2/tile.log).

**Location/cause:** `colour.rs::default_matrix` receives only `SwatchKind` and the box; it cannot distinguish tiled textures or their dimensions.

**Interpretation / recommendation:** the broad interim wording “default box after a click” can be read as the current generic mapping, while the cited spec explicitly gives tile-on a different default. Preserve the predecessor's P2/residual treatment, assign the texture default to **M2 C2.3 before texture rendering is accepted**, and have the orchestrator confirm that owner. This report does not silently treat native tiling as implemented or as covered by the solid/pencil fix.

The fill survives both representation changes. The ordinary split/merge/tie/sliver/hole variants pass; they do not supersede R2-04's fractional intersection failure.
