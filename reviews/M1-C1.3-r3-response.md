**C13-R3-01 in detail.** The ruled protocol, in `crates/persist/src/lock.rs`, with ADR-0014 §11 updated:
- **(a) Heartbeat fails closed.** `refresh` takes the arbiter and writes only when the file holds this session's
  token. A missing, unreadable or foreign lock is `project.lockedByOther`, and nothing is written. Maintenance's
  existing error path turns that into read-only for the session. A heartbeat therefore never recreates or replaces
  another publication. While a takeover holds the arbiter, the heartbeat is skipped, and the next one sees the
  outcome. Release on drop also happens under the arbiter, and only for this session's own token.
- **(b) Publication under the arbiter, then validated.** `acquire` holds `<lock>.takeover` while it:
  1. reads the state again;
  2. removes a stale lock;
  3. creates its lock exclusively, writes it and syncs it;
  4. reads the file back.

  It returns `Acquired` only when the file holds its token; otherwise `HeldByOther`. A takeover cannot interleave
  between create and write, and a resumed writer cannot announce ownership of a replaced publication.
- **The modification-time heuristic no longer protects live writers.** An unreadable lock counts as held until it is
  as old as a stale heartbeat (`STALE_SECS`, 5 minutes, by modification time); only then is it treated as abandoned.
  The round-2 two-second "settled" rule is gone.
- **C1.4 obligations recorded in ADR-0014 §11**, as listed by the reviewer: a paused arbiter beyond its 10 s expiry,
  PID reuse, clock jumps, and deterministic suspension tests at each boundary on NTFS and APFS.

**C13-R3-03 in detail.**
- `persistence::write` now carries content-addressed. Each omitted binary entry is copied to a private temporary,
  hashed, and kept as `<cache>/carried/<sha256>/<entry>`. When that copy already exists, it is reused and the
  temporary dropped. Repeated exports therefore keep one copy, and a later save reuses it. A failed copy removes its
  temporary.
- Closing a project, or replacing it by an open, create, backup or recovery install, empties the session cache: no
  live history depends on it any more. The exception is while that project is being saved, since the write may read
  from the cache. Executor stop still removes everything.
- The new builder test checks all of it: one cached copy after a Save As plus an export; undo still reaches those
  bytes; zero after close.
