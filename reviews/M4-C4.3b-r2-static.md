## Case 4: FAIL

Ownership checks: gestureLifecycle.ts:47-55 rejects old answers after begin(), adopt() or unmount(); answered():59-63 only arms a current token. Before the second press, an answer may arm the first token; begin():39-44 disarms it. During/after the second press, both success and refusal of the first token are ignored. CanvasView.tsx:720 assigns each played gesture a token; :765-769 aborts a playing agent on user press. Collector activity prevents starting a played gesture during the user's held gesture. Per-view lifecycle instances isolate two views. Adoption at :302-310 clears pending/released/playing state; unmount invalidates callbacks; asynchronous part loads at :271-277 check their captured parts object and generation. gestureOrder.ts:31-36 still places modal end after either commit outcome, preserving SI-157. Engine error envelopes follow the refusal branch. A never-answered request cannot arm clearing; it also cannot end the modal chain.

Number tokens eventually lose integer precision: after 2**53 increments begin() can reuse a number. This is an observation for an unreachable practical lifetime, not a separate severity finding.
