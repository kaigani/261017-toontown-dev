### C12-R3-02 — P1 — a staged checkpoint advertises new revisions but stores old stamps

**Sources:** `crates/executor/src/commands/checkpoint.rs::checkpoint_create` takes `predicted_rev()` then clones `cx.document()`; `doc.rs::doc_diff` observes the stored snapshot. **Contract:** spec 11 §7.3/§7.7, 10 REV-01/02, binding R1-10/R2-03.

Patch a stroke and create a checkpoint as the final step of the same atomic batch. Immediately query `doc.diff` from that checkpoint. Actual result is `fromRev:2,toRev:2` with a modified drawing at rev 2 and an empty patch, despite no intervening content change. Expected is an empty diff. The checkpoint's content is from the right step, but its document/object stamps are those of the unstamped staged copy; final commit stamps only the installed document.

**Reproduction:** C3 `checkpoint_after_stroke_edit_has_no_diff_at_same_committed_revision` fails. Capture a coherent, correctly stamped snapshot at the checkpoint's own step, preserving rollback and point-in-batch semantics; do not substitute the final batch content. Existing visibility, midway content, list/delete and rollback fixes are retained and tested.

### C12-R3-03 — P1 — identical overlapping wait retries return different original results

**Sources:** `crates/executor/src/run.rs::RequestCache::lookup`, `reserve`, `wait_finish`, `remember`. **Contract:** spec 11 §7.2, binding request-ID ruling R1-22, R2-06 reservation.

Hold a job. Start `job.wait(timeoutMs:800, requestId:"r3-overlap")`; while it is pending, start the identical request about 350 ms later. The first call times out and returns `state:"running", timedOut:true`. Release the job after that first reply: the duplicate returns `state:"succeeded"` with a job result. Same session, command, parameters, options and request ID; different envelopes.

`lookup` explicitly treats an identical pending request as a cache miss, so it starts a second wait. Each completion calls `remember`, allowing the later call to replace the original cached envelope. The reservation correctly blocks different commands, but does not enforce identical retry semantics.

**Reproduction:** C3 `overlapping_identical_waits_retain_one_original_envelope` fails. The test first verifies that the ID is actually reserved by probing a different command, then compares complete envelopes. Share the first in-flight completion with identical retries and preserve that original result in the cache. Keep different-parameter `request.conflict` and evicted-ID `request.unknownId` behavior.

### C12-R3-04 — P1 — filtering a staged diff loses drawing-content invalidation

**Source:** `crates/executor/src/commands/doc.rs::doc_diff`, especially construction of `invalidated` from already filtered `changes` and the fallback drawing-revision comparison. **Contract:** spec 11 §7.3 (queries see preceding steps), 10 REV-02 and `doc.diff`, binding R2-12.

In an atomic batch, patch a stroke's metadata then query `doc.diff` from the base revision with `types:["drawing"]` and `within` that drawing. Actual `changes:[]`; expected the containing drawing with the predicted revision. The type filter removes the stroke change before parent invalidation is calculated. The fallback revision comparison cannot recover it because staged documents have not yet received final stamps.

**Reproduction:** C3 `staged_drawing_only_diff_keeps_content_invalidation` fails. Compute invalidations from the unfiltered semantic changes/touched objects, then apply type/containment filtering to the resulting records. The existing standalone and 100k-stroke cases continue to pass; this is a composition hole in the round-2 repair.
