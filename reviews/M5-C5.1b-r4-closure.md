## Findings

### C51B-R4S-01 - P2 - Timed-out menu work retains the queue

Citation: E-62 (review brief: bounded recovery after timeout);
E-52, reviews/M5-C5.1-plan.md:682 (answer what the window did).
Code: desktop/src/shell/windowHooks.ts:166-171,185-194;
desktop/src-tauri/src/attached.rs:337-345 (timeout only removes host waiter).
Sequence: dispatch a menu request, then minimize main before its animation
frame. Its frame callback can remain suspended for the entire minimization.
The host caller times out, but nothing releases or cancels the window turn.
A second request, even to a vanished control (normally an immediate
notFound), waits behind that unresolved turn and also times out. This
continues as long as main stays minimized. Restoring main instead executes
the expired work and then the expired queued requests, opening stale menus.
Wrong: caller timeout neither releases the queue nor retires its UI work.

### C51B-R4S-02 - P2 - Restart forgets the still-active float

Citation: spec/11_agent_interface_mcp.md:237-241; E-52,
reviews/M5-C5.1-plan.md:679-680 (text field keeps its key).
Code: desktop/src-tauri/src/host.rs:283-285,107-109,379-388,402-409;
desktop/src/shell/windowHooks.ts:419-425.
Sequence: main reports false; an active float reports true while a field
is edited. Restart the engine without changing OS focus. Restart resets
Windows, including focused. Generation listeners resend both window facts,
but reports deliberately cannot select the active window. combined() uses

Wrong false: field-owned agent keys can run bindings instead of ui.busy.
The reverse (main retains true, active float false) spuriously refuses keys.
The new tests never restart while a float remains active.
