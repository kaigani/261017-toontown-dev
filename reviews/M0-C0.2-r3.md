## Round-2 defect sweep and manual workflow

- **Windows monotonic helper:** definition is `#[cfg(windows)]`, use is confined to the Windows injector; macOS exact-head clippy and actual Rust tests pass. The ns endpoints are monotonic; pairing them with wall time does not make cross-clock latency exact.
- **60-second test timeout:** increases the per-test deadline, with no weakened assertions. Prior wrappers still run their Rust/Python checks; CI's Mac tests actually execute. The new failing test remains an ordinary failure under this timeout.
- **Settle/geometry/refusal:** 500 ms lets the listener state render before the common rectangle is chosen; one-line status/header and fixed table areas remove the observed layout trigger. The guard checks containment before each run, not a continuous layout lock. Evidence-only page probe forces the first refusal, its one retained retry, then moves the canvas: exactly two injection calls and eleven retained failed records (two covering-window plus nine geometry refusals). No failure is overwritten. External resize during an in-flight run remains outside this quiet-matrix guarantee; per-frame root-window ownership checks are not a canvas geometry monitor.
- **Nested native refusal:** native probe errors remain inside `probe.error`; they are not retried by the new `run.error`-only retry branch. The analyzer recognizes and prints them as failed. Local real execution saved **15 failed records** (five web scenarios each with retry, five native probes), exit 0; analysis says 0 successful, 15 failed. Initial visibility refusals still print HWNDs rather than class/PID; the added class/PID diagnostics apply to in-stroke covering refusals. Neither detail silently turns failure into success evidence.
- **Context menu:** listener calls `preventDefault` on that event only; pointer handlers are unchanged. A page probe dispatches down/move/contextmenu/up twice: both ups and both menu records survive. Matrix-5 actual WebView2 ups corroborate this narrower result; it is not a claim of equal delivery under all loads.
- **Current manual Mac log:** `run-page-probe.py` renders the real page in Vitest/jsdom with `penSimulation:false`, `appkit-nsevent`, synthetic DOM pointer events, a certified mock native channel and populated metadata fields. Save produces v3 with empty runs/simulations, two web strokes, two native pose-only strokes, two menu records and saved metadata. The current analyzer accepts it, prints 250 Hz per stroke, ±30°/±45° extrema and raw native tilt. The downloaded Mac artifact's analyzer is byte-identical and accepts the same log under `python -I -S`. This is Windows execution of a Mac-mode page fixture, not WKWebView/AppKit execution.
- **User procedure:** artifact name, Apple Silicon tarball, executable path, quarantine command, absolute log path, metadata form, lift-separated strokes, Save/return instructions and optional analyzer command are coherent. Safari's auto-unzip branch now copies folder contents correctly. Metadata entry/Save clicks can still add app-wide native mouse episodes; hover creates no contact row, so users/reviewers must not equate row numbers blindly across paths.
