### C43A-R1-01 ? P2 ? Camera drawing mapping query refuses

Clause: `spec/02_drawing.md:101?104` explicitly says the Camera view's drawing-plane mapping MUST be queryable with `draw.viewMapping.get`.
Reproduction: open fixture; set current element Bob at frame 1; invoke `draw.viewMapping.get {view:"cameraView"}`.
Required: forward and inverse mapping for that drawing through its full scene transform and camera.
Observed: `arg.invalid`, "this needs the Drawing view's mapping". An agent cannot query the documented inverse mapping to place drawing input in the Camera view.
Permanent reproduction: `mapping::camera_drawing_mapping_is_queryable`; fails with product code unchanged from `3fb27030`.
Fix direction: return the Camera chain's current-element drawing-to-view matrix and inverse, with typed errors for unavailable planes.

### C43A-R1-02 ? P2 ? Scene coordinates use current rather than addressed element

Clause: `spec/02_drawing.md:61` full element inverse; ?13.1 item 5 (1151?1155) provides explicit drawing/element addressing and scene space. SI-146 specifies the addressed element's plane.
Reproduction: create Addressed square; set its static position to (3,2); leave Bob current; `draw.pivot.set {elementId:Addressed,frame:1,space:"scene",point:{x:3,y:2}}`.
Required: pivot (0,0) in the addressed drawing's units.
Observed: pivot approximately (700,200), because conversion uses Bob's plane. An agent explicitly editing another element places its pivot at the wrong location.
Permanent reproduction: `mapping::explicit_element_scene_point_uses_addressed_element`; fails with product code unchanged from `3fb27030`.
Fix direction: resolve the addressed drawing's owner before converting scene/view points; do not take the current element when an explicit target is supplied.
