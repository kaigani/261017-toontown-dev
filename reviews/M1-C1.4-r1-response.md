### Why the two C14-R1-16 sub-items are ticketed

- **`result.effectiveParams` (11 §8).** It changes the result contract of every command: 719 result schemas and the
  generated IPC types. Its defaults include the GUI's "last used" values, which arrive with the M4 dialogs. Doing it
  per command now would mean a second pass in M4.
- **Executed worked examples (11 §13).** They need the namespaces' commands, most of which arrive in M2–M9. The
  kernel namespaces get recorded examples (a golden fixture executed by a test) in the M2 agent-workflow follow-up.

Both tests fail when run with `--ignored`.

### What happens today with a handler that never returns (asked in C14-R1-05)

- **Document-thread work.** The caller gets `command.timeout` after the executor's budget (5 s by default). The
  document thread stays inside the handler, so later calls queue behind it and time out too. Nothing restarts the
  thread. When the handler returns, the queue drains and the executor recovers (C1.2,
  `c12_never_block.rs::a_handler_that_does_not_return_never_blocks_callers`). The MCP call thread is held only for the
  budget per call, never indefinitely, and `ping` keeps answering.
- **Server-owned work** (`list_commands`, `describe_command`, `get_docs`). This now runs under its own 5 s watchdog
  on a separate thread; the call thread continues and the stuck thread is abandoned.
- **Restarting the document thread** (a new engine with the document reloaded) is still the M4 gap 3, with the
  attached host.

## Other changes made while fixing

- **Arbiter abandonment** (`9fec5d6`, ADR-0014 §11.4). Recording every crash observation showed that a holder killed
  inside its arbiter window was taken over only after the 10 s abandonment age. An unprotected arbiter whose holder
  provably died now goes at once:
  - Windows: protection exists from creation;
  - elsewhere: the token is written after the `flock`.

  Only an empty, unprotected file waits. Takeover p50 is now tens of ms (`lock-liveness-*.json`). Two removers stay
  safe through `still_ours()`.
- **Pinned SDK.** CI pins the conformance SDK (`mcp==2.0.0`), following the SI-049 adjudication.
