## Findings

### C51B-R1S-01 - P2 - Show Timeline Selection never reveals the row

Citation: plan section 5 line 155; SI-216; design view section 1.
Code: desktop/src/timeline/TimelinePanel.tsx:390-398, 156, 651;
crates/executor/src/commands/timeline.rs:1125.
Sequence: scroll a long list to its top; an agent makes a bottom element
current, then invokes timeline.view.set with revealElementId null (or use /).
The host notice carries revealElementId, but the panel only parses view and
uses the rest to trigger reads. No code sets listRef.scrollTop for a reveal.
Wrong: the current row stays offscreen indefinitely. Correct: scroll the
requested row into the visible vertical window, including repeated reveals.

### C51B-R1S-02 - P2 - A rows answer can overwrite a newer playhead notice

Citation: plan section 5 lines 160-161; design view section 1 read-gate rule.
Code: desktop/src/timeline/TimelinePanel.tsx:226-230, 401-415, 181.
Sequence: a rows read snapshots frame 1; before its promise completes, a frame
change notice sets frameNow to 20. The rows answer then sets rows and clears
frameNow. Neither frame notice invalidates rowsGate or requests newer rows.
Wrong: after playback stops, the final frame can remain 1 with kernel frame
20 and no later event to repair it. Correct: reconcile frame notices and rows
answers in one ordering domain; an older snapshot must not clear a newer frame.

### C51B-R1S-03 - P2 - Required context items absent

Citation: spec/04_timeline_xsheet.md:704-706; E-2, E-9;
design view section 5.
Code: desktop/src/timeline/menus.ts:69 (rowMenu), 380 (cellMenu),
457 (rulerMenu); TimelinePanel.tsx:1018 (menu rendering).
Sequence: right-click a drawing cell. The menu has only Cut/Copy/Paste/Delete;
none of the exposure, insert, cycle or duplicate-drawing placeholders exists.
Right-click a row: import items, Toggle Constant Z, Add Default Keyframe and
Edit Sound are absent. The ruler lacks Sound Playback and Sound Scrubbing.
The shared menu disables deferred references only if they were supplied; it
never adds missing items. Correct: required later-owned items remain present,
disabled with owner; currently owned Constant Z is bound (E-2).

### C51B-R1S-04 - P2 - Context toggles never show checked state

Citation: spec/04_timeline_xsheet.md:708; plan section 7 line 258.
Code: desktop/src/timeline/menus.ts:236 (effect parameters), 457 (rulerMenu);
desktop/src/shell/ContextMenu.tsx:319 (item.check determines checked display).
Sequence: set free playback range, then open ruler context. Automatic Fit and
Free have no check property, so neither shows current mode. Show Effect
Parameters likewise always says Show and sends visible true even when on.
Correct: mode choices show the current mode and the per-effect toggle shows
its current state and permits turning it off.

### C51B-R1S-05 - P2 - Updating a note starts empty

Citation: spec/04_timeline_xsheet.md:405-408.
Code: desktop/src/timeline/dialogOpen.tsx:129-139;
desktop/src/timeline/menus.ts:355; desktop/src/timeline/dialogs.tsx:83.
Sequence: set an element note to Keep this instruction; open its row context
Element Note dialog. The dialog passes multiline true without initial text;
textDialog defaults initial to empty. Press OK without typing.
Wrong: the existing note disappears, and the editor never showed it for update.
Correct: label the action Update Element Note and prefill the current note.

### C51B-R1S-06 - P2 - Separate numeric field implementation

Citation: D-61 item 3 (reviews/M4-C4.3-plan.md:677-681);
design view section 7 explicitly requires the one numeric field.
Code: desktop/src/timeline/dialogs.tsx:12-57, 180-191;
desktop/src/shell/NumericField.tsx:19 (existing shared component).
Sequence: open Change Duration, type letters or an empty value, then blur.
The private NumberDialog retains the invalid text and waits for modal submit;
it does not restore the retained value under the shared field commit rule.
The batch-count field repeats this implementation. Correct: use the one
numeric field component and its invalid-entry, range and restoration rules.

### C51B-R1S-07 - P2 - Notice assertion relies on a fixed sleep

Citation: D-45 (reviews/M4-C4.3-plan.md:495), waits are for states.
Code: crates/executor/tests/c51b_font_scan.rs:270-271.
Sequence: scan released; retry commands return; notice delivery is delayed
beyond 100 ms by scheduling. Test sleeps 100 ms and drains the receiver once.
Wrong: a correct eventual notice fails the CI assertion. Correct: wait on the
receiver for the matching waiting:false state with a generous deadline.
This finding is about the test protocol, not measured product performance.

## Observations

Findings distinguish concrete code sequences from coverage concerns. Findings above are static event sequences, not live results.

- D-39 Timeline reasons: Peg Reset is registered but not implemented (M6 C6.1);
  context actions require real pointer/keyboard input (TL_CONTEXT_ONLY);
  canvas and menu geometry require the debugging port. The first is legitimate
  deferral; geometry needs real layout. Context actions being OS-only leaves
  CI without the promised end-to-end row for those controls: inventory tests
  inspect row names, not execution. timing-gui exercises gestures instead.
  Unit menu-model coverage cannot establish actual item reachability (R1S-03).
- Deferred owners inspected: none is C5.1 or earlier. Structured preference
  aliases and explicit cell clipboard forms have the E-4/E-5/E-6 reasons.
- reads.json carries Timeline reads on unrelated surfaces such as loadReport;
  declarations alone do not prove those surfaces actually mount the panel.

- Font readiness notice refreshes CanvasView, but is absent from the store
  availability event set (store.ts:35-42, 243). Prechecks that return fontsLoading
  can retain disabled availability until a separate refresh. This is an
  observation: no concrete mounted control with those exact parameters proved.
- Budget receipts agree with handoff table rounding: rows 17.2599 ms,
  exposures 2.3135 ms; bar/reorder/cell 483.4477/518.932/2.949 ms.
  Window control 17.7 ms; draw p95 0.1 ms (124/63/120 draws, zero over twice
  control); click 27 ms; wheel 20.1 ms; playback 48 frames, p95 48.3 ms.
  The reused window scene receipt says buildSeconds 4.45, not the original
  792-second construction; that original construction is not independently
  substantiated by this receipt. Known release misses are not findings.
- Receipts: real input 20 rows/130.9 s; D-39 71 rows; D-44 42 rows/418.7 s;
  restart 7 rows/74.7 s, banner 2.63 s. No new measurements made.
- The raised 20 s wait (c43-d39-bindings.py:3374) polls for a row in the
  inspection tree/DOM, asking for the panel again halfway; it is a state wait.
- TT_TEST_DEGRADE_TRIGGER is inside cfg(test-hooks) in degrade_hook.rs:15;
  --timing-check is rejected without m0-diagnostics (lib.rs:154-157).
  No confirmed product-build entry to either diagnostic path.
- All inspected document edits route through commands. Gesture refusals use
  the shared message path. ContextMenu and modal manager are reused; numeric
  inputs are the exception reported above. No native confirmation calls found
  in the Timeline modules. Static review does not establish live accessibility.
