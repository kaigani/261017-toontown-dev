# C5.1b — The engine stops: the banner, Restart, Recover (≈ 5 min)

Spec: 01 §12.1 (engine not responding), 01 §11 (recovery); ruling E-29 item 3. Automated on the Windows workstation:
`scripts/c51b-engine-restart.py` (the same steps with real input).

Needs a build with the dev-only trigger: `pnpm --dir desktop tauri build --debug --no-bundle --features test-hooks`.
Start it from a terminal with `TT_TEST_DEGRADE_TRIGGER` set to a file path that does not exist yet, for example
`set TT_TEST_DEGRADE_TRIGGER=%TEMP%\tt-stop` (macOS: `export TT_TEST_DEGRADE_TRIGGER=/tmp/tt-stop`).

1. Preferences › Files › Autosave interval: 1 minute. Create a project, add an element named Before, wait a minute
   (an autosave is made).
2. Create the trigger file (`type nul > %TEMP%\tt-stop`; macOS `touch /tmp/tt-stop`), then add any element → the action
   fails.
3. Within a few seconds the banner **The engine is not responding** appears, with the time of the last autosave; nothing
   covers its buttons (a list of failed reads, if shown, stays below it).
4. **Restart the engine** → the question **Restart the engine?**; **Cancel** → the banner stays.
5. **Restart the engine** again → **Restart** → the banner goes; the start screen offers the autosave as recoverable
   work.
6. **Recover** → the project opens with Before, without the element the engine stopped on.
