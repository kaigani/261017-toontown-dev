## 2. Rulings

- **O-15 (design note before code).** [M4-design-http-admission.md](M4-design-http-admission.md) was committed as
  `5b9ccf8` before any `http.rs` change. It lists every socket state and its owning bound, the formulas (threads
  `3 + C + S`, sockets `2 + C + L`), the full-pool rule, refusals without a thread, the session guard and the lock
  order; the code follows it (`e19c862`) with one builder test per invariant (I-1 to I-7; I-8, the lock order, holds
  by construction and is stated in the note). Two mechanisms were corrected while implementing, without changing an
  invariant, and the note says so: the eviction signal is a flag the worker checks every 50 ms (keeping a second
  socket handle for a shutdown reset ordinary answers on Windows: closing a duplicated socket handle resets the
  connection), and a quiet stream checks its client every second. **Full-pool rule, and why:** the newcomer is
  refused and the oldest pending connection evicted, rather than the newcomer admitted into the freed slot: the
  newcomer is itself unclassified and gets no precedence over a connection that may be about to complete its head;
  the refusal costs nothing and tells the client to retry at once, and its retry finds room. **What it does not
  promise:** a local process that opens a new connection between every refusal and its retry (an active flood) can
  keep a retry meeting a full pool; the bound is then §3's (no thread beyond C, no socket beyond C + L).
- **O-16 / O-17.** Implemented as ruled (§1); ADR-0021 decision 10 amended with both rules.
- **O-18 (recovery ownership).**
  1. *Check and write are one step.* The persist crate's recovery ownership lock is held by an engine's fenced write
     (fence check, owner record, copy) and fenced heartbeat from check to last write, and by `release_engine`
     (`recovery::write_owned`, `heartbeat_owned`). A write past its check finishes before a release; a write after a
     release sees the fence (set before the release is asked) and writes nothing. Test: a writer paused at the new
     `RecoveryWriteChecked` boundary of the persist crate's existing hook facility (`tt_persist::lock::hooks`, test
     builds only), in `crates/executor/tests/c41_isolated.rs` (ruling D-2's binary for process-wide hooks):
     `a_paused_recovery_write_finishes_before_the_release_and_a_later_one_writes_nothing`.
  2. *Scavenging.* The owner record (`engine` beside each entry) now holds the owner's process id and host as well as
     its engine token. At start, an entry with an owner record and no `recovery.json` whose owner is gone by the lock
     rule (process known dead on this host, or the record older than the stale time and the process not known alive)
     is removed; a completed recovery of a dead process is offered, never removed. Test:
     `restart::owner_records_without_a_completed_recovery_are_scavenged_at_start`.
  3. *Residual risk named.* A request in flight across a real restart still has no end-to-end test (a product build
     has no hanging command). The pure functions and units that cover it: `desktop/src-tauri/src/host.rs`
     `answer_of` (the answer of a request from an older generation becomes `command.timeout`, `reason:
     "engineRestarted"`; host test `a_restart_drops_old_flags_renumbers_events_and_answers_in_flight_requests_as_restarted`),
     `restart_from` (serialised; `restarts_are_serialised_and_a_waiting_one_does_not_restart_again`), `TokenGuard`
     (`a_request_token_is_owned_by_its_invocation`, `run_refuses_a_token_already_in_flight`), the watchdog's `due` and
     `Watchdog::record` (`the_cadence_is_fixed_and_three_misses_take_about_fifteen_seconds`,
     `three_misses_mark_and_one_answer_clears`, reviewer `supplied_clock_late_reply_resets_all_strikes`), the executor's
     `a_handler_that_does_not_return_never_blocks_callers` (`c12_never_block`), and the recovery fence above.

## 3. Observations

1. **Float geometry write-back** is now a trailing debounce (`floats::Debounce`): a geometry is sent once the gesture
   has been quiet for 250 ms after its last event, so a long drag sends one `window.panel.set`, as the design note
   says. Test on a supplied clock: `a_long_drag_sends_one_geometry_when_it_pauses`.
2. **The echo guard** is a pure value with the clock supplied (`floats::EchoGuard`: 400 ms settling after the host
   acts on a window; a move or resize ending within 1 px of the host's placement). Test:
   `the_echo_guard_settles_on_a_supplied_clock` (inside and at the end of the settle time, 1 px and 2 px, another
   window, a replaced placement).
3. **Form validity versus command availability** is stated in ADR-0021 decision 9: O-10's availability answers
   whether a command reference can run now, for every surface that offers a command; a dialog's OK is also disabled
   while its draft is invalid, which is local because it judges parameters not yet sent and changes with each
   keystroke; the command validates them again when it runs.

## 4. C41-R2-21: the bounds audit

A schema bound is wrong when it replaces a specified domain error for the same value. Each bound the audit listed:

| Bound | Domain error it could pre-empt | Decision |

| workspace `position` 1..1000 | none different: the domain's own error for a position outside 1..n+1 is `arg.invalid` too | kept |
