## Findings

### C51A-R1S-01 (P2): navigation that keeps the frame does not stop playback

Citation: spec/09_playback_export.md:138, navigation stops playback first.
Path: commands/timeline.rs:361-387 marks navigation and writes the frame;
commands/playback.rs:317-320 stops only if frame_changed (or scene changed).
Input: loop playback in a 1..60 range, current frame 1, invoke
 timeline.currentFrame.move {direction: "first", withinRange: true}.
Result: frame stays 1 and playing stays true; subsequent tick advances to 2.
Correct: playing false, frame 1, playback.stopped reason navigation.
This also applies to currentFrame.set of the already-current frame.

### C51A-R1S-02 (P2): equal relative plans accept changed drag content

Citation: E-10; reviews/M5-design-timeline-kernel.md section 5.2 requires
cell sources still hold grabbed drawings and bars commit the previewed result.
Path: timing_gesture.rs:426-451 emits only elementIds/startDelta for a body
move; :783-797 compares commands, not their resolved effects.
Input: selected peg bar start 1 duration 50, zoom 6 (16 px/frame), press
x=160,y=16, release x=192,y=16. Between press/release set its start to 2.
Both hit tests remain BarBody; both plans say startDelta:2 on the same id.
Result: commits start 4, whereas the press-time preview implies start 3.
Correct: cancel timeline.targetChanged. A command equality check alone does
not prove equality of relative-command results.
