# M1-C1.4 round 1 review

**Verdict: block.** Baseline `390600123f6af0fef7a2961375e7f6804a290940`, compared with `90881ba`. **0 P0, 15 P1, 2 P2 findings.** M1 must not merge on this checkpoint. No product code or specification was changed.

The generic command routing, ordinary transaction gate, fallback confirmations, SDK compatibility and local lock protection are substantial working foundations. The failures below are in the new agent boundary and its guarantees: malformed safety options commit changes, malformed confirmation content approves overwrites, a failed atomic batch publishes an activity file, and accepted elicitation breaks idempotent retries. The successful reference-client run does not establish those contracts.

Evidence is in `reviews/evidence/M1-C1.4-r1/`. `register.py`, `probe.py` and `analyse.py` regenerate the register and analysis from their inputs. Fresh CI downloads were compared byte for byte with the interrupted attempt's artifacts before using its release binary. The inherited draft conclusions were not adopted; tests and probes were rerun. The initial debug run had three setup timeouts during concurrent compilation; those are superseded by the cleanly completed release-binary run and the Cargo-wired rerun with a longer setup budget. The filter's independent five-second watchdog is unchanged.

## Findings

The permanent real-process tests are in `tests/adversarial/c14-r1-mcp.py`, invoked by `bins/headless/tests/c14_r1.rs`, so `cargo test` exercises them. They intentionally fail against this handoff. The Python suite runner also executes the static evidence/feature checks; runtime tests are skipped there unless `TT_REVIEW_BINARY` is set. `crates/mcp/tests/c14_r1_limits.rs` adds two executor/script regressions. `crates/mcp/tests/c14_r1_autosave.rs` supplies the protocol-level obligation-5 measurement.

### C14-R1-01 — P1: generic input schemas are published but not enforced

**Location:** `crates/mcp/src/server.rs:383`; `crates/mcp/src/tools.rs:508` and `:548`.

`arguments` that is not an object becomes `{}`. Unknown arguments are silently discarded. More seriously, `dryRun: "true"` becomes `false`, and `expectRev: []` becomes an empty map. A schema-invalid call therefore performs a real edit without the requested safety condition. Command parameter validation cannot catch an invocation option that the wrapper already removed.

**Repro:** create a project, call `run_command` for `doc.object.patch` with a scene target, a metadata change and the string `dryRun: "true"`; it returns `ok` with changes instead of rejecting the input. `set_properties` with `expectRev: []` also succeeds. `get_state` accepts both an array of arguments and an unknown argument despite its closed input schema.

**Requirement:** 11 §7 input schemas, §7.2 dryRun/expectRev, §8 validation; ADR-0013's typed boundary rule. **Tests:** `test_wrong_dry_run_type_does_not_commit`, `test_wrong_expect_rev_type_does_not_commit`, `test_non_object_tool_arguments_are_rejected`, `test_unknown_tool_argument_is_rejected`. Validate the complete wrapper input before conversion, including projections, pagination, option types and unknown fields.

### C14-R1-02 — P1: malformed elicitation content approves an overwrite

**Location:** `crates/mcp/src/server.rs:875`.

An `accept` action whose `/content/confirm` is absent or not a boolean defaults to `true`. This is the opposite of the requested boolean schema's meaning. In the real binary, `{action:"accept",content:{confirm:"false"}}` replaces an existing activity file.

**Repro:** offer the elicitation capability, request `agent.activity.export` onto an existing file with `onExists:"overwrite"`, and reply with the string above. The original bytes disappear. **Requirement:** 11 §6.3 rule 1, §6.2 overwrite policy, §14.8 E7; ADR-0015 decision 3. **Test:** `test_malformed_elicitation_does_not_overwrite`. Schema-invalid, missing and unrecognised answers must not authorize the operation.

### C14-R1-03 — P1: activity export escapes atomic rollback

**Location:** `crates/executor/src/commands/agent.rs:659`.

The handler calls `fsx::write_atomic` directly instead of deferring the write until the enclosing transaction passes its integrity/commit gate. An atomic batch with activity export first and an unknown command second returns `batch.stepFailed` but leaves the exported file on disk. This is a new persistence effect outside the standing staged-effects contract.

**Repro:** `batch {label:"rollback export",steps:[{id:"agent.activity.export",params:{path:<new file>}},{id:"no.such.command",params:{}}]}`. The first step writes even though the batch fails. **Requirement:** 11 §2 executor, §7.3 atomic transaction; ADR-0013 §17; standing C1.3 obligation 7. **Test:** `test_atomic_failure_has_no_activity_export_effect`. Cover both creation and confirmed replacement in the eventual fix; validation failures after the export must preserve the old file too.

### C14-R1-04 — P1: accepted elicitation loses requestId's successful outcome

**Location:** `crates/mcp/src/server.rs:709` (clearing `again.options.request_id`); `crates/executor/src/run.rs:815`.

The first invocation caches `needs_confirmation` under the caller's requestId. Acceptance reruns the command with its token and without that requestId. Retrying the original requestId retrieves the old confirmation and attempts to use its consumed token, returning `confirmation.expired` instead of the successful original result.

**Repro:** export over an existing file with requestId `confirmed-once`, accept elicitation, then repeat the same call and requestId. First response is `ok`; second is `error/confirmation.expired`. **Requirement:** 11 §7.2 idempotent calls; standing requestId rulings (`request.conflict`/`request.unknownId`); obligation 7. **Test:** `test_accepted_elicitation_preserves_request_id_result`. Store the final accepted/declined outcome as the logical call's outcome without executing a duplicate transaction.

### C14-R1-05 — P1: a short valid filter occupies the sole call worker

**Location:** `crates/mcp/src/server.rs:944` (`matches_filter`, recursive `glob`).

`list_commands {filter:"********************************Z"}` is schema-valid and triggers exponential recursive matching. It does not return within the reviewer's five-second watchdog. A following ordinary tool cannot run because the single call worker is still inside this matcher. Inline `ping` remains responsive, which can disguise the loss of the command surface.

**Requirement:** 11 P5, §14.6; ADR-0013 never-block contract; handoff known gap 3. **Test:** `test_filter_has_bounded_runtime`; `protocol-raw.json` includes a successful ping followed by a timed-out queued call. Use bounded matching and extend the watchdog to server-owned work. Today an executor handler that never returns also leaves the document thread occupied: caller timeouts do not restart it or free subsequent work. An MCP-side filter never enters that executor watchdog at all. The M4 restart deferral does not make this new M1 matcher conformant.

### C14-R1-06 — P1: persisted agent policy and limits are not restored

**Location:** `crates/executor/src/commands/agent.rs:343`; `crates/executor/src/session.rs:149`; `crates/executor/src/store.rs:169`.

`agent.policy.defaults.set` writes `agent.policy.defaults` to preferences and changes the in-memory hub, but a new executor constructs a default hub without reading those stored settings. Saved Observe becomes Assist on restart, expanding the next session's scopes; saved job and batch limits also reset.

**Repro:** use an isolated user directory; set Observe, maxBatchSteps=1, maxJobs=1 as the user; stop and restart with that same directory; connect a default agent. Its policy is Assist. **Requirement:** 11 §6.1 presets, §6.5 configurable limits, §15.1 defaults; 01 §1.1 settings load and §11. **Test:** `saved_observe_policy_and_limits_survive_restart` in `crates/mcp/tests/c14_r1_limits.rs`.

### C14-R1-07 — P1: the handed-off percentile evidence cannot be recomputed

**Location:** `crates/executor/tests/c14_measurements.rs:47`, `crates/executor/tests/c14_lock_races.rs:333`, `crates/mcp/tests/never_block.rs`; `reviews/evidence/M1-C1.4/measurements/` and both CI `c14-measurements/` directories.

The files called raw measurements retain summary quantiles, sample counts and selected scalar results, not the observations from which fingerprint, autosave, never-block and liveness percentiles were computed. The fresh CI downloads have the same limitation. Re-running an analyzer cannot reconstruct the submitted p99 or worst value from a p99 field. Receipt hashes prove byte identity, not statistical reproducibility.

**Requirement:** evidence hygiene ruling; obligations 2, 4 and 5, and the explicit recomputation charter. **Test:** `ReleaseFeature.test_percentile_evidence_retains_observations`. `verification.json` preserves each builder artifact and explicitly marks its recomputation limitation. Retain observations and derive summaries from them for both platforms. The reviewer separately retains all 719+719 protocol timings, 10,000 flood response records and ten protocol-autosave samples; those reviewer statistics are recomputable and do not retroactively verify the builder's measurements.

### C14-R1-08 — P2 ticket: obligation 1's save-under-lost-ownership assertion is untested

**Location:** `crates/executor/src/persistence.rs:273`–`finish_save`; `crates/persist/src/lock.rs:109`–`Boundary`; `crates/executor/tests/c14_lock_races.rs:97`.

The seven lock boundaries are exercised, but none suspends a save between its initial ownership check and completion. The finish-time check that must prevent clean/saved-revision/stamp advancement is only code-reviewed; the handoff explicitly acknowledges this. The binding obligation demanded a deterministic assertion, not an option to add one later.

**Requirement:** C1.3 round 3 obligation 1; ADR-0014 §11.5; 10 LOCK-02. **Repro/coverage evidence:** enumerate `Boundary` and the test suspension sites; there is no save boundary. Add a test-only save-boundary hook and deterministically replace/revoke ownership while the save is suspended, then check dirty state, savedRev, stamp, read-only state, recovery and the reported outcome on NTFS and macOS. This is a missing required proof, not a claim that the reviewed finish-time branch currently advances the marker incorrectly. No speculative timing-based failing test was added. **Final-run disposition:** downgraded from P1 to P2 under the completion brief: there is no reproducible runtime test of ownership loss during a suspended save at `3906001`. The existing hooks cannot suspend that interval, and adding a product hook is outside this review-only task. This remains a documented missing-proof ticket, not a demonstrated incorrect save result. No executable regression is claimed for 08; obligation 1 remains partially met.

### C14-R1-09 — P1: SI-047 is an unresolved RO-02 divergence

**Location:** `crates/executor/src/store.rs` (`stamp_of`/folder fingerprint); `crates/executor/tests/c14_measurements.rs:116`; `plan/spec-issues.md:464`.

A same-size external edit with its mtime restored is invisible, including at save. The reviewer changed one byte in the real project's package, restored mtime, and `project.save` returned a successful job instead of `needs_confirmation`. The builder's own control test explicitly asserts the blind spot. SI-047's claim that obligation 4 allows merely recording it misreads the obligation: it requires detection **or a documented spec-owner ruling**.

**Requirement:** 10 §8.5 RO-02; C1.3 obligation 4. **Test:** `test_size_and_mtime_preserving_edit_requires_confirmation`. Obtain the ruling before M1 merge or implement the required detection; this review does not choose a hashing policy or revise the spec.

### C14-R1-10 — P1: suspension hooks are enabled in ordinary product dependencies

**Location:** `crates/executor/Cargo.toml:12`.

The normal `tt-persist` dependency enables `test-hooks`, in addition to its dev-dependency. The normal/build dependency graph of `tt-headless` therefore includes the feature; it is not confined to test builds. `hooks::set` and its global hook slot are compiled into product library code under that feature. This does not claim that a remote client can call the hook setter.

**Requirement:** checkpoint charter's release-build exclusion and engineering diagnostic gating. **Test:** `ReleaseFeature.test_suspension_hooks_are_not_a_normal_dependency_feature`; proof: `release-features.log`. Isolate the feature to test/dev builds and demonstrate the release dependency graph excludes it.

### C14-R1-11 — P1: session limits depend on which wrapper submits the work

**Location:** `crates/mcp/src/script.rs:65`; `crates/mcp/src/server.rs:747` (wrapper-only batch limit), `:789` (job limit).

The server checks maxBatchSteps before its generic batch call, but script mode directly calls `batch_audited` without that check. With maxBatchSteps=1, a two-step script succeeds. maxJobs likewise lives at the individual tool-wrapper boundary rather than the shared command-admission boundary, leaving alternate submission paths to audit.

**Requirement:** 11 §3 same batch structure, §6.5 per-session limits; ADR-0015 decision 8; one command layer. **Test:** `configured_batch_limit_applies_to_batch_script`. The confirmed failing case is maxBatchSteps in script mode; the maxJobs batch-path concern is code-reviewed, not presented as a measured concurrency reproduction. Enforce limits once where every agent submission reaches them, and test generic, typed, batch and script entry points.

### C14-R1-12 — P1: elicitation is not one correct audit record per call

**Location:** `crates/mcp/src/server.rs:694` and `:710`; `crates/executor/src/lib.rs:403`.

An accepted protocol call is audited twice: once as `needs_confirmation`, then again as `ok`. A declined call is initially audited as pending, but the server constructs `confirmation.declined` afterward without updating that record. The fixture covers token fallback, not a logical call completed by elicitation, so its successful byte comparison does not disprove this failure.

**Repro:** accept an overwrite elicitation, then read `app://activity`; two entries name the one export call. **Requirement:** 11 §11; ADR-0015 decision 4's exactly-one promise; obligation 7. **Test:** `test_elicitation_is_one_audit_entry_per_tool_call`. Separate internal confirmation phases from the externally completed call and record its final status exactly once, with an accurate duration.

### C14-R1-13 — P1: malformed UTF-8 terminates the usable input stream

**Location:** `crates/mcp/src/server.rs:210` (`read_line` error treated as EOF).

A byte `0xff` followed by a newline makes `read_line` return an error, which the reader treats as connection closure. The following valid `ping` is never answered. The server already recovers from ordinary malformed JSON; malformed text encoding needs the same bounded frame-level treatment required by this review's robustness contract.

**Requirement:** 11 §4 stdio protocol; malformed-input charter. **Test:** `test_invalid_utf8_frame_does_not_destroy_stream`. Read bounded bytes, classify invalid encoding per frame and retain synchronization with the next newline.

### C14-R1-14 — P1: output failure, backpressure and EOF can pin shutdown

**Location:** `crates/mcp/src/server.rs:127`, `:160`, `:210`, `:285`, `:1187`.

`send` ignores write/flush errors. Closing the client's stdout read end leaves an unusable server session running. EOF while an elicitation is pending joins the worker before signalling closure or waking `ask`, so it can wait the full 300-second elicitation lifetime after the client has gone. A client that never reads output also pins shutdown after finite input and EOF; the probe retained 3,701 buffered output bytes before forced teardown.

The progress-order fix holds `st` while synchronously writing output. A full pipe can therefore hold both state and output locks, preventing inline requests that need state from progressing. I found no demonstrated inverse lock acquisition cycle; the demonstrated problem is blocking I/O under a shared state lock, plus unbounded reader/work queues. Frame size is checked only after `read_line` has allocated the entire line, so maxInlineBytes is not an allocation bound.

**Requirement:** 11 P5, §4 cancellation/lifecycle, §6.5 resource limits, §14.6; charter's closed/non-reading clients. **Tests:** `test_closed_stdout_ends_the_unusable_session`, `test_eof_while_eliciting_ends_the_session`, `test_nonreading_client_with_eof_does_not_pin_the_session`. Use bounded transport queues and a shutdown path that fails pending asks, stops blocked writers and signals closure before joining workers. Do not solve this by claiming cancellation of committed document work.

### C14-R1-15 — P1: exported activity is not safely replayable

**Location:** `crates/executor/src/commands/agent.rs:647`; `crates/executor/src/lib.rs:403`.

Batch export explicitly filters out every record whose command is `batch`, losing successful committed edits. Ordinary records retain only command parameters, so an invocation-level `dryRun:true` is lost; exporting and replaying that entry performs a real edit. Discovery tools recorded under names such as `list_commands` also need a defined replay representation, since those are not registered command IDs.

**Repro:** commit a one-step batch containing metadata `replaySentinel`, export format=batch, and observe the operation is absent. Separately dry-run `set_properties` with `dryRunSentinel`; the exported step contains the patch without dryRun. **Requirement:** 11 §11 replayable batch JSON, §3 script replay; §7.2 no-effect dry runs. **Tests:** `test_activity_batch_export_keeps_committed_batch_operations`, `test_activity_batch_export_does_not_turn_dry_runs_into_edits`. Preserve transaction/options semantics or explicitly omit non-replayable entries with a reported reason.

### C14-R1-16 — P2 ticket: complete the state, event and discovery data contracts

**Location:** `crates/mcp/src/server.rs:814`; `crates/executor/src/run.rs:759`; `crates/mcp/src/docs.rs:153`.

`get_state` augments/projects the command envelope after auditing it, so it differs from `run_command app.state.get`, despite 11 §7.8's identical-data promise. The augmentation is needed to expose policy/scopes under §7.1; bring that data into the shared query contract rather than inventing a second state shape. `include:["jobs"]` also cannot manufacture running jobs absent from the underlying state.

Undo/redo emit `doc.changed` but no `doc.undone`/`doc.redone` producer exists, although 11 §9.2 requires those events. Namespace docs list separate command request examples rather than a worked end-to-end example; describe-command examples do not include executed results as §13 asks. Effective defaults are not uniformly returned as `result.effectiveParams` (§8). Several result schemas are intentionally map-valued and the common envelope schema requires only `status`, so schema validation alone is weak evidence of these fields.

**Tests:** `test_get_state_matches_the_command_envelope`, `test_undo_and_redo_emit_the_declared_events`; `declarations-runtime.json` retains all 32 focused declarations for the documentation/schema comparison. **Owner:** builder, kernel contract follow-up before M2 agent workflows; actual UI/view fields remain M4 and domain summary computations remain their owning milestones. This is one P2 ticket with related observable-data subitems, not a claim that the deferred renderer already works.

### C14-R1-17 — P1: unknown cancellation suppresses a future request

**Location:** `crates/mcp/src/server.rs:325`, `:301`; repeated initialization at `:453`.

Every cancellation requestId is inserted into an unbounded set without checking whether that request exists. Cancelling unknown id 9000 and then sending a new tools/list with id 9000 suppresses the new call entirely. The call gets no response even though it was not in progress when the cancellation arrived. A second initialize also succeeds and changes negotiated protocol/capabilities on an existing session instead of refusing the lifecycle transition.

**Requirement:** 11 §4 MCP lifecycle/cancellation; robustness charter for unknown/completed IDs and reinitialize. **Tests:** `test_unknown_cancellation_does_not_cancel_a_future_request`, `test_second_initialize_is_rejected`. Track live requests, discard unknown/completed cancellations, bound their state, and keep initialization a single transition. Duplicate request IDs were also driven as malformed input: the server returned both responses and remained pingable; that client-side protocol violation did not itself reproduce a crash.
