## 2. Behaviour notes a reviewer will want

- **One list.** Renders, describe, hit test, convert, contact sheet and range all read `render_list::build`; a render is a
  pure read (no revision, history, selection, frame or event change; `c33_render::a_render_is_a_pure_read`).
- **Order** (SI-106): background elements first, foreground last, then world Z (rounded to 1e-6 field), then Timeline
  rows bottom to top. Background elements extend their last exposure to the scene length.
- **Projection.** Planes are parallel to the table plane, so each element's drawing → pixel map is affine; with
  `inspect.frame.describe {detail: "full"}` it is reported as `drawingToImage`.
- **Bitmaps** (SI-105): 10 §4.9 placement; native size `[s, 0, 0, −s, tx, ty]`, `s = 1200 / cameraWidth`. The M1
  fixture's sample bitmap (`[1, 0, 0, 1, −960, 540]`) is reported `outOfFrame`: read by 10 §4.9 it lies above the frame.
- **Spaces** (SI-109): `camera` = fields from the camera centre on the table plane, y up; `image` = pixels at the camera
  size; image/camera points go onto the plane Z = `z` (default 0).
- **Range delivery**: every frame and the companion manifest are staged as hidden `.tt-partial-<token>` siblings and
  renamed at the job's commit point; a cancelled or failed job leaves nothing (`c33_range::a_cancelled_range_publishes_nothing`).
- **Determinism**: the debug in-process executor and the release headless binary render the same bytes (the gate
  checks `gate-index.json`); repeated renders, undo/redo and save → open give the same bytes.
- **Fonts**: goldens contain no text (ADR-0016); contact-sheet labels use built-in digit bitmaps (SI-108).
- **`cargo fmt --all` on Windows** passes all 308 target roots on one command line: about 33 100 characters from this
  builder's 67-character worktree root (over Windows' 32 767, os error 206), about 26 400 from CI's checkout root. CI
  passes; adding many more test targets would need `cargo fmt -p` per package there too.
