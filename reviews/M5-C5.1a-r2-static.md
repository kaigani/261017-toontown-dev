## Findings

### C51A-R2S-01 (P1): finite gesture coordinate overflows before clamp

Citation: E-21 (panic sweep), E-7 (interpreter is product code under usual
rules); host.rs:890 documents arg.invalid for malformed samples.
Path: host.rs:902-905 accepts finite f64 samples without coordinate bounds;
timing_gesture.rs:216 casts to i64, then :217 multiplies/adds unchecked,
before the clamp at :218. plan calls frame_at at :401 for every gesture.
Concrete input: open fixture; timing_replay(User,
{surface:ruler, zoomLevel:0, firstFrame:1, platform:windows},
[{x:1e300,y:12}], false). Keys/string values above denote JSON strings.
The finite cast saturates to i64::MAX; framesPerCell is 10. Multiplication
panics in debug, outside run_step, degrading the executor and losing the
live session. Later requests refuse. In release the multiplication wraps
before clamping, producing frame 1 for a huge positive coordinate.
Correct: reject the sample or saturate before arithmetic; no panic and no
wrapped frame. Static proof; not executed.

### C51A-R2S-02 (P2): changed drag options bypass outcome comparison

Citation: E-23 and E-28, reviews/M5-C5.1-plan.md section 15: the absolute
outcome must still equal the press-time outcome for every gesture kind.
Path: timing_gesture.rs:497-514 emits cell.range.move without options;
:789-791 compares only Documents, and :913-947 compares cell ids/notes,
not preferences. State::of (:95-135) does not capture transfer options.
cell.rs:754-755 resolves the current DragDrop set at commit, then :834-839
removes or clears source cells and :849-853 adjusts destination according
to that set; :886-892 inserts or overwrites.
Concrete input: one unlocked drawing column exposing distinct drawings
[A,B,C] at frames 1,2,3; select only frame 1. Store
 timeline.transferOptions.set {operation: 'dragDrop', options:{exposure:true}}.
Press the selected cell and drag horizontally by two frames within its row.
Before release store the same operation with exposure:false; change nothing
in the document. The snapshot comparison passes exactly (same document).
Release commits [blank,B,A] by clearing frame 1 and overwriting frame 3.
The press-time exposure:true operation would yield [B,A,C] (remove frame 1,
then insert at adjusted frame 2). Correct: cancel with timeline.targetChanged
when the effective transfer rule changes this result, or freeze the press-time
options so that the previewed result is committed. Copy and link use the same
unfrozen set and similarly switch destination insertion to overwrite.
Static proof; no application/test execution.

## Observations

Case 1: read the response and both round 1 reports, checked opposite drawing

Case 2: run_step catches handler plus settle; run_staged and batch_atomic
restore Rollback before announcing containment. Preferences are deferred
Effects, not disk writes in the handler; staged save effects likewise apply
at acceptance. Events stay in the session until the request flush. Request
cache intentionally remembers the failed envelope: identical requestId retry
returns that failure, not a new invocation. Agent confirmation/activity records
are intentionally retained. Checkpoints restore; revision/history commits are
outside this boundary. Memo inserts only completed computations. Cancellation
already set by a caller does not bypass the panic error/rollback path.
The exhaustive Session pattern in panic_tests.rs:153-180 has no rest pattern;
a new top-level field causes a compile error. It does not classify new nested
OpenProject/AgentHub fields automatically.

Observation: jobs.rs:313-326 requests cancellation, not reversal. cancel at
:293-299 can lose to a job commit point, and completed outputs remain. The
panic test uses a cooperative waiting worker, so proves neither cancellation
of a completed worker nor removal of files it published. No concrete existing
product-handler panic after such a publish was established by this reading;
this is a limit of the stated nothing-changed guarantee, not a finding.

Case 3: all Request variants (Invoke, Batch, Open, WaitBegin/Finish,
Snapshot, List, Run, Tick, PlaybackTick, Maintenance) enter the outer match
catch in lib.rs:1099-1149. The degraded branch broadcasts once and breaks;

maintenance::stop releases project/cache rather than taking a fresh snapshot.

cannot run after receiver drop. This reading does not prove reversal of their

MCP server.rs:1943 drops every shell.* event before client delivery, covering

Case 4: challenged these 25 safe sites from r1-sweep-sites.txt (file basenames
and listed line numbers): playback 86,132,135,143,174,224,399,496,508;
timeline 74,75,154,166,231,306,387,388,605,612,623,679,680,692,734,743.

normalization defends 135; remainder bounded by n defends 143; floating

The sweep is a candidate finder, not a proof: no arithmetic or as-cast
pattern, no recursion-depth detection, and its Duration pattern misses general
subtraction. Computed indexing is matched heuristically; chunks/step_by are
matched but not validated. Manual check of the six added files found the
unchecked cast/arithmetic combination in finding 01. No chunks(0), step_by(0)
or Duration/Instant subtraction defect found there; playback now uses checked
or saturating time operations. Hierarchy traversal relies on model validity.

Argument sweep: calls() generates reversed pairs and enum cross products,
but fixed numeric samples are not schema-specific min/max endpoints. It
omits e.g. zoom index 9 and does not recurse all combinations of object
members. A contained panic fails both the internal-error assertion and final
counter assertion (E-29 item 5). timeline.backgroundColour.set gets no
schema-valid call: every string candidate misses its hex colour pattern.
The five event entries currentFrame.changed, playbackRange.changed,
playback.started, playback.stopped, playback.range.changed are not callable
handlers (deliberately). Other action/query schemas have plausible valid
calls; success is not asserted and unknown targets may still refuse later.
The handoff's 1551 calls therefore should not be read as handler coverage.
