## 3. Ruling O-24

1. **The generated inventory.** `scripts/check-availability-inventory.py` runs in the `lint` job (both OSes). It walks
   every implemented, non-agent-only command, collects every refusal code from the handler and the executor functions
   it reaches (call resolution, forwarding helpers, local code choices and limits in its header), drops the codes the
   command's static checks return first, and checks `docs/availability-inventory.md`: 1,090 pairs of 228 commands;
   `parameter` 607, `precheck` 214, `execution` 236, `asks-user` 13, `unreachable` 19, `deferred` 1. It fails on a
   missing pair, a stale row, a `precheck` row whose code the precheck cannot reach or that names no states, an unknown
   class, a `deferred` row without an owner. Two additions to the ruling's classes, for your acceptance: `unreachable`
   (the scanner follows calls by name and over-approximates; each such row names the guard that makes the path
   impossible, for example `resolve_unsaved` returning at once without a project) and `*` rows (a code with the same
   class for every command: `internal`, the work budgets, the agent-only confirmations and permissions; a row of its
   own takes precedence).
2. **Every state pair C4.1 can build is a precheck.** New or extended prechecks by family (all reuse the handler's own
   resolution where one exists):
   - drawing: one precheck from the handler's steps (`draw::Steps`, `target_existing` mirrors `target` without creating)
     for 48 commands; the stroke- and text-addressed commands check the object's drawing;
   - cell: `on_cells` around `cell_target` and the kind checks, plus `exposure.set`, `fill.apply`
     (`cell.frameBeforeSelection`), `cycle.create`, `columnate.apply`, `label.set`, `clipboard.apply`
     (the target column, an elements clipboard's scene), `clipboard.set` (cutting whole elements);
   - element and anim: `on_elements` around `targets` (`element.notFound` with nothing given, selected or current),
     `one_scene`, the toggles, `order.move` and `visibility.set` (Exposure Sheet columns), `hierarchy.select`,
     `element.create` and the camera queries (the current scene), `anim.key.add` / `anim.transform.set`
     (transformable targets);
   - edit: cut, copy and delete run `pick` and `deletion_refusal` (locked drawings and elements, the last camera; now
     the first step of the handler's `delete_with`); paste runs `paste_refusal` (the kind against the context and the
     destination, the current drawing, element or scene, a locked target drawing, a target column without exposure,
     copied elements no longer in the project);
   - others: `render.frame.run` / `render.range.run` (scene, frame, camera), `xsheet.exposures.set` and
     `element.order.set` (scene), `colour.recolour.apply` (scene), `draw.repositionAll.apply` (something to move),
     `colour.fillMapping.set` (a copied mapping), `draw.centreLine.apply` (the handler's own source resolution, now
     the shared `centre_line_sources`).
   Building the second sweep found four more enabled-but-refusing references, fixed the same way: `colour.paint.*`
   with no target, `draw.selection.set` without the parameter its `by` needs, `draw.line.add` without `from` or
   without a previous line to continue, and `cell.clipboard.set` cutting a locked element or the last camera.
3. **The sweep grows with the inventory.** `availability::every_precheck_pair_refuses_and_passes_as_the_table_says`
   reads the table: for each of the 156 `precheck` rows with states it builds the refusing state and the passing

## 4. Selection and clipboard prechecks constant; the bounded reads bounded

- The emptiness checks read the shared list's length (no copy). The facts that need a walk (the kinds and locks of the
  selected elements, a copied element or drawing still in the project, an exposure column's cells, the result of a
  cell or element precheck on a selection) are computed once per value and document revision (`crate::memo`, keyed by
  the selection list's or the clipboard's shared `Arc` with a weak reference, so a key cannot be reused; the clipboard
  is now `Arc<Value>`, replaced whole), during availability only (the pipeline runs prechecks inside transactions and
  computes directly). The last-camera rule scans the scene's elements up to the first camera that stays instead of
  placing the whole tree (the handler gains the same; with 991 cameras one `element.delete` precheck took 214 ms
  before). `deletion_refusal` collects descendants with one walk of the typed scene tree instead of re-reading the
  scene's JSON.
- A chunk ends after 32 references or once it has held the document thread 2 ms, so the first pass after a change
  holds the thread at most the slice plus one precheck; what a selection picks is computed once for cut, copy and
  delete (each adds only its deletion refusals). On the Windows CI runner (about 1.6 times slower than the
  workstation) the first version (5 ms slice, one walk per command) held one request 22 ms in run 43574480533; with
  this change the longest request is 9.5 ms on the workstation.
- `passes_stay_constant_on_a_large_project` now also builds 10,101 selected elements, those elements on the clipboard,
  a current column of 10,000 runs, and a scene with 991 cameras (one current); in each it asserts the steady pass
  (≤ empty + 20 ms, < 50 ms) and that no request of the first pass after the change holds the thread more than 20 ms.
  Measured (debug, workstation): first pass after selecting 10,101 elements 53 ms in all, longest request 9.5 ms, then
  5.6 ms; clipboard 6.9 ms (1.2 ms), then 5.6 ms; long column 9.0 ms (2.9 ms), then 5.5 ms; 991 cameras 7.0 ms
  (1.1 ms), then 5.4 ms; empty project 5.5 ms.

## 5. Skipped heartbeats

- A skipped recovery heartbeat (`heartbeat_owned` now returns whether it ran) leaves it pending, and the next
  maintenance pass (a second later) retries only the recovery heartbeat, without waiting for the next interval.
  `c41_isolated::a_skipped_heartbeat_is_retried_at_the_next_maintenance_pass` holds another engine's recovery write
  inside the ownership lock, shows the heartbeat skipped, releases it and shows the heartbeat written at the next pass.
- `RecoveryInfo::orphaned` keeps its M1 rule (a stale heartbeat, or a process known dead on this host), and the
  release marker (`heartbeatAt` at the epoch, now the named constant `RELEASED`) is stale by that rule. **Not done as
  asked, and why:** "do not report a recovery as orphaned while its owner is a live process of this host" contradicts
  the reviewer's M1 persistence tests, which must pass unchanged:
  `crates/persist/tests/c13_r2_format.rs::recovery_claim_expires_when_actual_child_owner_exits_and_release_restores_metadata`
  has a child process claim a copy whose owner (the test process) is alive with a heartbeat from 2000, and
  `c13_r1_persistence`, `c13_r3_persistence`, `c14_r2_contracts` and `c22_r2_commands` recover such copies of the
  current process. A first version (`4e7897c`, `81e7add`) let liveness decide and failed them (run 43576610853,
  Windows `check`); it is reverted in the final head. What prevents a live engine's copy from being listed by
  skipped heartbeats is the retry at the next pass: its copy goes stale only if the ownership lock is held for the
  whole stale age (five minutes). If you want liveness to decide, it needs a ruling on those M1 tests.
  `restart::a_released_copy_is_offered_and_a_fresh_live_one_is_not` covers the release marker and a fresh copy of
  another live process (spawned by the test).
