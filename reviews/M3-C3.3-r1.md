## Findings

### C33-R1-01 — P1 — sub-microfield ties can reverse Timeline order

**Clause:** 05 §2.8; SI-106's ruling preserves the within-tier rule that depths differing by less than `1e-6` field use Timeline order. The ruling establishes role tiers; it does not replace the tolerance with rounding buckets.

**Reproduction:** `c33_r1_contract::sub_microfield_depth_difference_uses_timeline_order`; run `cargo test -p tt-executor --locked -j 4 --test c33_r1_contract sub_microfield_depth_difference_uses_timeline_order`.

Two overlapping normal elements at Z `0.00000049` and `0.00000051` exchange their reported draw order when those depths are swapped, although the difference is only `2e-8` field and the Timeline is unchanged. `render_list.rs` sorts by `(z * 1e6).round()`, placing them in different buckets. Required: the two-node tie follows Timeline order. Fix the tolerance grouping without introducing a non-transitive epsilon comparator; specify the treatment of longer near-equal chains explicitly. The same list feeds rendering, descriptions and picking.

### C33-R1-02 — P1 — `wait: true` returns only a job ID

**Clause:** 09 §11.1 item 4; adjudication of SI-107.

**Reproduction:** `c33_r1_contract::wait_true_returns_completed_manifest`; run `cargo test -p tt-executor --locked -j 4 --test c33_r1_contract wait_true_returns_completed_manifest`.

A one-frame range with `wait: true` returns `{"jobId":"job-1"}`. The test settles that job before failing, so it leaves no running job. Required: the waiting form returns the final result within its timeout. `render_range_run` explicitly discards `p.wait`; accepting the parameter and requiring a second `job.wait` call is a divergence, not a documented equivalent. Implement the wait on the caller side, retaining request ownership and keeping the document thread free.

### C33-R1-03 — P1 — failed publication leaves a final frame behind

**Clause:** ADR-0020 decision 8; checkpoint charter item 6 and readiness item 9, atomic delivery of frames and companion.

**Reproduction:** `c33_r1_contract::failed_sequence_publication_leaves_no_frames`; run `cargo test -p tt-executor --locked -j 4 --test c33_r1_contract failed_sequence_publication_leaves_no_frames`.

The test places a nonempty directory at the second frame's target, then exports two frames with overwrite policy. The job reaches `failed`, but `shot-1.png` has already been published. No successful companion delivery accompanies it. Required: failed delivery leaves the original destination set intact and publishes no subset. Staging alone does not make the subsequent rename loop atomic. Preflight invalid target kinds and implement a publication transaction with recovery/rollback, including preservation of overwritten originals.

### C33-R1-04 — P1 — known inline limits are checked after rendering work

**Clause:** ADR-0020 decision 8; never-block acceptance, charter item 7. The specific inline error in 09 §11.1 item 3 is `render.inlineTooLarge`; general resource limits use `limit.exceeded`.

**Reproduction:** both tests in `c33_r1_limits`; run `cargo test -p tt-executor --locked -j 4 --test c33_r1_limits`.

With a 100 ms request budget and a 300 ms test-only work-charge delay, an inline `2049 × 1` frame and a two-column sheet of four 2048-pixel cells both return `command.timeout`. Their excessive dimensions are known before scene evaluation. Required: refuse the known dimension limit before evaluation, raster allocation or encoding. The frame path checks in `deliver`; the sheet checks after allocating, rendering and encoding the whole sheet. Move dimension checks ahead of work; retain the encoded-byte check after encoding, with bounded/cancellable encoding work.

### C33-R1-05 — P1 — generic render selection overrides are absent

**Clause:** 11 §7.5, `render_frame` input and the visibility-override requirement.

**Reproduction:** `c33_r1_tools::render_frame_accepts_exclude_override`; run `cargo test -p tt-mcp --locked -j 4 --test c33_r1_tools render_frame_accepts_exclude_override`.

The generic tool rejects `exclude` with `arg.unknown` at `/exclude` (additional property not allowed); its schema also omits `include`. The probe requests exclusion of Bob and compares the answer with a render after independently hiding Bob. A successful status alone is insufficient: the PNG must actually omit the element. Required: an agent can override the default scene visibility through the documented tool without changing the document. Add the parameters, validation and execution semantics with parity tests, or obtain an explicit scope disposition; the existing handoff does not name this omission as a deferral.

### C33-R1-06 — P2 — required render timing metadata is omitted

**Clause:** 11 §7.5, `render_frame` output; adjudication of SI-107.

**Reproduction:** `c33_r1_tools::render_frame_reports_render_ms`; run `cargo test -p tt-mcp --locked -j 4 --test c33_r1_tools render_frame_reports_render_ms`.

The generic result omits `renderMs`. SI-107 gives byte-comparable results as the reason. The cited clause explicitly includes timing, while deterministic PNG bytes do not require volatile timing metadata to be equal. Supply the required measurement and keep volatile metadata outside deterministic comparisons, or obtain a specific specification disposition. This report does not rule that the clause may be removed.

### C33-R1-07 — P2 — an empty render bypasses cancellation

**Clause:** ADR-0020 decision 8; charter item 7, every render observes cancellation inside the rasteriser.

**Reproduction:** `c33_r1_cancel::empty_frame_observes_requested_cancellation`; run `cargo test -p tt-render --locked -j 4 --test c33_r1_cancel`.

A valid empty scene renders successfully even when its cancellation callback always returns an error. The callback is only invoked in the item loop, so an empty list never calls it. Required: cancellation is observed for every render, including empty compositions. Check at entry and around rasterisation boundaries. `flush`/`render_with` also run without callbacks; this probe demonstrates the empty-list hole, not a measured 30-second overrun of those calls.

The same empty-list hole is present at `2184ae8`; this is a newly demonstrated acceptance defect, not a claimed C3.3 regression.

### C33-R1-08 — P2 — process death retains staged sequence files

**Clause:** checkpoint charter item 6, kill/cancel cleanup; ADR-0020's staging and failure-cleanup contract.

**Reproduction:** `c33_r1_crash::killed_sequence_leaves_no_staged_files`; run `cargo test -p tt-executor --locked -j 4 --test c33_r1_crash killed_sequence_leaves_no_staged_files`.

A child test process starts a range with deliberately slow work charges. The parent waits until a `.tt-partial-` file exists, terminates the child, waits for process exit and checks the directory. A hidden staged PNG remains. No final frame is published in this reproduction. Cooperative cancellation cleanup passes elsewhere; it does not establish cleanup after process death. Add durable staging ownership and a tested recovery policy, or explicitly settle the crash-cleanup acceptance contract. Do not describe the kill case as leaving no files.
