## 5. Budgets (plan §6, ruling D-33)

Workstation: Windows 11, NVIDIA GeForce RTX 4090, display 60 Hz, release build, OS input, 30 scene drags per scene and
back end. Scenes: the sample scene (Bob, Ann) and a 1,000-element scene (E-C1's fixture).

**The control (D-33).** On the start screen, before any project, a `requestAnimationFrame` loop doing no work paced
at a median of **17.5 ms** (WebGL2 run) and **17.6 ms** (WebGPU run), p95 18.1-18.2 ms, with the display reporting
60 Hz: the cap is external (a display or compositor limit, likely a driver frame-rate cap at refresh minus 3). C4.2b's
committed receipts on this machine had 16.7 ms; C4.2b's own measurement script, unchanged, gives 17.5 ms today. The
frame budget is therefore assessed as D-33 states: work per frame p95 at most 8 ms (frame callback start to the end of
submission) and at most 1 % of intervals longer than twice the control median. `C4.3-camera-view.md` step 9 asks a
person to repeat the measurement on an uncapped 60 Hz display, where plan §6's 17.5 ms bound applies.

| Quantity | Bound | Sample, WebGL2 | Sample, WebGPU | 1,000 elements, WebGL2 | 1,000 elements, WebGPU |
|---|---|---|---|---|---|
| Work per frame p95, idle | ≤ 8 ms | 0.2 ms | 0.3 ms | 0.6 ms | 0.8 ms |
| Work per frame p95, during drags | ≤ 8 ms | 0.2 ms | 0.2 ms | 1.8 ms | 1.9 ms |
| Intervals > 2 × control median (35 ms), idle / drags | ≤ 1 % | 0 % / 0 % | 0 % / 0 % | 0 % / 0 % | 0 % / 0 % |
| Drag feedback p95 (a sample to the frame drawing the preview) | ≤ 16.7 ms | 0.5 ms | 0.3 ms | 2.1 ms | 2.9 ms |
| Release-to-committed p95 (30 samples) | ≤ 50 ms (sample scene) | 32.9 ms | 33.2 ms | 57.7 ms (recorded) | 58.7 ms (recorded) |

Plan §6 names the 1,000-element scene for the frame time only; its release-to-committed is recorded with its parts
(the kernel's answer and the redraw, about half each).

**A performance defect the measurement found and fixed** (`445d1c26`): the canvas model found each scene entry by a
linear search per entry, twice a frame, and each entry's bucket by another scan; the summary stringified every
resident drawing every frame. On the 1,000-element scene, WebGL2, before the fix: work p95 8.5 ms idle and 10 ms during
drags, drag feedback 9.6 ms, release-to-committed 76 ms. The model now indexes a scene once (key → entry, key →
bucket) and the summary is rebuilt only when its inputs change.

Kernel-side budgets (document-thread holds, the scene answer) are the C4.3a handoff's §5, unchanged. E6's wait: the
agent's change during a held press is answered after the release (OS mode), and fails `ui.busy` before the release when
the press is held past `waitForUserMs` (10 s).
