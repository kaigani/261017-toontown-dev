**R58: preemption, explained with citations (the row itself is fixed above).** 11 P5 ("Never block") says: "No
command invoked by an agent may open a modal dialog, file picker, colour picker or confirmation box, or wait for user
input." 11 §14.6 is the corresponding modal-UI test. Neither requires preempting a handler that loops because of a
defect. In-process preemption is not possible for safe Rust threads, which cannot be terminated safely. What the
executor guarantees is now proven by a test: no caller waits past the budget, the outcome is indeterminate (SI-020),
and service resumes when the handler returns. Recovery from a handler that never returns is a host restart of the
engine process (C1.4 owns the headless and MCP process lifecycle). On modal interception: the kernel crates link no
UI (`scripts/check-headless-deps.py`, a CI gate), so no handler can open a modal. GUI modal interception belongs to
the desktop shell in M4 C4.1 and the parity gate in C4.3.
