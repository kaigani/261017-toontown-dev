### C11-R3-01 — opaque text received mouth-track range validation — **fixed** (`386f032`)

- **Diff side.** `diff_json` emits a mouth range operation only for the declared field: a `SoundPlacement` own view's
  `/mouthTrack/mouths` (`change.rs:479`), next to the existing `Element` `/exposure` rule. The same suffix inside

`range_operations_apply_only_to_declared_fields`.

### C11-R3-02 — the stateless `invert` corrupted numeric object members — **fixed by removal** (`386f032`)

`change::invert(patch)` and its path-shift helper are removed from the public API. `apply_with_inverse` and
`invert_against` (`change.rs:523,531`) are the only inversion. The module docs, ADR-0010 §4, ADR-0011 §7, the
handoff and traceability now say so, and every caller is updated (edits above and the builder-owned callers). The
reviewer's test passes: inverting against the pre-state knows `/a` is an object, so nothing shifts.

### C11-R3-03 — zero-count exposure runs deleted a frame — **fixed** (`386f032`)

- **Patch boundary.** `expand_runs` (`change.rs:379`) refuses any run with count 0. A range replace whose `value`
  or `oldValue` contains one is therefore `arg.invalid`, raised before anything is mutated. Totals stay bounded, and
  window consistency (`to`, current content) was already checked.
- **Model check.** `Element` reports every zero-count run as `runCount` (`validate.rs:838`), even for values built
  through the public `Deserialize`.

Tests: M3 `zero_length_exposure_runs_are_invalid_range_payloads`, the unit tests

### C11-R5-01 — the frame limit is now a structural post-condition — **fixed** (`a448459`)

Per the ruling, the bound no longer depends on operation type or path shape. It holds at two layers; the per-operation
pre-checks from R4 remain as fast paths.

1. **Patch application** — `change.rs:593`, `:605`. `apply_with_inverse` (and therefore `apply` and
   `invert_against`) applies the patch to a staged copy. After **every** operation, `check_frame_fields` re-checks
   every declared frame-bearing field (an element's `exposure`, a placement's `mouthTrack/mouths`; never inside
   `meta`/`ext`) that the operation can have changed, at both its `path` and its `from`:
   - every field on the way to the written location: a count written at `/exposure/0/1`, an append at `/exposure/-`;
   - the written location itself: a whole mouth string, a `copy`/`move` destination;
   - every field inside the written value (`scan_frame_fields`, `:628`): a whole placement or element replaced.

   Each field must satisfy its invariants (`check_frame_field`, `:662`): runs with counts ≥ 1 and at most 100 000
   frames (arithmetic, before any expansion), and mouth strings of at most 100 000 letters. The first failure
   returns that operation's `doc.limitExceeded` (or `arg.invalid` for a malformed run) with `details.pointer` and
   `details.maxFrames`. The input is never modified, and a refused batch returns no value, so earlier operations of
   the batch are not applied either. The four reviewer shapes pass: whole mouth `add`/`replace`, a nested count, an
   append batch with a preceding marker write, and `copy`/`move` from opaque `meta` into `exposure`.
2. **Document commit** — `document/mod.rs:425`, `Document::with_patched_entry(key, patch)`. The patch is applied to
   a copy of the entry's JSON (layer 1). The staged entry is revalidated through the full input path
   (`object::from_json`: schema, canonical form, object rules including exposure totals); its ID must be unchanged
   (ID-01). The entry then replaces the old one in a copy-on-write clone, and the clone's complete `issues()` —
   every integrity rule and every 10 §5 limit, including scene length — must contain no error. Only then are the
   staged snapshot and the patch's concrete inverse returned. On any failure the errors are returned with
   `details.pointer`; `self` is immutable and stays byte-identical. ADR-0010 §4 records that the C1.2 executor
   commits through this primitive.

**Property test** (`crates/model/tests/staged_commit.rs`):
- `random_patches_never_commit_a_document_with_integrity_errors` (proptest, 256 cases): random RFC 6902 sequences —
  add with overwrite or `-` append, remove, replace, move, copy, test — on a random entry of a seeded sample
  document. The value pool includes 100 000 / 100 001 frames, 50 001 counts, zero, 2^31, oversized runs, 100 001-
  letter mouth strings, invalid names, wrong types and nulls. It asserts that the original document stays
  byte-identical, that a committed document has no error-severity issue, that every refusal carries
  `details.pointer`, and that the returned inverse is concrete.
- `staged_commit_sweep_commits_and_refuses` (1 500 fixed seeds): both outcomes occur; this run committed 92 and
  refused 1 408 (`gates/staged-commit-nocapture.log`).
- `document_level_frame_writes_are_refused_and_leave_the_document_unchanged`: a 100 001-frame exposure count and a
  100 001-letter mouth string, written through `with_patched_entry` on real fixture elements, give
  `doc.limitExceeded` at the operation's pointer, and the document is unchanged.
