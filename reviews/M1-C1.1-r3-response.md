## P1

### C11-R3-01 — opaque text received mouth-track range validation — **fixed** (`386f032`)

- **Diff side.** `diff_json` emits a mouth range operation only for the declared field: a `SoundPlacement` own view's
  `/mouthTrack/mouths` (`change.rs:479`), next to the existing `Element` `/exposure` rule. The same suffix inside
  `meta`/`ext` is diffed as an ordinary value.
- **Apply side.** A range operation on any other path, or under a `meta`/`ext` token, is refused with
  `arg.invalid` (`change.rs:615`). So a range-shaped patch can never range-validate opaque data either: opaque values
  are replaced wholesale.

Tests: M3 `opaque_mouth_track_lookalikes_are_ordinary_json_changes` (both namespaces) and the unit test
`range_operations_apply_only_to_declared_fields`.

### C11-R3-02 — the stateless `invert` corrupted numeric object members — **fixed by removal** (`386f032`)

`change::invert(patch)` and its path-shift helper are removed from the public API. `apply_with_inverse` and
`invert_against` (`change.rs:523,531`) are the only inversion. The module docs, ADR-0010 §4, ADR-0011 §7, the
handoff and traceability now say so, and every caller is updated (edits above and the builder-owned callers). The
reviewer's test passes: inverting against the pre-state knows `/a` is an object, so nothing shifts.

### C11-R3-03 — zero-count exposure runs deleted a frame — **fixed** (`386f032`)

- **Patch boundary.** `expand_runs` (`change.rs:379`) refuses any run with count 0. A range replace whose `value`
  or `oldValue` contains one is therefore `arg.invalid`, raised before anything is mutated. Totals stay bounded, and
  window consistency (`to`, current content) was already checked.
- **Model check.** `Element` reports every zero-count run as `runCount` (`validate.rs:838`), even for values built
  through the public `Deserialize`.

Tests: M3 `zero_length_exposure_runs_are_invalid_range_payloads`, the unit tests
`range_replace_checks_types_window_and_bounds` (three zero-run payloads) and
`zero_count_exposure_runs_are_reported_by_the_model_check`.

## P2 (fixed now; no tickets)

### C11-R3-04 — property discovery narrowed the value domain — **fixed** (`386f032`)

`property_schema` (`schema.rs:649`) still collects every candidate down the path, but only the property's own
declaration contributes validation keywords, kept whole: it follows only its `$ref` chain, so `anyOf`/`oneOf` stay
intact. Later candidates from kind rules contribute annotations only.

Results: `/colourId` accepts an ID and `null`; `/tip` accepts all four tips; nested conditional paths and `$ref`
annotations still resolve. Tests: M3 `property_schema_preserves_nullable_value_domains`,
`property_schema_preserves_every_enum_alternative`, and `property_schema_nested_conditionals_and_ref_annotations_survive`
(still green).

### C11-R3-05 — mixed double/wide-integer alternatives rejected — **fixed** (`386f032`)

`wireJson.ts`: an `anyOf`/`oneOf` alternative applies when the container validates as parsed, or after coercion
under that alternative alone. Coercing under one alternative converts its large doubles and keeps its wide
integers. Both T3 cases pass: the three-branch `mixed` value and the generated Element inside `anyOf(Element,
null)` with `rev = 9007199254740997n`, which is not rounded. The reviewer's 10 MB validation measured 1 075 ms
(`measurements/ts-10mb-drawing-node.log`).

### C11-R3-06 — anonymous declarations without `x-since` — **fixed** (`386f032`)

The annotation pass (`schema.rs:356`) now descends into anonymous declarations: object alternatives of
`anyOf`/`oneOf`/`allOf`, inline objects under properties, items, prefix items and map values. It does not descend
into `if`/`then`/`else` predicates. `DynamicParam`'s `value` and `keyframes` carry `x-since: "1.0"`. Test: M3
`anonymous_variant_property_declarations_have_since`.
