## C01-R4-01 — constant folding after the chunk scan — **fixed**

I measured first. In Vite 8 / rolldown, `renderChunk` still sees `String.fromCharCode(...)`, while `generateBundle`
already sees the minified code `window.__TAURI_INTERNALS__.invoke("app_info")`. The final-output check therefore sits
in `generateBundle`, so it also covers `write: false` builds such as the reviewer's regression. It is repeated on disk.

- **Dedicated chunk.** `vite.config.ts` uses `build.rolldownOptions.output.manualChunks`. Vite 8's name for
  `rollupOptions`; `rollupOptions` is a deprecated alias. `transportChunk()` (in `boundary/vite-plugin.ts`) places
  `src/ipc/tauriTransport.ts` and every `@tauri-apps/*` module in `tauri-transport`. The real app emits
  `assets/tauri-transport-<hash>.js` (1.36 kB).
- **`generateBundle` (after minification).**
  - No other chunk's `moduleIds` contains the transport or a Tauri module, and the transport chunk contains nothing
    else.
  - The transport chunk exports at most as many bindings as `src/ipc/index.ts` imports from it (parsed from
    `index.ts`). Rolldown has no `importedBindings`, so the comparison uses the export count against the import
    list.
  - Only a chunk containing `src/ipc/index.ts` may import it (`imports` / `dynamicImports`).
  - Every other emitted `.js`/`.mjs`/`.cjs`/`.html` output is scanned.
- **`writeBundle`.** The same checks run on the files as written to disk.
- **Shared scanner** (`boundary/scan.mjs`, plain JS so Node runs it directly). Matching is case-insensitive for
  `__tauri` and `@tauri-apps`. It decodes `\xHH`, `\uHHHH`, `\u{…}`, `&#NN;` and `&#xHH;` escapes, decodes
  `String.fromCharCode` / `fromCodePoint` sequences and `atob('…')` literals, and folds constant string expressions in
  the AST: `+`, templates with constant parts, `.concat`, `[…].join`, `fromCharCode`, `String.raw` and `atob`. The
  transform-time, `renderChunk` and final-output checks all use it. `renderChunk` attribution counts AST hits, which
  add up across modules.
- **Standalone check.** `boundary/check-dist.mjs` scans `dist/` on disk and requires exactly one `tauri-transport`
  chunk. The `build` script is now `vite build --config vite.config.ts && node boundary/check-dist.mjs dist`, so the
  check runs even if plugins or `manualChunks` are disabled; it then fails because no transport chunk exists, or
  because Tauri code shows up in another file. CI runs it through `pnpm --dir desktop build`, and Tauri's
  `beforeBuildCommand` runs it too.
- **Lint.** For shipped `src/` code, with the transport and tests exempt:
  - `no-restricted-properties` forbids `String.fromCharCode`, `String.fromCodePoint`, `String.raw`, and `atob` on
    `window` / `globalThis` / `self`;
  - `no-restricted-globals` forbids `atob`;
  - `no-restricted-syntax` forbids `.concat` on string or template literals, `.join` on array literals, and templates
    with literal-only pieces.
- **Tests.**
  - The reviewer's R4 regression passes.
  - My five cases (`String.fromCharCode`, `'__TAU'.concat('RI_INTERNALS__')`, `[..].join('')`, `${'_'}` template
    pieces, `atob('X19UQVVSSV9JTlRFUk5BTFNfXw==')`) each fail real-config builds both unminified and with default
    minification.
  - Direct `generateBundle` cases cover a minified invoke in another chunk, escaped, char-code and HTML forms, Tauri
    modules outside the chunk, foreign modules inside it, extra exports, and a wrong importer.
  - `check-dist.mjs` runs on synthetic `dist` folders: clean, five disguised forms, an HTML mention, and a missing
    transport chunk.
  - 16 new lint cases with positive controls.
- **ADR-0001** now describes three layers: lint on source, the bundler on the resolved module graph, and a
  final-output scan of the written files. It states that names assembled from run-time data stay out of scope by
  design.

## C01-R4-02 — worker builds lack the boundary — **fixed by prohibition; ticketed to M1 C1.2**

For shipped `src/` code, lint forbids:
- `no-restricted-globals`: `Worker`, `SharedWorker`, `Worklet`;
- `no-restricted-properties`: `navigator.serviceWorker`, and `Worker` / `SharedWorker` / `Worklet` on `window`,
  `globalThis` and `self`;
- `no-restricted-syntax`: `new URL(…, import.meta.url)` and `?worker` / `?sharedworker` import specifiers.

A build case shows that a worker-importing entry fails lint. Its Tauri-importing worker also fails the real build,
because the final-output scan sees the emitted worker asset. The traceability row says "wire the IPC boundary into
worker compilation before lifting the worker ban" (M1 C1.2). ADR-0001 and the handoff (gap 13) record it.
