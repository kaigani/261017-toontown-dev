## C01-R2-01 — IPC boundary: bundleable extensions, outside modules, inline disables, raw transport — **fixed** (`5c0938f`)

**Bundler** (new; `desktop/boundary/vite-plugin.ts`, registered first in `desktop/vite.config.ts` and therefore
active in dev, build and Vitest). Checks are made on **resolved module ids**, not on how a specifier is spelled:
- a module inside an `@tauri-apps` package may be imported only by `src/ipc/tauriTransport.ts` (or by the package
  itself);
- `src/ipc/tauriTransport.ts` may be imported only by `src/ipc/index.ts`;
- every application module (anything outside `node_modules`) must be `desktop/index.html` or live under
  `desktop/src/`. In Vitest mode only, test code may also load `<repo>/tests/`, which the round-1 bridge
  `src/test/adversarial.test.ts` needs, and `desktop/boundary/`;
- application modules other than the transport may not mention `__TAURI*` or `@tauri-apps` in their source at all.
  The boundary's own definition files and the two sample-holding boundary tests are exempt; they are test or tooling
  code that is never bundled into the app.

The dev server re-resolves already-resolved modules by URL with `index.html` as a placeholder importer. That is not
an import edge, so only the location rule applies to it; this is documented in the plugin. Verified against a running
`vite` dev server: the app's modules are served (200). Probes that import Tauri directly or import the raw transport
are refused with HTTP 500 and the boundary message.

**Linter** (`desktop/boundary/eslint.js`, built into `eslint.config.js`):
- the boundary rules now apply to every `ts,tsx,mts,cts,js,jsx,mjs,cjs` file in the desktop package (JS files are
  linted without type information);
- `@eslint-community/eslint-plugin-eslint-comments` `no-restricted-disable` (all boundary rules and the plugin's own
  rules) plus `no-unlimited-disable`. I verified that the plugin's reports survive a blanket `/* eslint-disable */`.
  `reportUnusedDisableDirectives: error` is also on;
- `no-restricted-imports` forbids `**/tauriTransport` everywhere except `src/ipc/index.ts`, and a selector forbids
  dynamic `import()` of it;
- modules under `src/` may not import outside `src/`. These are per-directory-depth `no-restricted-syntax` selectors
  (depth ≤ 12, enforced by a test), plus rules that make relative specifiers canonical and ban absolute, drive,
  `file:`/`data:`/`http(s):`/`virtual:` and backslash specifiers. Test files may additionally reach `<repo>/tests/` and
  `desktop/boundary/`. I chose `no-restricted-syntax` over a custom rule so violations carry the rule ids that the
  reviewer's tests and the eslint-comments restriction already cover.

## C01-R2-02 — schema validation used inherited properties — **fixed** (`65fec88`)

Implemented as ruled (`desktop/src/ipc/schema.ts`):
- `plainDataViolations` accepts only plain JSON data. Prototypes must be `Object.prototype` or `null` for objects and
  `Array.prototype` for arrays. Properties must be own, enumerable, string-keyed data properties: no accessors,
  functions, symbols, sparse arrays, cycles, non-finite numbers or nesting beyond 64 levels.
- `violations` uses own-property semantics only. Required fields use `Object.hasOwn(value, k)`, iteration uses
  `Object.keys`, and values and schema properties are read through own-property descriptors after
  `Object.hasOwn(schema.properties, k)`. There is no `in` and no bare indexing on schema maps; the schema kind is
  tested with `Object.hasOwn` too.
- `certify` checks that the original is plain, takes a `structuredClone` snapshot, validates the snapshot, and returns
  it. `createHostApi` uses `certify` for every response and event, so callers receive exactly what was validated, and
  later mutation of the transport's object cannot change it.

**Own tests**, as requested:
- prototype-named keys (`__proto__`, `constructor`, `prototype`, `toString`, `hasOwnProperty`, `valueOf`) at the top
  level, nested, and inside array items;
- a schema that legitimately declares `constructor` still validates it as an own key;
- `Object.create(...)` values at the top level and nested, and `Object.create(...)` transports through the real
  `ping()` and menu-event paths;
- class instances, accessors, non-enumerable properties, functions, symbols, holes, cycles, excessive depth and an
  own `toJSON`;
- snapshot isolation.

Cost: the 1 MiB ping round trip on WebView2 rose from p50 ≈ 21 ms to ≈ 26 ms (the clone of a 1 MiB string).
Bulk data moves to binary IPC in C0.3 anyway.

## C01-R2-03 — malformed SPDX operands behind an allowed OR — **fixed** (`43575b6`)

Every operand is validated against SPDX 2.3 Annex D before evaluation:
- licence operands must be an SPDX License List identifier (current or deprecated, matched case-insensitively as
  Annex D requires) with at most one trailing `+`, or `[DocumentRef-idstring:]LicenseRef-idstring`;
- `WITH` needs an SPDX licence identifier on its left and an SPDX exception identifier on its right.

Anything else (`+`, `:`, `and`, `Unknown-License`, `LicenseRef-`, `MIT++`, unknown exceptions) makes the whole
expression invalid, so it fails closed. The list data comes from `spdx-license-ids` (CC0-1.0) and `spdx-exceptions`
(CC-BY-3.0), added as root **dev** dependencies used only by this build-time gate and never shipped. ADR-0003 rule 1
documents this. There are 9 evaluator tests, including 13 malformed-operand cases and positive `LicenseRef`,
`DocumentRef`, case-insensitive and deprecated-id cases. The reviewer's 4 tests and the round-1 `licensing` and
`allowlist` cases pass.
