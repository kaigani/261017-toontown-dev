## 2. Model: placeholders and schemas

None of the 63 rows carries a generated placeholder (checked: `declared.json` `placeholders` is empty for all of them).
The model's element/cell/channel shapes (`entities/element.rs`, `scene.rs`, `drawing.rs`, `channel.rs`) are already
the 10 §4.5–§4.12 shapes; C3.1 uses them unchanged except:

- the 04 §17.5 read model (`element.get`) and the 04 §17.2 exposure-sheet object are new result types with derived
  fields (`parentId`, `depth`, `timelineIndex`, `xsheetIndex`, `cloneGroupId`, `cloneIds`, `hiddenByParent`,
  `effectiveMarkerColour`, `drawingCount`, `media`);
- `importOptions` (SI-008) and `channels` stay as they are: channels are C3.2's, kept migratable (versioned manifest,
  `meta`/`ext` opaque, D-5 per-axis position recorded as an SI in C3.2 with the spec's default).

## 3. Decisions and spec issues (SI-085 onward, spec's recommended default each time)

- **SI-085** static light table: 04 §15.3/§18 #13 say "saved with the scene" and "not undoable", but 10 §4.3 has no
  scene field. Default: per-scene list in the project's session UI state (10 §6.12), outside revisions and undo.
- **SI-086** hierarchy cycle code: 04 §17.6 `element.hierarchyCycle` vs 10 §5 `anim.hierarchyCycle`. `element.*`
  commands use the 04 code; `anim.*` (C3.2) the 10 code.
- **SI-087** batch count: 04 §3.2 `element.countOutOfRange` vs 10 §5 `element.tooMany`. 04's code (the command's owner).
- **SI-088** media and sound cells: 13.20 lists media/sound cell edits, but media sequences (10 §4.15) and sound
  placements (§4.14) are M8's model. C3.1 refuses them with `cell.notApplicable` + `details.owner` (media → M8 C8.3,
  sound → M8 C8.1); `element.mediaLength.set` likewise refuses with `command.notImplemented`-style owner details until
  media import exists. (Declared deferral, not silent narrowing.)
- **SI-089** `element.timing.set {keyframes: "scale"}` rounding: scaled key frames are rounded half-up to integers; a
  collision refuses with `anim.keyExists` (10 §5) and changes nothing.
- 04 §18 defaults adopted as written: Exposure-Sheet focus → column order (agents always pass `order`), `Name_1`
  suffixes, 64-char names, delete-on-cells explicit `shift`, annotations excluded from render by default (C3.3),
  keyframes beyond a shortened duration removed, blank runs keep their length, light table not undoable, unreferenced
  drawing storage purged on save.

## 4. Engineering rules applied

- One command layer: every handler stages JSON patches through `Cx::patch_entries`/`patch_objects`; the integrity
  gate and canonicalisation (10 §4.7) run on commit. No direct model mutation.
- Every action is exactly one undo step; `ui`/`toggle`-no/queries never touch history; explicit targets never change
  the selection or current frame (17.1-2); `cell.noTarget` when neither target nor selection exists.
- **Work budgets**: a `TIMING_WORK_BUDGET` account (units ≈ one cell/frame touched) charged by every exposure
  operation (expanding runs, shifting, cycles, columnate, window reads/writes, clipboard), every hierarchy walk and
  every bank scan; refusal `limit.exceeded` before the watchdog. Result-size rule: a result scene longer than
  100 000 frames refuses with `doc.limitExceeded` (10 §5) before anything is staged. The budget's calibration
  (worst-case corpus: 100 000-frame columns × 1 000 elements, 999-cycle, 10 000-drawing banks) is retained as raw
  observations under `reviews/evidence/M3-C3.1/`.
- No `unwrap`/`expect`/`panic`/`unsafe`/`#[allow]` in product code; the allow inventory (98 lints / 40 files) does not
  grow (`scripts/check-product-allows.py`).

## 5. Tests and evidence

- `crates/anim/tests/c31_exposure.rs`: unit tests per 04 §13 example (`1 1 2 2 3 3` → ones, cycles ×3, columnate
  none/continuous/forward-backward incl. n = 1 and total-frames truncation) and seeded proptest properties
  (runs ⇄ frames round trip and canonical form; insert/remove inverse; set-length preserves the drawing sequence and
  blank-run lengths; fill never shifts; cycle length = k × range).
- `crates/executor/tests/c31_elements.rs`, `c31_cells.rs`, `c31_xsheet.rs`, `c31_bank.rs`: every command's success
  path, every 04 §17.6 error code it can raise, one-step undo/redo, `dryRun`, `expectRev`, explicit target vs
  selection, events, save/open round trip (byte-identical resave), determinism (same sequence twice → identical
  documents and IDs-modulo-generation).
- Handoff obligations exercised in C3.1:
  - **7** (timeline ops on the common staged/cancellation path): one-step undo, request-owned queued and running
    cancellation through the test spin hook, no late mutation after timeout, guarded replay after an intervening edit.
  - **5** (selection/zone IDs): drawing selection and zone IDs unchanged across unrelated element edits (rename,
    reorder, reparent, exposure edits); only an own-layer change prunes the selection.
  - **6** (owner resolution/stretch fills): `element.duplicate`, `element.clone`, `cell.drawing.duplicate`,
    `element.drawing.duplicate` preserve C24-T1 owner resolution and mirrored stretch fills, through undo/redo and
    save/open; owner deletion and opaque `meta`/`ext` namespaces preserved.
  - **1**: `tool.symmetry.set` stays session-only — regression test that none of the C3.1 commands persist it.
  - **3/2/4** belong to C3.2/C3.3 (transforms, render lists, bitmap/image elements in renders); C3.1 provides the
    exposure/hierarchy/visibility/order read model they consume.
- The reviewer-owned suites (`tests/adversarial/`, `c0*_r*`, `c1*_r*`, `c2*_r*`, `desktop/src/test/`) run unchanged.
