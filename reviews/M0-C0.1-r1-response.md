## C01-R1-01 — licence expression parsing; allow-list drift — **fixed** (`cf3df37`)

`scripts/check-npm-licenses.mjs` now uses a real recursive-descent SPDX parser (OR < AND < WITH, nested parentheses,
`X+`, whole-expression `WITH` exceptions; lower-case operators, unbalanced or non-SPDX strings fail closed) with 8
`node --test` cases, wired into `pnpm test`. There is now **one** allow-list: the JS gate reads `deny.toml`
`[licenses] allow`, and 0BSD was added there per the orchestrator's ruling. ADR-0003 rule 1 lists exactly the
approved set (user's list + Unicode-3.0 + 0BSD). **Test amendment:** the reviewer's `allowlist` case asserted
`satisfies("0BSD") === false`, which contradicts that ruling. I replaced it with a stricter drift check: JS list =
`deny.toml` list = ADR-0003 set, and licences outside it (Unlicense, CC0, MIT-0, BlueOak, LGPL, GPL, AGPL) are rejected.
The `licensing` case is unchanged and passes. The same commit removes the tracked `__pycache__` bytecode the
review noted.

## C01-R1-02 — dynamic imports bypass the IPC boundary — **fixed** (`3ce0475`)

The boundary rules now live in `desktop/eslint.ipc-boundary.js` and apply to `src/**`. They cover static, type-only
and re-export imports; `import()` of `@tauri-apps/*`, and **any** non-literal `import()` specifier; `require()`;
`import.meta.glob` (including through a cast) and any `import.meta` use other than `.env`/`.url`/`.hot`; string and
template literals naming `@tauri-apps`; `__TAURI*` as identifiers, properties, computed literals and globals; and
`eval`/`new Function`. Only `src/ipc/tauriTransport.ts` is exempt. `src/ipc/boundary.lint.test.ts` lints 18 bypass
samples (all must fail) and 3 positive cases (the transport file, ordinary host-API code including a literal
`import('../ipc')`, and the whole real source tree) through the project's real ESLint config. The reviewer's
`imports` regression passes. Limit, documented in the rules file: deliberate obfuscation built at run time (e.g.
computed global names) cannot be detected statically, which is why non-literal `import()`, `eval` and `new Function`
are banned outright.

## C01-R1-03 — validators accept values that violate their types — **fixed** (`42f2d74`)

`src/ipc/schema.ts` is a small JSON-Schema-subset validator (`type`, `properties`, `required`,
`additionalProperties`, `enum`, `pattern`, `minimum`/`maximum`, `items`, `anyOf`). `src/ipc/wireSchemas.ts` declares
every host→front-end value in that form: all `EngineInfo` fields required, `runMode` enum, version patterns; u64 fields
are integers in [0, 2^53−1]; objects reject arrays and unknown keys; menu `params` must be a plain object and
`command` must match the command-id grammar. Because the descriptors are JSON Schema, M1 can substitute
registry-generated schemas without changing callers. There are 8 new schema tests, and all 6 C01-R1-03 regressions pass.

## C01-R1-04 — EngineInfo is not a superset of app.info.get — **fixed by renaming the claim; `app.info.get` deferred to C1.4** (`405e55b`)

Per the orchestrator's ruling, `locale`/`languages[]` are not faked. The doc comments on `EngineInfo`
(`crates/engine/src/lib.rs`), the `app_info` IPC command (`desktop/src-tauri/src/ipc.rs`) and the TS type
(`desktop/src/ipc/types.ts`), plus the handoff, now say it is **internal bootstrap info** (the 11 §4 server-info
fields plus platform/arch), not the `app.info.get` query. The full query (01 §12.1, with locale and languages) is
ticketed to M1 C1.4 in `plan/traceability.csv`. **Test amendment:** the reviewer's test was literally the
"superset" claim (named `…_is_a_superset_of_app_info_get`, asserting locale/languages). As the ruling directs, it now
pins the renamed claim instead: `c01_r1_04_engine_info_is_bootstrap_info_not_app_info_get` asserts every 11 §4
field is present and that none of the three sources still calls EngineInfo a superset of `app.info.get`. The IPC
command keeps the name `app_info` because the reviewer's permanent front-end tests call `appInfo()`.

## C01-R1-07 — benchmark does not check the echoed payload — **fixed** (`7c6ac42`)

`pingOnce` now verifies seq, payload length and an FNV-1a checksum after the clock stops, so verification is not
timed. The sent-side checksum is computed once per burst. A mismatch throws, and `runIpcBench` turns that into
`ok: false`. Three new tests cover dropped, truncated and same-length corrupted echoes; the C01-R1-07 regression
passes. A re-run on real WebView2 still reports `ok: true` (p50 0.70 / 0.70 / 1.80 / 20.7 ms for 0 B / 1 KiB /
64 KiB / 1 MiB).
