## 1. Changed in rounds 2 and 3 and the closure checks

- **Attached-mode transport (C41-R2-01 to -03, C41-R3-01, -02; rulings O-15, O-20).** Admission designed first in
  [M4-design-http-admission.md](M4-design-http-admission.md) and implemented to it; the thread bound is `3 + C + K·S`
  with K = 20 per session, every transient session thread capped with a typed refusal (`concurrentJobWaits`,
  `serverWork`, `maxJobs`), measured in OS threads with idle sessions and with one session at every cap at once
  (exactly 20 above the baseline).
- **Preferences (C41-R2-04, -05; O-16, O-17).** An object supplied for an object-typed preference merges over the
  present value and is validated whole; a stored object falls back per member.
- **Freshness (C41-R2-06, -07, C41-R3-04, -06, -21).** One quorum invariant ([float design note](M4-design-floating-windows.md)
  §3a); `inspect.ui.tree` answers `renderedSeq`, declared required and nullable (SI-121).
- **Availability (C41-R2-08, C41-R3-03, C41-R5-01, -02; rulings O-10, O-23, O-24).** Designed first in
  [M4-design-availability.md](M4-design-availability.md): each command with a state refusal declares a precheck, which
  the pipeline runs immediately before the handler and availability runs after the static checks, on the session lent
  to read-only contexts, in chunks of at most 32 references or 2 ms. Completeness is mechanical:
  `docs/availability-inventory.md` classifies every refusal code of every GUI command's handler (1,090 pairs), the
  `lint` job checks it (`scripts/check-availability-inventory.py`), and a second sweep builds a refusing and a passing
  state for each of the 156 `precheck` rows with states; facts about large selections, the clipboard and exposure
  columns are read once per value.
- **Keys (C41-R2-09).** A key bound to a disabled command answers `command.disabled` with the reason; an agent's key
  under the user's dialog or text field answers `ui.modalOpen` or `ui.busy`.
- **Floats (C41-R2-10).** One reconciliation at a time from the current kernel state; every path that shows floats
  respects the global flag, which is announced.
- **Recovery ownership (O-18; closure).** Fence check and write are one step with respect to release; orphaned owner
  records are scavenged at start; the heartbeat on the document thread never waits for the ownership lock, a skipped
  one is retried at the next maintenance pass (the M1 orphan rule stays: a stale heartbeat or a dead process; see the
  r5 response §5 for the conflict with "never orphaned while its owner lives").
- **Agent server (C41-R3-05; O-21).** `--mcp-http` forces the server on at start-up only; the discovery file is
  rewritten in place at a fixed 4 KiB.
- **Messages (C41-R2-20, C41-R3-20; O-11, O-19).** The help checker collects codes at constructor sites whatever their
  shape and through constants; 125/125 with help.
- **Documentation (C41-R2-22, C41-R1-22; closure item 4).** ADR-0021 decisions 5 and 9 and ADR-0022 decisions 2 and 5
  record the contracts above; the manual scripts give exact steps.

## 6. Residual risks and human-only checks

- **Availability.** Where a refusal depends on the kinds of the selected objects (a group to ungroup, a line to
  convert, a text to break apart) the precheck checks that the selection holds objects and the handler refuses the
  rest: P3 under ruling O-24 item 4, recorded row by row. The scanner follows calls by name inside the executor and not
  into the model or persistence crates (its header); the two dry-run sweeps are the dynamic check. The first pass after
  a large selection changes reads it once (53 ms in all for 10,101 elements on the workstation's debug build, no
  request over 10 ms); the passes after it cost what an empty project costs.
- **A request in flight across a real engine restart** has no end-to-end test (a product build has no hanging
  command); covered by pure functions and units and the recovery fence (O-18). A person checks it on a real stuck
  engine.
- **Splitter drags** use the interim same-place `window.panel.move` (O-3a); SI-118 stays open with the spec owner.
- **Message help coverage** of codes built at run time is outside the text scanner (O-19; M11 C11.1).
- **Known timing flakes (rule: rerun once with `gh run rerun --failed`, always report):** `c14_r1_autosave`;
  `c23_r2_timeout`; and the two M3 macOS margins identified in the r5 response §1,
  `c34_r1_contract::sequential_wait_timeout_retains_job_identity` and
  `c34_round4::a_queued_batch_wait_is_bounded_from_its_callers_enqueue_not_from_its_start` (owner M11 C11.1, for a
  measured, margin-safe rewrite). On the workstation, under a full parallel workspace run, `c23_r4_closure` and
  `c23_round3` (200 ms and 800 ms watchdog budgets) also failed once; alone they pass (twice), and CI passed them. No
  rerun was needed in run 43578841139.
- **Human-only checks** (the scripts of `reviews/manual/M4/`, eleven): tablet input (pressure and tilt with a physical
