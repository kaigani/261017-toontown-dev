## A2: PASS against normative contract

The requested cancellation probe conflicts with ADR-0020 decision 8 rule 4: ?Request cancellation never cancels a job.? It explicitly names command.timeout, reason cancelled, jobId and continued execution. The screenshot note 1a moves the capture into that job/wait path and says cancellation of the job stops rasterisation. Thus request cancellation returning promptly while its named job continues is documented behavior. The provisional C42A-R2-01 in the earlier A2 commit is withdrawn after reading this explicit exception; it is not a finding and its proposed cancellation assertion is not a builder obligation. The final test cancelled_capture_jobs_finish_after_request_returns checks the normative continuation behavior. Ten cancelled calls return command.timeout / cancelled with jobId, and all ten jobs reach success. Process thread count returns to baseline after completion. There is no demonstrated permanent thread leak. If screenshot request cancellation is intended to cancel the capture too, a ruling must distinguish it from decision 8 rule 4.

Mapping extreme grid passes at pan (1e7,-1e7), zoom 1/16 and 64, angles 0/90/180/270/37.5/-123.45. Three independent affine points exercise composition and conversion agreement. Absolute tolerance 2e-5 admits over 100 ulps for the largest 6.4e8 intermediate terms (~1.2e-7 ulp), including cancellation and inverse scaling. Invalid zoom states refuse; round-one tests also cover malformed/oversized pan and both valid endpoints. C42A-R1-01 closed.

Capture snapshot test passes: one ordered batch submits a full capture then adds geometry before collecting the job; captured PNG is byte-identical to the pre-edit PNG, while the subsequent capture differs. This uses the documented batch pending-job path to make ordering deterministic. Existing round-one PNG/crop/known-pixel and synchronous drawing-render equality tests pass, preserving the common rasteriser result; there is no archived pre-fix PNG hash to independently compare across historical executables.

Six concurrent captures reached six unfinished jobs and all returned identical PNGs. The amended note specifies a job thread per capture, no numeric concurrency cap or typed admission refusal. jobs.rs submit immediately spawns one thread per job; it neither queues behind a worker pool nor imposes a cap. This is an observation, not a new requirement. A 2048-square capture on a 40ms budget returned job.waitTimeout in 43.66ms; the job remains addressable and was awaited. The caller budget is bounded; cancellation does not stop raster work (documented job exception above). Ten cancelled captures: OS process threads 7 before, 7 after all jobs finished; no persistent thread leak observed, but cancellation does not release the work early. C42A-R1-02 is closed against the amended contract.

Final new executor suite: six pass, no failures. All workers/jobs finish before assertions or handback.
