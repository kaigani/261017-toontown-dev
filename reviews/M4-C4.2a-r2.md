## A2: FAIL

C42A-R2-01: cancelling the request returns command.timeout with reason cancelled, but does not cancel its capture. Ten consecutive requests all left jobs that completed with state succeeded. A cancelled agent capture continues consuming CPU and memory; concurrent abandoned requests can keep rasterising. Permanent test cancelled_capture_stops_its_job fails at a2b5101, and must pass with its body unchanged. The probe switches to cancelled only after the capture job exists. All ten jobs are awaited before the final assertion. Source: lib.rs waited/wait_envelope delegates to wait_sliced, which returns on cancellation without cancelling the screenshot job; Capture::run only sees JobProgress.cancelled. Requirement: ADR-0020 decision 8 explicitly requires caller cancellation inside the rasteriser, including queries; amended screenshot note 1a says job cancellation stops between slices. This is a capture query, not an explicitly submitted long-running render job whose wait may be abandoned independently.

Mapping extreme grid passes at pan (1e7,-1e7), zoom 1/16 and 64, angles 0/90/180/270/37.5/-123.45. Three independent affine points exercise composition and conversion agreement. Absolute tolerance 2e-5 admits over 100 ulps for the largest 6.4e8 intermediate terms (~1.2e-7 ulp), including cancellation and inverse scaling. Invalid zoom states refuse; round-one tests also cover malformed/oversized pan and both valid endpoints. C42A-R1-01 closed.

Capture snapshot test passes: one ordered batch submits a full capture then adds geometry before collecting the job; captured PNG is byte-identical to the pre-edit PNG, while the subsequent capture differs. This uses the documented batch pending-job path to make ordering deterministic. Existing round-one PNG/crop/known-pixel and synchronous drawing-render equality tests pass, preserving the common rasteriser result; there is no archived pre-fix PNG hash to independently compare across historical executables.

Six concurrent captures reached six unfinished jobs and all returned identical PNGs. The amended note specifies a job thread per capture, no numeric concurrency cap or typed admission refusal. jobs.rs submit immediately spawns one thread per job; it neither queues behind a worker pool nor imposes a cap. This is an observation, not a new requirement. A 2048-square capture on a 40ms budget returned job.waitTimeout in 43.66ms; the job remains addressable and was awaited. The caller budget is bounded; cancellation does not stop raster work (finding above). Ten cancelled captures: OS process threads 7 before, 7 after all jobs finished; no persistent thread leak observed, but cancellation does not release the work early. C42A-R1-02 remains open through its cancellation regression.

New executor suite: five pass, one fails (the new cancellation finding). All workers/jobs finish before assertions or handback.
