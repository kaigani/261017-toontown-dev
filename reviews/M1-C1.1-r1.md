## P1 findings

### C11-R1-01 — Duplicate split entries are overwritten before integrity validation

**Location:** `crates/model/src/document/mod.rs:157`–the map construction in `assemble`; `from_parts` at line 148. **Spec:** 10 ID-01, §5 IDs, §7.2 duplicate-ID reporting/repair.

Append an element with the same ID but a different name to `DocumentParts.elements`, then call `Document::from_parts`. It succeeds: `collect()` into a `BTreeMap` replaces the first entry before the index or `issues()` can discover the duplicate. This loses original content and also prevents C1.3 from implementing the named repair on top of this assembly path. Check duplicates before collapsing the input into keyed maps and retain enough information for the load report.

**Test:** M `duplicate_entry_ids_must_not_silently_overwrite_content` (line 32).

### C11-R1-02 — The public “validated document” constructor accepts schema-invalid entities

**Location:** `crates/model/src/document/mod.rs:148,405`; `crates/model/src/validate.rs:127`; public derived `Deserialize` in entity definitions. **Spec:** 10 §4.2, §5, §2.8; plan §3.2 validated model boundary.

Deserialize a project through its public `serde::Deserialize` implementation with a pen's `minSize=101`, `maxSize=102`, then pass it to `Document::from_parts`. The supposedly checked document is accepted because `Check` verifies relationships/finite numbers but not all schema ranges. The precondition that callers have validated parts is not represented by the public types, and the constructor says local rules are checked again. Close this alternate construction path or perform equivalent complete validation at assembly; this is distinct from the explicitly unchecked load/repair `assemble` API.

**Test:** M `document_assembly_rechecks_schema_ranges_after_public_deserialize` (line 76). No public `&mut` escape from an existing `Document` was found.

### C11-R1-03 — Opaque user data is interpreted as model objects, rewritten, and omitted from diffs

**Location:** `crates/model/src/object.rs:28`; `crates/model/src/change.rs:327,486`. **Spec:** 10 §2.2 `meta` never interpreted / unknown `ext` preserved verbatim; §2.6 patches describe changes.

An extension value `{"type":"element","name":"  e\u0301  "}` is rewritten to `{"type":"element","name":"é"}` by recursive name normalization. Separately, changing `meta.items` from `[{"id":"a","type":"pen"}]` to `[{"id":"a","type":"scene"}]` produces an empty patch: the generic array diff treats arbitrary two-key objects as child stubs and compares IDs only. Applying the generated patch does not produce the target JSON. Traverse declared containment slots, and keep opaque values outside model-specific normalization and collection logic.

**Tests:** M `extension_and_metadata_names_are_never_interpreted` (line 41), `diff_does_not_treat_opaque_arrays_as_child_collections`.

### C11-R1-04 — Patch inversion and elided-value application lose data

**Location:** `crates/model/src/change.rs:499,537,618`. **Spec:** 10 §2.6 every change set invertible, elided values require rereading; RFC 6902 add/move semantics; RFC 6901 root pointer.

Add `/a=2` over `{a:1}`, with `oldValue:1`: applying its inverse yields `{}`. Move `/a` onto existing `/b` in `{a:1,b:2}`, with the overwritten old value supplied: inverse restores only `{a:1}`. An elided replace with no value writes `null` instead of refusing an incomplete patch. The helper also rejects RFC 6902 root add even though its public API claims RFC 6902 behavior; this last case is an API completeness issue, not a claim that `doc.object.patch` must allow replacing the document root. Preserve overwritten destinations in inverses and reject elided/incomplete operations before application.

**Tests:** M `add_over_existing_object_property_is_invertible`, `move_over_existing_object_property_is_invertible`, `elided_patch_must_not_write_null`, `root_add_is_rfc6902_replacement`.

### C11-R1-05 — Required entity semantics are missing from the validated input boundary

**Locations:** `crates/model/src/validate.rs:149,215,257,316,449,611`; `crates/model/src/document/mod.rs:781`. These are model invariants, not the deferred rendering/import algorithms.

### C11-R1-06 — Canonical JSON depends on map insertion history

**Location:** `crates/model/src/canonical.rs:171`; `crates/model/src/entities/scene.rs:54`; ADR-0011 decision 3. **Spec:** 10 JSON-02/05, AG-06.

Two scenes with equal `paletteStyles` mappings in reversed insertion order produce different canonical bytes. The same problem occurs for equal metadata maps. The native scene-map example avoids any dispute about preserving opaque extension text. ADR-0011 calls the stored map order “part of the document state,” but spec 10 §4.3 defines a map, not an ordered collection. Establish a deterministic map ordering instead of redefining equality to mean construction history.

**Tests:** M `canonical_scene_map_order_is_not_document_state`, `canonical_map_order_does_not_depend_on_insertion_order`.

### C11-R1-07 — The Rust text path silently rounds opaque large integers

**Location:** `crates/engine/src/wire.rs:69`; `Cargo.toml:36` (`preserve_order`, `float_roundtrip`, no `arbitrary_precision`). **Spec:** 10 §2.2 extension preservation; ADR-0012 lossless text-transport claim.

Rust → JSON text after receiving `{"com.example.tool":{"n":-18446744073709551615}}` returns `-18446744073709552000`. The TypeScript parser preserves that integer as `bigint`, but Rust's generic `Value` falls back to f64 outside its i64/u64 integer representation. Typed i64/u64 boundaries, including u64::MAX and 2^53+1, pass; this finding concerns opaque JSON, not a demand for arbitrary precision in fields explicitly defined as IEEE-754 doubles. Preserve the opaque number or reject it explicitly instead of silently changing it.

**Test:** W `opaque_json_integer_outside_u64_is_not_silently_rounded` (line 6).

### C11-R1-08 — Conditional schemas break valid large-double IPC readback

**Location:** `desktop/src/ipc/wireJson.ts:233` (`childSchemas`), generated Element `allOf`/`if`/`then`. **Spec:** 10 §1.1 finite double, §2.8 one schema; 11 §14.2 conformance; ADR-0012.

Set the fixture drop-shadow transform origin's x to `1e20`. The canonical integer-looking token becomes `bigint`; coercion never follows the applicable `then` branch to discover its double schema, and `certifyWireText(..., Element)` returns undefined. This rejects a valid model value instead of delivering it unchanged. Evaluate the relevant conditional branch when selecting child coercion schemas.

**Test:** T `coerces doubles declared inside generated conditional effect schemas`.

### C11-R1-09 — Accepted model objects can exceed the canonical writer's depth limit

**Location:** `crates/model/src/object.rs:28,52`; `crates/model/src/canonical.rs:171`; `crates/model/src/lib.rs` depth constant. **Spec:** 10 JSON-05, §2.2 preservation; C1.1 validated-snapshot/depth readiness guarantee.

Place a 140-level object inside pen metadata. `object::from_json::<Pen>` succeeds, although canonical writing has a 128-level limit; normalization simply stops descending at that limit instead of rejecting input. The TypeScript boundary uses a separate 64-level limit. Define and enforce compatible acceptance/rendering limits at the model input boundary so accepted state can always be saved and transported (with paging where appropriate).

**Test:** M `metadata_depth_is_enforced_at_model_input`.

### C11-R1-16 — Generic serialization converts non-finite numbers to null

**Location:** `crates/model/src/canonical.rs:182`; `crates/engine/src/wire.rs:60`. **Spec:** 10 §1.1, JSON-03; ADR-0011/0012 explicitly claim rejection.

`canonical::to_canonical(&f64::NAN)` and `to_wire_json(&f64::NAN)` succeed with JSON null. They first call `serde_json::to_value`, which has already discarded the invalid numeric value before the custom writer can reject it. `format_f64(NaN)` itself correctly errors, so the existing formatter tests miss the public serialization path. Check finite numbers during serialization or use a serializer that rejects them.

**Tests:** M `canonical_serialization_rejects_nonfinite_values`; W `typed_nonfinite_wire_numbers_are_rejected_not_changed_to_null`.

### C11-R1-20 — Cloning the production ID generator duplicates IDs

**Location:** `crates/model/src/id.rs:193` (`#[derive(Clone)]`), `next` at line 216 and its same-millisecond counter branch. **Spec:** 10 ID-01/02, D1.

Generate one system ID, clone that generator, then request one Element ID from each instance in the same millisecond. Both increment the copied previous random counter and return the exact same ID; the newly obtained OS randomness is discarded in that branch. One million sequential IDs from one generator pass, which does not protect callers of the public Clone API. Remove the unsafe duplication of generator state, share the monotonic state, or reseed cloned production generators without sacrificing uniqueness.

**Test:** M `cloning_a_system_generator_cannot_duplicate_ids`; exact duplicate values are preserved in `final-model-regressions.log`.

## P2 findings

### C11-R1-10 — Valid deep library objects have unusable canonical paths

**Location:** `crates/model/src/path.rs:26`; `crates/model/src/document/paths.rs:113`. **Spec:** 10 §2.4, AG-03; 11 §5.1.

A valid library with 34 nested folders assembles successfully and returns a canonical path for its leaf. Resolving that path fails because the parser caps paths at 32 segments. ### C11-R1-11 — Schemas reject own stubs and accept wrong child-stub types

**Location:** `crates/model/src/schema.rs:274,305`; `crates/model/src/document/render.rs` depth-zero rendering. **Spec:** 10 §2.2 “Both forms validate against the schema,” §2.8 every get result validates.

The project's depth-zero result fails the Project schema. Conversely, a scene stub in the project's palette slot passes it because child wrappers use the unrestricted shared `Stub` definition. The builder's depth test explicitly skips validating depth zero; root unknown-field tests do not catch wrong-type child stubs. Model the root alternatives and constrain each slot's stub type.

**Tests:** M `depth_zero_results_validate_against_their_object_schema`, `child_stub_type_must_agree_with_the_containment_slot`.

### C11-R1-12 — The specified swatch id input alias is rejected

**Location:** `crates/model/src/object.rs:52`; `crates/model/src/entities/palette.rs` Swatch `colourId` alias; generated Swatch required fields. **Spec:** 10 §2.2.

Replace a valid swatch's `colourId` with `id`. Although serde has the alias, validation runs first and rejects missing `colourId`/unknown `id`. Normalize the alias before validation or express the accepted input alternative in the schema without allowing contradictory IDs.

**Test:** M `swatch_id_alias_is_accepted_by_the_validated_input_path` (line 61).

### C11-R1-13 — Required schema annotations are missing

**Location:** `crates/model/src/schema.rs:274,313`; entity `type` definitions. **Spec:** 10 §2.7 persisted read-only class, §2.8 property-introduction `x-since`.

`Pen.properties.minSize` lacks `x-since`, and envelope `type` lacks `readOnly:true`. Adding `x-since` only to object schemas does not identify the version introducing each property. This matters when C1.2 discovers writable fields and C1.3 handles format evolution; a const type currently limits actual changes, so this is P2 metadata incompleteness.

**Test:** M `schema_properties_have_format_introduction_annotations`.

### C11-R1-14 — Frame/int schemas use unsigned 32-bit bounds

**Location:** `crates/model/src/entities/channel.rs` Key frame; `crates/model/src/schema.rs:99`. **Spec:** 10 §1.1 `int` signed 32-bit unless otherwise stated; §4.12.

A scalar key at frame `2147483648` passes validated Channel input. Schemars bounds mirror Rust u32 instead of the specified positive subset of signed int. Revisions and byte sizes have separately justified wide transport; that does not justify every frame/count field taking unsigned-32 range.

**Test:** M `int_means_signed_32_bit_unless_spec_states_otherwise`.

### C11-R1-15 — NFC normalization applies only to recognized names

**Location:** `crates/model/src/object.rs:28`. **Spec:** 10 §1.1 string input normalization.

An element note containing decomposed `e\u0301` is persisted in that form. Names are normalized but ordinary persisted text is not. Apply the string rule to declared text fields while honoring the separate opaque-data requirements in finding 03.

**Test:** M `nfc_applies_to_persisted_strings_beyond_names` (line 52).

### C11-R1-17 — Rust and TypeScript disagree on hostile JSON acceptance

**Location:** `desktop/src/ipc/wireJson.ts:48`; `crates/engine/src/wire.rs:69`. **Spec:** 10 §1.1 UTF-8 strings; 11 §14.2 cross-boundary conformance; ADR-0012 strict parser.

TypeScript certifies an ErrorInfo whose message is the unpaired surrogate `\ud800`, which Rust rejects. In the other direction Rust accepts nested duplicate keys in arbitrary request values, silently keeping the last, while the TS parser rejects them. Establish a single strict text-domain policy; this is a compatibility/data-validation defect, not a demonstrated privilege bypass.

**Tests:** T `rejects unpaired surrogate strings that the Rust UTF-8 reader cannot accept`; W `nested_duplicate_keys_are_rejected_in_requests`. Invalid UTF-8 and trailing-byte controls are rejected by Rust.

### C11-R1-18 — The old validator pin has a reproduced used-keyword correctness gap

**Location:** `Cargo.toml:41`; `crates/model/src/schema.rs:659`; ADR-0011 decision 5 and consequences. **Spec:** 10 §2.8; orchestrator MIT-0 ruling.

`jsonschema` 0.18.3 rejects integer `9007199254740995` under `{type:"integer",multipleOf:5}` even though it is exactly divisible. `multipleOf` is a keyword emitted for transition size; today's 5–100 transition range avoids the failing magnitude, so this is P2 rather than a claimed exploitable transition bug. The [upstream changelog](https://github.com/Stranger6667/jsonschema/blob/master/CHANGELOG.md) records an integer-to-f64 `multipleOf` correction in 0.46.9; a fetched copy is preserved in evidence. With MIT-0 accepted, retaining 0.18.3 is no longer justified by the stated license constraint. Upgrade to a maintained version after running this regression, both validators' conformance tests and performance checks; do not assume every later fix applies to 0.18.3 without a reproduction. No `unevaluated*`/`$dynamicRef` requirement was invented, and the u64 maximum-bound control passed.

**Test:** M `jsonschema_integer_multiple_of_does_not_round_before_testing`.

### C11-R1-19 — Property-schema lookup cannot traverse real nested fields

**Location:** `crates/model/src/schema.rs:581,603`. **Spec:** 10 §10.2 `doc.schema.get {property}`; §2.8 discoverable shared schema.

`property_schema(Element, "/channels/rotation/keys/0/value")` returns None even though this is a real persisted field. The resolver looks through only one non-null alternative, so child stub/full unions stop it; its array traversal also ignores `prefixItems`. Fix the already-published model helper before C1.3 exposes it through the doc command.

**Test:** M `property_schema_resolves_nested_child_and_tuple_fields`; primary reproduced failure is the child union. The tuple assertion is retained to cover the subsequent traversal once that first failure is fixed.

Accepted named handoff deferrals are revision stamping/transaction queue/undo/redo/expectRev/events (C1.2), touched-object diff cost (C1.2), derived result computation and special-reference context (C1.2), persistence repairs/migrations/newer-minor policy/new-project assembly (C1.3), and effect descriptors/remaining particle defaults (M7).
