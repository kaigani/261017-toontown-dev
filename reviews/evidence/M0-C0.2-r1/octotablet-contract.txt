README.md (octotablet 0.1.0, Cargo.lock checksum)
1: # Device-agnostic Cross-platform Tablet Library 🐙✨
2:
3: Cross-platform high-level tablet/pad/stylus library, reporting connected hardware features and providing easy-to-use
4: event-based access to user input.
5:
6: ## Platform Support
7: | Platform                             |      Support |
8: |--------------------------------------|-------------:|
9: | Linux/Wayland (`tablet_unstable_v2`) | Complete[^1] |
10: | Windows (Ink `RealTimeStylus`)       | Complete[^2] |
11: | Linux/X11 (`xinput`)                 |     I'll try |
12: | MacOS                                |  Help needed |
13: | IOS                                  |  Help needed |
14: | Android                              |  Help needed |
15: | Windows (`Winuser.h` Pointer API)    |  Not planned |
16: | Windows (`wintab`, proprietary)      |  Not planned |
17:
18: [^1]: Compositor conformance to this protocol is hit or miss and some features may not work (to be expected from an unstable protocol I guess!)
19: [^2]: Only Tablets and Tools - Pads and associated hardware are not exposed by the Ink API. The status of pad hardware on windows is dire, often reported as emulated mouse/keyboard events!
20:
21: ## Device Support
22: So far, tested on:
23: * *Wacom Cintiq 16* \[DTK-1660\]
24: * *Wacom Intuos (S)* \[CTL-4100\]
25: * *Wacom Intuos Pro small* \[PTH-451\]
26: * *Wacom Pro Pen 2*
27: * *Wacom Pro Pen 2k*
28: * *XP-Pen Deco-01*
29:
30: ## Documenting
31: By default, documentation contains the current platform's capabilities only (ie, building docs on windows will omit everything wayland-related).
32: Run `rustdoc` with the `docsrs` cfg set in order to generate documentation for all platforms regardless of host platform:
33: ```bash
34: RUSTFLAGS="--cfg docsrs" cargo doc
35: ```
36: This is still restricted by enabled features.
