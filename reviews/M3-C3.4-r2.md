## Findings

### C34-R2-01 — P1 — an already-cancelled invocation can commit

Clause: request-owned cancellation, ADR-0020 decision 8 and the round-2 commit/cancel charter. Permanent reproduction: `c34_r2_cancellation::already_cancelled_mutation_never_commits`. Pass a probe that is already true to `invoke_served_until` for `element.create` on a fresh fixture. Required: no change or undo/event publication after cancellation has won. Observed: success with a complete change envelope and an undo record; document revision advances. `call_until` enqueues without checking the probe and checks it only following a receive timeout; a fast reply bypasses it entirely. Fix direction: establish cancellation acceptance before enqueue and arbitrate cancellation against commit, preserving remembered outcomes and retries. Polling alone is not an acceptance boundary. The test fails by design at the reviewed head.

The additional permanent `short_waited_batch_cannot_commit_with_an_already_cancelled_probe` fails too: its one-frame waited job and subsequent mutation completed in **6.74 ms**, within one polling slice, with revision 2 instead of 1. A completed job therefore does not cure the missed initial cancellation. The 100-trial commit/retry matrix otherwise preserves one undo record, one `doc.changed` emission, identical remembered envelopes and no repeat execution.

### C34-R2-02 — P2 — direct job.wait ignores caller cancellation

Clause: request cancellation must stop waiting while leaving the job independently owned; ADR-0020 decision 8 and the explicitly requested direct-job.wait check. Permanent reproduction: `c34_r2_cancellation::direct_job_wait_observes_cancellation_probe`. Start a range job, then call direct `job.wait` with a true probe and 500 ms timeout. Required: `command.timeout`, `details.reason = cancelled`, retained jobId, early return. Observed: the probe is never called; the ordinary job result or wait timeout wins. The early return in `invoke_served_until` calls `job_wait(inv)` without the probe; both its begin/finish calls and `jobs.wait` omit it. Fix direction: make the direct and attached-retry wait paths cancellation-aware, preserving requestId ownership and settlement. This is bounded waiting, not job cancellation. The test settles the job before asserting and fails by design.

### C34-R2-03 — P2 — ADR's unqualified document-thread claim contradicts the accepted batch path

Clause: ADR-0020 decision 8, "the caller's request (never the document thread) waits"; round-2 never-block charter. Permanent failing reproduction: `tests/adversarial/c34-r2-contract-text.py`. The direct caller wait is off-thread, but `document_thread` dispatches `Request::Batch` to `Core::batch`; `finish_batched_job` and the batch `job.wait` step call `wait_sliced` synchronously there. Required: accurately qualify the already accepted bounded sequential-batch exception, or implement off-thread batch continuations if the universal claim is intended. Observed: unqualified wording remains. Fix direction: document the exception and the measured remaining-budget bound. This finding does not reopen the accepted design or demand a different job-cancellation contract.

### C34-R2-04 - P2 - intentional queued cancellation falsely reports a stopped document thread

Clause: 11 error taxonomy reserves `internal` for unexpected failure; round-2 queued-request/error-shape charter. Permanent failing reproduction: `c34_r2_measurements::discarded_queued_cancellation_does_not_report_a_dead_document_thread`. Queue a mutation with a true cancellation probe behind a waited batch, let the worker discard the marked request, settle the export and issue `doc.state.get`. Required: an honest cancellation outcome and a usable document thread. Observed: the request is safely skipped, but its envelope is `internal` with message `the document thread has stopped`; the subsequent state query succeeds. The cancelled request drops its reply sender at dequeue, and `call_until` maps that disconnection to `stopped()` without considering the marked token. Fix direction: return an explicit cancellation refusal for discarded requests (or distinguish a marked request's reply disconnection from actual worker death), aligned with SI-111; do not cancel its job or conceal a real worker failure. The test cleans up and verifies session usability before its final failing assertion.

## Source-reviewed boundaries and residual risks

The confirmation retry path calls `begin_effect` before re-invocation. That method shares the cancellation lock, marks the request committed and makes subsequent cancellation ignored, so a cancellation which wins before that point prevents acting on the answer. The second call now receives the same probe. This provides a defined arbitration point, rather than proving every scheduler interleaving.

Cancellation tokens increment an AtomicU64; the pending-token BTreeSet is cleared by `forget` both when a queued cancelled request is discarded and when a running request completes. There is no public table-size observable. The intended storage bound is outstanding marked calls, rather than historical calls; practical token reuse would require u64 wrap. A late-mark/worker-forget interleaving remains a source-review risk: marking after the worker's forget has no subsequent cleanup. Finite stress alone cannot prove the set bounded under every interleaving. No unsupported memory-size claim is made.

`wait_sliced` checks the probe only after a timed-out slice. A terminal record returned in the same slice wins and is returned normally. This gives a consistent completed-job outcome but does not establish which side won at every external cancellation instant. Builder tests' five-second threshold is loose relative to the polling interval; it is not evidence of a universal twenty-millisecond response bound. Scheduler delay, work-account safe points and the extra batch poll must be included when interpreting measurements.

The requestId cache separately caps entries at 100,000 and bytes at 64 MiB (with its existing last-entry rule). Its bounded cache does not itself bound the cancellation-token set. Memory/table telemetry for that private set is unavailable to these public-API probes; no universal memory-bound claim is made. Exact same-instant commit/cancel scheduling remains a finite-test limitation. The short-job reproduction and confirmation cancellation cover concrete boundaries without claiming exhaustive enumeration.
