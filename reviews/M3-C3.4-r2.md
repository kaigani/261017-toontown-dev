Clause: request-owned cancellation, ADR-0020 decision 8 and the round-2 commit/cancel charter. Permanent reproduction: `c34_r2_cancellation::already_cancelled_mutation_never_commits`. Pass a probe that is already true to `invoke_served_until` for `element.create` on a fresh fixture. Required: no change or undo/event publication after cancellation has won. Observed: success with a complete change envelope and an undo record; document revision advances. `call_until` enqueues without checking the probe and checks it only following a receive timeout; a fast reply bypasses it entirely. ### C34-R2-02 — P2 — direct job.wait ignores caller cancellation

Clause: request cancellation must stop waiting while leaving the job independently owned; ADR-0020 decision 8 and the explicitly requested direct-job.wait check. Permanent reproduction: `c34_r2_cancellation::direct_job_wait_observes_cancellation_probe`. Start a range job, then call direct `job.wait` with a true probe and 500 ms timeout. Required: `command.timeout`, `details.reason = cancelled`, retained jobId, early return. Observed: the probe is never called; the ordinary job result or wait timeout wins. The early return in `invoke_served_until` calls `job_wait(inv)` without the probe; both its begin/finish calls and `jobs.wait` omit it. Fix direction: make the direct and attached-retry wait paths cancellation-aware, preserving requestId ownership and settlement. This is bounded waiting, not job cancellation. The test settles the job before asserting and fails by design.

## Source-reviewed boundaries and residual risks

The confirmation retry path calls `begin_effect` before re-invocation. That method shares the cancellation lock, marks the request committed and makes subsequent cancellation ignored, so a cancellation which wins before that point prevents acting on the answer. The second call now receives the same probe. This provides a defined arbitration point, rather than proving every scheduler interleaving.

Cancellation tokens increment an AtomicU64; the pending-token BTreeSet is cleared by `forget` both when a queued cancelled request is discarded and when a running request completes. There is no public table-size observable. The intended storage bound is outstanding marked calls, rather than historical calls; practical token reuse would require u64 wrap. A late-mark/worker-forget interleaving remains a source-review risk: marking after the worker's forget has no subsequent cleanup. Finite stress alone cannot prove the set bounded under every interleaving. No unsupported memory-size claim is made.

`wait_sliced` checks the probe only after a timed-out slice. A terminal record returned in the same slice wins and is returned normally. This gives a consistent completed-job outcome but does not establish which side won at every external cancellation instant. Builder tests' five-second threshold is loose relative to the polling interval; it is not evidence of a universal twenty-millisecond response bound. Scheduler delay, work-account safe points and the extra batch poll must be included when interpreting measurements.
