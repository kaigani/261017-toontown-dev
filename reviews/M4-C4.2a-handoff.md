# M4 C4.2a handoff: the headless kernel side of the interactive Drawing view

Builder: Claude Opus 5.5. Branch `m4-desktop-shell`. Scope per ruling D-3 ([plan](M4-C4.2-plan.md) §15): parts B (views
and the one mapping), D (pens and tool settings), E (drawing aids), the Rust half of C (tool state, gesture to command,
per-tool exact equivalence between headless `pointer` and the direct command), the headless half of F (`pointer`,
`screenshot` on the virtual view, tool keys in `key`) and H (inventory, prechecks, both sweeps). Design notes 3 to 6 were
pushed before the code (`751bd4e`): [gestures](M4-design-gestures.md), [pointer](M4-design-pointer.md),
[screenshot](M4-design-screenshot.md), [views](M4-design-views.md). Head, CI run and counts: §7.

## 1. What C4.2a delivers

- **Commands (52 + the MCP `pointer` tool).** All 9 `view.*`, the 25 `tool.*` that had no handler (`tool.symmetry.set`
  existed and moved into the drawing settings), all 17 `drawAid.*` and `inspect.screenshot`. Their worked examples are
  executed and retained (`crates/registry/src/example-results.json`); `desktop/src/ipc/generated/commands.ts` is
  regenerated.
- **Views and the one mapping (part B; note 6, V1-V5).** View state per view window and per type in the kernel's UI
  state (not undoable, not persisted: SI-128); the mapping is one Rust function (`shell::doc_to_view` /
  `view_to_doc`) published as matrices by `draw.viewMapping.get` (now reading the live window), `view.coordinates.convert`
  and the host-only `shell.view` announcement (the note said `view.changed`, which the registry cannot add; corrected with
  the code). View space now reaches `colour.pick`, `colour.paint.*`, `colour.gap.close`, `inspect.hitTest` and
  `inspect.coordinates.convert` (SI-065, SI-109); a named view also scales view-pixel tolerances by its zoom (02 §13.3).
  `render.frame.run {composition: "activeView"}` renders the Drawing view (SI-107 updated; other view types and ranges:
  M4 C4.3). With `letAgentMoveView` off an agent's view change refuses `permission.denied` (`details.preference`).
- **Tools, options, pens (part D).** One active tool shared by the views, the last-used tool per group and group cycling
  (02 §5.1); per-tool options checked all or nothing (`tool.notApplicable`, `tool.valueOutOfRange`), the Pencil's
  thickness source shared with the shape tools (02 §13.2); pens as project content with their undo labels ("New Pen",
  "Delete Pen", "Rename Pen", "Set Pen Style") and 02 §6.1's min/max rule; the current brush and eraser pens are project
  scope (`session.json`; default 02 §7.7's `Pen 3` / `Eraser 2`, else the family's first). Everything else is the user's
  `drawing` settings file under ADR-0021 decision 13's rules (D-7d: version, shape, a corrupt file told once and the
  defaults used). `tool.active.changed`, `tool.options.changed`, `tool.pen.changed` are emitted.
- **Drawing aids (part E).** Grid, onion skin and its style, the onion-skin cycle, auto light table, light-table shade,
  the panel flag, Show Strokes, current drawing on top, selection display and background, announced as
  `drawAid.changed`. The static light table shares the per-scene light table of the Exposure Sheet (SI-085, SI-126):
  entries track their source and drop out when it is deleted.
- **Gestures and `pointer` (C Rust half, F headless; notes 3 and 4).** `crates/executor/src/gesture.rs`: one input model
  (view point, pressure, tilt, pointer kind, modifiers, simulated time), `to_command` building 02 §13.3's equivalent
  command with every current setting explicit (current pen, colour, thickness, layer from Draw Behind / Draw on Top
  Layer, symmetry, gap mode, the view for tolerances), the temporary overrides of 02 §5.2 (pen eraser end, temporary
  Select, Alt to Dropper). Covered tools: Brush, Pencil, Stroke, Rectangle, Ellipse, Line, Polyline, Select (click,
  marquee, lasso, drag-move and copy, pivot drag), Eraser, Cutter, Scissor, Paint, Unpaint, Paint Unpainted, Dropper,
  Close Gap, Zoom, Grabber; the others answer `command.notImplemented` (SI-129). `ExecutorHandle::pointer` runs a whole
  call as one document-thread request (P1) and answers the first refusal's envelope (with `details.gesture`) or
  `{commands: [{commandId, params, result, documentRev}], hover}`; the MCP `pointer` tool calls it. Limits: 10,000
  events (SI-130), finite coordinates, view navigation refused inside a gesture, `scene`/`camera` spaces refused in the
  Drawing view, an unreleased gesture discarded (D-7c).
- **`screenshot` headless (note 5, S1, S2, S4).** The target view window at its virtual size through the final software
  rasteriser, now one function shared with `draw.drawing.render` (`draw_render::rasterise`); `region` crops; the 2048 px
  cap is checked before rendering; panels other than view windows and `dialogs` refuse `view.notFound` headless; the
  Camera view type: M4 C4.3.
- **Keys.** One single-key group key per tool group in the drawing context (`S`, `B`, `F`, `E`, `Z`, `T`; SI-131 item
  7); `key {view}` aims a bound `view.*` command at that view without moving the user's active view.
- **Availability (part H).** 46 new (command, code) pairs classified; prechecks for every state refusal
  (`drawAid.staticLightTable.*`, `render.frame.run` with `activeView`, the navigation commands' one-of groups so a bare
  reference agrees with the dry run); two new sweep states (`drawing-view`, `painted-zone-selected`), and the
  `draw.centreLine.apply` / `drawing.centreLineOnFill` row is no longer untestable (plan §8).
- **Registry drift fixed (plan §1).** `owners.rs` maps `view` and `drawAid` to M4 C4.2 and `inspect.ui.tree` to C4.1;
  the `pointer` refusal no longer names M2 C2.3.

## 5. Residual risks

- **Selection drags** decide "on the selection" by the selection's bounding box, not the objects' outlines; a drag
  starting in an empty corner of the box moves the selection.
- **Polyline across calls:** headless, one call's clicks are one gesture (committed at the call's end unless a double
  click or a closing click ended it); the GUI keeps a Polyline open across input until it is ended (C4.2b).
- **The static light table** lives in session state, not yet in the project's `session.json` (SI-085, M5 C5.2).
- **Known timing flakes** as in the C4.1 handoff (rerun once, always report).
