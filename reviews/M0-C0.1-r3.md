**New findings**

**C01-R3-01 — P1 — Inline ESLint rule configuration plus a static escaped global bypasses both guards**

Locations: `desktop/boundary/eslint.js:113–122`; `desktop/boundary/vite-plugin.ts:29`, `:105–118`. Introduced by `5c0938f`. Target: C0.1.

`no-restricted-disable` handles `eslint-disable` directives, but does not prevent `/* eslint rule: off */` configuration comments. The actual ESLint config emits **zero diagnostics** for:

```js
/* eslint no-restricted-syntax: off */
export const bypass = () => window['\u005f\u005fTAURI_INTERNALS__'].invoke('app_info');
```

The real production Vite configuration also accepts it. Its pre-transform textual scan does not see the escaped underscores, and the emitted chunk contains `window["__TAURI_INTERNALS__"].invoke("app_info")`. This is a static property literal decoded at compile time, not the accepted deferral for names assembled from runtime variables. Separately, `/* eslint no-restricted-imports: off, no-restricted-syntax: off */` suppresses every lint diagnostic for a direct package import. Thus both the inline-disable prohibition and the actual HostApi boundary remain unenforced.

Repro: `node --test tests/adversarial/c01-r3-boundary.test.mjs`. Its first two cases fail; the second verifies that the raw invoke survives emission. Permanent test: `tests/adversarial/c01-r3-boundary.test.mjs`, registered in `desktop/src/test/c01-r3-node.test.ts`. Evidence: `boundary-attacks.log`. Requirement: binding R2-01 ruling; ADR-0001 decision 1; `desktop/src/ipc/README.md:5`; plan §3.2 and spec 11 P2's subsequent single-command-layer guarantee.

**C01-R3-02 — P1 — The dev re-resolution exception also exempts real production HTML imports**

Location: `desktop/boundary/vite-plugin.ts:93–100`. Introduced by `5c0938f`. Target: C0.1.

Any absolute import attributed to `desktop/index.html`, except `/src/main.tsx`, is classified as re-resolution and checked with `edge: false`. There is no dev-only condition or distinction between a synthetic importer and a real HTML module edge. A root HTML module containing:

```html
<script type="module">
import { createTauriTransport } from '/src/ipc/tauriTransport.ts';
window.bypass = createTauriTransport;
</script>
```

builds successfully with the real production config and emits the transport and `window.bypass = createTauriTransport`. HTML is not covered by the JS/TS linter. The test supplies this HTML through an **order: pre** HTML fixture hook at the real entry path, before Vite processes its imports; it does not replace the boundary plugin or edit product files. The identical import from another HTML entry under `src/` is rejected, identifying the special-case path as the cause.

Repro/test: third case of `node --test tests/adversarial/c01-r3-boundary.test.mjs`, failing with “Missing expected rejection.” Evidence: `boundary-attacks.log`. Requirement: binding R2-01 ruling and ADR-0001, specifically “only src/ipc/index.ts may load the transport.”

**C01-R3-03 — P2 — Counting array properties does not prove dense array indices**

Location: `desktop/src/ipc/schema.ts:70–71`. Introduced by `65fec88`. Ticket: M1 C1.1, before generated model/schema integration.

The preflight compares the number of own names other than `length` to the array's length, without verifying that those names are exactly the indices. `const a = new Array(1); a.extra = 'data'` passes `plainDataViolations`. It survives `structuredClone` and certification under an unconstrained JSON field. A real `createHostApi(...).onMenuCommand` listener receives `{params: {data: a}, ...}` instead of dropping it. JSON serialization would replace the hole with null and lose `extra`, contradicting the promised plain JSON data contract. A 196-case length/hole/extra matrix found 21 false accepts: named properties compensate for holes.

Repro: `pnpm --dir desktop exec vitest run src/test/c01-r3-schema.test.ts`, first three cases. Permanent test: `desktop/src/test/c01-r3-schema.test.ts`; evidence: `schema-attacks.log`, `schema-measure.log`. Requirement: R2-02 plain-data ruling and response's explicit no-holes/no-extra-array-property claim; `schema.ts:6–10`; IPC README. This is P2: it requires a constructed in-process transport value; ordinary JSON parsing does not synthesize this shape. The original prototype/required-field attacks remain closed.

**C01-R3-04 — P2 — Uncloneable transport values throw outside the HostApi rejection/drop paths**

Locations: `desktop/src/ipc/schema.ts:162–165`; callers `desktop/src/ipc/hostApi.ts:60`, `:75`. Introduced by `65fec88`. Ticket: M1 C1.1.

A transparent `new Proxy(validPing, {})` passes the prototype/property preflight but `structuredClone` throws `DataCloneError`. `host.ping()` therefore rejects with a raw DOMException rather than `HostError {code: 'ipc.invalidResponse'}`; an equivalent proxy menu event throws synchronously through the listener rather than being dropped. The exception is outside the `transport.invoke` catch. This does not certify invalid data, but it breaks the advertised stable-error and malformed-event behavior introduced around the new snapshot step.

Repro: R3-04's three cases in `pnpm --dir desktop exec vitest run src/test/c01-r3-schema.test.ts`. Permanent test/evidence: same schema test and `schema-attacks.log`. Requirement: IPC README's stable HostError contract, `hostApi.ts:74` malformed-event drop contract, R2-02 transport-unknown validation ruling. P2 because this is an in-process alternate/mock transport case, not a claim that JSON received from Rust contains Proxy objects.

**C01-R3-05 — P1 — New validation primitives break the declared Safari 15/macOS 12.0 floor**

Locations: `desktop/src/ipc/schema.ts:45`, `:49`, `:76`, `:164`; declared targets `desktop/vite.config.ts:20` and `desktop/src-tauri/tauri.conf.json:34`. Introduced by `65fec88`. Target: C0.1.

The new guard requires `Object.hasOwn` and the global `structuredClone`, without a fallback/polyfill. The app explicitly targets `safari15` and minimum macOS `12.0`. Apple's [Safari 15.4 release notes](https://developer.apple.com/documentation/safari-release-notes/safari-15_4-release-notes) identify both APIs as new in Safari 15.4, shipped with macOS 12.3; the [WebKit release announcement](https://webkit.org/blog/12445/new-webkit-features-in-safari-15-4/) also documents the new clone API. Thus an allowed older WebKit runtime can fail even valid host responses with `TypeError` before completing certification. Vite's syntax target does not provide either missing runtime function, and both calls remain in the emitted bundle.

Repro: R3-05's two tests independently remove each API, call the real `certify(isPingResponse, validPing)`, restore the host global, and assert successful validation. Both fail. Test: `desktop/src/test/c01-r3-schema.test.ts`; evidence: `schema-attacks.log`, `runtime-api-bundle-paths.txt`. This is a compatibility inference supported by primary release documentation and simulated missing-API tests, **not an actual run on an older Mac**. Current macos-latest CI cannot prove the minimum WebKit target. Requirement: existing declared platform floor and C0.1 cross-platform shell contract. Supply compatible implementations or explicitly resolve the minimum-runtime change; do not silently narrow support.
