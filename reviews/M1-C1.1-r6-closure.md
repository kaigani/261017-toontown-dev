**C11-R6-01 — P1 — Staged commit returns an inverse for the uncanonicalized intermediate state**

Requirement: spec 10 §2.6 change descriptions and invertibility, the accepted pre-state inversion ruling, and the new `with_patched_entry` contract to return the next snapshot **with its inverse**. ADR-0010 §4 directs C1.2 to use this primitive. The failure is already observable through the C1.1 public model API and does not depend on future executor behavior.

Cause: `document/mod.rs:456` computes `(after, inverse)` from raw JSON. The subsequent `staged(&after, id)` at **:474** calls `object::from_json` at **:434**, whose canonicalization merges adjacent exposure runs (`object.rs:53`, `:88–118`). The API returns the original inverse unchanged at **:480**. Its array positions describe the unmerged intermediate array rather than the returned document.

| Valid edit through `with_patched_entry` | Actual returned snapshot / inverse result | Permanent regression |
|---|---|---|
| Append `[A,1]` to an exposure whose last run is `[A,24]` | Snapshot merges to `[A,25]`; inverse still removes `/exposure/4`, which no longer exists. Applying it returns `arg.invalid`, `array index out of range`. | `staged_append_inverse_survives_run_merging` |
| Starting from `[[A,2],[B,3]]`, replace `/exposure/0/0` with `B` | Snapshot canonicalizes to `[[B,5]]`. Returned inverse changes index 0 back to `A`, producing **`[[A,5]]` instead of `[[A,2],[B,3]]`**. Undo succeeds, and `issues()` reports no errors, despite changing three frames incorrectly. | `staged_inverse_restores_frames_after_runs_merge` |

Staging does **not** clone the whole document per operation. The JSON entry is cloned once before the patch loop; normalization reparses that entry once afterward.
