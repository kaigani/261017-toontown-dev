## Reference coverage

The model's complete asset/pen reference inventory is:

- `SoundPlacement.assetId`: element `/placements/*/assetId`, `x-ref: asset`.
- `ProducedFor.assetId`: element `/placements/*/mouthTrack/producedFor/assetId`, `x-ref: asset`.
- `MediaSequence.assetId`: element `/sequences/*/assetId`, `x-ref: asset`.
- `SpinePen.penId`: drawing `/nodes/*/strokes/*/spine/pen/penId` (also recursively beneath group `children/*`), `x-ref: pen`.

The new test asserts schema resolution at all four nested pointers. The integrity gate explicitly validates placement and sequence asset targets/kinds. The timing snapshot's produced-for reference and nullable historical pen reference are also marked and repointed, even though the gate does not independently reject them as dangling. Asset/pen object IDs in the project's owned lists are identities, not incoming references. No asset/pen reference field lacks an `x-ref`.

For precision, `doc.object.refs` is broader than the builder's comment suggests: `doc_lint::references` resolves ID-equal strings and map keys, excluding opaque data and handling owned child slots separately; it does not itself consult `x-ref`. Thus an ID-equal label can appear in that query without becoming a schema-declared reference eligible for replacement. This existing query behavior is not a regression or a new scope item.

Other ID-bearing model fields without `x-ref`, outside asset/pen replacement, are: scene `columnOrder` and `paletteStyles` keys/values; element exposure drawing IDs; lip-sync `mapping.A` through `mapping.G` and `mapping.X`; swatch `values` style-ID keys; colour-recovery `colourId`, `paletteId`, `styles[].styleId` and the nested swatch's identity/style keys; asset link `libraryId`, `itemId` and string `versionId`; library-item string `versionId`; and owned-object `id`/`colourId` fields, child-list/child-reference stub identities. Constructors' `ProjectInit`/`SceneInit`/`ElementInit` ID inputs mirror these stored fields rather than adding reference positions. File/blob paths and free strings are not typed asset/pen IDs. See `evidence/M1-C1.3-r4/id-fields.txt` and `crates/model/src/entities/`.
