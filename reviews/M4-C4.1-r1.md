## Findings

### C41-R1-01 ? P1 ? closing a dialog over IPC never clears modal state

Clause: charter 8 and 12; ADR-0021 decisions 5, 7 and 8; busy-arbitration contract.

Reproduction: open and close Preferences, then try a shortcut or an agent focus change. `desktop/src/shell/messages.tsx` sends `{"modal":null}` on close. `ShellReport.modal` is `Option<Option<ModalReport>>` with ordinary serde deserialization: both an omitted field and explicit null become outer `None`. `report_shell` therefore ignores the closing report, retaining the dialog indefinitely. Rust-only builder tests construct `Some(None)` directly and bypass this wire defect.

Permanent reproduction: `cargo test -p tt-executor --test c41_r1_review closing_dialog_over_json_clears_modal_and_shortcuts`. **Fails at ac2e9ff.** The test deserializes both reports from actual JSON, posts them, and reads `app.state.get` through the executor. Expected null; observed Preferences dialog after close. Evidence: `executor-probe.txt`.

Required: closing the last dialog releases user priority and shortcut suspension. Observed: focus-changing agent calls remain refused and action calls remain busy; shortcuts remain suspended until another modal report replaces the state or the engine restarts. Fix direction: distinguish absent from explicit-null fields at deserialization, preserving the current partial-report contract. Owner: C4.1 kernel/host boundary.

### C41-R1-02 ? P2 ? HTTP transport accepts remote bind addresses

Clause: charter 10; ADR-0022 decision 2 (remote binding refused pending authorization).

Reproduction: start `tt_mcp::http` with `0.0.0.0:0`; it succeeds. `start` directly calls `TcpListener::bind(opts.bind)` without checking loopback. The desktop forwards its command-line address to this API unchanged.

Permanent reproduction: `cargo test -p tt-mcp --test c41_r1_review remote_bind_is_refused`. **Fails at ac2e9ff**, using a real wildcard listener, dropped on assertion unwind. Evidence: `build-probe.txt`.

Required: refuse remote binds until the specified authorization exists. Observed: a caller can expose the bearer-authenticated service on every IPv4 interface. This test does not claim unauthenticated command execution. Fix direction: reject non-loopback IPv4 and IPv6 addresses before binding; test both families. Owner: C4.1 transport.

### C41-R1-03 ? P2 ? ambiguous HTTP security headers and transfer framing are accepted

Clause: charter 10; ADR-0022 decision 2; HTTP parser security boundary.

Reproduction: send DELETE /mcp with (a) invalid then valid Authorization, (b) foreign then local Host, or (c) Transfer-Encoding: chunked alongside Content-Length: 0. All three receive 404 unknown session, proving they passed authentication/host/framing checks and reached session lookup. `read_request` overwrites duplicates in a HashMap and ignores Transfer-Encoding.

Permanent reproduction: `cargo test -p tt-mcp --test c41_r1_review` tests `duplicate_authorization_is_refused`, `duplicate_foreign_host_is_refused`, and `ambiguous_transfer_framing_is_refused`. **All fail at ac2e9ff** over real loopback sockets. Evidence: `build-probe.txt`.

Required: reject ambiguous credentials, authority and framing before dispatch. Observed: last-header-wins interpretation and unsupported framing accepted. No intermediary smuggling exploit or token-free browser command execution is claimed. Fix direction: validate HTTP syntax and framing before collapsing headers; reject duplicate singleton security fields and unsupported transfer codings. Owner: C4.1 transport.

### C41-R1-04 ? P2 ? unsupported settings versions are silently loaded

Clause: charter 5; ADR-0021 decision 13; spec 01 section 11.

Reproduction: write a preferences envelope with correct format/kind, `formatVersion: "999.0"`, and a valid dark-theme value, then call the production settings reader. It returns Data. `tt_persist::settings::read` never examines formatVersion.

Permanent reproduction: `cargo test -p tt-executor --test c41_r1_review unknown_settings_version_is_quarantined`. **Fails at ac2e9ff.** The test removes its temporary directory before asserting. Evidence: `executor-probe.txt`.

Required: unsupported settings are set aside and reported, with other files retained. Observed: arbitrary future versions are interpreted as current data. Fix direction: validate/migrate supported versions before returning Data, including missing/wrong-type version fields; preserve unsupported input. Owner: C4.1 settings reader.

## Continuation: HTTP admission boundary

### C41-R1-05 ? P2 ? unauthenticated requests allocate the maximum body before authentication

Clause: charter 10 (slow senders, connection bounds, up-front MAX_BODY allocation); ADR-0022 decision 2 bearer-authenticated transport.

Reproduction: connect over loopback, send POST /mcp with Host: localhost and Content-Length: 67108864, omit Authorization, and send no body bytes. The server gives no rejection before the socket read bound. `read_request` allocates the full 64 MiB vector and calls `read_exact` before `serve_connection` checks credentials. The accept loop starts a thread per connection with no admission cap. The 30-second timeout applies per read, not to total request lifetime.

Permanent reproduction: `cargo test -p tt-mcp --test c41_r1_review unauthenticated_large_body_is_refused_before_reading_payload`. **Fails at ac2e9ff**: no response, socket timeout after 2.0079251 s measured with Instant. One connection only; shutdown is performed before assertion. Evidence: `http-continuation.json`. The test sends no bearer or body and requires a 401 before payload transfer. It uses a generous local read bound, not a sleep.

Required: reject missing credentials before reserving a large payload; bound total unauthenticated connections and their memory/time exposure. Observed: any local process can reserve 64 MiB per connection without a token; many concurrent connections can exhaust resources. This is a local denial-of-service finding, not a demonstrated browser command-execution path. No destructive load test was run. Fix direction: parse bounded headers, validate security before body allocation, enforce connection/in-flight body budgets and absolute receive deadlines. Owner: C4.1 HTTP transport.

### C41-R1-06 — P2 — HTTP authority validation rejects valid DNS case and accepts URL paths

Clause: charter 10; ADR-0022 decision 2, loopback Host/Origin validation.

Reproduction: authenticated POST /mcp with Host: LOCALHOST returns 403. Host: localhost/foreign returns 404 unknown session, showing that an invalid HTTP authority passed validation. The common loopback_host helper strips schemes and paths rather than parsing the distinct Host and Origin grammars; comparison is case-sensitive. This is an interoperability and validation defect; no remote-origin authentication bypass is demonstrated.

Permanent reproductions: `cargo test -p tt-mcp --test c41_r1_review part_c_http --locked`. `dns_host_case_is_insensitive` and `host_cannot_contain_url_path` both **fail at ac2e9ff**, on the first POST assertion. Required: accept case-insensitive loopback DNS names and validate authority/origin syntax before the loopback comparison. Owner: HTTP transport. Fix direction: separate authority and origin parsing; prohibit paths/schemes/userinfo in Host; validate origin schemes and ports. Evidence: `part-c-http.txt`. ## Part C — A: HTTP attached mode remainder (charter 10)

Verdict: **divergent**, C41-R1-06 plus previously settled 02/03/05. Real application socket lifecycle probe `tests/adversarial/c41-r1-http-lifecycle.py` passes all checks at ac2e9ff; receipt `part-c-lifecycle.json`. It initializes 32 sessions, observes the 33rd refused, deletes one, proves that id dead and admission restored. No load beyond the specified cap was used.

Token generation: agent.rs:404 requests 24 random bytes (48 hex characters); HTTP session ids request 16 bytes (32 hex). Both use fsx.rs:57 getrandom::fill. **Residual security risk:** on OS randomness failure this helper falls back to timestamp plus counter, appropriate for temporary names but not credentials. No randomness-failure injection exists on this call path; normal generation length/encoding was measured, but entropy failure was not induced. token_ok compares equal-length bytes with an XOR/OR fold without a content-dependent early exit; length and missing/prefix checks are early exits. This is source evidence, not a compiler-level constant-time guarantee. Wrong and right bearer probes show no token in HTTP bodies or captured process output. The transport does not pass Authorization into its JSON-RPC loop or audit entries; only the body is forwarded. The shell logger prints endpoint/error strings, not options. No frontend token rendering path was found in the desktop/src token/discovery search; regeneration returns only discoveryFile.

Host/Origin: `authority_matrix` covers POST, GET and DELETE. Suffix attacks and userinfo-like authority, empty value, missing Host and Origin null are refused; bracketed IPv6 with/without port passes. Source matches only lowercase literal names: trailing-dot localhost and uppercase are refused. Input `localhost/foreign` is wrongly accepted (new finding). Scheme stripping is inappropriate for Host. No remote-origin credential bypass is claimed.

Sessions: the map is keyed only by the unpredictable bearer session id. Supplying B's id selects B's routes/input, never A's; requests, GET sender, backlog and cancellation loop are allocated per Session. Supplying a stolen A id with the shared installation credential impersonates A; there is no additional client identity binding. DELETE removes the map entry, drops the sender, and disconnects the protocol reader. Abandoned sessions have **no idle expiry**: ChannelReader waits on recv while the map retains its input sender. One authenticated client can occupy all 32 slots until DELETE or server restart; existing sessions continue. The cap check and insertion use separate locks, so it is not a concurrent admission guarantee. These are residual availability risks; no unspecified expiry duration is invented as an acceptance requirement.

Lifecycle: shell.rs:173 sync_agent_server starts only for the launch flag or persisted agent.server.enabled; catalogue default is false. Without either it calls stop_http. Ordinary process restart therefore stays off unless the preference/flag requests serving. Host::restart preserves serving when already active; this is engine restart, not a process relaunch. Host::write_discovery writes Settings/agent-discovery.json and the optional explicit discovery target, containing format/version, endpoint, token and processId. stop_http and graceful quit do **not remove** it; abrupt-exit probe confirms it remains. This preserves the per-installation token but leaves stale endpoint/process metadata. A preplanted parseable file with any string token is trusted without format/length checks (Host::token); the per-user directory is the trust boundary. POSIX replacement sets 0600; Windows relies on inherited per-user-folder ACLs. A second-account ACL test requires a separate account and is not claimed. File-removal behavior is reported as observed rather than equated with credential rotation.
