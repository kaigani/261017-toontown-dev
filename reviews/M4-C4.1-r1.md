## Findings

### C41-R1-01 - P1 - closing a dialog over IPC never clears modal state

Clause: charter 8 and 12; ADR-0021 decisions 5, 7 and 8; busy-arbitration contract.

Reproduction: open and close Preferences, then try a shortcut or an agent focus change. `desktop/src/shell/messages.tsx` sends `{"modal":null}` on close. `ShellReport.modal` is `Option<Option<ModalReport>>` with ordinary serde deserialization: both an omitted field and explicit null become outer `None`. `report_shell` therefore ignores the closing report, retaining the dialog indefinitely. Rust-only builder tests construct `Some(None)` directly and bypass this wire defect.

Permanent reproduction: `cargo test -p tt-executor --test c41_r1_review closing_dialog_over_json_clears_modal_and_shortcuts`. **Fails at ac2e9ff.** The test deserializes both reports from actual JSON, posts them, and reads `app.state.get` through the executor. Expected null; observed Preferences dialog after close. Evidence: `executor-probe.txt`.

Required: closing the last dialog releases user priority and shortcut suspension. Observed: focus-changing agent calls remain refused and action calls remain busy; shortcuts remain suspended until another modal report replaces the state or the engine restarts. Fix direction: distinguish absent from explicit-null fields at deserialization, preserving the current partial-report contract. Owner: C4.1 kernel/host boundary.

### C41-R1-02 - P2 - HTTP transport accepts remote bind addresses

Clause: charter 10; ADR-0022 decision 2 (remote binding refused pending authorization).

Reproduction: start `tt_mcp::http` with `0.0.0.0:0`; it succeeds. `start` directly calls `TcpListener::bind(opts.bind)` without checking loopback. The desktop forwards its command-line address to this API unchanged.

Permanent reproduction: `cargo test -p tt-mcp --test c41_r1_review remote_bind_is_refused`. **Fails at ac2e9ff**, using a real wildcard listener, dropped on assertion unwind. Evidence: `build-probe.txt`.

Required: refuse remote binds until the specified authorization exists. Observed: a caller can expose the bearer-authenticated service on every IPv4 interface. This test does not claim unauthenticated command execution. Fix direction: reject non-loopback IPv4 and IPv6 addresses before binding; test both families. Owner: C4.1 transport.

### C41-R1-03 - P2 - ambiguous HTTP security headers and transfer framing are accepted

Clause: charter 10; ADR-0022 decision 2; HTTP parser security boundary.

Reproduction: send DELETE /mcp with (a) invalid then valid Authorization, (b) foreign then local Host, or (c) Transfer-Encoding: chunked alongside Content-Length: 0. All three receive 404 unknown session, proving they passed authentication/host/framing checks and reached session lookup. `read_request` overwrites duplicates in a HashMap and ignores Transfer-Encoding.

Permanent reproduction: `cargo test -p tt-mcp --test c41_r1_review` tests `duplicate_authorization_is_refused`, `duplicate_foreign_host_is_refused`, and `ambiguous_transfer_framing_is_refused`. **All fail at ac2e9ff** over real loopback sockets. Evidence: `build-probe.txt`.

Required: reject ambiguous credentials, authority and framing before dispatch. Observed: last-header-wins interpretation and unsupported framing accepted. No intermediary smuggling exploit or token-free browser command execution is claimed. Fix direction: validate HTTP syntax and framing before collapsing headers; reject duplicate singleton security fields and unsupported transfer codings. Owner: C4.1 transport.

### C41-R1-04 - P2 - unsupported settings versions are silently loaded

Clause: charter 5; ADR-0021 decision 13; spec 01 section 11.

Reproduction: write a preferences envelope with correct format/kind, `formatVersion: "999.0"`, and a valid dark-theme value, then call the production settings reader. It returns Data. `tt_persist::settings::read` never examines formatVersion.

Permanent reproduction: `cargo test -p tt-executor --test c41_r1_review unknown_settings_version_is_quarantined`. **Fails at ac2e9ff.** The test removes its temporary directory before asserting. Evidence: `executor-probe.txt`.

Required: unsupported settings are set aside and reported, with other files retained. Observed: arbitrary future versions are interpreted as current data. Fix direction: validate/migrate supported versions before returning Data, including missing/wrong-type version fields; preserve unsupported input. Owner: C4.1 settings reader.

### C41-R1-07 - P3 - duplicate desktop tokens lose cancellation ownership

Clause: ADR-0021 decision 3; ADR-0020 decision 8.

Reproduction by source trace: host.rs:132-138 inserts a fresh flag unconditionally under the supplied token. With A and B in flight under the same token, cancel selects B, not A. B never inherits A's flag. When A returns, its unconditional remove also removes B's entry, making B uncancellable. The normal frontend generates increasing tokens, reducing ordinary exposure; trusted callers can reuse them. No runtime collision reproduction is claimed. Owner: desktop host. Reject an occupied token or give each invocation an ownership guard whose drop removes only its own entry.

The same remove is not unwind safe: an unwinding invocation skips it. Normal success, error and timeout envelopes all take the remove path; process abort frees the process map. An indefinitely stuck invocation retains its flag until return. No panic injection facility is exposed, so this is source evidence, not an induced panic or an assertion that ordinary executor errors unwind.

## Part D - E: settings persistence remainder

Verdict: **divergent**, C41-R1-08/09; previously settled 04 is not re-reported.

Write sequence: fsx.rs:153-181 creates parent, creates a unique sibling exclusively, writes all bytes, sync_all, closes, renames over target, then syncs parent on POSIX. Kill before rename leaves the old target (or missing target for a first write) and a partial/complete temporary; after rename the new target is visible. Windows parent-directory durability is explicitly not guaranteed by this safe API. Normal error cleanup removes the temporary. No separate buffered flush is necessary for File::write_all. New orphan reproduction establishes missing restart cleanup.

Missing directories: reads produce Missing and startup uses defaults; ensure_dirs ignores directory-creation errors (store.rs:291-296). Unreadable existing files attempt set-aside; set_aside ignores rename failure and reports a path that may not exist. Startup does not refuse for these failures. Accepted preference writes discard write errors at run.rs:852, so a read-only/unwritable directory can silently lose persistence; this is source evidence, not a Windows ACL experiment. No claim that the readonly attribute implements directory ACL denial.

Shape matrix: production reader accepts any data Value for all five kinds. preferences requires an object only in the caller; recent uses typed deserialization with default on failure; state individually filters member types; keymap uses from_stored filtering; workspaces passes raw data onward. No caller quarantines these shape errors. Unknown extra envelope fields are tolerated; extra preference keys have no effective catalogue entry. read_limited caps each input at 64 MiB and oversized files go through set_aside, independently of other kinds; no >1 MB evidence artifact was created.

Archive: settings.rs:96-100 chooses only a millisecond timestamp and ignores rename failure. Distinct timestamps accumulate forever (no pruning). Same-millisecond collisions may replace the earlier aside on replacement-capable filesystems; no deterministic clock hook exists here and no runtime collision is claimed. These are additional source-confirmed deficiencies; no arbitrary retention limit is invented as a spec value.

Acceptance/order: effects are applied by the single document worker after acceptance; run.rs:843-852 writes preferences synchronously from staged values. Refused validation never reaches stage, dry-run effects are discarded, and cancellation before acceptance discards them. Consequently rapid accepted calls serialize their disk replacements in acceptance order; an older asynchronous write cannot overtake a newer one. A cancellation after a commit stands under ADR-0020 decision 8. Failed writes remain a separate persistence-loss risk. Validation receipt: part-d-settings.txt (2 expected failures).
