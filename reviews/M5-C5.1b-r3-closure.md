## Findings

### C51B-R3S-01 - P2 - Concurrent menus answer with another request's menu

Citation: E-52, reviews/M5-C5.1-plan.md:682 (answer what window did);
reviews/M5-design-timeline-view.md:175-177 (menuId names the opened menu).
Code: desktop/src/shell/windowHooks.ts:155-173, 185-189.
Sequence: two sessions send Shift+F10 to timeline.tracks and timeline.ruler
before the next animation frame. Both handlers dispatch immediately, then
await requestAnimationFrame independently. The ruler replaces the cell menu.
Both continuations query the same global first menu and answer its id.
Wrong: the tracks request reports timeline.rulerMenu rather than its cell
menu. Request ids isolate host replies but do not isolate window execution.

### C51B-R3S-02 - P2 - Per-window deduplication loses focus ownership

Citation: spec/11_agent_interface_mcp.md:237-241, 360-362 (user input
priority and real key rules); E-52, plan:679-680 (text field keeps its key).
Code: desktop/src/shell/windowHooks.ts:394-404, 412-416;
desktop/src-tauri/src/host.rs:375-384; desktop/src/App.tsx:156,386.
Sequence: focus a text field in the main window (reports true), then focus a
non-text control in a float (reports false, host marks float focused). Return
to the same main field. Its fact still equals its locally cached true, so
focusin sends nothing. The host remains on the float's false indefinitely
until a different fact or generation occurs in main.
Wrong false: an agent's field-owned keys can run bindings instead of ui.busy.
The reverse sequence (main non-text, float text, main non-text) leaves true;
wrong true refuses ordinary agent keys with ui.busy after editing has ended.
Page mutation reports also deduplicate and cannot repair either state.

## Observations

- Case 1: ordinary key guards precede routing. Non-string view is refused
  before routing; unknown controls return before focus changes; no-menu
  restores focus. Routed ids are monotonic; timeout removes the entry and
  late answers are ignored. Restart and window destruction drain waiters.
  Event/answer are host IPC, not registered MCP tools or command references.
- The window does not check request.generation before dispatching a queued
  menu event. A restart drains the host waiter but does not cancel that UI
  work; stale-event behavior deserves a live boundary check.
