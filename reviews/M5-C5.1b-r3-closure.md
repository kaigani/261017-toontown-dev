## Findings

### C51B-R3S-01 - P2 - Concurrent menus answer with another request's menu

Citation: E-52, reviews/M5-C5.1-plan.md:682 (answer what window did);
reviews/M5-design-timeline-view.md:175-177 (menuId names the opened menu).
Code: desktop/src/shell/windowHooks.ts:149-166, 175-181.
Sequence: two sessions send Shift+F10 to timeline.tracks and timeline.ruler
before the next animation frame. Both handlers dispatch immediately, then
await requestAnimationFrame independently. The ruler replaces the cell menu.
Both continuations query the same global first menu and answer its id.
Wrong: the tracks request reports timeline.rulerMenu rather than its cell
menu. Request ids isolate host replies but do not isolate window execution.

### C51B-R3S-02 - P2 - Background mutation steals text-focus ownership

Citation: spec/11_agent_interface_mcp.md:237-241, 360-362 (user input
priority and real key rules); E-52, plan:679-680 (text field keeps its key).
Code: desktop/src/shell/windowHooks.ts:394-414;
desktop/src-tauri/src/host.rs:375-384; desktop/src/App.tsx:156,386.
Sequence: start an inline rename in main, then edit a field in a Timeline
float. Main retains its document.activeElement while its window is inactive.
An agent deletes the main rename's element. That input unmounts; the new main
MutationObserver reports false even though the person is editing in float.
Host::report_from treats any textFocus report as window activation and marks
main focused. The kernel stays false while the float field keeps focus:
float page mutations deduplicate its unchanged true and send no correction.
Wrong false: agent field-owned keys can run bindings instead of ui.busy.
Wrong true would instead refuse agent keys with ui.busy after editing ended.
The sensor has no document.hasFocus/active-window gate and sends ownership
changes from background DOM changes as well as genuine focus transitions.

### C51B-R3S-03 - P2 - Element Colours drops typed whitespace

Citation: E-53, reviews/M5-C5.1-plan.md:695-698 (kernel decides, same rule
for colours); handoff section 4 (typed colour sent, refusal keeps dialog).
Code: desktop/src/timeline/dialogs.tsx:278-292.
Sequence: open Element Colours, enter three spaces in Marker and a valid
#112233 in Background, then OK. Marker is omitted because trim() is empty;
only Background is sent. The command succeeds and the dialog closes.
Wrong: the invalid typed Marker never reaches validation and no refusal is
shown. With both fields spaces, OK is disabled and no reason can be obtained.
Only truly empty fields are the documented leave-unchanged sentinel.
