## 2. Two CI findings at the first push (run 43127865912)

- **`m3 properties release` (macOS): a latent passage-frame defect, fixed.**
  - **Failure:** `c32_passage::passage_agrees_with_the_exact_oracle` (builder, C3.2) is a 4096-case proptest with a
    fresh seed per run. This run drew h = [0, 0, 7, -3], mid = 5, len_a = 1, len_b = 2, arc = 90, where the product
    reported 3.6 and the exact answer is 3.
  - **Cause:** the velocity curve's maximum in the second sub-segment equals the arc exactly (0.9 at s = 1/2, frame
    3, a tangent touch), then falls back and crosses again near 3.6. The candidate scan evaluates that extremum in
    doubles one rounding error below the arc and misses it.
  - **Fix:** `tcb::PASSAGE_TOUCH` = 1e-12 relative. A node or extremum candidate within that of the arc reaches it;
    the bisection is unchanged. Recorded in ADR-0019's constants table.
  - **Evidence:** the regression test `c32_passage::a_tangent_touch_at_an_extremum_is_the_passage` pins the case
    (frame 3); the property passed three runs of 4096 cases in release locally. The fault predates C3.4: this round
    didn't touch `tt-anim` until this fix.
- **Windows `check`: `c34_r3_probes::panicking_probe_leaves_worker_alive` (reviewer) under `RUST_BACKTRACE=1`.**
  - **Cause:** a probe that panics becomes visible to the worker only when the caller thread unwinds, which happens
    after the panic hook. With `RUST_BACKTRACE=1` the Windows hook symbolises a backtrace for longer than the 250 ms
    question bound. The worker then fails open as ruling C34-R3-01 requires, so the action commits, which the test's
    no-commit assertion excludes. Locally it is deterministic: with `RUST_BACKTRACE=1` it commits 3/3, and with
    `RUST_BACKTRACE=0` it passes 3/3.
  - **CI change:** the test runs unchanged in its own `check` step with `RUST_BACKTRACE=0` and is skipped by exact
    name in the main test step. The step runs the main step's own test binary directly: `cargo test --workspace
    --locked --no-run --message-format=json`, with the main step's arguments, names the executable without building.
    A separate `cargo test` with a target filter rebuilt: 438 s with `-p tt-executor` (run 43137048940, Windows `check`
    56 min 36 s) and 183 s with `--workspace --test` (run 43144010462, 47 min 15 s).
  - **Product:** no product change can let the worker see a panic before the hook finishes without breaking the
    bound.
  - **For the orchestrator:** confirm this placement, or rule that a probe panicking after the bound may commit, in
    which case the test's assertion needs amending.
