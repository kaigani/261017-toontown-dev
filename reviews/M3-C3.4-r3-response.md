| **C34-R3-01** (P1) the document thread waits on caller code | **Accepted; fixed as ruled.** | `caller::asks` waited up to 5 s for an answer on the document thread and took silence as cancellation. Calls without a probe (`invoke_served`, `batch`, `batch_audited`) still carried a link through the never-cancelled default. | Each question is bounded by `ask_bound(budget)` = min(`ASK_BOUND_MAX` 250 ms, budget/4). Silence is not cancellation: the request proceeds as not cancelled at that boundary, the link is latched unresponsive, and nothing more is asked for it, so one request stalls the document thread by at most one bound. A gone caller (disconnected) counts as cancelled. Calls without a probe carry no link and ask nothing; a probed query has a notice-only link and is never asked. The caller checks its watchdog deadline before taking a reply, so a caller held past its budget inside its own probe answers the timeout (a commit that happened stands, as ADR rule 3 says). `test-hooks` counts the questions. ADR-0020 decision 8 states that probes must not block, what the worker does when one does, and the two bounds. | Reviewer `blocked_probe_does_not_starve_other_callers_past_watchdog` passes unchanged. Builder `c34_round3`: plain calls and probed queries ask **0**; a probed 1000-step action batch asks **1 + 3×1000** (dequeue, then start, acceptance and pre-commit per step), and a 1000-step batch of steps that change no document asks **1 + 2×1000**. A never-answering probe on a 1000-step batch asks **once** and finishes in 602 ms against 296 ms plain, a 250 ms bound and the caller's own 600 ms probe stall; all steps run. An unrelated query during a stall waited **262 ms** (bound 250 ms). The silent request's outcome is the uncancelled one (committed, rev +1). |
| **C34-R3-02** (P2) refusals don't name their cause | **Accepted; fixed.** | `cancelled_check` and the work-account mappings answered `command.timeout` without the cause, and the token didn't record whether it was marked by timeout or by cancellation. | The token keeps its cause: `CancelState::mark` (timeout) versus `mark_cancelled` (caller), `cause`, and the thread's `cancel_cause` / `cancel_reason`. `cancelled_check` reports `reason: "cancelled"` for a caller's cancellation and keeps the watchdog wording for a timeout. Every invocation and batch envelope labels a `command.timeout` refusal `reason: "cancelled"` when the running token's cause is the caller, which covers the work-account path wherever the geometry, timing, render or replay code refused. A timeout is never relabelled. | Reviewer `worker_boundary_refusal_identifies_cancellation_reason` passes unchanged. Builder `c34_round3::a_caller_cancellation_on_the_work_account_path_says_cancelled` (a render stopped at a work-account check by its caller's cancellation: `reason: "cancelled"`) and `::a_watchdog_timeout_on_the_work_account_path_is_not_a_cancellation` (a 300 ms watchdog expiry is not labelled cancelled; the token's cause is timeout versus cancelled). |
