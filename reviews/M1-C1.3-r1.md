### C13-R1-01 — P1: Save effects escape dry runs and failed atomic batches

Location: `crates/executor/src/persistence.rs:379`. Requirement: 11 §7.2 dryRun and §7.3 atomic batches; plan §3.2; C1.2 closure persistence-effects ticket.

Repro/result: Create a saved project, modify a scene, and dry-run `project.close {onUnsaved:"save"}`. The package is rewritten, a backup is created, and the in-memory clean marker/savedRev move even though documentRev rolls back. The captured state is documentRev 2 / savedRev 3 / dirty false. An atomic batch containing the same save-close followed by an invalid patch also writes the package and leaks the clean marker despite returning batch.stepFailed.

`save_now` calls `finish_save` from the handler before commit and without a dry-run guard. Deferring only Close/Install/Prefs does not contain these effects. Keep file effects and clean-marker changes consistent with the invocation's commit outcome; the rejected batch must not publish an uncommitted snapshot.

Permanent regression: `crates/executor/tests/c13_r1_persistence.rs` — `dry_run_close_with_save_does_not_write_the_project_or_backups`, `failed_atomic_batch_after_save_does_not_leak_disk_or_clean_marker_changes`.

### C13-R1-02 — P1: Lock ownership is bypassed by same-path Save As and is not exclusive during stale takeover

Location: `crates/persist/src/lock.rs:160`. Requirement: 10 LOCK-01/LOCK-02; 01 §3.2 read-only Save/Save As behaviour.

Repro/result: Session A owns a package; B opens it read-only, edits, then calls Save As at the same path with overwrite. B's job succeeds, overwrites A's file and clears its own readOnly state. Independently, eight simultaneous stale-lock takeovers return multiple Acquired handles: 3–7 owners observed in first trials, with all handles kept alive until counting.

In project.rs:730, same-path Save As passes `lock=false` and never rejects a live foreign lock. The stale-lock path replaces the file and performs a separate read-back; this is not an exclusive takeover. Enforce current ownership at replacement and use an exclusive arbitration mechanism for takeover.

Permanent regression: `crates/executor/tests/c13_r1_persistence.rs` — `save_as_current_path_does_not_overwrite_another_sessions_lock`, `concurrent_stale_lock_takeover_has_only_one_owner`.

### C13-R1-03 — P1: Interrupted folder-save rollback leaves a mixed version

Location: `crates/persist/src/save.rs:598`. Requirement: 10 SAVE-02; ADR-0014 §2 completion-or-rollback claim.

Repro/result: Handcraft the documented journal state after its first rename: project.json already has new bytes, a later palette temporary is missing, and that palette still has old bytes. Recovery declares rollback, deletes the journal, and leaves new project bytes with the old palette.

The non-resumable branch only deletes remaining temporaries. It has no old copies with which to restore already replaced entries. Preserve enough information to restore every applied change or guarantee completion of the complete new version; do not discard the journal while leaving a mixed version.

Permanent regression: `crates/persist/tests/c13_r1_format.rs` — `partial_folder_rollback_restores_every_already_replaced_entry`.

### C13-R1-04 — P1: Malformed journals can delete project entries before container validation

Location: `crates/persist/src/save.rs:607`. Requirement: 10 SAVE-02 and §7.1/§7.2 fail-closed loading; REP-02 content preservation.

Repro/result: A folder with project.json and `.save-journal.json` containing `{format:"unrelated-format", deletions:["project.json"]}` loses project.json when recovery runs. The journal has neither the recognized format nor a renames array. `load` calls journal recovery before scanning or validating the container.

Any parsed JSON initially counts as valid, absent arrays default to empty, and an empty rename list is resumable. Validate the full journal structure and operation constraints before any filesystem mutation, and preserve existing content when the journal is malformed.

Permanent regression: `crates/persist/tests/c13_r1_format.rs` — `malformed_journal_cannot_delete_an_arbitrary_project_entry`.

### C13-R1-05 — P1: Unknown newer-minor properties disappear on a frozen entry

Location: `crates/persist/src/repair.rs:272`. Requirement: 10 VER-02; REP-02; 11 §14.3; ADR-0014 §5.

Repro/result: In a 1.3 folder, put both an unknown loopType and unknown root/nested transform properties on one element. Load and save it as a package. The enum survives, but futureProperty and futureTransform are absent from the saved JSON. The ordinary 1.0 fixture and the builder's separate-entry newer-minor test pass.

Overlay splitting removes unknown properties before `substitute_unknown_values` captures FrozenEntry.raw. `save::entry_text` selects frozen raw data and bypasses overlay merging. Preserve the complete original entry when freezing, including all unknown nested content.

Permanent regression: `crates/persist/tests/c13_r1_format.rs` — `newer_minor_unknown_properties_survive_on_the_same_frozen_entry`.

### C13-R1-06 — P1: Folder entry edits are invisible to external-change detection

Location: `crates/executor/src/store.rs:255`. Requirement: 10 RO-02; FMT-01; 10 §6.4 folder integrity; 01 §3.6.

Repro/result: Create a folder project, externally edit project.json without changing manifest.json, run maintenance, make a local scene edit, and save. No project.changedOnDisk is returned; the save proceeds. Folder projects are explicitly intended for text and version-control edits where the manifest entry list is omitted.

Only manifest.json size/mtime is watched for folder projects. Observe the entry tree or an equivalent reliable fingerprint, and recheck before replacing externally edited content. Positive tests establish that reload and keep-mine work for a detected package change; the folder detection prerequisite is missing.

Permanent regression: `crates/executor/tests/c13_r1_persistence.rs` — `folder_entry_change_is_detected_even_when_manifest_is_unchanged`.

### C13-R1-07 — P1: Failed package export deletes the previous destination

Location: `crates/executor/src/commands/doc_io.rs:1201`. Requirement: 10 SAVE-01; spec A doc.package.export; 01 §12.1 overwrite policy.

Repro/result: Open an indexed package with an unknown binary entry, truncate that source externally, and export to an existing destination using overwrite. Reading the source fails and the job fails, but the complete previous destination has already been deleted.

`doc.package.export` removes an existing file before invoking the atomic writer, defeating save_package's replace-on-success behaviour. Keep the destination until the replacement has been written and verified.

Permanent regression: `crates/executor/tests/c13_r1_persistence.rs` — `failed_package_export_overwrite_keeps_the_previous_destination`.

### C13-R1-08 — P1: Recovery does not claim an orphaned copy for its new owner

Location: `crates/executor/src/commands/project.rs:1193`. Requirement: 10 REC-01/REC-02, AUTO-04; SI-046 project.recoveryInUse; ADR-0014 §10.

Repro/result: Create stale recovery data for an untitled project. A recovers it successfully; B immediately recovers the same ID successfully as well. The persisted owner/heartbeat are unchanged. Either session can then discard-close and delete the shared binary source of the other session.

The recovery ID is installed into the open project without an exclusive recovery claim or immediate owner refresh. Claim recovery data atomically before installation, release/update that claim through save/close, and reject the second owner with project.recoveryInUse.

Permanent regression: `crates/executor/tests/c13_r1_persistence.rs` — `recovering_an_untitled_copy_claims_it_before_a_second_session_can_recover`.

### C13-R1-09 — P1: Repair at revision exhaustion is installed as clean

Location: `crates/persist/src/load.rs:357`. Requirement: 10 REV-03, REP-01 and LOAD-03; C1.2 revision-exhaustion rollback ruling.

Repro/result: Set a folder manifest's documentRev to u64::MAX and give the project an invalid name requiring repair. Loading succeeds with a repaired-count of 1, documentRev still u64::MAX, and `Loaded.repaired == false`. The executor consequently does not mark the repair as a modified load transaction.

Saturating addition makes the repaired revision equal the saved revision, and the equality is then used to decide whether repair happened. Reject an exhausted candidate requiring repair with a structured invalid-format/limit error; do not silently install an unstamped repair.

Permanent regression: `crates/persist/tests/c13_r1_format.rs` — `repairs_at_exhausted_document_revision_fail_closed`.

### C13-R1-10 — P1: Nested Windows drive prefixes pass ZIP name validation

Location: `crates/persist/src/zip.rs:85`. Requirement: 10 ZIP-01 unsafeEntry; FMT-01 equivalent safe forms.

Repro/result: `safe_name("vendor/C:/escape.bin")` and `safe_name("vendor/D:relative.bin")` return true. On Windows the same split-and-join logic used by folder writing turns the first name under C:\intended-root into `C:escape.bin`, outside the intended root.

The drive-letter check examines byte 1 of the entire name, not every component. Reject drive prefixes/Windows path special forms before accepting an archive or journal name and verify resolved write targets stay under their destination.

Permanent regression: `crates/persist/tests/c13_r1_format.rs` — `zip_names_reject_drive_prefixes_in_every_path_component`.

### C13-R1-11 — P1: Import replace silently behaves as rename for scene-name conflicts

Location: `crates/executor/src/commands/bundle.rs:1021`. Requirement: 10 §6.8 / §10.2; spec A doc.import.json; ADR-0014 §7 explicitly promises rename/replace/fail.

Repro/result: Export Scene-1 from a fresh project, then import it into another fresh project with onConflict:replace. The call succeeds with both Scene-1 and Scene-1-2; the existing scene was not replaced.

The scene conflict branch handles fail separately and routes every other policy to unique-name generation. Implement replace as an atomic replacement of the intended conflicting subtree with coherent references; retain rename only for the rename policy.

Permanent regression: `crates/executor/tests/c13_r1_persistence.rs` — `import_replace_replaces_a_same_named_scene_instead_of_renaming_it`.

### C13-R1-14 — P1: Package inspection reads the complete archive twice to identify its type

## Spec-issue adjudication

**SI-044 is a real specification conflict**, not a reason to restore invalid live state. REP-01 literally asks for undoable repairs, whereas 10 §5 and the accepted C1.2 load gate prohibit that invalid pre-state. A visible, non-undoable Repair on Open base is a defensible resolution: edit.history.get exposes it, undo is disabled at the base, the original file is unchanged until save, and discard-close is available. Recommend the spec owner adopt the base-step interpretation explicitly; do not mark the literal REP-01 row conformant before that ruling. Content preservation still needs C13-R1-05, and revision exhaustion needs C13-R1-09; the architectural decision does not discharge either.

**SI-045 is a genuine checkpoint sequencing deferral.** 10 RO-02 requires needs_confirmation; 11 §6.4/plan M1 C1.4 own that protocol. The structured project.changedOnDisk error with both choices is a reasonable C1.3 kernel precursor. The fresh package test exercises both choices. C1.4 must turn it into the actual confirmation flow and must not treat the error hint as completed confirmation. Folder detection is an independent C1.3 defect.

**SI-046 is legitimate catalogue work.** 11 §10 explicitly says area-specific codes are listed in their owning sections, so codes such as doc.unknownValue/project.saveInterrupted are not invalid merely because they are absent from the generic table. The additional runtime codes in the handoff (backup/recovery not-found, recovery-in-use, asset.inUse, fs.ioError, colour.unresolved and the two result warnings) are recorded in SI-046. Its reason-value list omits the implemented unsupportedCompression reason from zip.rs; reconcile that documentation when incorporating the list. No new modal interaction or invented confirmation code was found. Keep colour recovery owned by M2 C2.2.
