## C04-R1-01 — tablet outcome tables — fixed

ADR-0009's decision is now a rule set in four steps. The go/no-go report carries an identical copy between
`<!-- tablet-rules -->` markers, and the new test `desktop/src/test/decisionTables.test.ts` fails if the copies
differ.

- **Step 0: is the log evidence?** It covers four cases:
  - the analyzer rejects the log, or it is not a `manual` log → repeat the run;
  - a stroke is missing or marked a mistake → repeat that stroke;
  - the device lacks a capability by its specification → that row is n/a. This handles pens without tilt or barrel
    rotation;
  - synthetic input → never evidence.
- **Step 1: nine capability rows**, as ruled:
  - pen type; pressure ≥ 256 levels; pressure ≥ 1024; tilt; twist; coalesced events; sustained ≥ 120 Hz; ≥ 200 Hz;
    stationary pressure-only updates;
  - each row has numeric pass / partial / fail bounds taken **only from figures the analyzer already prints** (pointer
    column, `Hz`, pressure distinct/implied, tilt extrema, twist range and non-zero count, the coalescing line);
  - each row is applied to the web path and to each native candidate.
- **Step 2: what each web-path result requires.** Every partial and fail cell names its mitigation: a native path
  for that attribute, a documented reduced feature, or a floor change left to the user (ADR-0005). None defers. The
  native candidates have a stated priority:
  - Windows **R** (RealTimeStylus on the main window, measured in T-W1 itself), then **H** (needs E-H1), then **D**
    (needs E-D1);
  - macOS **A**, measured in T-M1.
- **Step 3: the platform decision.** The outcomes are W, a W + native hybrid, a named pending experiment, W with a
  documented limitation, platform no-go, or both-platform no-go (decision 7).

**Coverage.** The reviewer's counterexamples now resolve:
- **A 120 Hz web stream with pressure and tilt:** row 8 is partial, so W is kept below target.
- **240 Hz without coalescing:** row 6 is a fail, but row 7 passes, so W.
- **Both paths with pressure but no tilt:** tilt-driven options are disabled on that platform as a documented
  limitation.
- **A Windows pen without rotation:** twist is n/a.
- **Pressure, but incomplete tilt and twist, with unusable fallbacks:** documented limitations, not an undefined
  outcome.

No architecture is chosen.

**Measurement support.** The rows need two things the procedures did not yet have:
- **Stroke 6 (stationary pressure)** is added to the Mac test, and the "About this run" notes now ask for the pen's
  tilt and rotation support.
- **T-W1 has a written procedure** (`docs/manual-tests/M0-C0.4-tablet-windows.md`): the same six strokes, the
  diagnostics build from the CI artifact, E1 run by the builder on the same hardware, and the Windows Security
  prompts noted.

## C04-R1-02 — canvas decisions — fixed

ADR-0007 gains a normative "Canvas rule set". The report's (b) carries the identical block, checked by the same test,
and (c) defers to it. It defines:
- **Per-scene target**, the same for paths100k, groups1k and brush10k: met = complete run with `meetsTarget: true`
  (fps ≥ 57). Missed includes "insufficient samples". Failed and unavailable are separate states.
- **Back-end selection** (ruled):
  - measure both back ends at first launch and on a GPU, driver or webview change;
  - pick the back end whose **worst** scene is faster; a tie goes to WebGPU;
  - a failed back end is excluded until the next version change;
  - the user can override.

  WebGPU that is available but slower therefore selects WebGL2.
- **Outcome matrix**, covering:
  - an unanalyzable log → rerun;
  - WebGL2 failing while WebGPU works → investigate, with the platform and floor conclusion withheld;
  - both back ends failing → no-go until investigated;
  - all scenes met → go;
  - only paths100k missed → go, plus culling and level-of-detail;
  - **brush10k missed while paths100k is met (or missed)** → go-with-condition: Rust pre-tessellation and fill
    level-of-detail, re-measured in E-C2, then a native-wgpu prototype if it still misses;
  - groups1k missed → native-wgpu prototype required.

The reviewer's counterexamples:
- **60 / 60 / 40 fps on WebGL2:** go-with-condition. The report no longer says "native-wgpu prototype" for that case.
- **WebGL2 60 / 60 / 60 with WebGPU 60 / 40 / 60:** WebGL2 is selected, then go.

## C04-R1-03 — ProRes is not lossless — fixed as ruled

ADR-0008 now keeps the two properties apart:
- **Alpha-capable:** PNG-in-MOV and ProRes 4444.
- **Lossless:**
  - PNG image sequences;
  - FFV1 (native LGPL `ffv1`) in MKV, and in MOV once the muxer is verified;
  - PNG-in-MOV only after the same verification.

ProRes variants are labelled "visually lossless". JPEG sequences and H.264 are never offered as lossless. E-FF1
verifies the lossless outputs by decoding them and comparing every pixel and alpha value with the rendered frames.
SI-001 is reworded: it stays open only for the "≈ CRF 18 equivalent" question, and the lossless half is recorded as
settled by the ruling.

## C04-R1-04 — movie determinism — fixed

ADR-0008 §4 distinguishes three properties:
- **(i) Raster determinism** (06 §6.7), which ADR-0006 settles.
- **(ii) Repeat-encode determinism** (09 §11.1(6)), stated as a requirement to meet or escalate:
  - the bitexact flags and the stripped timestamps, version tag and UUID atoms;
  - fixed muxer choices;
  - single-threaded or deterministic encoder options;
  - the manifest records the encoder used.
- **(iii) Cross-platform movie identity**, which is not required.

E-FF1 now exports each format twice with `deterministic: true`, in two processes on each platform, and compares
SHA-256. It does this per muxer path (MP4, MOV, MKV) and for AAC (platform and native) separately, and inspects the
remaining metadata. If a platform encoder varies, deterministic mode uses an allowed software path on that platform:
FFV1 or PNG-in-MOV for video, native `aac` or PCM for audio. A software H.264 encoder needs a user licensing decision.
If no allowed path meets a format's guarantee, it is escalated as **SI-002**. Until a ruling, that format rejects
`deterministic: true` with a typed error. The guarantee is never dropped silently.

## C04-R1-05 — shell no-go logic — fixed

The report's shell section has a three-row outcome table:
- check failures with a running app → M1 defects;
- a non-launch **with the Gatekeeper/signing dialog reported** (text or screenshot) → M11 signing;
- **any other launch failure, exit or crash** → no macOS shell or floor conclusion until diagnostic **D-M1** has run.

D-M1 is the new step 2a of `docs/manual-tests/M0-C0.1-shell-macos.md`:
- `sw_vers` and `uname -m`;
- `file` on the app binary (architecture check);
- the headless `--selftest` on the same Mac;
- a direct launch with stderr captured;
- `log show` for the process;
- the newest `~/Library/Logs/DiagnosticReports/toontown*.ips`.

The table lists how each D-M1 result routes: a build or packaging fix; a floor question for the user (ADR-0005); or
an investigation before any macOS shell conclusion. The Qt condition stays "fails on both platforms".

## C04-R1-06 — licence-gate claim — fixed

- **The claim.** The sentence saying any FFmpeg-linking crate fails the existing gate is replaced. ADR-0008 §5 now
  states that `cargo deny` and the JS gate evaluate declared SPDX licences only, and cites the reviewer's
  `license-link-probe.json`.
- **Native-linkage check.** It is added as an **M10 C10.1 obligation** (ruled), and I run it from the first sidecar
  build at M8 C8.3. It fails on any `links` key in `cargo metadata`, or any build-script `cargo:rustc-link-lib` from
  `cargo build -vv`, outside a reviewed allow-list. That list never admits libav* or x264.
- **Component whitelist.** It is explicit: the build starts from `--disable-everything`, and every encoder, decoder,
  muxer, demuxer, parser, bsf, protocol and filter is enabled by name. The sidecar gate compares the `-encoders`,
  `-decoders`, `-muxers` and `-demuxers` lists for **equality** with the manifest, rather than checking for presence.
- Traceability has a row for the check.
