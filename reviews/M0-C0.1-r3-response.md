## C01-R3-01 — inline ESLint configuration and the escaped static global — **fixed** (`f4d551f`)

**(a) Lint.** `linterOptions.noInlineConfig: true` now applies to every JS/TS file in the desktop package, so no
inline ESLint configuration of any kind takes effect: `eslint-disable*` and `/* eslint rule: off */` alike. The two
inline exceptions that existed (`mockTransport.ts`, `schema.ts`) moved into `eslint.config.js`. `eslint-comments`
still reports any disable directive, so such comments cannot sit in the tree unnoticed. With inline config inert, the
escaped literal `'__TAURI_INTERNALS__'` is caught by the `Literal` selector, because esquery compares the
decoded value.

**(b) Bundler.** The plugin is now a pair (`desktop/boundary/vite-plugin.ts`):
- `toontown-ipc-boundary-scan` runs in normal order, after Vite's TS/JSX transform. It parses each application
  module except the transport (`parseAst` from Vite) and rejects any decoded string literal, template element or
  identifier that mentions `__TAURI` or `@tauri-apps`, plus any textual match. Plain `.js`, which Vite does not
  transpile, is parsed too, so escapes are decoded there as well. HTML and CSS get the textual scan.
- In `renderChunk`, every emitted chunk is parsed and its mentions are attributed through `chunk.modules`. Any mention
  in a module other than the transport or `@tauri-apps` package code fails the build, and the chunk's total must
  equal the attributed sum.

**Tests** (`src/ipc/boundary.build.test.ts`):
- escaped global in `.js` and `.ts`, and an escaped package name in a template, built with the real config, must fail;
- three unit tests of the chunk attribution: allowed via the transport, rejected from another module, rejected when
  unaccounted for.

The reviewer's first two cases pass.

## C01-R3-02 — `index.html` importer exception — **fixed** (`f4d551f`)

- **`build`:** no exception. `index.html`, including inline module scripts (`?html-proxy` importers), may import only
  `src/main.tsx`.
- **`serve`:**
  - A re-resolution with exactly `index.html` as the placeholder importer is accepted only for module ids this plugin
    has already approved through a real import edge (a `Set`).
  - Two narrow allowances: third-party non-Tauri packages, and, under Vitest only, its own entry files (test files,
    setup file) and test-support folders.
  - A placeholder fetch that races an in-flight edge waits for pending edges before being judged.
- **Config selection:** `dev`, `build`, `preview` and `test` in `desktop/package.json` all pass
  `--config vite.config.ts`, and Tauri's before-commands run those scripts. `boundary.build.test.ts` asserts both.
- **Vitest's transform cache:** isolating each test file revealed that its persistent `fsModuleCache` (default on in
  Vitest 5) lets a cached module skip `resolveId`/`transform` entirely. That is a boundary gap and the source of
  order-dependent results, so `test.fsModuleCache: false` is set. Every test file now passes when run alone,
  verified twice, and the full suite passes.

**Tests:**
- two HTML inline-module builds must fail (raw transport; even the host API, because only `main.tsx` is allowed),
  and the real `index.html` must build;
- a dev-server test: an unapproved transport fetch is refused, and becomes servable after `main.tsx` → `ipc/index.ts`
  approves it.

The reviewer's third case and the config-selection audit pass.

## C01-R3-05 — validation primitives above the declared floor — **fixed** (`30958cc`; ADR-0005)

The floor is kept as ruled: macOS 12.0 / Safari 15.0, and Windows 10 1809+ with evergreen WebView2 (Chrome 110 API
floor). `src/ipc/schema.ts` uses no `Object.hasOwn` and no `structuredClone`:
- `hasOwn()` wraps `Object.prototype.hasOwnProperty.call`;
- `copyPlainData()` is an own deep copy of already-preflighted plain data. It keeps the prototype (`Object.prototype`
  or `null`), defines keys (never assigns them) so an own `__proto__` stays an own key, never calls getters, and is
  validated again after copying;
- `certify` never throws.

**Automated floor check:**
- `browserslist` (`safari 15`, `chrome 110`) in `desktop/package.json` and `eslint-plugin-compat` (`compat/compat`) on
  shipped `src/**` code (tests excluded; they run in Node);
- `src/test/platformFloor.test.ts` asserts that browserslist, Vite `build.target` and Tauri `minimumSystemVersion`
  agree, and that `compat/compat` rejects `Object.hasOwn`, `structuredClone` and `Array.prototype.at` while
  accepting the floor-safe replacement;
- a unit test removes **both** APIs at once and certifies a real `createHostApi(...).ping()` response.

ADR-0005 records the floor. The handoff lists "raise to macOS 13?" as an open question for the user. Both reviewer
R3-05 tests pass. Side effect: the 1 MiB WebView2 round trip is back to p50 20.2 ms (it was ~26 ms with
`structuredClone`).

## C01-R3-03 — holes compensated by named array properties — **fixed** (`30958cc`)

This was fixed by the same rewrite. The array preflight now requires the own names to be exactly
`"0".."length-1"` (integer keys come first in ascending order), so a hole can no longer be offset by a named
property. The reviewer's three cases pass, and there are new controls (hole + name, extra name, dense arrays,
empty arrays). The traceability row records it as done.

## C01-R3-04 — uncloneable Proxy values — **ticketed to M1 C1.1** (`30958cc`)

Not fixed by the rewrite. Without `structuredClone` (the floor), a transparent `Proxy` cannot be told apart from
plain data. The new behaviour:
- `certify` copies a proxy into validated plain data through its traps, then validates the copy, so no invalid data
  is certified;
- it never throws, even for traps that throw (own test);
- it does not *reject* the proxy, which is what the reviewer's three cases expect.

Per the ruling, those three cases are marked `it.fails` with their bodies unchanged and a comment citing the ticket.
They will flip to failing when M1 rejects proxies. The ticket is in `plan/traceability.csv`, with known gap 9 in the
handoff. Real host values are JSON-parsed and are never proxies.
