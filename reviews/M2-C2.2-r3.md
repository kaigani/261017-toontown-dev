## Findings

### C22-R3-01 — P1: import revision reset corrupts opaque `meta` and `ext`, including recovery copies

**Clause:** 10 §2.2 opaque data preservation, §4.11 full swatch copies; REV-01/02 distinguish model revisions from user data; C1.3 import fidelity and the round-2 complete-copy ruling.

**Reproduction:**

```text
cargo test -p tt-executor --locked --test c22_r3_commands import_revision_reset_preserves_opaque_meta_and_ext_for_both_id_policies -- --nocapture
cargo test -p tt-executor --locked --test c22_r3_commands load_and_import_recovery_keep_nested_extensions_meta_deformable_and_path_protection -- --nocapture
```

Export a drawing with `ext["org.review.payload"] = {"type":"swatch","rev":777,"nested":[{"type":"foreign","rev":888}],"flag":true}` and `meta.record = {"type":"foreign","rev":999}`. Import with `idPolicy:"preserve"` or `"new"` (the contract's actual remapping spelling). Both operations succeed, but the three opaque `rev` values become **0**. Names, types and the other fields survive. A recovered swatch's nested extension `{"type":"foreign","rev":321}` likewise survives normal load but changes to revision 0 on import. The final recovery variant deliberately retains that failing assertion. [Raw command observations](evidence/M2-C2.2-r3/executor-r3.log).

**Required:** stamp actual imported model objects with the target transaction revision while preserving opaque user data verbatim, even when its keys resemble model fields. Recovery must not inherit already-corrupted copies.

**Cause / fix direction:** `commands/bundle.rs::reset_revs` recursively enters every member, recognizes any dictionary with `type` and unsigned `rev`, and rewrites it. It does not stop at `meta`/`ext` and does not require a known model-object position or type. Traverse actual model-object fields, preserve opaque subtrees, and stamp only objects being imported. Checking the `type` string alone is insufficient: an extension may legitimately use `"swatch"`. Add the revision-reset rule and opaque-data guard to traceability and the handoff; the response declares the change, but those two documents do not specifically record it.

### C22-R3-02 — P2: tile-on click dimensions come from sorted style IDs rather than the first palette style

**Clause:** 03 §7.2; SI-065's first-style interim rule; the R2-05 fix explicitly promises the same selection as `colour.pick`.

```text
cargo test -p tt-executor --locked --test c22_r3_commands texture_click_uses_palette_first_style_and_drag_and_tile_off_stay_unchanged -- --nocapture
```

Use a valid two-style palette whose ordered `styles` list is reversed relative to lexicographic style IDs. Its first style's tile-on texture is 17×9; the other style's is 31×23. Clicking a 100×50 zone stores **`[31,0,0,-23,1000,1050]`**; required under the accepted interim rule: **`[17,0,0,-9,1000,1050]`**. Tile-off gives `[100,0,0,50,1000,1000]`; the explicit 30×40 drag gives `[30,40,-40,30,1000,1000]` for both tile modes, and both controls execute before the failing assertion. [Raw observation](evidence/M2-C2.2-r3/executor-r3.log).

`colour.rs::tile_size` uses `s.values().values().next()`, which selects map-key order. `colour.pick` correctly uses `pal.styles().first().id()` and looks that ID up. Use the owning palette's first style, without changing the separately owned renderer-axis convention. Keep the predecessor's P2 classification for the texture default; this does not reopen the accepted first-style staging decision.

### C22-R3-03 — P1: the endpoint pass bypasses the collinear no-junction rule

**Ruling:** round-2 exact crossing classification and ADR-0017 §1: both ends on the other's line are collinear, **never a junction**; shared directions/overlap/retracing are not junctions.

```text
cargo test -p tt-vector --locked --test c22_r3_geometry exact_interior_endpoint_and_snapped_collinear_controls -- --nocapture
```

Unchanged A runs `(-10,0) → (10,0)`. Changed B runs `(-5,0) → (5,0)`. The exact pair classifier rejects the overlap, but the later T-junction pass splits A into **three** pieces at x=−5,+5. The second variant B=`(-5,0.001) → (5,-0.001)` becomes collinear only after snapping and also produces the unnecessary junctions. Both raw variants are printed before the assertion. The perpendicular endpoint control `(0,5) → (0,0)` correctly splits A once and remains required. [Raw geometry observations](evidence/M2-C2.2-r3/vector-r3.log).

**Cause / fix direction:** `planar/node.rs`'s endpoint-nearest-stroke loop adds records after `meet` has excluded collinearity; it has no shared-direction exclusion. Apply the ruled grid classification consistently to this pass while retaining true perpendicular T-junctions and endpoint ties at an existing multi-stroke junction. The general open-end proximity rule could independently be read to require the current cuts; the more specific, binding collinear exclusion governs this review. This records that interaction for the orchestrator; it does not propose withdrawing the ruling.

### Unrequested C1.3 revision normalization (REV-01)
