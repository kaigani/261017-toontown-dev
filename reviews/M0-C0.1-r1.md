# M0-C0.1 adversarial review, round 1

**Verdict: block.** There are **0 P0, 3 P1, and 4 P2 findings** against `24a2562` on `review/m0-c01-r1`. The baseline builds and tests pass, and the published Windows/macOS/Linux CI evidence is real, but the JavaScript licence gate can approve mandatory GPL/AGPL, the advertised IPC import boundary is bypassable without a lint or type error, and response validation does not enforce the types it promises. Those are existing C0.1 guards, not missing M1 features. Product code and `spec/` were not changed; only tests, test registration, review scripts, evidence, and this report were added.

Reviewed on Windows 11, Rust 1.98.1 MSVC, Node 22.23.2, pnpm 10.12.1, Python 3.13. Local evidence is in
[`evidence/M0-C0.1-r1/`](evidence/M0-C0.1-r1/). Commands below assume the checkout root. The baseline had
45 passing Rust tests and 22 passing Vitest tests. With the new regressions, the Rust adversarial target has
**5 failures and 2 passing controls**, and Vitest has **8 failures and the original 22 passes**. Clippy with
`-D warnings`, Rust formatting, front-end lint, typecheck, and formatting pass with the review additions.

## Findings

### C01-R1-01 — P1 — Licence expression parsing can approve mandatory GPL/AGPL

**Location:** `scripts/check-npm-licenses.mjs:12` (also lines 8, 13–14).

The outer-parentheses regex removes the first and last parentheses even when they belong to separate groups.
The subsequent `OR` split ignores nesting. The exported function returns `true` for:

```text
(MIT OR Apache-2.0) AND (GPL-3.0-only OR AGPL-3.0-only)
```

Every valid choice for that expression requires GPL or AGPL. Reproduce with
`node tests/adversarial/guards.mjs licensing`; it fails `true !== false`. Positive controls establish that
`MIT OR GPL-3.0-only` is accepted and `MIT AND GPL-3.0-only` is rejected. The production dependency gate calls
this exact function, so a green licence check is not sufficient to enforce the policy. No currently shipped
dependency was found to require GPL: this is a broken admission gate, not a claim about the present bundle.

There is also allow-list drift: the JS list permits `0BSD`, which the Rust list does not, and ADR-0003 adds it
although the handoff calls Unicode-3.0 the only addition. Align the lists with the approved policy or obtain an
explicit policy decision; do not silently broaden one ecosystem's gate.

**Requirement:** plan §6.3; C0.1 licensing brief; ADR-0003 rules 1, 3, 5. Correct SPDX Boolean evaluation and the
approved list must be fixed in M0, before dependencies accumulate.

**Tests:** `tests/adversarial/guards.mjs` (`licensing`, `allowlist`), called by the two `c01_r1_01_*` tests in
`tests/adversarial/c01.rs`. Both fail under `cargo test --workspace --locked`.

### C01-R1-02 — P1 — Dynamic imports bypass the front-end IPC boundary

**Location:** `desktop/eslint.config.js:23`.

Added this temporary file outside `src/ipc`, ran the real lint and typecheck commands, then removed it:

```ts
export async function bypass(): Promise<unknown> {
  const { invoke } = await import('@tauri-apps/api/core');
  return invoke<unknown>('app_info');
}
```

`pnpm lint` exits **0**, and `pnpm typecheck` exits **0**. A static `import { invoke } from
'@tauri-apps/api/core'` in the same file exits **1** with `no-restricted-imports`, establishing that the intended
rule was active. Dynamic `import()` is simply uncovered. Any UI module can call arbitrary host commands through
this path instead of the typed, replaceable transport. This is an architectural enforcement failure; it is not
a claim that a current UI module already abuses it.

**Requirement:** ADR-0001 decision 1; C0.1 typed-IPC deliverable; plan §3.1; spec 11 P2 and §2. The M0 boundary
must cover the language's supported import forms before it is relied on during M1.

**Test:** `tests/adversarial/guards.mjs` (`imports`), called by
`tests/adversarial/c01.rs::c01_r1_02_dynamic_import_cannot_bypass_ipc_boundary`. It checks the static rejection
control and fails because the dynamic bypass has zero diagnostics. Actual CLI outputs are
`static-import-lint.log`, `dynamic-import-lint.log`, and `dynamic-import-typecheck.log` in the evidence directory.

### C01-R1-03 — P1 — Host validators certify values that violate their declared types

**Location:** `desktop/src/ipc/hostApi.ts:75`; related validators at lines 61, 65, 84.

`isEngineInfo` only checks `name`, `version`, `formatVersion`, and `registryVersion`. Removing any of
`platform`, `arch`, or `runMode` from an otherwise valid response still resolves `appInfo()` successfully;
`runMode: "telepathy"` also passes. Callers receive a typed `EngineInfo` with fields missing or invalid.
The same boundary accepts `seq: -1` in a supposedly Rust-u64 ping response and forwards menu events with
`params: []` as a `Record<string, unknown>`, because `isRecord` accepts arrays.

Reproduce with `pnpm test`: six tests labelled C01-R1-03 fail. These use the real `createHostApi` with controlled
transport responses, not a duplicate implementation of the validator. This defeats the specific M0 promise
that transport values remain `unknown` until validated, and lets host/frontend drift cross the supposedly
checked boundary silently.

**Requirement:** C0.1 typed-IPC deliverable; `desktop/src/ipc/README.md`; plan §5.3 tests-before-merge;
spec 11 §10 and §14.2 provide the subsequent schema/error contract. Generated M1 types do not excuse an unsound
validator shipped and advertised in M0.

**Tests:** `tests/adversarial/frontend-cases.ts`, registered by
`desktop/src/test/adversarial.test.ts`; missing fields, invalid enum, negative integer, and array parameters.

### C01-R1-04 — P2 — Engine info is not the claimed superset of app.info.get

**Location:** `crates/engine/src/lib.rs:70` and `:105`; matching omission in `desktop/src/ipc/types.ts:31`.

The serialized object contains neither `locale` nor `languages[]`, both required by `app.info.get`.
`cargo test -p tt-headless --test adversarial_c01 c01_r1_04` fails on the actual serialized engine info.
The versions and run mode needed for the MCP handshake are present, but the handoff and source comments calling
this a *superset* of `app.info.get` are false.

**Requirement:** spec 01 §12.1 / `A_command_registry.md:58`; spec 11 §4 server info; plan M1 C1.4.
Ticket for M1: add the missing fields or distinguish the internal bootstrap-info type from the spec query.
Adding these wire keys can be additive, so there is no evidence that M1 must break existing wire fields.

**Test:** `tests/adversarial/c01.rs::c01_r1_04_info_is_a_superset_of_app_info_get`. A separate passing
`wire_engine_info_field_names_match_typescript` test compares real Rust serialization keys with the handwritten
TS interface: both sides currently agree on the same incomplete shape.

### C01-R1-05 — P2 — Browser mock and Rust disagree on the ping size limit for Unicode

**Location:** `desktop/src/ipc/mockTransport.ts:34`; contrast `crates/engine/src/ping.rs:36`.

The mock measures JS UTF-16 code units with `.length`; Rust measures UTF-8 bytes with `String::len`.
`"é".repeat(524_289)` is accepted in the mock but Rust rejects it with `limit.exceeded`,
`details.value = 1048578`, `details.limit = 1048576`. Browser tests can therefore approve a request that the
real host rejects. The current ASCII benchmark does not expose this.

**Requirement:** C0.1 interchangeable mock/Tauri transport deliverable; plan §5.3; the explicitly documented
byte contract in `crates/engine/src/ping.rs:9`. Ticket for the IPC/mock tests before extending the API in M1.

**Tests:** the failing C01-R1-05 case in `tests/adversarial/frontend-cases.ts` and the passing real-engine control
`tests/adversarial/c01.rs::c01_r1_05_rust_control_rejects_multibyte_over_limit`.

### C01-R1-06 — P2 — The no-GUI/GPU proof admits real graphics imports

**Location:** `scripts/check-headless-deps.py:24`, `:18`, `:104`.

Reproduced with a real PE executable, not just a string mock:

```text
rustc --edition 2024 tests/adversarial/fixtures/graphics_import.rs -o target/review/graphics-import.exe
python scripts/check-headless-deps.py target/review/graphics-import.exe
```

The output includes `linked libraries (win32): dcomp.dll, ...`, then `forbidden libraries: none` and
`headless dependency check passed`; exit **0**. DirectComposition is a graphics dependency. The deny list also
misses `d3d10_1.dll` and `win32u.dll`; the crate expression misses `sdl2`, `sdl2-sys`, and `ash`.
The fixture is only compiled and inspected, not executed. Its import is retained without calling the API.

The actual headless binary's imports are clean, and the desktop negative control correctly fails on six other
DLLs. The listed OpenGL/D3D11/DXGI/User32/GDI32/Shell32 and Cocoa/AppKit/Metal/QuartzCore controls all fail as
intended. `ole32` and `winmm` are absent from the deny list, but absence alone would not establish a display
dependency: COM and timing/audio uses need separate consideration. Direct import scanning also does not prove
that transitively imported or dynamically loaded libraries never load GUI code.

**Requirement:** spec 11 §3; plan M0 headless proof; handoff's no-window-system claim. Ticket to strengthen the
guard and accurately scope its claim before using it for new rendering/audio dependencies in C0.3/M1.

**Tests:** `tests/adversarial/headless_guard.py`, invoked by `c01_r1_06_*` in `tests/adversarial/c01.rs`;
the permanent executable fixture is `tests/adversarial/fixtures/graphics_import.rs`.
`graphics-import-proof.log` preserves the successful false-negative run.

### C01-R1-07 — P2 — The IPC throughput benchmark does not check the echoed payload

**Location:** `desktop/src/lib/latency.ts:39` (used by `desktop/src/diagnostics/ipcBench.ts:25`).

The measurement checks only `response.seq`. A transport that returns the correct sequence but drops every
payload (`payload: null`) still produces a report with `ok: true` for a 1 KiB burst. This would keep the CI smoke
gate green while the claimed JSON round-trip byte volume is wrong. The present Rust ping does echo the payload;
the defect is in the measurement's ability to detect a regression.

**Requirement:** plan M0 C0.1/C0.3 performance evidence; plan §5.3 tests-before-merge; handoff's "JSON both ways"
claim. Ticket for C0.3: verify payload equality/length before reporting throughput, outside the timed interval
where appropriate.

**Test:** C01-R1-07 in `tests/adversarial/frontend-cases.ts`; it deliberately corrupts only the response payload
and expects `runIpcBench(...).ok` to be false. It currently fails with `true`.

## Deferrals and residual risks for M1

- The executor/mutation-capability design remains prose. M1 must prove that model access cannot bypass the
  executor across crates, with compile-fail and parity tests; Rust crate privacy alone does not grant a separate
  crate privileged access. No existing mutable model API violates that boundary today.
- Registry, schema/example/never-block gates, MCP protocol and permissions, persistence, revision/conflict
  semantics, and E1–E7 are genuinely future milestones. No M0 shell ping test establishes those guarantees.
- `window.fullScreen.set` currently toggles host state without an `enabled` parameter. M1 must adapt the menu
  gesture into the spec's explicit boolean command, and route workspace/panel actions through queryable state.
  Predefined OS menu actions and About need a documented parity policy; the registry has no obvious About ID.
- Generated wire schemas in M1 must cover runtime validation and numeric representability, not only TS field
  names. The passing handwritten-key drift test deliberately does not claim full schema/type equivalence.
- Removing/gating release diagnostics after M0 is a real obligation. They currently write a CLI-selected path
  and exit the app; they must not accidentally become unrestricted MCP operations when that server arrives.
- C0.3 needs real renderer hashes, FMA/f32/libm/formatting coverage where used, and integrity-checked binary IPC
  measurements. This review's basic arithmetic agreement does not decide the rasterizer choice.
- Quit dirty-project handling in M1, focus-aware text editing/secondary Redo/full layout/start screen in M4,
  and signing/notarisation/universal binaries in M11 are plausible deferrals. They do not justify leaving the
  three broken C0.1 gates above until those milestones.

No product fixes were made. **Verdict remains block until the three P1 findings are resolved and re-reviewed.**
