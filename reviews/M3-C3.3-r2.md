## New findings

### C33-R2-01 — P1 — recovery deletes files outside its staging namespace

**Clause/ruling:** C33-R1-08, charter A: files not owned by the product remain untouched. ADR-0020 decision 11 grants recovery of files written with a job token, not arbitrary suffixes.

**Reproduction:** `cargo test -p tt-executor --locked -j 4 --test c33_r2_recovery recovery_preserves_non_product_marker_files`.

The independent test writes `.artist-notes.tt-partial-draft` containing `user working material`, then exports one 32-pixel frame into that directory. The export succeeds, but reading the user's file returns Windows error 2 (file not found). No product job creates token `draft`: actual staging tokens are generated from six random bytes. `staging_token` accepts any nonempty alphanumeric suffix, so `sweep` treats the user's file as stale staging and removes it.

**Observed versus required:** ordinary export destroys unrelated working material; required recovery must leave it byte-identical. The test deliberately remains failing. Its companion counter test is serialized because the evaluation recorder is process-wide; this changes no product expectation.

**Fix direction:** restrict recovery to an owned, validated staging namespace with durable ownership information. At minimum reject names/tokens the writer cannot produce; do not treat a matching substring alone as proof of ownership. Test partials and backups, malformed tokens, unrelated marker-like names and simultaneous jobs/processes. Preserve orphan restoration and warning receipts under the accepted crash contract.

### C33-R2-02 — P2 — cancelled recovery omits swept-file warnings

**Clause/ruling:** C33-R1-08 requires swept files to be listed in warnings, including cancellation/failure recovery.

**Reproduction:** `cargo test -p tt-executor --locked -j 4 --test c33_r2_wait waiting_caller_does_not_block_document_reads`.

The test starts a slow 48-frame waiting export, injects `.cancel.png.tt-partial-abcdef123456` after the entry sweep, and proves that a concurrent document read answers within 300 ms. The waiting call returns `job.waitTimeout` with its `jobId`; the test cancels that still-addressable job and waits for its final state. The file is removed and the state is `cancelled`, but the serialized final job record has neither a recovery warning nor the swept filename. The assertion checks the complete record, not an assumed warning pointer. Observed record: state `cancelled`, progress 0, message `Rendering frame 1`, with no result or error fields.

**Required:** retain the recovery warning and swept names in a caller-observable completion/error receipt. **Fix direction:** carry the result of the cancellation/failure `sweep` into the retained job diagnostic rather than dropping it. The current handler calls `sweep(&job.dir)` and discards its return; the job runner also omits the cancellation error/result. Add cancellation and failure receipts without converting either state to success. This test remains failing after its responsiveness, timeout, cancellation and cleanup assertions pass.

## Residual risks

1. C33-R2-01 blocks closure because normal export can delete user working material. C33-R2-02 additionally leaves cancelled recovery without its required diagnostics.
2. Disk-full was not induced by exhausting the host's roughly 330 GB of free storage. There is no injectable filesystem in the reviewed path. Source rollback plus directory/read-only/late-target failures do not establish every hardware, ACL, concurrent-writer or rollback-failure case.
3. Cancellation is observed around encoding and raster boundaries; no independent deterministic pause *inside* an encoder is exposed. The review does not certify a hard latency bound within one encode/flush call. Encoded-byte rejection remains a post-encoding check; the repeated PNG/hash tests establish deterministic payloads, not exhaustive incompressible-image limits.
4. Seeded depth and finite deep/broad geometry probes do not exhaust near-singular transforms. Arbitrarily tiny perturbations at an exact grouping threshold can legitimately change membership; stability claims require a margin from that threshold.
5. The counter is process-wide test machinery. Serializing recorder users is necessary; it is absent from product feature graphs. Shared-list source paths and command counts do not establish future view/cache readers.
6. `anim.changed` provides conservative invalidation, not exact pixel-change equivalence. Effects, bones, views, import, audio and hardening remain with their named milestones. Integer inspection queries stay distinct from fractional `anim.*` evaluation.
