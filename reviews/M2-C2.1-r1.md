## Findings

### C21-R1-01 — P1: fitting checks samples but misses the input polyline between them

`crates/vector/src/fit.rs:323` (`fit_run`, and `max_error` immediately above it). Fit `(0,0), (100,50), (200,0)` with smoothness 0. An independent point-to-line-segment distance checker samples each resulting cubic at 10,001 parameters: the fitted curve reaches **3.3126932006 du** from the input polyline, against **0.25 du**. The three samples alone do not constrain the intervening curve. The two-point recursive base case also accepts its tangent-controlled curve without an interior error check.

Requirement: 02 §3.3 steps 3–4 and §14 decision 4; the review brief explicitly requires maximum error against the input polyline. This is geometry C2.2 will consume. Fix the acceptance/error bound, including recursive base cases. The builder property test allows `1.5 × tolerance + .05` and measures only input samples, so its green result does not close this case.

Regression: `crates/vector/tests/c21_r1_geometry.rs::fitted_curve_stays_within_tolerance_of_input_polyline`. Evidence: [geometry-final.log](evidence/M2-C2.1-r1/geometry-final.log).

### C21-R1-02 — P1: brush placements omit pressure extrema and substantially under-sweep

`crates/vector/src/brush.rs:124–171`. Use the straight spine `(0,0) → (100,0)`, round pen min 0/max 100, pressure `[(0,0),(.1,1),(.2,0),(1,0)]`. At normalized arc length .1, the swept tip is a radius-50 disk centered at `(10,0)`. The computed outline's maximum y is only **32.3296471893**; `(10,49)`, a full du inside the required disk, is outside the returned fill. This is much larger than union-grid or outline-fitting approximation error.

Requirement: 02 §3.2 pressure interpolation and §3.4 continuous width and union of swept tips. Placements must account for pressure-map knots and curvature/arc-length error; a fixed placement interval alone cannot guarantee the union. The existing “cover every tip” property checks expanded bounding boxes of spine anchors, not tip containment.

Regression: `c21_r1_geometry::brush_sweep_includes_pressure_peak_between_placements`. Same geometry log retains the bounds and failure. The separate square-loop hole control and tip/dab/reversal matrix pass; those controls do not negate this pressure case.

### C21-R1-03 — P1: three implemented setters reject the common target parameters

`crates/executor/src/commands/draw_stroke.rs:504`, `draw_text.rs:337` and `draw_text.rs:510` parameter structures. `draw.stroke.set`, `draw.text.set`, and `draw.textFormat.set` with a local ID, `elementId: scene:#1/element:"Bob"`, and `frame: 1` all return **`arg.unknown`** for `elementId`/`frame`. Their helpers resolve only a drawing ID, a compound object ID, or current drawing.

Requirement: 02 §13.1(4); ADR-0016 §2 and SI-056 explicitly promise this superset for every C2.1 drawing command. Reuse common target resolution and retain `drawing.staleRevision` checks on the resolved drawing. This is not the separately declared scene/view-coordinate deferral.

Regression: `crates/executor/tests/c21_r1_contracts.rs::object_setters_accept_common_cell_addressing`. [contracts-final.log](evidence/M2-C2.1-r1/contracts-final.log) retains all three error envelopes.

### C21-R1-04 — P1: simultaneous outline and spine edits retain contradictory authorities

`crates/executor/src/commands/draw_stroke.rs:814`. Create a brush, then use one `doc.object.patch` to replace `/points/0/0` with 1000 and `/spine/pressure` with `[[0,.2],[1,.2]]`. The transaction commits the distant outline **and keeps the old spine** with the changed pressure. The `(spine_changed=true, outline_changed=true)` match falls through. A later pressure edit can consequently erase the direct outline edit by re-sweeping the stale spine.

Requirement: 02 §3.2 and §14(2), direct outline edits discard the spine; §13.6 requires the same validation/update through generic properties. Prefer rejecting contradictory simultaneous authorities or consistently making the directly edited outline authoritative. Full staged validation must remain in place.

Regression: `c21_r1_contracts::direct_outline_edit_discards_spine_when_pressure_also_changes`. The complete committed stroke is in the contracts log. The builder's isolated spine-only and outline-only patch tests pass.

### C21-R1-05 — P1: generic text patches bypass paragraph invariants

`crates/model/src/validate.rs:422` validates text runs but never checks paragraph ranges against the text; `crates/executor/src/commands/doc.rs:949–953` normalizes only stroke targets. Create `"one\ntwo"`, then patch `/paragraphs` to `[]`. This succeeds, advances the revision, and persists zero paragraphs for two lines. Read-back normalization can hide the malformed stored state by synthesizing paragraphs later.

Requirement: 02 §3.7, 10 §4.9 paragraph representation, 02 §13.6 generic-property equivalence, and binding obligations 3/10. Enforce the paragraph representation at the common integrity boundary, including ranges, rather than relying only on text command constructors. Reject atomically or normalize before committing.

Regression: `c21_r1_contracts::generic_patch_enforces_one_paragraph_per_line`. The contracts log shows committed length 0 versus required 2.

### C21-R1-06 — P1: valid dense input monopolizes fitting beyond the document watchdog

`crates/vector/src/fit.rs:174–214`, `corners`/`reach`. Supply 100,000 distinct points `(i × 10^-9, 0)`, smoothness 3, closed true. Every point lies within the tolerance of every other point, so each directional reach scans almost the whole list for each point: approximately 20 billion distance checks. The subprocess still runs at **30 seconds** and the regression terminates it. The open-path control finishes in **29.49 seconds** locally. This is not a non-returning test hook: ordinary accepted geometry reaches this path.

Requirement: binding obligation 11 (bounded geometry work/autosave responsiveness), 02 §3.3 sample processing and §13.1 agent operation, ADR-0013's serialized-worker/watchdog limitation. Caller timeout does not stop this computation or free the document worker for autosave. Remove the quadratic search for below-tolerance neighborhoods or reject/handle this degeneracy promptly without changing the geometric contract.

Regression: `c21_r1_geometry::dense_100k_input_finishes_within_document_watchdog_budget`. Its ignored worker is an operational child explicitly executed by the ordinary parent test, which kills and reaps it at the bound. [dense-closed-input.log](evidence/M2-C2.1-r1/dense-closed-input.log) and the final geometry log retain the timeout; [dense-input.log](evidence/M2-C2.1-r1/dense-input.log) retains the passing open control. This probe does not establish a cross-machine runtime bound.

### C21-R1-07 — P1: drawing content edits do not emit the required drawing event

`crates/executor/src/run.rs:560–570` emits only `doc.changed`; no product producer of `draw.drawing.changed` exists. Subscribe, change the drawing pivot, undo, and redo. All three calls emit generic document events but **no `draw.drawing.changed`**. The registry still labels that event NotImplemented, owner M2 C2.3.

Requirement: 02 §13.6, §3.12 revision/identity reporting, and spec A's `draw.drawing.changed` row: every content change, including undo/redo, reports drawing ID/revision, command ID and created/modified/removed IDs. Deferring the event declaration does not implement that contract for the content commands now enabled. Emit from the common commit path so patches, batches, undo/redo and checkpoint restore agree.

Regression: `c21_r1_contracts::content_changes_emit_drawing_event_including_undo_redo`. All observed event names are retained in the contracts log.

### C21-R1-08 — P1: edit results omit their resolved drawing identity

`crates/executor/src/commands/draw_stroke.rs:537` (`StrokeSetResult`); analogous result types in `draw.rs:510` and `draw_text.rs`. `draw.stroke.set` succeeds but returns only `strokeIds`, `removedIds`, and `rev`; `drawingId` is absent. Pivot, delete, group/ungroup, text-set and text-format results have the same omission. When these operations default to current drawing, agents cannot identify the resolved drawing directly from the promised result. Generic envelope change records are a different contract.

Requirement: 02 §13.1(11): every edit result includes `{drawingId, rev}` and changed-ID reporting. The shorter §13.5/spec-A rows do not explicitly revoke the common rule. Add the common identity to result declarations, generated IPC, and retained examples; audit all edits' created/modified/removed reporting at the same time.

Regression: `c21_r1_contracts::edit_results_report_the_resolved_drawing`. The result schema currently validates the omission, demonstrating why schema validation alone is insufficient.

### C21-R1-09 — P1: decomposed Unicode text is rejected after run lengths become stale

`crates/executor/src/commands/draw_text.rs:256` and `:403`, together with `crates/model/src/input.rs:204–223`. `draw.text.add` with `"e\u0301"` fails `arg.invalid / runsCover`; creating `"e"` and inserting `"\u0301"` at code-point index 1 fails identically. Constructors compute runs/paragraphs for the unnormalized text; the model then NFC-normalizes it to one code point while retaining the two-code-point ranges.

Requirement: 10 §1.1 NFC strings, §4.9 code-point ranges, 02 §3.7/§7.6 text editing. Normalize text and update its formatting ranges consistently, including compositions spanning an insertion/run boundary. This prevents ordinary combining-character input before any renderer exists. The pure-layout Unicode smoke test passes because it bypasses the model input boundary.

Regression: `c21_r1_contracts::decomposed_unicode_text_is_accepted_and_ranges_follow_normalization`. [unicode.log](evidence/M2-C2.1-r1/unicode.log) retains both failures. The initial real MCP run independently encountered the same error in [surfaces.log](evidence/M2-C2.1-r1/surfaces.log).

### C21-R1-10 — P2: a valid closed path at the advertised anchor limit cannot reimport its read-back

`crates/vector/src/path.rs:182`: `n / 3 + 1 > MAX_ANCHORS` counts an extra endpoint even for a closed Bézier list. A closed `Path` with 100,000 anchors passes `Path::check`; its own 300,000-control-point Bézier list is rejected as exceeding 100,000 anchors. Open paths need the extra endpoint; closed paths do not. This is an engine boundary inconsistency, not a claim that the spec mandates 100,000 anchors in a single stroke.

Requirement: 02 §13.4 Bézier conventions and read-back/content round trip; declared `MAX_ANCHORS` contract. Owner: builder C2.1, before expanding the large-path corpus in C2.4. Regression: `c21_r1_geometry::closed_path_at_anchor_limit_reimports_its_own_bezier_list`; [anchor-limit.log](evidence/M2-C2.1-r1/anchor-limit.log).

## P2 follow-ups and residual C2.2 risks

**C21-R1-11 (P2, builder C2.1/C2.3 before enabling symmetry through M4 C4.2):** extend the cross-OS corpus to nonidentity mirror/kaleidoscope maps and configured command-created copies. `symmetry_setting` currently returns `(None,false)` unconditionally; a `symmetry:true` command in the digest exercises identity only. Text layout bounds are intentionally excluded and need same-font layout tests, not a false cross-machine equality promise.

**C21-R1-12 (P2, builder C2.4, final scale gate M11 C11.1):** retain the measured 100k-stroke edit/allocation/OS-memory/queue-delay budgets when replacing whole-entry staging. Current normal edit latency is a documented performance limit; optimize while preserving the full semantic/reference gate, exact inverses and dropped-snapshot reconstruction. The snapshot object count is not a byte budget, and explicit checkpoints still retain snapshots independently.

C2.2 must not build on out-of-tolerance spines, under-swept brush boundaries, contradictory spine/outline state or malformed stored text. Resolve the nine P1s first. Expand bridge/holes/disconnected-contour and large-coordinate tests before trusting coincident-edge topology; existing small-grid controls and cross-OS equality do not prove general containment or absence of self-intersections. Preserve missing-colour reporting until actual recovery exists. UI gesture equivalence, final pixels, device QA and attached multi-client behavior keep their C2.3/M3/M4 owners.
