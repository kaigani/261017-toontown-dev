**C01-R2-02 — P1 — Schema validation mistakes inherited properties for declared or validated fields**

Locations: `desktop/src/ipc/schema.ts:62–65`, with the overly broad object predicate at line 26.

`schema.properties[k]` searches the prototype chain. For undeclared JSON keys `__proto__`, `constructor`, `toString`, and `hasOwnProperty`, it finds an inherited object/function and treats it as a property schema. That object has no `type`, so validation succeeds instead of enforcing `additionalProperties: false`. For example, JSON-parse a valid EngineInfo with `"__proto__": {}` added: the real `createHostApi(...).appInfo()` resolves successfully. The same bug bypasses nested-object extra-key rejection. These inputs are ordinary JSON with own properties; no global prototype pollution is required or performed by the test.

Separately, required-field checking uses `k in value`, whereas value validation only visits `Object.entries(value)`. A transport returning `Object.create({seq: 'not a u64', payload: [], engineUptimeNs: 'not a u64', handlerNs: -1})` therefore resolves `host.ping()` as a certified `PingResponse` without validating any fields. That second repro is an in-process transport-object attack, not a claim that normal JSON parsing synthesizes inherited fields. The advertised `unknown`-to-typed validator still must not certify it. The previous guard read and checked each field and rejected this case.

Requirement: C0.1 typed-IPC contract, `src/ipc/README.md`, response C01-R1-03's promise to validate every field and reject unknown keys; plan §5.3 and the subsequent spec 11 §14.2 schema boundary. Required fields and schema property membership need own-property semantics; non-plain transport objects must not bypass validation.

Permanent tests: [`desktop/src/test/c01-r2-schema.test.ts`](../desktop/src/test/c01-r2-schema.test.ts), automatically included by Vitest. Repro command: `pnpm --dir desktop exec vitest run src/test/c01-r2-schema.test.ts`. **Seven failures, five passing controls**; full output is `schema-attacks.log`.

Controls reject NaN/Infinity, negatives, fractions, 2^53, numeric strings, nested arrays, ordinary extra keys, and prototype names used as enum values. Negative zero is accepted as the integer zero. `anyOf` behaves correctly for tested branches. The current fixed wire patterns handle 100,000-character adversarial inputs promptly; schemas are internal, so an arbitrary hostile regex is not currently an external attack surface. Invalid-response errors do not expose rejected payload values. All current response/event entry points use the guards; no product `as EngineInfo`/`as PingResponse` bypass was found. This is a validator defect rather than an omitted call site.

**C01-R2-03 — P2 — Malformed SPDX operands are accepted behind a permitted OR branch**

Locations: `scripts/check-npm-licenses.mjs:56`, `:84`, `:103`.

The parser considers any non-operator token an identifier, including `+`, `:`, `and`, an empty-suffix `LicenseRef-`, and `MIT++`. Consequently `satisfies('MIT OR +')`, `satisfies('MIT OR and')`, and `satisfies('MIT OR GPL-3.0-only WITH +')` all return **true**. An unknown SPDX identifier hidden behind MIT also passes. Boolean evaluation is now correct, but it evaluates a tree whose operands have not all been validated as SPDX syntax.

Requirement: ADR-0003 rule 1 and the response's explicit malformed/non-SPDX fail-closed claim; [SPDX Annex D.1/D.4.2](https://spdx.github.io/spdx-spec/v2.3.1/SPDX-license-expressions/) requires valid operands on both sides of OR. This is P2 because the reproduced expressions still have an explicit MIT alternative; I found no recurrence of the original valid-expression mandatory-GPL acceptance and no currently shipped forbidden dependency. Ticket full syntax/identifier validation before adding dependency exceptions. Valid `LicenseRef-private` alone is rejected by policy, while `MIT OR LicenseRef-private` correctly passes; that is not part of this finding.

Permanent test: [`tests/adversarial/c01-r2-licenses.test.mjs`](../tests/adversarial/c01-r2-licenses.test.mjs), included by the Vitest node wrapper. `node --test tests/adversarial/c01-r2-licenses.test.mjs` yields **one failure and three passing controls**. Evidence: `license-attacks.log`.
