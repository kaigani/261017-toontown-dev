## New findings

### C12-R4-01 — P1 — stamped checkpoints produce phantom staged drawing changes

**Regression from `79e3c59`.** `checkpoint.create` now captures `Cx::stamped_document()` (`crates/executor/src/commands/checkpoint.rs:78`, `cx.rs:577`), fixing the original post-commit stamp defect. But `doc_diff`'s `state_at` still clones the **unstamped** staged document (`crates/executor/src/commands/doc.rs:1255`). Its fallback drawing invalidation compares the checkpoint's new drawing revision against the staged drawing's old revision (`doc.rs:1359`). The unequal stamps manufacture a change where content is identical.

Reproduce an atomic batch of `doc.object.patch` on a stroke, `checkpoint.create`, then `doc.diff {sinceCheckpoint: ...}`. Actual: `fromRev:2,toRev:2`, with one drawing `modified`, `rev:2`, `patch:[]`. Expected: `changes:[]`. A second test interleaves an outer checkpoint, an unrelated scene edit, an inner checkpoint and queries of both: the unchanged drawing is still spuriously reported. The same queries immediately after commit are empty, proving the staged/committed inconsistency. This violates spec 11 §7.3 query visibility and the retained checkpoint/diff contract.

**Evidence:** [immediate envelope](evidence/M1-C1.2-r4/checkpoint-staged-immediate.json), [nested envelopes](evidence/M1-C1.2-r4/checkpoint-nested.json), [permanent regression log](evidence/M1-C1.2-r4/logs/new-regressions.log). Tests: `immediately_querying_a_staged_checkpoint_is_empty`, `nested_checkpoints_do_not_reinvalidate_unchanged_drawing_content`.

**Correction:** compare coherent revision views or derive invalidation from semantic changes when querying staged state. Preserve post-stamp checkpoint content, point-in-batch snapshots, rollback, restoration and real drawing invalidation. Owner: **C1.2 executor builder**. Command row `doc.diff`; requirement rows R12 and R37.

### C12-R4-02 — P1 — context typing imports sibling-command constants

**Regression from `49c2133`.** `field_index` groups commands by their first two ID segments and uses `into.setdefault(k, v)` for every nested typed field (`scripts/gen-command-declarations.py:952`). - `export.publish.service.list` with a signed-in service's `connected:true` is rejected because `export.publish.account.close` supplied `{const:false}`. The owning section explicitly supports service sign-in and boolean account status (09 §4.9, §12.3). The `account` and `service` subfamilies share the overly broad `export.publish` key.
- `storyline.play.changed {playing:false,globalFrame:17,sceneId:"closure-scene"}` is rejected because `storyline.play.start` supplied `{const:true}`. The event explicitly covers both started and stopped playback (08 command table, lines 731–739).

The independent random sample found the first row; a targeted scan of newly added constants found the second. Different two-segment families remain isolated in the probe, but that does not prevent the demonstrated subfamily collision or command-local constant narrowing. Permanent tests: `configured_publishing_services_can_be_connected`, `storyline_playback_changed_can_announce_a_stop`.

**Correction:** use the owning field's domain and structural context; do not use a sibling's command-specific literal as a general field type. Preserve the fourteen repaired declarations and SI-tagged placeholders. Owner: **C1.2 registry builder**; eventual handlers remain with **M10 C10.2** and **M9 C9.2**.
