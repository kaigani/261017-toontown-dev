**C01-R4-01 — P1 — Final constant folding happens after the emitted-chunk boundary scan**

Location: `desktop/boundary/vite-plugin.ts:220` (`renderChunk`); the scan introduced in `f4d551f`. Requirement: the binding R3-01 ruling and ADR-0001 require every emitted mention to be attributable to the transport or Tauri package code. Target: C0.1, before closure.

This ordinary `.js` source has zero lint diagnostics:

```js
export const bypass = () => window[
  String.fromCharCode(95,95,84,65,85,82,73,95,73,78,84,69,82,78,65,76,83,95,95)
].invoke('app_info');
```

With the real production Vite config and its default minification, it builds to:

```js
var e = () => window.__TAURI_INTERNALS__.invoke("app_info");
export { e as bypass };
```

The permanent regression imports that emitted module against a stub `window` and verifies that `bypass()` calls the raw host with `app_info`; it then fails explicitly. The code is retained, callable, and outside both allowed origins. There are no runtime variables or unknown inputs in the property-name expression. The compiler actually folds it, so the accepted limitation for names assembled at runtime does not dispose of this case.

`node reviews/evidence/M0-C0.1-r4/late-fold-app.mjs` independently reproduces it through the **ordinary app build**, injecting an import into the real `main.tsx` through a fixture transform without editing it. Even a diagnostic `renderChunk` hook with `order: 'post'` sees `String.fromCharCode(...)`; the final app bundle contains `window.__TAURI_INTERNALS__.invoke(...)`. Thus moving the existing scan later within that hook alone is insufficient. The final output needs a check after compiler folding/minification, with the required origin enforcement retained. No product fix was made here.

Permanent test: [tests/adversarial/c01-r4-boundary.test.mjs](../tests/adversarial/c01-r4-boundary.test.mjs), registered through [desktop/src/test/c01-r4-node.test.ts](../desktop/src/test/c01-r4-node.test.ts). Evidence: `r4-regression.log`, `late-fold-app.json`, `review-test.log`. This is an incomplete R3-01 repair, not a claim that the round-3 change first introduced computed global access.
