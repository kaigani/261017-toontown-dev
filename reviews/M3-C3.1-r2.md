### C31-R2-01 ? P1 ? Splitting delegated writes reorders RFC 6902 operations

- **Clause/ruling:** 10 AG-02; ADR-0013 ?2; C31-R1-03 requires the owning semantics for RFC 6902 as well as `props`.
- **Reproduction:** `cargo test -p tt-executor --locked -j 4 --test c31_r2_variants r03_rfc_test_must_observe_the_preceding_delegated_write`.
- **Input:** set Bob's note to `before731`, then patch with `[test /note == before731, replace /note = after731]`.
- **Observed:** `doc.patchTestFailed`, although the test precedes the write and should pass. The command rolls back. `doc_object_patch` separates delegated operations from the remainder, applies all delegated writes first, then applies the ordinary operations, including `test`.
- **Required:** preserve RFC 6902 operation order over one staged object. The shown patch succeeds and is one undo step; a later failing test must roll back every earlier effect.
- **Fix direction:** dispatch delegated operations while interpreting the ordered patch, using the shared owning handlers and one acceptance transaction. Do not reorder operations by property ownership. Preserve `props` followed by `ops` ordering too.
- **Independent transport evidence:** `sdk-r2.json` reproduces the refusal through official `mcp==2.0.0`, with a fresh project.

### C31-R2-02 ? P1 ? RFC `copy` bypasses delegated semantics and events

- **Clause/ruling:** 10 AG-02; 04 ?10.2, ?13.21, ?17.4; C31-R1-03.
- **Reproduction:** `cargo test -p tt-executor --locked -j 4 --test c31_r2_variants r03_rfc_copy_to_visibility_has_the_owning_command_consequence`.
- **Input:** make Bob current, hide it in the scene, then `doc.object.patch` with `{op:"copy",from:"/visibleInScene",path:"/visibleInXsheet"}`.
- **Observed:** `visibleInXsheet` becomes false, but Bob remains current and no owning `element.state.changed` event is emitted. `delegated_op` handles `add`/`replace` and some `remove` operations only; `copy` falls through to generic mutation.
- **Required:** an RFC write to a delegated property has the same validation, application, UI consequences and area events as the owning command. Hiding the current column moves the current element and announces the change.
- **Fix direction:** resolve the copied value from the current staged object and feed the destination write through its owning handler. Audit RFC `move` source removal/destination writing under the same rule; do not add another semantic implementation.
- **Control:** all seven delegated families, both patch forms, both colour and visibility fields, compare field-by-field with direct commands; objects, selection and complete area-event payloads match for the tested `replace`/`props` forms. A two-bank, four-user clone test also passes. Official SDK evidence independently reproduces the bypass.

### C31-R2-03 ? P1 ? Generic cell paste can overwrite vector artwork with image cells

- **Clause/ruling:** 04 ?13.16 typed clipboard and `cell.typeMismatch`, ?13.21 image-to-vector refusal; C31-R1-04's common typed payload/bridges.
- **Reproduction:** `cargo test -p tt-executor --locked -j 4 --test c31_r2_variants r04_generic_bridge_refuses_image_cells_into_vector_column`.
- **Input:** copy Background image cells 1?2 with `cell.clipboard.set`, then `edit.paste {context:"xsheet",destination:{elementId:Bob,frame:20}}`.
- **Observed:** success, one revision, and the image drawing named `1` overwrites Bob's same-named vector drawing. The receipt records deletion of Bob's vector nodes and colour-recovery entry. Generic paste reads the shared payload but does not enforce its source column type.
- **Required:** `cell.typeMismatch` and no document/history mutation, as the cell-specific bridge requires. A vector bank accepting bitmap nodes structurally does not permit this column-type transfer.
- **Fix direction:** share source/destination compatibility validation with `cell.clipboard.apply`, before binary insertion or drawing placement, including deleted-source and cross-project cases. Add both transfer directions and the generic special-paste entry point as controls.

### C31-R2-04 ? P1 ? Generic cut leaves notes on removed or cleared cells

- **Clause/ruling:** 04 ?7.2, ?13.16; SI-093; C31-R1-05. Notes follow cells; cut/remove clears their notes.
- **Reproduction:** `cargo test -p tt-executor --locked -j 4 --test c31_r2_variants r05_generic_cut` (two failing tests).
- **Input:** after clearing fixture notes, note frame 1 as `cut731` and frame 3 as `tail731`; select 1?2. Test ordinary `edit.cut` and `edit.cutSpecial {options:{createDeleteExposure:true}}` separately.
- **Observed:** both leave `{1:"cut731",3:"tail731"}`. Ordinary cut should clear note 1; shifting cut-special should remove it and move `tail731` to frame 1. The generic cell-deletion branch only patches `/exposure`.
- **Required:** the same SI-093 note mapping as `cell.clipboard.set {cut:true}`, in the same transaction and undo step.
- **Fix direction:** use the shared note/exposure edit path for generic cut, cut-special and applicable generic delete routes; keep copied notes in the shared payload. Retain independent undo/redo and save/open controls.
- **Controls:** all 12 cell-specific operators pass new two-end note probes and undo/redo, overlapping move onto noted cells passes, and shifted notes survive save/open. The new official SDK probe independently confirms ordinary generic cut leaves its note.

### C31-R2-05 ? P1 ? Derived names still exceed the valid 64-character domain

- **Clause/ruling:** 04 ?3.2, ?4.2, ?13.16; 10 ?1.3; C31-R1-08's valid generated-name boundary.
- **Reproductions:** `cargo test -p tt-executor --locked -j 4 --test c31_r2_variants r08_max_length_effect_name_keeps_required_derived_rows_valid`; run `r08_generic_new_drawing_copy_name_fits_64_characters` in the same target.
- **Observed A:** creating a clipping element named with 64 `?` characters refuses `doc.schemaViolation`: the generated `-mask` row is 69 characters. `unique_names` bounds its `_n` branch, but takes an overlength derived base unchanged when it is free. The clipping case is the executable reproduction; skeleton/particle row generation uses the same path.
- **Observed B:** copy a drawing named with 64 `?` characters to a bank already containing that name, then generic `edit.pasteSpecial` with `overwriteDrawings:false`: the dashed `-2` branch produces 66 characters and refuses `doc.schemaViolation`.
- **Required:** valid source/base names have deterministic, unique generated companion/copy names inside 64 Unicode characters. Required rows cannot make a valid creation request fail.
- **Fix direction:** centralize bounded derived-name planning, including its unsuffixed base and the generic dashed-copy branch. Truncate before adding the meaningful suffix, then test collisions after truncation and digit-width changes. Do not truncate caller-entered names silently.
- **Controls:** three NFC-equivalent clone-column names create one drawing, and element clone/duplicate suffixes cross `_9` to `_10` correctly. The official SDK also reproduces the 64-character clipping refusal.

### C31-R2-06 ? P1 ? Binary clipboard entries are not remapped on a destination collision

- **Clause/ruling:** 04 ?13.16, ?14.1??14.2; C31-R1-04 requires self-contained artwork and destination remapping.
- **Reproduction:** `cargo test -p tt-executor --locked -j 4 --test c31_r2_persistence r04_binary_entry_collision_must_not_replace_copied_art_with_destination_bytes`.
- **Input:** two distinct seeded, saved projects contain different valid 1?1 PNGs at `banks/review-r2-shared.png`. Copy the source Background cell, open the destination project, paste at frame 30, save, and read the referenced blob from the saved package.
- **Observed:** pasted drawing metadata retains source hash `69f47bd20953bfac24e3caf5ba9fbe8a7b19222518c1641568b294e4cb6c1845`; its actual entry bytes hash to destination value `7761f8b75934f679ca2a8b6239a76cfa14b925e237617e104fb4c1103ef4783b`. `ArtPayload::ensure_blobs` inserts only when an entry is missing and never compares/remaps a collision.
- **Required:** copied artwork retains its bytes and destination artwork retains its own bytes. The copied drawing's reference must follow a newly planned destination entry when content differs at that name.
- **Fix direction:** stage a command-wide blob mapping with byte/hash comparison, deterministic fresh entry allocation, and rewriting of typed drawing/texture/asset references. Preserve opaque namespaces. Apply accepted blob changes with the same transaction; test failed/dry-run calls do not leak binary changes.
- **Control:** source deletion ? project close ? another project ? paste ? save/open with no entry collision preserves the actual source bytes. The finding uses byte hashes rather than the deferred bitmap renderer.
