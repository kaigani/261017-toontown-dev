### C44A-R1S-01 | P2 | S2 | A second window can replace a settled decision

Rule: D-58 and design note 2 section 4: the agent receives the person's decision and a request decided elsewhere leaves the sheet.
Location: crates/executor/src/commands/agent.rs:528-545 (especially pending.decision assignment at 539).
Input/state: two windows show confirmation cf_X for an overwrite. Window A sends {confirmationId: cf_X, accept: false}; before the MCP hold's next 100 ms poll, window B sends {confirmationId: cf_X, accept: true} from its still-visible sheet. Reverse the booleans for the opposite failure.
Expected: the first decision settles the request; subsequent answers are refused without changing it.
Deduced: respond only prunes by age, gets the still-present record and unconditionally assigns Some(accept). Both commands succeed; the held call consumes the last answer and may overwrite despite the first Decline. The sheet's asynchronous re-read cannot serialize two windows.
Smallest fix: reject a record with decision already set (and an expired record) before assigning; add a kernel test with two consecutive conflicting responses before token consumption.
