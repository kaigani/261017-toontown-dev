**New findings**

**C11-R3-01 — P1 — Ordinary opaque text changes acquire mouth-track validation.**

`crates/model/src/change.rs:471` recognizes a range solely from the suffix `/mouthTrack/mouths`, including inside opaque data. The new validator at `:695` permits only A–G/X, so a schema-valid Pen with `meta["com.example.tool"].mouthTrack.mouths = "hello"` cannot be diffed/applied to the equally valid value `"world"`: `apply` returns `arg.invalid` at the metadata pointer. The same reproduction fails under `ext`. This is a new observable regression from e49b4e9: before its letter validation, this overbroad range selection did not refuse ordinary strings.

**Requirement:** spec 10 §2.2 (`meta` never interpreted, `ext` preserved), §2.6 usable/invertible changes; R1-03. **Permanent test:** M3 `opaque_mouth_track_lookalikes_are_ordinary_json_changes` (`:115`) first validates both full Pen objects and then records failures for both namespaces. Restrict semantic range detection to actual declared mouth-track slots; opaque JSON edits must retain general JSON semantics. **Owner:** model builder. **Due:** C1.1 closure before C1.2.

**C11-R3-02 — P1 — Stateless move inverse confuses numeric object members with array indices and corrupts unrelated data.**

`change.rs:584` shifts a destination whenever the source token parses as an integer, without knowing the parent container type. Start with `{"a":{"0":"source","1":{"x":"old"},"2":{"x":"untouched"}}}`. Apply `move from /a/0 to /a/1/x, oldValue:"old"`, then `invert(patch)`: the inverse copies the moved value back to `/a/0` and replaces **`/a/2/x`**. Both operations succeed; `/a/1/x` remains `"source"` and the unrelated `/a/2/x` becomes `"old"`. There is no error or pre-state restoration.

**Requirement:** spec 10 §2.6; public `invert` rustdoc promises exact results for concrete paths carrying overwrite oldValue. **Permanent test:** M3 `resolved_stateless_move_inverse_does_not_shift_numeric_object_keys` (`:138`); its `invert_against` control succeeds. This source-attributed e49b4e9 regression is outside the passing pre-state property, which never tests the stateless function. Remove the unsafe general promise/API or require enough state to distinguish array insertion from object-member insertion; unsupported cases must fail without corrupting content. **Owner:** model builder. **Due:** C1.1 closure; C1.2 must use `apply_with_inverse`.

**C11-R3-03 — P1 — Invalid exposure range payload with count zero silently removes a frame.**

`change.rs:373` deserializes runs into `(Option<Id>, u32)` but does not enforce count ≥ 1; the `0..c` loop treats a zero count as an empty replacement. The new `apply_range` validation at `:710` relies on that expansion. On `{"exposure":[["dr_a",3]]}`, replace `/exposure` with range `{from:2,to:2}`, `oldValue:[["dr_a",1]]`, `value:[["dr_b",0]]`. It **succeeds with `[["dr_a",2]]`**, silently deleting an exposure frame. Subsequent validation of the result cannot detect that the malformed input requested an invalid run.

**Requirement:** spec 10 §4.7 count ≥ 1; §2.6 range changes; R2-03's complete typed payload validation. **Permanent test:** M3 `zero_length_exposure_runs_are_invalid_range_payloads` (`:102`), also covering a valid run followed by a zero run. This is incomplete R2 closure, not a claim that zero-run acceptance was newly introduced. Validate each run's count and frame-domain bounds before expansion/splicing; return a typed error atomically. **Owner:** model builder. **Due:** C1.1 closure before transaction/patch consumers.

**C11-R3-04 — P2 ticket — Property discovery intersects mutually exclusive alternatives.**

`schema.rs:657` merges every candidate's first occurrence of each keyword into one object. `property_schema(Pen,"/colourId")` now has both `anyOf(Id,null)` and top-level `type:"string"`/Id pattern, rejecting the valid `null`. `property_schema(Pen,"/tip")` acquires `const:"round"`, rejecting `oval`, `square` and `flat`. The whole-object schemas remain correct. This is an e49b4e9 regression; nested path discovery and reference annotations can remain fixed while this domain narrowing is repaired.

**Requirement:** spec 10 §2.8 and §10.2; R1-19/R2-06. **Tests:** M3 `property_schema_preserves_nullable_value_domains` (`:158`) and `property_schema_preserves_every_enum_alternative` (`:185`). **C11-R3-05 — P2 ticket — Mixed double/wide-integer alternatives reject valid replies.**

`wireJson.ts:302` probes a branch either with every bigint unchanged or every bigint converted to Number. A valid branch requiring **both** a large double and a wide integer matches neither probe. With three numeric alternatives discriminated by `kind`, `{kind:"mixed",x:1e19,revision:9007199254740997n}` validates as an in-memory schema value but `certifyWireText(stringifyWireJson(value), schema, {})` returns `undefined`. **Requirement:** spec 10 §2.8 and ADR-0012 lossless/schema-directed readback; R2-05. **Tests:** T3 mixed branch (`:40`) and generated nullable reply (`:46`).
