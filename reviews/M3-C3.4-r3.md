## New findings

### C34-R3-01 — P1 — a blocking caller probe stalls unrelated requests beyond their watchdog

Ruling: probe misbehaviour / document-thread stall beyond budget for other callers. Permanent reproduction: `crates/executor/tests/c34_r3_probes.rs::blocked_probe_does_not_starve_other_callers_past_watchdog` (fails). Use an 800 ms executor budget; let the first acceptance probe return false, then block its dequeue answer for six seconds. Issue an unrelated state query while the probe blocks. Required: other callers retain usable service within the watchdog. Observed: unrelated query times out after **804.3755 ms**; the worker waits in `caller::asks` for up to **five seconds**, exceeding the configured budget. The isolated final repeat timed out after **812.2404 ms** with the same 800 ms budget. Subsequent state query succeeds, so this is a stall, not permanent death. Fix direction: avoid synchronously gating the document worker on arbitrary caller code; enforce a bound compatible with the remaining request/watchdog budget and isolate probe evaluation. Merely documenting that probes should return promptly does not satisfy this charter's explicit arbitrary-probe requirement. The borrowed closure runs on the caller, so the issue is availability, not unsound lifetime erasure.

### C34-R3-02 ? P2 ? worker-boundary cancellation omits the adopted reason

Clause: SI-111 interim ruling and ADR-0020 decision 8. Permanent reproduction: `crates/executor/tests/c34_r3_edges.rs::worker_boundary_refusal_identifies_cancellation_reason` (fails). A deterministic probe returns false before enqueue and at dequeue, then true at invocation start. Required: `command.timeout` with `details.reason: "cancelled"`. Observed: `command.timeout`, but `details.reason` is absent (`Null` in the assertion); `cancelled_check` supplies only `commandId`. This makes the record indistinguishable from watchdog expiry despite the adopted interim shape. Fix direction: retain the cancellation cause through worker checks and emit the SI-111 reason for caller cancellation, including step/acceptance/pre-commit paths; do not relabel genuine watchdog expiry as caller cancellation. The request is safely refused; no committed change is demonstrated here.

### C34-R3-03 ? P2 ? a marked queued request masks real worker death

Clause: ADR-0020 decision 8, queued discard versus real death; explicit round-3 ruling that real death must answer `internal`. Permanent reproduction: `crates/executor/tests/c34_r3_edges.rs::cancelled_queued_request_reports_real_worker_death_as_internal` (fails). Suspend an earlier request at the test-only `Committed` boundary for 300 ms, enqueue a second live request, let its caller cancellation mark its token, then panic the worker in the earlier request. Required: the queued request reports `internal` because the worker died without sending `Discarded`. Observed: it reports `command.timeout`; a following query returns `internal`, independently confirming actual death. In `call_with`, reply disconnection plus `marked` is treated as cancellation even without an explicit discard notice. Fix direction: use positive `Discarded` evidence to classify intentional dequeue refusal; a marked token alone cannot establish worker survival or intentional discard. This is a bounded diagnostic gap, distinct from the closed original C34-R2-04 reproduction. No additional product panic path is introduced by this reviewer test: it uses the existing gated hook.
