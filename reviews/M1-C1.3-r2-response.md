**C13-R2-01 in detail.**
- **Dirty check.** `resolve_unsaved` and `save_now` treat the project as unsaved when the live project is modified
  **or** the invocation has staged or sealed changes (`persistence::unsaved`). An atomic batch's own edits are
  therefore saved.
- **Stamp inside an atomic batch.** `save_now` no longer seals. When the batch's steps have succeeded,
  `batch_atomic` stamps `modifiedAt` into the batch's own staged changes (`stamp_staged`). The batch commits as
  one transaction and one undo step. A transaction sealed during a batch is now an internal error instead of being
  dropped.
- **One revision.** The pending save takes its snapshot just before the commit, from the document the commit
  installs (`txns.last().after`). The file therefore holds exactly the committed revision.
- **After the commit.** The clean marker goes to the history position the commit reached (`apply_pending`), then
  the Close and Quit effects run.
- **Unchanged.** Dry runs and failed batches still write nothing (the R1 regressions pass), and the frozen-entry
  guard still runs before the write.

**C13-R2-03 in detail.**
- **Assets and pens** (items of the project's lists) are replaced by name. The replacement takes a fresh ID, because
  media entry names embed the asset ID and undo must find the old bytes under the old name. Every reference to the
  old ID in the document follows: placements, media sequences, strokes' `penId`, everything outside the opaque
  `meta`/`ext`.
- **`idPolicy: "preserve"` ID conflicts** are replaced too: scenes, elements (wherever they are, removed as
  `edit.delete` removes them), assets and pens.
- **Latent bug fixed:** under `preserve`, ID conflicts used to be collected whatever the policy, and failed
  `rename`/`replace` at the end. They now fail only under `fail`.
- **Policies for assets and pens:** both now follow `rename` (07 §2.3: "a different file with an already-used name
  gets a unique name") and `fail`. Pens used to rename even under `fail`.
- The whole import is one patch and one undo step.

**C13-R2-05 in detail.** `MAX_COMPONENT_BYTES` is 200 UTF-8 bytes:
- APFS limits a component to 255 UTF-8 bytes.
- NTFS limits it to 255 UTF-16 units, which is never more than the UTF-8 byte count.
- A folder save creates hidden siblings `.<name>.<12 hex>.tmp` / `.old`, 18 bytes longer than the name.

**C13-R2-06 in detail.**
- `journal::apply` runs the ordinary replacements, then the removals, then `manifest.json`.
- Recovery that completes a save (`apply_pending`) uses the same order.
- `FolderOptions::crash_after_renames == renames` now stops after the last rename, before the journal is deleted.
