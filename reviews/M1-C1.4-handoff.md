## What was built

### `tt-mcp` (`crates/mcp`)

- **`server.rs`**: an MCP server, revisions 2025-06-18 and 2025-11-25, over newline-delimited JSON-RPC 2.0.
  - **Lifecycle:** `initialize` (version negotiation; `instructions` equals `app://docs/agent-guide`;
    `_meta.toontown` carries `{registryVersion, formatVersion, runMode, sessionId, policy, scopes}`), `ping`.
  - **Tools:** `tools/list` and `tools/call`; `structuredContent` is the command envelope and `outputSchema` is the
    envelope schema, with annotations.
  - **Resources:** `resources/list`, `resources/templates/list`, `resources/read`, `resources/subscribe` and
    `resources/unsubscribe`, with `notifications/resources/updated` coalesced to one per resource per 100 ms.
  - **Other methods:** `prompts/list` and `prompts/get`; `completion/complete`; `logging/setLevel` with events as
    `notifications/message`; `notifications/progress` and `notifications/cancelled`;
    `notifications/tools/list_changed`.
  - **Requests to the client:** `elicitation/create` (confirmations) and `roots/list` (the client's roots join the
    session's).
  - **Threading:** requests run in arrival order on one call thread; `job_wait` waits on its own thread (ADR-0015 §6).
- **`tools.rs`**:
  - The 28 generic tools of 11 §7 and their mapping onto commands.
  - Typed tools: `.` becomes `_` and the command's own schema is used.
  - `pointer` answers `command.notImplemented` with milestone M2 C2.3; `key` and `type_text` with M4 C4.2.
- **`resources.rs`**: 8 resources and 10 templates, each read through a registry command.
- **`prompts.rs`**: the ten prompts of 11 §12. **`docs.rs`**: the agent guide, object model, coordinates, errors, and
  one doc per namespace with an example per command. **`jsonrpc.rs`**: the parser and error codes.
- **`script.rs`**: batch-script mode. It replays a `batch` input as an agent session named `batch-script` and writes a
  JSON-lines log (`start`, one `step` per step, `end`).

### Executor (`tt-executor`)

- **Agent hub** (`agents.rs`): sessions, policies, scopes (never `app`), roots, limits.
  - Confirmation tokens (`cf_…`) are single use, live five minutes, and are bound to the session, command, parameter
    fingerprint, `documentRev` and an optional condition binding.
  - Activity entries have redacted parameters.
  - `Cx::confirm` raises a confirmation from any handler; `run()` turns it into `needs_confirmation`.
  - `invoke_audited`, `batch_audited` and `audit_call` record exactly one entry per call.
- **Confirmation categories:**
  - **overwrite:** `project.saveAs`, `project.create`, `doc.package.export`, `doc.asset.export`, `doc.export.json`,
    `agent.activity.export`;
  - **destructive:** `doc.asset.remove`;
  - **discard:** `onUnsaved: discard`;
  - **externalChange:** `project.save` (SI-045).
- `app.info.get`; `app.state.get` lists the agent sessions.

### Headless binary

`toontown-headless --mcp-stdio | --run <batch.json>` takes these options:
- `--project` (waits for the open job);
- `--out` (the batch log);
- `--policy`, `--grant`, `--allow-path` (repeatable), `--preauthorize`;
- `--typed-tools [ns,…]` (MCP mode only);
- `--user-dir` (default: the platform folder).

Exit statuses: 0 ok, 1 failure, 2 usage error or an invalid batch, 4 I/O, 5 a batch step failed.

### 1–2. Write exclusivity, PID reuse and clocks (ADR-0014 §11.4–§11.5)

**Design.** The holder keeps its lock file, and every arbiter its `.takeover` file, open for its whole life:
- Windows: a write handle shared for read, write and delete;
- elsewhere: an exclusive `flock`.

`lock::probe` proves a live holder. On Windows it opens the file while refusing to share writing; elsewhere it takes a
shared `flock`. The kernel releases the handle or `flock` at process death. Consequences:
- a protected lock that probes *held* is never stale, whatever the heartbeat, the clocks or the PID say;
- a protected lock of this host that probes *free* is taken over at once (PID reuse no longer matters);
- a protected arbiter is never removed as abandoned;
- ages and PIDs apply only where the probe cannot answer;
- `process_alive` is bounded (2 s);
- a heartbeat and a publication read back and check their arbiter, and a resumed participant that lost either fails
  closed.

Saves check ownership again when they finish: under lost ownership the clean marker and stamp do not advance, and the
session goes read-only.

**Tests.** `crates/executor/tests/c14_lock_races.rs` suspends one participant deterministically through
`tt_persist::lock::hooks` (`test-hooks`) and races eight openers. The suspended participants:
- a publisher at `ArbiterTaken`, `PublishCreated` and `PublishWritten`;
- a heartbeat at `HeartbeatChecked` and `HeartbeatWritten`;
- a release at `ReleaseChecked`;
- a takeover at `TakeoverDecided`.

In every case there is at most one `Acquired`, and the resumed participant keeps or loses ownership correctly. The
file also covers:
- an arbiter paused past its 10 s abandonment age (real wait), never removed;
- a resumed heartbeat whose lock was replaced, which fails closed and writes nothing;
- a reused PID (a protected lock naming our own live PID), taken over;
- clock jumps both ways: unit test `lock::tests::a_live_lock_is_protected_and_never_stale`; future-dated unprotected
  locks are bounded by file age;
- a **crashed holder process** (the test binary re-run as a child and killed), taken over.

The suite runs on NTFS locally and on APFS in CI (macOS `check`).

**Measured (Windows):**
- probe of a held lock: p50 4.3 µs, p99 6.8 µs;
- `acquire` on a held lock: p50 67 µs;
- crashed holder taken over 8 ms after the kill;
- `process_alive` fallback: 25 ms (bound 2 s).

`measurements/lock-liveness-windows.json` lists every liveness bound.

**Change during C1.4.** The first version protected the Windows lock with a read-only share mode, which made the lock
file impossible to replace. Two C1.3 reviewer regressions (`crates/persist/tests/c13_r3_format.rs`,
`c13_r4_lock.rs`) act as a foreign writer that replaces or overwrites the lock, and they failed. The reviewer tests
were left untouched; the protection was reworked (`cbad15e`) so that foreign replacements stay possible and are caught
by the token checks, while liveness stays kernel-backed.

### 3. NFC/NFD and case

`project.saveFailed`, reason `nameCollision` with both names. The package keeps both names byte for byte. An existing
on-disk spelling of a kept entry is never scheduled for removal, so nothing is overwritten and no journal entry
collides.

5. **Obligation 5 "under queued MCP requests"** was measured with queued executor calls. MCP calls enter the same
   executor queue through the server's single call thread. Owner: none, unless the reviewer asks for a protocol-level
   run.
6. **E7's `network` half** (a `network` command answers `permission.denied` under Assist) has no command to run: no
   M1 command declares the `network` scope. The scope check is generic (`c12_policy.rs` covers other scopes). Owner:

7. **Temporary folders.** Tests leave `%TEMP%\tt-*` folders when they fail, and the debug `target/` grows large (82 GB

   hygiene ticket.
