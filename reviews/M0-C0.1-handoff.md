## How to build, run and test

Windows (this machine) and macOS use the same commands from the repository root (see `docs/dev-setup.md`):

```sh
pnpm install --frozen-lockfile
pnpm --dir desktop build
cargo test --workspace && cargo clippy --workspace --all-targets -- -D warnings && cargo deny check
pnpm lint && pnpm typecheck && pnpm test && pnpm format:check && pnpm licenses:check
cargo run -p tt-headless -- --selftest
pnpm --dir desktop tauri dev                          # interactive
pnpm --dir desktop tauri build --bundles nsis         # macOS: --bundles app
target/release/toontown(.exe) --ipc-bench out.json    # automated IPC latency benchmark
```

macOS on a real Mac: `docs/manual-tests/M0-C0.1-shell-macos.md` (download CI artifacts, remove quarantine, check the
menu bar, layout, IPC readout, `--ipc-bench`, headless self-test).

markedly faster than WebView2 for large JSON payloads (1 MiB p50 5 ms vs 20 ms locally / 41 ms on the runner), which
the C0.3 binary-IPC measurements will revisit.

## Known gaps (explicit, nothing silently narrowed)

1. **Menu clicks not driven interactively on Windows.** Menu construction, ids, enablement, accelerators and dispatch
   (`resolve`) are unit-tested; the window was launched and captured; but I did not inject clicks/keystrokes into the
   native menu (injecting input into the user's desktop session is unsafe here). The macOS manual script covers the
   interactive menu checks; the Windows equivalent is the same procedure with Ctrl/F11/Alt+F4. Tell me if you want an
   automated UI-driving test (e.g. WebDriver via `tauri-driver`, which supports Windows only) added now rather than in M4.
2. **Edit-menu accelerators vs. text fields.** Edit items are custom (bound to `edit.*` command ids, disabled with no
   project). Once text inputs exist, native Cut/Copy/Paste inside webview text fields needs focus-aware routing
   (macOS needs Edit-menu items for ⌘C/⌘V in WKWebView; Windows accelerator tables swallow Ctrl+C even when the item
   is disabled). Deferred to M4 (C4.1, 01 §6.2).
3. **`app.quit` does not yet apply the unsaved-changes rule** (01 §1.2): no project can be open in M0. M1 routes it
   through the executor with `onUnsaved`.
4. **Ctrl+Y as a secondary Redo on Windows** (01 §6.1) needs the keymap (one accelerator per menu item); M4.
5. **macOS build is arm64 only** (`macos-latest` is Apple Silicon). Universal/x86_64 builds are M11 packaging unless
   the user's Mac is Intel.
6. **Unsigned bundles.** macOS needs `xattr -dr com.apple.quarantine`; Windows SmartScreen may warn. Signing and
   notarisation are M11.
7. **Wire types are hand-written** on both sides (`ipc/types.ts` vs Rust structs). From M1 they are generated from
   the registry's JSON Schemas.
8. **`desktop/src/diagnostics/` and the `--ipc-bench` flag are M0 measurement hooks**, not spec commands; they are
   unreachable from the menu and from agents and will be removed or gated behind a dev build after M0. They are not
   under `src/spikes/` because they instrument the product shell rather than prototype a feature; C0.2/C0.3 reuse them.
