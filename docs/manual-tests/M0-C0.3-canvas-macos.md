# M0 C0.3 — Canvas throughput on macOS (manual, user-run)

**What this is.** Toontown draws its canvas inside a web view (WKWebView on macOS). This test measures how fast the
web view can draw large vector scenes that the app's Rust side sends it:
- 100 000 curves;
- 1 000 moving groups;
- 10 000 brush strokes.

It runs by itself for about two minutes, pans and zooms each scene for 10 seconds, saves one log file, and quits. You
do not judge anything. The numbers are computed from the file afterwards.

**You need:** an Apple Silicon Mac with macOS 12 or newer, and about 5 minutes. A laptop should be plugged in. Use
the built-in display or one external display, not mirrored. Optional: Python 3, to print the results table yourself.

## 0. Get the build

Same download as the tablet test (`docs/manual-tests/M0-C0.2-tablet-macos.md` step 0). If you already unpacked a
build there, download the newest one again: the canvas test needs the build from the C0.3 branch head.

1. Open <https://github.com/kaigani/261017-toontown-dev/actions?query=branch%3Am0-foundations> and click the most
   recent run with a green tick.
2. Under **Artifacts**, download **`desktop-macOS`**.
3. In Terminal:
   ```sh
   mkdir -p ~/toontown-m0 && cd ~/toontown-m0
   rm -rf desktop && unzip -o ~/Downloads/desktop-macOS.zip -d desktop
   tar -xzf desktop/Toontown-macos-arm64.app.tar.gz -C desktop
   xattr -dr com.apple.quarantine desktop/Toontown.app
   ```
   The top-level `Toontown-macos-arm64.app.tar.gz` is the **M0 diagnostics build**, which these steps need. The
   `default-build/` folder in the same artifact is the product build without diagnostics; it refuses `--ipc-bench`
   and `--spike` (C0.4), so do not use it here.
   If Safari already unpacked the zip into `~/Downloads/desktop-macOS`, replace the `unzip` line with
   `rm -rf desktop && mkdir desktop && cp -R ~/Downloads/desktop-macOS/. desktop/`.

## 1. Run it (one command)

Close other heavy apps, then paste:

```sh
~/toontown-m0/desktop/Toontown.app/Contents/MacOS/toontown --spike canvas --spike-log ~/toontown-m0/canvas-mac.json --spike-auto
```

What you should see:
- the window opens, fills the screen, and its first line reads **"C0.3 canvas throughput spike — not product UI.
  Back ends: …"**;
- the canvas shows thousands of coloured curves, then blobs in a grid, then brush strokes. Each set slowly zooms in
  and out and drifts in a circle for 10 seconds;
- a table under the canvas fills in one row per scene;
- if the first line lists `webgpu, webgl2`, everything runs twice: first with WebGPU, then with WebGL2;
- after about 1–3 minutes the app quits by itself, and Terminal shows the prompt again.

While it runs, **do not click, type or move the window**, and keep it in front: macOS slows down hidden or covered
windows, which would spoil the numbers.

If the app has not quit after 5 minutes, press ⌘Q and note that in your message. The log is then missing, which is
also a result.

## 2. Run it once more with WebGL2 only

WebGL2 is the path every supported Mac has, so it is measured on its own as well:

```sh
~/toontown-m0/desktop/Toontown.app/Contents/MacOS/toontown --spike canvas --spike-log ~/toontown-m0/canvas-mac-webgl2.json --spike-auto --spike-renderer webgl2
```

The first line now says `Back ends: webgl2 (forced with --spike-renderer webgl2)`.

## 3. Optional: print the results table

```sh
python3 ~/toontown-m0/desktop/analyse-canvas-log.py ~/toontown-m0/canvas-mac.json > ~/toontown-m0/canvas-mac-results.md
python3 ~/toontown-m0/desktop/analyse-canvas-log.py ~/toontown-m0/canvas-mac-webgl2.json >> ~/toontown-m0/canvas-mac-results.md
open -e ~/toontown-m0/canvas-mac-results.md
```

## 4. Send the files back

Reply through the channel you received this request on, attaching:
- `~/toontown-m0/canvas-mac.json` and `~/toontown-m0/canvas-mac-webgl2.json` (required). If they are too large for
  your channel, compress them first: `gzip -k ~/toontown-m0/canvas-mac*.json`;
- `canvas-mac-results.md` if you made it;
- your **Mac model** and **display** (e.g. "MacBook Pro 14-inch M3, built-in ProMotion display");
- anything odd: stutter you could see, a blank canvas, error text in the table.

## How the results are read (for the reviewers)

`scripts/analyse-canvas-log.py` validates the log and recomputes every number from raw per-frame samples. It
rejects version mismatches, missing runs and incomplete samples. Per back end and scene it reports:
- bytes and time per render-list transfer;
- Rust encode time, decode time and upload time;
- display refresh, fps, frame-interval p50/p95/max and long frames;
- CPU and GPU frame times.

| Criterion | Target | Note |
|---|---|---|
| 60 fps pan/zoom, 100 000 paths | fps ≥ 57 ("met"); display refresh reported beside it | recorded per back end; "missed" is a result, not a test failure |
| WebGL2 works on its own | the forced-WebGL2 log has 3 successful runs | mandatory path (plan §2.3) |
| WebGPU | recorded if `navigator.gpu` yields an adapter | otherwise the run says why ("requestAdapter() returned null", …) |

The log records the macOS build (`sw_vers`), the WebKit version, the GPU string WebKit exposes (usually only "Apple
GPU"), the device pixel ratio and the canvas size.
