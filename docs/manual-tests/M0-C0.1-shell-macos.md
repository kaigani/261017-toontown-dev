# M0 C0.1 — Desktop shell and headless binary on macOS (manual, user-run)

Purpose: confirm on a real Mac that the CI-built, unsigned app launches in WKWebView, shows the native menu bar
including the macOS application menu, lays out the three dockview panels, and that IPC works; and that the headless
binary runs. CI already builds both and runs the automated IPC benchmark on the `macos-latest` runner; this script
covers what a runner cannot show (the menu bar and the window as a person sees it).

Time needed: about 10 minutes. Record results in the table at the end and send it back to the orchestrator.

## 0. Get the build

1. Open the repository's **Actions** tab on GitHub, open the latest green `ci` run on branch `m0-foundations`.
2. Download the artifacts **`desktop-macOS`** and **`headless-macOS`** (zip files).
3. In Terminal:
   ```sh
   mkdir -p ~/toontown-m0 && cd ~/toontown-m0
   unzip ~/Downloads/desktop-macOS.zip -d desktop
   unzip ~/Downloads/headless-macOS.zip -d headless
   tar -xzf desktop/Toontown-macos-arm64.app.tar.gz -C desktop
   # The build is unsigned; remove the download quarantine so Gatekeeper lets it start:
   xattr -dr com.apple.quarantine desktop/Toontown.app headless
   chmod +x headless/toontown-headless
   ```
   The top-level `Toontown-macos-arm64.app.tar.gz` is the **M0 diagnostics build**, which these steps need. The
   `default-build/` folder in the same artifact is the product build without diagnostics; it refuses `--ipc-bench`
   and `--spike` (C0.4), so do not use it here.
   The build is **Apple Silicon (arm64) only**. On an Intel Mac, stop and report "Intel Mac — needs x86_64 build".

## 1. Headless binary

```sh
./headless/toontown-headless --version
./headless/toontown-headless --selftest
```
Expected:
- `--version` prints `toontown-headless 0.0.1 (Toontown 0.0.1; format 0.0; registry 0.0.0; macos-aarch64)`.
- `--selftest` prints five `[ok]` lines (`engine.components`, `engine.versions`, `engine.ping`,
  `determinism.ieee754`, `headless.mcpLinked`) and ends with `self-test passed`. The `determinism.ieee754` line
  shows hash `d22c8ec2eb9c269ed207f8421f83e96edcf58774894cfad3186b5e2169ad5a16` — the same as on Windows.

## 2. Launch the app

```sh
open desktop/Toontown.app
```
Expected:
- A window titled **Toontown** opens (about 1280 × 800) with a dark interface.
- If macOS says the app "is damaged" or "cannot be opened", re-run the `xattr` command above and retry; if it still
  refuses, use right-click › Open once. Report which was needed, **with the exact text of the macOS dialog** (a
  screenshot of that dialog is fine). Only a reported Gatekeeper/signing dialog is treated as a signing matter (M11).

### 2a. If the app still does not open, or quits or crashes (no Gatekeeper dialog)

Do not retry further. Run these and send all output. They show *why* it failed, and no conclusion about the macOS
shell or the platform floor is drawn until that is known.

```sh
cd ~/toontown-m0
sw_vers; uname -m                                           # macOS version and CPU architecture
file desktop/Toontown.app/Contents/MacOS/toontown           # must say arm64
./headless/toontown-headless --selftest                     # does the engine run on this Mac at all?
./desktop/Toontown.app/Contents/MacOS/toontown 2>&1 | tee launch-stderr.txt   # start directly; wait 10 s, then Ctrl-C
log show --last 5m --style compact --predicate 'process == "toontown"' > launch-log.txt
ls -t ~/Library/Logs/DiagnosticReports/ | grep -i toontown | head -3     # crash reports, newest first
```

Attach `launch-stderr.txt`, `launch-log.txt` and the newest `toontown*.ips` file from
`~/Library/Logs/DiagnosticReports/`, if one exists.

## 3. Menu bar

Expected, in the system menu bar while Toontown is frontmost:
1. **Toontown** (application menu): About Toontown · Settings… (⌘,) · Services · Hide Toontown (⌘H) · Hide Others
   · Show All · Quit Toontown (⌘Q).
2. **File**: New Project… (⌘N) · Open… (⌘O) · Close Project (⌘W, greyed) · Save (⌘S, greyed) · Save As… (⇧⌘S,
   greyed). No Exit/Preferences item in File on macOS.
3. **Edit**: Undo, Redo, Cut, Copy, Paste, Delete, Select All — all greyed (no project is open, spec 01 §1.3).
4. **View**: Reset View (greyed) · Restore Default Workspace · Toggle Full Screen (⌃⌘F).
5. **Help**: Toontown Help. (No About item here on macOS.)

Then:
- Choose **File › New Project…** → status bar (bottom left) shows `project.create is not implemented yet (M1
  (command), M4 (dialog))` in amber.
- Drag the **Timeline** tab onto the right of the window (so the layout changes), then choose **View › Restore
  Default Workspace** → the layout returns to Drawing (large, top left), Timeline (below it), Properties (right,
  full height). Status bar shows `workspace.reset done`.
- Press **⌃⌘F** → the window goes full screen; press it again → it leaves full screen.
- **Toontown › About Toontown** → a native About panel with name Toontown and version 0.0.1.

## 4. Panels and IPC readout

Expected:
- Three panels with tabs **Drawing**, **Timeline**, **Properties**; Properties shows *No properties / Nothing is
  selected.*
- Status bar, right side: `IPC ping (tauri): <n> ms` updating about once a second, and `Toontown 0.0.1 ·
  macos-aarch64`.
- Click **Measure 500** → after a second or two the readout adds `burst n=500 p50 … p95 … max … ms`. Write down the
  three numbers.

## 5. Automated benchmark (same as CI, on your machine)

```sh
./desktop/Toontown.app/Contents/MacOS/toontown --ipc-bench ~/toontown-m0/ipc-bench-mac.json
cat ~/toontown-m0/ipc-bench-mac.json
```
Expected: the window opens briefly and closes by itself within ~30 s; the file contains `"ok": true` and four
bursts (0, 1024, 65536, 1048576 bytes). Send the file back.

## 6. Quit

- **⌘Q** quits immediately (no project is open, so there is no unsaved-changes prompt yet).
