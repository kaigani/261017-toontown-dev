# M0 C0.2 — Tablet input on macOS (manual, user-run)

**What this is.** Toontown is a desktop animation app in development. Before building its drawing tools we need to
know what a real drawing tablet delivers on a Mac through the two ways the app can read it:

- **Web path:** pointer events inside the app's web view (Apple's WKWebView, the same engine as Safari): pressure,
  tilt, twist, and `getCoalescedEvents()`.
- **Native path:** AppKit `NSEvent` tablet events read by the app itself and sent to the page.

You draw a few strokes in a test window, save one JSON file, and send it back. Nothing is installed on your Mac and
nothing is sent anywhere automatically. You do **not** need to judge the results: every number is computed from the
file. A tablet that reports fewer than 200 samples per second is recorded as **below target**, which is a result,
not a failure of the test.

**You need:** an Apple Silicon Mac (M1 or later) with macOS 12 or newer; a pressure-sensitive tablet with its driver
installed and working (Wacom, XP-Pen, Huion, …); about 15 minutes. Optional: Python 3 (macOS offers to install it the
first time you type `python3` in Terminal) to print the results table yourself.

## 0. Get the build

1. Open <https://github.com/kaigani/261017-toontown-dev/actions?query=branch%3Am0-foundations> and click the most
   recent run with a green tick.
2. At the bottom of the run page, under **Artifacts**, download **`desktop-macOS`** (a zip). You need to be signed in
   to GitHub to download artifacts.
3. Open **Terminal** (Applications › Utilities) and paste these lines (they unpack the app into `~/toontown-m0` and
   clear the "downloaded from the internet" flag, because this test build is not signed):
   ```sh
   mkdir -p ~/toontown-m0 && cd ~/toontown-m0
   rm -rf desktop && unzip -o ~/Downloads/desktop-macOS.zip -d desktop
   tar -xzf desktop/Toontown-macos-arm64.app.tar.gz -C desktop
   xattr -dr com.apple.quarantine desktop/Toontown.app
   ```
   If `unzip` says the file does not exist, your browser saved it elsewhere or already unpacked it: use the path of
   the downloaded `desktop-macOS.zip` (or of the folder it was unpacked into) instead.

## 1. Start the test window

Paste this into Terminal (it also sets where the log file is written):

```sh
~/toontown-m0/desktop/Toontown.app/Contents/MacOS/toontown --spike tablet --spike-log ~/toontown-m0/tablet-mac.json
```

You should see a window titled Toontown whose first line reads **"C0.2 tablet input spike — not product UI. Native
backend: appkit-nsevent"**, a light-grey canvas, a row of buttons, two tables (**Web path** and **Native path**) and
a box **About this run (saved with the log)**.

- If you see a different layout (panels named Drawing / Timeline / Properties), the command was not copied fully.
  Close the window and paste it again.
- If macOS says the app "cannot be opened", run the `xattr` line from step 0 again.

Click **Start native listener**. The status text next to the buttons should change to
`Native listener running (appkit-nsevent).` If it says `Native listener failed: …`, carry on anyway and include that
text in your message.

## 2. Fill in "About this run"

Type into the boxes (they are saved inside the log file; nothing is uploaded):

| Box | Where to find it |
|---|---|
| Computer | Apple menu › About This Mac (e.g. "MacBook Pro 14-inch, M3, 2023") |
| macOS / Windows version | Apple menu › About This Mac; click the version to see the build (e.g. "15.3 (24D60)") |
| Safari / WebKit version | Open Safari › Safari menu › About Safari (e.g. "18.3 (20620.2.4.11.5)") |
| Tablet model | On the tablet's label or in the driver app (e.g. "Wacom Intuos Pro M, PTH-660") |
| Tablet driver version | The driver app's About box (e.g. Wacom Center › About) |
| Your name, Notes | Optional; note anything unusual (other pen, display tablet, Sidecar, …) |

## 3. Draw five strokes

Draw each stroke **as one continuous stroke**, then **lift the pen**, then start the next. Do them in this order and
do not click **Clear**. The tables update four times a second; the lower table in each column lists the most recent
strokes, one row each, numbered in the order you drew them. If you make a mistake, just carry on and say so in your
message (e.g. "stroke 3 was a mistake").

| # | Stroke | How |
|---|---|---|
| 1 | **Pressure ramp** | One slow horizontal line over about 5 seconds, from the lightest touch you can make to full force. |
| 2 | **Speed** | About 5 seconds of fast small circles at medium pressure, without lifting the pen. |
| 3 | **Tilt** | Put the tip on one spot, keep it there, and tilt the pen slowly left, right, towards you and away (about 5 s). |
| 4 | **Barrel rotation** (only if your pen reports it, e.g. Wacom Art Pen; otherwise skip) | Keep the tip on one spot and roll the pen between your fingers. |
| 5 | **Hover** (no contact) | Move the pen about 5 mm above the surface across the canvas without touching it. |

Blue dots are the web path (bigger = more pressure); small red dots are the native path. Both should follow the pen.

## 4. Save the log and quit

Click **Save log**. The status text shows `Log saved: /Users/<you>/toontown-m0/tablet-mac.json (<n> bytes).` If it
also says `Not filled in: …`, fill in those boxes and click **Save log** again (it overwrites the same file). Then
quit with ⌘Q.

## 5. Optional: print your results table

The download contains the analysis script. In Terminal:

```sh
python3 ~/toontown-m0/desktop/analyse-tablet-log.py ~/toontown-m0/tablet-mac.json > ~/toontown-m0/tablet-mac-results.md
open -e ~/toontown-m0/tablet-mac-results.md
```

It prints the environment, then one table row per stroke for each path (samples, duration, samples per second and
whether that meets the 200 Hz target, intervals, pressure levels, tilt, twist) and the web path's coalescing and
latency figures. This is exactly what the reviewers compute from your file; you do not need to interpret it.

## 6. Send the files back

Reply through the same channel you received this request on (GitHub issue or pull-request comment, chat or e-mail),
attaching:

- `~/toontown-m0/tablet-mac.json` (required). If it is larger than your channel allows, compress it first:
  `gzip -k ~/toontown-m0/tablet-mac.json` and send `tablet-mac.json.gz`.
- `~/toontown-m0/tablet-mac-results.md` if you made it in step 5.
- One or two sentences on what you saw: visible lag, gaps in the dots, dots not following the pen, error messages.

## How the results are read (for the reviewers)

All values come from `scripts/analyse-tablet-log.py` on the returned log (it recomputes everything from the raw
samples and rejects unknown log versions). Strokes are contact episodes: web = pointerdown..pointerup; native = mouse
down (or the first tablet point with pressure) .. mouse up, proximity-out, or pressure returning to zero.

| Criterion | Stroke | Recorded value | Target |
|---|---|---|---|
| Pen recognised | 1–3 | web `pointer` = `pen#…`; native tool `pen` (or `eraser` when the eraser end is used) | pen on both paths |
| Pressure resolution | 1 | `pressure levels (distinct / implied)`: distinct values observed, and the grid implied by the smallest step | reported next to the hardware specification; the driver's pressure curve can change both, so neither proves hardware resolution on its own |
| Tilt | 3 | `tilt` yes; ranges in the header lines | present, spanning ≥ ±30° |
| Rate | 2 | `Hz`, `vs 200 Hz` | ≥ 200 Hz meets target; lower is **below target** (record the value; not a failure) |
| Loss | 1–2 | `loss`: on a real tablet there is no reference stream, so it reads `unknown, gap heuristic only`; `>2x median` intervals are listed as a heuristic | reported, not certified |
| Coalesced events (web) | 2 | API available (yes/no) and batching observed, separately; per-dispatch counts | recorded |
| Twist | 4 | `twist` non-zero count | non-zero if the pen has barrel rotation |
| Latency (web) | 2 | handler − event: oldest coalesced, newest, all samples | recorded, no threshold in M0 |

A web-path value that is worse than the native path's on the same stroke is exactly the evidence C0.4 needs; it is
a result, not a failed run. The log also records the macOS build (`sw_vers`), WebKit version (user agent), backing
scale and window geometry, so the environment does not have to be reconstructed later.
