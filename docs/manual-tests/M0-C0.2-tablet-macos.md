# M0 C0.2 — Tablet input on macOS (manual, user-run)

Purpose: measure what a **real tablet** delivers on your Mac through both input paths of the spike, so the go/no-go
report (C0.4) can decide whether WKWebView pointer events are good enough or the native fallback is needed:

- **Web path:** pointer events inside the app's webview (WKWebView): pressure, tilt, twist, `getCoalescedEvents()`.
- **Native path:** AppKit `NSEvent` tablet events read by the Rust host and streamed to the page. (`octotablet`, the
  plan's native library, has no macOS support, so the macOS native path uses AppKit directly.)

Assumes an Apple Silicon Mac and a pressure-sensitive tablet with its driver installed (Wacom, XP-Pen, Huion…).
Time needed: about 15 minutes. You send back one JSON file.

## 0. Get the build

1. Open the repository's **Actions** tab, then the latest green `ci` run on branch `m0-foundations`.
2. Download the **`desktop-macOS`** artifact (a zip).
3. In Terminal:
   ```sh
   mkdir -p ~/toontown-m0 && cd ~/toontown-m0
   rm -rf desktop && unzip -o ~/Downloads/desktop-macOS.zip -d desktop
   tar -xzf desktop/Toontown-macos-arm64.app.tar.gz -C desktop
   xattr -dr com.apple.quarantine desktop/Toontown.app
   ```
4. Write down: Mac model, macOS version (Apple menu › About This Mac), tablet model, pen model, driver version.

## 1. Start the spike (one command; it also chooses where the log goes)

```sh
~/toontown-m0/desktop/Toontown.app/Contents/MacOS/toontown --spike tablet --spike-log ~/toontown-m0/tablet-mac.json
```

Expected: the window shows **"C0.2 tablet input spike — not product UI. Native backend: appkit-nsevent"**, a light
canvas, a toolbar, and two readout columns: **Web path (pointer events)** and **Native path (host listener)**. If the
window instead shows the normal Drawing/Timeline/Properties layout, the `--spike tablet` flag did not reach the app;
check the command.

Click **Start native listener**. The status line should say `Native listener running (appkit-nsevent).`

## 2. Strokes (draw on the canvas with the pen)

Do these in order; do not click **Clear** between them. The readouts update four times a second over the last 5000
samples.

| # | Stroke | How |
|---|---|---|
| A | **Pressure ramp** | One slow horizontal line over about 5 seconds, from the lightest touch you can make to full force. |
| B | **Speed** | About 5 seconds of fast small circles at medium pressure, without lifting the pen. |
| C | **Tilt** | Hold the pen tip still on one spot and tilt the pen slowly left, right, towards you and away for about 5 s. |
| D | **Barrel rotation** (only if your pen reports it, e.g. Wacom Art Pen) | Hold the tip on one spot and roll the pen. |
| E | **Hover** | Move the pen 5 mm above the surface across the canvas without touching. |

Blue dots are the web path (size follows pressure); small red dots are the native path. Both should follow the pen.

## 3. Save and send the log

Click **Save log**. The status line shows `Log saved: /Users/<you>/toontown-m0/tablet-mac.json (<n> bytes).` Quit with
⌘Q and send `~/toontown-m0/tablet-mac.json` to the orchestrator, with the notes from step 0 and any observations
(lag you can see, gaps in the dots, dots that do not follow the pen).

## Pass criteria (evaluated from the log; the readout shows the same numbers)

For **each** path, after strokes A–C:

| Criterion | Readout row | Pass |
|---|---|---|
| Pen recognised | `pointer types` (web) / native shows packets | web reports `pen`; native reports packets with tool `pen` |
| Pressure resolution | `pressure distinct / implied levels` | **implied levels ≥ 1024** where the tablet hardware has ≥ 1024 levels (record the hardware's spec); otherwise equal to the hardware's level count |
| Tilt | `tilt present (x range, y range)` | `yes`, with ranges spanning at least ±30° during stroke C |
| Rate | `rate (Hz, contact)` | **≥ 200 Hz** during stroke B (tablets typically report 133–266 Hz; record what you get) |
| No dropped samples | `gaps > 2× median` | **0** during strokes A–B at ≥ 200 Hz |
| Coalesced events (web only) | `coalesced events supported`, `coalesced per dispatch (p50 / max)` | `yes`, and p50 > 1 during stroke B (events arrive faster than frames) |
| Twist (if the pen has it) | `twist present` | `yes` during stroke D |
| Latency (web, informational) | `event → handler latency p50 / p95` | record the values; no threshold in M0 |

If the web path fails a criterion that the native path passes, that is exactly the evidence C0.4 needs. Report it;
it is not a failed test run.
