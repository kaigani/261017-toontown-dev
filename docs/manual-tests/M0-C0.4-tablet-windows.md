# M0 C0.4 — real-tablet session on Windows (T-W1)

**Status: pending user.** You need a Windows PC with a pen tablet or pen display (Wacom, or any Windows Ink pen).
This is the physical-pen counterpart of the synthetic C0.2 measurements; ADR-0009 cannot pick the Windows tablet path
without it. You draw six strokes in a test window, save one JSON file and send it back. Nothing is installed.

If you use the builder's PC, first deal with the two **Windows Security** prompts that have been open since
2026-10-17. Their dimming layer covers the desktop, so the pen cannot reach the test window. The builder does not
touch them.

## 0. Get the build

1. Open <https://github.com/kaigani/261017-toontown-dev/actions?query=branch%3Am0-foundations> and click the most
   recent run with a green tick.
2. Under **Artifacts**, download **`desktop-Windows`** and unzip it, e.g. to `C:\toontown-m0\desktop`.
   The top-level `toontown.exe` is the **M0 diagnostics build**, which this test needs. The `default-build\` folder is
   the product build without diagnostics; it refuses `--spike`.

## 1. Start the test window

In PowerShell:

```powershell
cd C:\toontown-m0
.\desktop\toontown.exe --spike tablet --spike-log C:\toontown-m0\tablet-win.json
```

Click **Start native listener**. The status should read `Native listener running (…)`. If it says
`Native listener failed: …`, carry on and include that text in your message.

## 2. Fill in "About this run"

| Box | Where to find it |
|---|---|
| Computer | Settings › System › About (device name and processor) |
| macOS / Windows version | `winver` (e.g. "24H2, OS build 26100.…") |
| Safari / WebKit version | write `WebView2` (the log records the exact runtime version itself) |
| Tablet model | the tablet's label or the driver app (e.g. "Wacom Intuos Pro M, PTH-660") |
| Tablet driver version | the driver app's About box; also say whether **Windows Ink** is on in the Wacom settings |
| Your name, Notes | In **Notes**, write the pen model and whether it supports **tilt** and **barrel rotation** (from its specification). |

## 3. Draw six strokes

Draw each stroke as one continuous stroke, lift the pen, then start the next. Keep this order and do not click
**Clear**.

| # | Stroke | How |
|---|---|---|
| 1 | **Pressure ramp** | One slow horizontal line over about 5 seconds, from the lightest touch to full force. |
| 2 | **Speed** | About 5 seconds of fast small circles at medium pressure, without lifting the pen. |
| 3 | **Tilt** | Tip on one spot; tilt the pen slowly left, right, towards you and away (about 5 s). |
| 4 | **Barrel rotation** (only if the pen supports it; otherwise skip) | Tip on one spot; roll the pen between your fingers. |
| 5 | **Hover** (no contact) | Move the pen about 5 mm above the surface across the canvas. |
| 6 | **Stationary pressure** | Tip on one spot, **do not move it**; press harder and lighter, slowly, three times (about 5 s). Lift. |

## 4. Save, optionally analyse, send back

1. Click **Save log**, then close the window.
2. Optional: `python desktop\analyse-tablet-log.py tablet-win.json > tablet-win-results.md`.
3. Send `tablet-win.json` (and the results file if you made it) through the usual channel. Add one or two
   sentences on what you saw: gaps in the dots, lag, dots not following the pen, errors.

## How the results are read (for the reviewers)

The analyzer's per-stroke tables feed the fixed rule set in `docs/decisions/ADR-0009-tablet-input.md` ("Decision",
Steps 0–3), for the web path W and the native candidate R (RealTimeStylus on the main window, which is the "native"
column of this log).
- If a row needs a native path and R does not pass it, the next experiments are E-H1 (decoded raw HID) and then E-D1
  (dedicated input window).
- **E1** (the WebView2 DevTools-protocol input trace) is run by the builder on the same hardware once it is
  available. It localises where updates are lost; it does not change the table.
- Synthetic runs (`--spike-auto`) are never evidence for this table.
