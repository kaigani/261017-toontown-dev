# M0 C0.4 — real-tablet session on Windows (T-W1)

**Status: pending user.** You need a Windows PC with a pen tablet or pen display (Wacom, or any Windows Ink pen).
This is the physical-pen counterpart of the synthetic C0.2 measurements; ADR-0009 cannot pick the Windows tablet path
without it. You draw six strokes in a test window, save one JSON file and send it back. Nothing is installed.

If you use the builder's PC, first deal with the two **Windows Security** prompts that have been open since
2026-10-17. Their dimming layer covers the desktop, so the pen cannot reach the test window. The builder does not
touch them.

## 0. Get the build

1. Open <https://github.com/kaigani/261017-toontown-dev/actions?query=branch%3Am0-foundations> and click the most
   recent run with a green tick.
2. Under **Artifacts**, download **`desktop-Windows`** and unzip it, e.g. to `C:\toontown-m0\desktop`.
   The top-level `toontown.exe` is the **M0 diagnostics build**, which this test needs. The `default-build\` folder is
   the product build without diagnostics; it refuses `--spike`.

## 1. Start the test window

In PowerShell:

```powershell
cd C:\toontown-m0
.\desktop\toontown.exe --spike tablet --spike-log C:\toontown-m0\tablet-win.json
```

Click **Start native listener**. The status should read `Native listener running (…)`. If it says
`Native listener failed: …`, carry on and include that text in your message.

## 2. Fill in "About this run"

| Box | Where to find it |
|---|---|
| Computer | Settings › System › About (device name and processor) |
| macOS / Windows version | `winver` (e.g. "24H2, OS build 26100.…") |
| Safari / WebKit version | write `WebView2` (the log records the exact runtime version itself) |
| Tablet model | the tablet's label or the driver app (e.g. "Wacom Intuos Pro M, PTH-660") |
| Tablet driver version | the driver app's About box; also say whether **Windows Ink** is on in the Wacom settings |
| Pen has tilt / Pen has barrel rotation | `yes` or `no`, from the pen's specification |
| Your name, Notes | Optional; in **Notes** write the pen model and anything unusual |

## 3. Do six actions (A1–A6)

First click once on an empty part of the page (not in a box), so the keys do not type into the form. Then, for every
action: press and release **Space**, do the action, lift the pen, press and release **Space** again.
- The line under the toolbar always says which action is next (`Next: A1 pressure ramp. Press Space to start (K =
  skip).`).
- The keys mark where each action starts and ends in the log. That is how the analysis tells your strokes apart from
  clicks on buttons and boxes, so do not skip the Space presses.
- A press counts when the key is **released**. Holding a key down does nothing extra, and a second press within half
  a second is ignored, so just press each key once, normally. The log records every Space/K press either way.
- If an action goes wrong, carry on with the next one and say so in your message (e.g. "A3 was a mistake").

Keep this order and do not click **Clear**.

| Action | What you do | How |
|---|---|---|
| **A1** | **Pressure ramp** | One slow horizontal line over about 5 seconds, from the lightest touch you can make to full force. |
| **A2** | **Speed** | About 5 seconds of fast small circles at medium pressure, without lifting the pen. |
| **A3** | **Tilt** | Put the tip on one spot, keep it there, and tilt the pen slowly left, right, towards you and away (about 5 s). |
| **A4** | **Barrel rotation** | Only if your pen has it (e.g. Wacom Art Pen): keep the tip on one spot and roll the pen between your fingers. If it has none, press **K** instead of Space to skip A4. |
| **A5** | **Hover** (no contact) | Move the pen about 5 mm above the surface across the canvas without touching it. |
| **A6** | **Stationary pressure** | Put the tip on one spot and **do not move it**. Press harder and lighter, slowly, three times (about 5 s). Then lift. |

## 4. Save, optionally analyse, send back

1. Click **Save log**, then close the window.
2. Optional: `python desktop\analyse-tablet-log.py tablet-win.json > tablet-win-results.md`.
3. Send `tablet-win.json` (and the results file if you made it) through the usual channel. Add one or two
   sentences on what you saw: gaps in the dots, lag, dots not following the pen, errors.

## How the results are read (for the reviewers)

The analyzer applies the fixed rule set in `docs/decisions/ADR-0009-tablet-input.md` ("Decision", Steps 0–3) and
prints it as `### Decision (ADR-0009 tablet rule set)`.
- It scores the web path W and the native candidate H (RealTimeStylus on the main window, the "native" column of
  this log).
- Raw HID (R) and a dedicated window (D) are not measured by this log. They are scored only after experiments E-R1
  and E-D1.
- **E1** (the WebView2 DevTools-protocol input trace) is run by the builder on the same hardware once it is
  available. It localises where updates are lost; it does not change the table.
- Synthetic runs (`--spike-auto`) are never evidence for this table.

### Action → contact episode (for the reviewers)

The analyzer assigns episodes to actions from the Space markers (`### Actions` table of its output), so the mapping
never relies on counting. For reference, a clean run maps as below.
- The web path sees only contacts on the canvas.
- The native path also records the clicks made before A1 (Start native listener, the form, the Notes box) as its
  first *k* episodes, and the Save click after A6.
- Those clicks lie outside every action span and are listed as "outside every action".

| Action | Pen without barrel rotation (A4 skipped with K) | Pen with barrel rotation |
|---|---|---|
| A1 | web episode 1, native episode k + 1 | web 1, native k + 1 |
| A2 | web 2, native k + 2 | web 2, native k + 2 |
| A3 | web 3, native k + 3 | web 3, native k + 3 |
| A4 | omitted (state `skipped`) | web 4, native k + 4 |
| A5 | performed, no events (hover is not a contact) | performed, no events |
| A6 | web 4, native k + 4 | web 5, native k + 5 |

An action marked done with no contact on a path reads "performed, no events". That is a measurement (for example,
A6 on a path that drops pressure-only updates), and it is distinct from "omitted" (skipped with K), "unfinished"
(saved mid-action) and "not recorded" (never reached).
